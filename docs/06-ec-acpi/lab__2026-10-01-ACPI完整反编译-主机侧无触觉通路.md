> 日期：2026-10-01
> 方法：从注册表零权限 dump 全部 ACPI 表 → ACPICA `iasl 20251212` 完整反编译 → 逐条归因

## 〇、一句话

> **在这台机器的 ACPI 里，不存在任何触觉 / LRA / 震动通路。**
> 全部 32 张表（761,859 字节，DSDT 反编译后 **100,645 行 ASL**）中，
> `LRA` / `HAPTIC` / `VIBR` / `MOTOR` / `AW869` / `CA4F` **命中 0 次**；
> 而一度可疑的 `MLR1` / `MLR2` / `MOFD` / `MMCM` / `MBGS` **已逐条归因到 EC 的功耗/热管理寄存器组**。

★ **关键点**：`HKLM\HARDWARE\ACPI` **普通用户可读**，不需要管理员。所以 ACPI 分析完全离线、零风险。

### 踩过的两个坑（后续别再犯）
1. `HKLM\HARDWARE\ACPI` 下 `SSD1`..`SSDS` 是**平级表键**，**不是** `SSDT` 的子键。只走 `DSDT`/`SSDT` 会**漏掉 30 张表**。
2. `iasl` 反编译模式**不能用 `-o <path>`**（报 `Option requires a single-character suboption: -o`）。正确用法：`iasl -e <SSDT...> -d <DSDT.bin>`，`.dsl` 自动落在输入旁边。

## 二、本机 ACPI 结构事实

### 2.1 I²C / SMBus 控制器（16 条）
```
\_SB.PC00.I2C0 … I2C7     ← 8 条（PCH）
\_SB.PC02.I2C0 … I2C7     ← 8 条
+SBUS                     ← 另有 SMBus 节点
```
触控板：`\_SB.PC00.I2C0.TPAD`（`ACPI\GXTP5100\1`，从地址 1，400 kHz）

### 2.2 EC 命名空间
```
\_SB.PC00.LPCB.EC0.*      ← 141 处引用（分布在 DSDT + SSDC/SSDE/SSDG/SSDL/SSDM/SSDP/SSDQ）
\_SB.PC00.LPCB.H_EC.*     ← 26 处
\_SB.WMI5*                ← Lenovo WMI 接口（5 个字段）
```

### 2.3 ★ 关机键：`MLR1` 的真身（`DSDT.dsl:88349-88371`）

```asl
OperationRegion (LA3M, SystemMemory, 0xFE0B0F00, 0xFF)
Field (LA3M, ByteAcc, Lock, Preserve)
{
    Offset (0xBD),
    MLR0, 8, MLR1, 8, MLR2, 8, MLR3, 8,      // 0xBD..0xC0
    Offset (0xD0),
    PL1V, 8, PL2V, 16, CTAU, 8, GTGP, 8, GPAB, 8,
    Offset (0xDE),
    MPL1, 1, MPL2, 1, MTAU, 1, MTGP, 1, MPAB, 1, , 10, MOFD, 1
}
```

⇒ **`MLR1`/`MLR2` 不是方法，是 EC RAM 的 8 位硬件寄存器**（`0xFE0B0F00 + 0xBD/0xBE`）。

### 2.4 `_Q47` 在干什么（`DSDT.dsl:99088-99130`）

```asl
Method (_Q47, 0) {
    Debug = "Q47 trigger"
    If (WMI5.DSIF == One) {
        If ((MLR1 > 0) && (MLR1 != WMI5.LPWR)) {
            WMI5.SDRF = ...
            If (MLR1 >= 0x82) { ...WMI5.SDRF = One... }      // 阈值 0x82
            WMI5.LPWR = MLR1
            Notify (WMI5, 0xD0)
        }
        If ((MLR2 > 0) && (MLR2 != WMI5.LSCN)) {
            WMI5.LSCN = MLR2
            Notify (WMI5, 0xD1)
        }
    }
}

Method (_Q48, 0) {
    Debug = "Q48 trigger"
    If ((WMI5.DSIF == Zero) || (MOFD == One)) {
        If (MMCM == Zero) { CPL1 = PL1V * 8; CPL2 = PL2V * 8 }   // ★ PL1/PL2 = 功耗限制
    }
}

Method (_Q50, 0) { Debug = "Q50 trigger"; MBGS("Notify D2."); Notify(WMI5, 0xD2) }
```

**归因结论**：
- `PL1V`（8 位）+ `PL2V`（16 位）就在 `MLR1` 隔壁，且 `_Q48` 里做 `PL1V * 8` ⇒ **Intel 标准 package power limit**
- `LPWR` / `LSCN` / `SDRF` / `DSIF` / `OVTP` = 电源与散热语汇
- `MOFD` 是 `Offset(0xDE)` 的单个 bit，与 `MPL1/MPL2/MTAU/MTGP/MPAB` 同组
- `0x82` 阈值比较 = 经典电源/电池状态握手

⇒ **这是一套 EC → WMI 的功耗/热管理通知机制。与触觉无关。**

## 三、❌ 已否证：我这一轮自己的错误推断

| 我说过 | 状态 | 否证依据 |
|---|---|---|
| "`MLR1`/`MLR2` = LRA #1/#2，这是触觉控制面" | ❌ **撤回** | `Field(LA3M)` 里它是 EC RAM 字节，邻居是 `PL1V/PL2V/MMCM`（功耗/热） |
| "`Q47 trigger` 是触发震动" | ❌ **撤回** | 它把 EC 寄存器转发给 `WMI5.LPWR/LSCN` 并发 `Notify(D0/D1)` |
| "UMP45 完全正确" | ❌ **撤回** | 没验证到"EC 控制 LRA"这一步；本机 ACPI 里根本没有触觉通路 |
| "顺手在 DSDT 里发现了 LRA 触发方法" | ❌ **撤回** | 那是 `FundamentalDeviceResetTriggeredOnD3ToD0`（PCIe 复位）+ 电源寄存器 |

**教训（与项目既有纪律一致）**：
> **在 AML/二进制里"看到一个像缩写的名字"，不是证据。必须反编译到 `OperationRegion` / `Field` / 调用点，看清它的邻居和值域。**
> 本轮我连犯两次：先把 `MLR1` 读成 LRA，又把 `_Q47` 的调试串读成震动触发。

✅ **仍然成立的新事实**：本机 **16 条 I²C 控制器**全表（先前只记了 1 条）；**`HKLM\HARDWARE\ACPI` 零权限可读**；完整反编译工具链已就位。
