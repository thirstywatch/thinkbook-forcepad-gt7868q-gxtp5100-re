# BIOS 现场测试结果（2026-09-14，用户实测）

> **【参考 · 实测记录】** 项目当前权威状态：`PREFLIGHT-STATE.md`。
> 本记录与 `PREFLIGHT-STATE.md` §7 的 H1（主机能否到达 TF100A）**无直接关系**，两者不冲突。

## 观察

| 项 | 结果 |
|---|---|
| BIOS Setup（F1/F2）里触控板 | **可以正常使用**（光标能动、可点击） |
| BIOS 里**点按是否震动** | **会震** ✅ |

## 含义（三条，都很硬）

1. **触觉是模组完全自主的**：BIOS 阶段没有 Windows、没有驱动、没有任何主机软件，点按照样震。
   ⇒ 压力过阈值 → GT7868Q → TF100A → LRA 这条链**不需要主机参与**。
2. ⇒ **厂商根本没理由提供"主机触发"接口** —— 这与我们实测的描述符（`Col02 out=0`、page 0x0E 下只有 `Intensity`）
   以及 Linux 上游 RFC 的「device-initiated 设备…主机无法发起力反馈」**完全自洽**。
3. ⇒ **分工确认**：**GT7868Q 决定"何时震"**（压力阈值判定），**TF100A 只负责"怎么震"**（波形 + TIM/PWM 驱动 LRA）。
   这也解释了为什么在我们手上那份 TF100A 明文镜像里，"播放"函数的调用者找不到 —— 扣扳机的是 GT7868Q，
   而它的固件是**加密的 100,608 字节**（AES，16 字节块重复率 10.97%，非标准压缩，实质不可破）。

## 由此得到的最终闭环

> **要实现"滑动跟随震动"，必须在 GT7868Q 的"何时震"判定里加一条"滑动也震" —— 而那正落在加密固件里。**<br>🔴 **2026-10-02 更正**：那片固件**不是**加密，是 **1024 B 周期 XOR 加扰**，**且已解出**（《全书》§19）。但"无读通路 ⇒ 回刷不了"这个**结论不变**。

| 路线 | 状态 |
|---|---|
| HID 主机触发 | ❌ 接口不存在 |
| 厂商命令空间 | ❌ 无震动命令；不可安全枚举（会打挂） |
| TF100A 固件改 | ❌ 它只管"怎么震"；且改它需要经 GT7868Q 转发刷写 |
| GT7868Q 固件改 | ❌ **加密 + eFuse 验签 + 无自助刷回** |
| 解密加密载荷 | ❌ AES；无密钥线索；ECB 码本攻击也只对"已知明文"有效（我们不知道代码明文） |
| **方案 A：外置执行器 + 手势软件** | ✅ **唯一可行，零风险** |

### 那么"当时不能用"只有两种解读

| 解读 | 是否需要新机制 | 说明 |
|---|---|---|
| **① 指的是"没进系统之前"那个环境**（安装界面 / WePE），口语里叫"BIOS" | **不需要** —— `DESIGN.md` §2.2 已解释 | WinPE 里没有 `Intel Serial IO + Sunia SPB + hidi2c` 这套栈 ⇒ 触控板在系统视角里根本不存在。用户 09-13 的原话也正是"**系统安装界面和微pe**" |
| **② 真的是 BIOS Setup（F1/F2）里不能用** | **需要**，且**尚无解释** | 同一版 BIOS 现在能用、当时不能用 ⇒ 只能是**触控板当时的状态不同**（最可能是 EC 级的"禁用触控板"闩锁——用户实测 F8 就是禁用键（见下文实证节）），或那次 BIOS 初始化触控板失败 |

| 结论 | 是否受影响 |

| 主机**没有**触发触觉的接口（`Col02 out=0`、page 0x0E 只有 `Intensity`） | ✅ 不受影响 —— BIOS 也走同一条 HID/I2C 通路，它同样没有触发接口 |

> ★ 反过来说，这条补充也**不能**用来复活"EC 控制触觉"的说法：Windows 侧设备树里触控板父设备是
> `PCI\VEN_8086&DEV_7E78`（Intel I2C 控制器），**EC 不在数据通路上**；而且点按震动在**没有任何主机软件**时就能发生。

## ★★ 定案（2026-09-14，用户回答）：当时**连震动都没有** ⇒ 不是 HID 栈问题

用户明确回答：**"两个都是用不了的，用不了也就是不震动。"**
（问的是"安装界面/微PE"与"真 BIOS Setup"这两种环境；两者都不可用，**且都点按不震**。）

### 这条回答的判据价值（决定性）

| 现象 | 含义 |
|---|---|
| 光标不动、**但点按仍震** | 模组**活着**，只是"触摸输入上报"没了（今天的两次冻结、以及 LKML 的 latch 都属于这类） |
| 光标不动、**而且不震** | ★ **模组当时根本没在运行**（未上电 / 被 EC 关掉 / 停在 Bootloader 无应用） |

⇒ **"当年 BIOS 里也不能用"不需要"BIOS 缺 HID 驱动栈"来解释**：
即使 UEFI 的 HID 栈完美，**面对一个不在运行的模组也一样读不到**。
⇒ 解读 ② 的真正归因是**模组/EC 层面的状态**，而不是主机软件层。

### 三种失效形态（本项目实测/文献，务必区分）

| 形态 | 触摸 | 点按震动 | 诱因 | 恢复 |
|---|---|---|---|---|
| **轻度：输入挂起** | ✗ | **✓** | 类 0x20 **高频读取**（683 次 / 50–75 s） | 杀进程 + 等 **1–2 分钟**（当天两次都自愈） |
| **重度：永久 latch**（LKML djedi 同芯片） | ✗ | **✓**（模组仍活着） | 厂商命令枚举（如 `0x0E`） | **只有彻底断电**（EC 复位流程） |
| **整模组未运行** | ✗ | **✗** | 未上电 / **EC 禁用开关（本机 `F8`）** / 停在 Bootloader（**刷写被中断**） | **先按两次 `F8`（关→开）**；无效再走完整断电 EC 复位；**刷写不可中断** |

### ★★★ 实证（2026-09-14，用户实测）：**按 F8 ⇒ 不能移动 + 没有震动**

用户明确：**禁用键是 `F8`**，**按下后既不能移动、也没有震动**。

⇒ **这是"整模组未运行"那一格的签名**，与另外两种失效形态**可一眼区分**：

| 操作/失效 | 能移动 | 点按震动 | 判定 |
|---|---|---|---|
| 正常 | ✓ | ✓ | — |
| 版本 A：输入挂起（高频读取诱发） | ✗ | **✓** | 模组活着，仅上报断 |
| 版本 B：永久 latch（命令枚举诱发） | ✗ | **✓** | 模组活着，仅上报断 |
| **按 F8（EC 级禁用）** | ✗ | **✗** | ★ **模组未运行** |
| 重装那天（用户追述） | ✗ | **✗** | ★ **同一格** |

### ★ 用户再补充（2026-09-14，**推翻了上一条的 F8 解释**）：**没装驱动** + **那时没有热键功能**

用户原话：**"我那时候没装任何驱动，没有热键功能的"**。

| 事实 | 推论 |
|---|---|
| 重装当时**没装任何驱动** | **Windows / 安装界面用不了** = 没有 `Intel Serial IO + SPB + hidi2c` 栈，触控板在系统视角里**根本不存在**（= 文档原有解读 ①，用户 09-13 原话即"**系统安装界面和微pe**"）—— **平常原因，无需新机制** |
| **F8 的禁用功能需要驱动**（无驱动时**无热键功能**） | ★ **F8 不能解释那天的"不震"** —— 那天既然没驱动，F8 就是不生效的。<br>⇒ 这条也**同时**说明：今天能复现"不能移动 + 不震"，是**驱动层实现**的禁用；它是**另一个机制**，与当年无关 |

### ⇒ 那天的"BIOS 也不能用 + 不震"**仍未解释**（但已排除两类）

- **排除**：HID 栈缺失 —— BIOS Setup **自带**驱动，不依赖 Windows 栈（09-14 实测 BIOS 里可用）；
- **排除**：`F8`（那天无驱动 ⇒ 无热键功能）；
- **剩余候选**（都无法回溯验证：重装前 System 日志已被抹掉，最早一条 = 09-02 16:34:48）：
  1. **模组当时未运行**（未上电 / 停在 Bootloader / 被 EC 关掉）；
  2. **早先（有驱动时）由驱动写入的"禁用"状态遗留在模组/EC 里**，而重装后没有驱动再去解除它
     ⇒ 于是 BIOS 与无驱动的 Windows **同时**看不到它；
  3. 或者用户当时的"不震"只是**推断**（"既然不能用，那大概也不震"），而非真的按下去点按过 ——
     若如此，唯一硬的观察只是"**BIOS Setup 里不能动**"，成因仍未知。
- ★ **诚实结论**：这条历史**无法定案**，且**对任何震动结论都没有影响**（见下节）。**不再继续追。**

### ★ 仍然有用的一条（今天的实测价值）

**"不能移动 + 不震"这个签名，可以由【驱动层禁用】产生**（`F8`，需驱动）。
所以今后若再出现该签名，**先在有驱动的 Windows 里按两次 `F8`（关→开）** 是最省事的排查/恢复动作 ——
这条与"当年为什么"无关，纯属运维手段。



### 对既有结论的影响：**零**

- "BIOS 里点按会震 ⇒ 触觉是模组自主"这条证据**依然成立**（那次测试是在触控板**可用**状态下做的）；
- "主机没有触发触觉的接口"**不受影响**；
- 只是把"当年 BIOS 不能用"明确为**已排除 HID 栈与 F8、成因仍未定案**（不影响任何结论），并新增了**三种失效形态**的区分（对上表）。

> 已验证（用户实测）：按 **`F8`** ⇒ **不能移动且点按不震**（需**已装驱动**的环境；见上节实证）。
> **未验证**：再按一次 F8 是否恢复（假设它是切换式开关，但**没有实测**）。因此把它当恢复手段使用时，请**谨慎**（先确认再依赖）。

## 附带确认

- 触控板当前**状态良好**（BIOS 里可用、点按有震动），两次事故后完全恢复。
- 原生点按触觉**保持可用**：我们不碰它、也不会破坏它 —— 方案 A 只是**额外加**一个"主机侧执行器"，
