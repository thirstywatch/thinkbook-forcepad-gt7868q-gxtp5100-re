# 载荷 A 字段定名 —— 对照模板 与 可行观测清单（2026-10-04）

> 本文件只解决一件事：**载荷 A 里那些"4 字节字段"到底能不能被命名？**
> 结论先行：**它很可能不是"参数表"，所以"给字段命名"这个框架本身要改**（§一）。
> 配两份可用的东西：**已成功的"字段 ↔ 物理量"对照（当模板）**（§二）＋ **现在真正可行的观测清单**（§三，含两条被排除的路与我自己的更正）。

## 一、★ 决定性结构判据：载荷 A 的"机型相关块"**不是"表 + 字段"**

方法（把用在活配置体上的同一招搬到载荷 A）：**双轴逐字节位置差异剖面** ——
对 16 字节网格的**每一列**，分别统计
- **机型轴**：我们 vs `cap22001E0D` / `cap26002816`
- **版本轴**：`cap22001E0D` vs `cap26002816`

| 块 | 机型轴（逐列） | 版本轴（逐列） |
|---|---|---|
| `0x06000`（机型相关） | **70–74% × 全部 16 列** | 2–5% × 全部 16 列 |
| `0x01000` GLINK（机型相关） | **87–90% × 全部 16 列** | 17–27% × 全部 16 列 |
| `0x10000`（机型相关） | 69–74% × 全部 16 列 | 27–40% × 全部 16 列 |
| `0x04000`（机型相关） | 72–79% × 全部 16 列 | 46–56% × 全部 16 列 |
| `0x08000` / `0x0C000` / `0x13000` / `0x16000`（版本相关） | 75–98% | 50–97% |
| `0x0FF00` / `0x1E000`（固定资产） | **全 0** | **全 0** |

> ### ★★★ 关键对比（这是本文件最重要的一张表）
> | | **活配置体**（1024 B，运行期配置） | **载荷 A 的块** |
> |---|---|---|
> | 跨机型差异落点 | **集中在特定区段**（节点表 A/B、映射表 C 整体不同，其余区段 `same`） | **均匀分布在所有字节位置** |
> | 结构解释 | "**同一张表 + 机型相关字段**" | "**整块按机型重新生成**" |
>
> **⇒ 载荷 A 的"机型相关块"不是"参数表改几个字段"，而是"整块换内容"。**
> **⇒ 因此"给 4 字节字段命名"这个问法本身可能不成立** —— 如果每块是"按机型整体算出来的系数/图案/查表"，
> 那么 4 字节只是**数据的步长**，不是"参数槽位"。**这条把原来那个问题重新定义了。**

**旁证（同一结论的第二条）**：活配置体里那三处机型差异**能读出整数含义**（节点 25 vs 16、映射表 32 项 vs 27 项，见 §二）；
而载荷 A 的差异是**逐位均匀**的 ⇒ 读不出"某个字段是 32"这种结构。

## 二、★ 已成功的"字段 ↔ 物理量"对照（当模板用）

**这是本项目目前唯一一处把字段和物理量对上的地方**，值得当模板：

| 字段位置 | 我们（14 G6+） | `cap22001E0D` / `cap26002816` | 物理含义（推断） | 判据 |
|---|---|---|---|---|
| `+0x037` **node table A** | 25 个节点号（升序带空隙） | **16 个** | 该板用到的**传感节点数** | 两轴交叉：同机型两版一致、异机型不同 |
| `+0x064` **node table B** | `2D..3F`（19 项） | 到 `3C` 为止（**16 项**） | 第二组节点/通道 | 同上 |
| `+0x09A` **mapping table C** | **32 项**置换 | **27 项** + `ff` 填充 | **节点→通道映射**，项数 = 通道数 | 同上 |
| `+0x020` 混合参数 | 尾部 `2c 4a 4b 00 01` | `01 02 03 04 05` | 通道/节点索引列表 | 同上 |
| `+0x040` 附近某字节 | `20`（=32） | `1a`（=26） | **疑似通道数** | 单字节、方向一致 |

**为什么可信（三条）**
1. **三处独立区段方向一致**（节点表 A、节点表 B、映射表 C 都说"我们的更多"）；
2. **两轴交叉**：同机型两个版本之间这些区段**一致**，异机型之间**不同** ⇒ 排除"随机/版本"解释；
3. **与物理事实方向吻合**：本机触控板 `135 × 80 mm`（加大版），比同系机型更大。

**⇒ 模板用法（将来定名载荷 A 的字段时照这个来）**
1. 先确定"两个轴"：**同机型不同版本** + **同版本不同机型**（我们已有 3 份 GT7868Q）；
2. 差异必须**落在区段/字段上**（而不是逐位均匀）——**否则就说明它不是参数表**（载荷 A 属此列）；
3. 结果要与**独立的物理量**（板尺寸、通道数、压力范围、扫频/时序）至少一条对上。

## 三、现在**真正可行**的观测清单（含两条被排除的路）

### A. 现在就能做（只读、零风险）

工具：`<LAB>\touchpad-lab\poc\gxmem.py`（厂商内存通道，已修好并用过）
协议（与 `Gx.cs` 一致，实测 11/11 成功）：
```
读: 0E 20 00 00 05 01 <addr16BE> <size16BE>   -> HidD_SetOutputReport(h, buf, 65)
写: 0E 20 00 00 <len+5> 00 <addr16BE> <len16BE> <data...>
响应: 0E 20 <cont> <seq> <len> <data...>      <- HidD_GetInputReport(h, buf, 65)
```

```bash
cd "<LAB>\touchpad-lab\poc"
python gxmem.py selftest                      # 通道自检：读 0x4000 期望 A7 E0 ED B1
python gxmem.py read 0x4000 16                # 单次读
python gxmem.py dump 0x4000 0x8000 out.bin    # 全 32 KB（★ chunk=256、带 delay/retries：
                                              #   連读太快会让设备卡住）
python gxmem.py snap 0x4000 0xC000 16 snap_a.bin           # 静息快照
# 手指按住触控板，再采一次：
python gxmem.py snap 0x4000 0xC000 16 snap_b.bin           # 按压快照
python gxmem.py diff snap_a.bin snap_b.bin 0x4000 16       # 看哪里变
```
- **已采过的素材**（不用重采）：`poc/` 下 6 份 32 KB dump（`dumpA`/`dumpFull1`/**`pressA`/`ramPress`**/**`relA`/`ramRest`**）；
- **已做完的分析**：按压/松开差异 **16,867 / 32,768 字节**，长差异段对应 `0x5F00` 压力帧族（60 B/帧、多副本）；
- **本轮新增结论**：**载荷 A 的内容不在 RAM**（三份 dump 零命中；对照 config body 命中 150 次、地址精确 `0x96F8` ⇒ 方法有效）。

### B. ❌ 已排除，不要重做

| 路径 | 为什么不行 |
|---|---|
| **写注入**（往片内内存写参数再看行为） | §19.34：**32 KB 可写空间逐一写回，无一生效**（能写进、能保持，但不影响行为） |
| **夹主机 `SDA/SCL` 看 8051 是否读这几块 flash** | 🔴 **技术上不可行（本项目此前写错过这条）**：**芯片内部读 flash 的流量不出现在 I²C 总线上**。夹 `SDA/SCL` 只能看**主机 ↔ 触控 IC** 的报文，那条路已被 §19.33/§19.34 否证完 |

### C. 需硬件 / 厂商（现有条件下做不了）

| 路径 | 说明 |
|---|---|
| 芯片内部地址/数据总线探针 | 直接看 8051 是否取指/取数到 `0x04000–0x1E000`；需拆模组 + 探针/示波器 |
| 8051 程序本身 | 载荷 A 不含程序（§8.5 三条正向判据全否）⇒ 主程序在 ROM 或未随包分发 |
| 厂商软件设计指南（`DG_AW86927S_*` 那类） | 触控侧对应的是汇顶客户权限文档（官方社区已两次回复"不公开"） |

## 四、结论与边界

1. **载荷 A 的"4 字节字段命名"这条路，按现有证据应当放弃**——
   因为它**不是参数表**（双轴逐位剖面均匀，与活配置体的"区段集中"形成对照）；
2. **"载荷 A 是什么"目前最准确的表述**：**按机型整体生成的高熵数据包**（通用常量 2 KB + 型号级模板 8 KB + 若干机型相关块 + 若干版本相关块 + 1 保留区），
   与"参数表"（= 活配置体 1024 B，已解到字段级）**是两类不同的东西**；
3. **能继续做的事只剩两类**：**扩展样本**（跨机型统计，纯离线、需要更多厂商包）与**硬件级观测**（探针/ROM）；
4. **本轮把一条错计划改正了**（夹 I²C 看 flash 读），并给出**唯一还能纯离线推进的方向**（样本扩展）。
