# GT7868Q 外部资料汇总 —— 公开可得边界（2026-10-04）

> **一句话**：**88 脚的引脚分配表拿不到 —— 且已由汇顶官方两次书面回复确认"触控资料不公开对外提供"**（§5b.1）。
> 本文件汇总两轮深挖从**公开渠道**拿到的 **10 组此前项目里没有的硬信息**，其中 5 组对"拆机量哪根线"有直接价值。

### 1.1 官方产品线定位（Goodix 官网原文）

- **Newton Touchpad®**：官方把「**触控 + 高精度力感应集成到单芯片**」的方案叫 Newton Touchpad，面向笔记本触控板与可拆卸键盘 folio。
- 触控板控制器系列公开指标：**报点率 ≤ 240 Hz** · 触控板尺寸 **≤ 160 × 100 mm** · **AI 掌拒算法** · 支持 Windows / Chrome OS / Android。
- ⚠️ **对本项目的意义**：本机是「GT7868Q（触控）+ TF100A（独立力 IC）」的**分离式**架构，**不是** Newton Touchpad 的单芯片方案 ⇒ **本机的力感应不在 GT7868Q 内**，这条与既有结论（力数据由 TF100A 采集）互相印证，不是矛盾。

## 二、★ 板级事实（跨机型一手对比，本轮新增）

### 2.1 coreboot：Google Brya 变体 `pujjolo`（Intel Alder Lake Chromebook）

```c
/* src/mainboard/google/brya/variants/pujjolo/overridetree.cb */
device ref i2c5 on
    chip drivers/i2c/hid
        register "generic.hid"  = ""GXTP5100""
        register "generic.desc" = ""Goodix Touchpad""
        register "generic.irq"  = "ACPI_IRQ_WAKE_LEVEL_LOW(GPP_F14_IRQ)"
        register "generic.wake" = "GPE0_DW2_14"
        register "generic.detect" = "1"
        register "hid_desc_reg_offset" = "0x20"
        device i2c 0x2c on end
    end
end
```

| 项 | 值 |
|---|---|
| 总线 | **I2C5**（Intel PCH，`I2C_SPEED_FAST`） |
| **从地址** | **`0x2C`** |
| 中断 | `GPP_F14` —— **电平触发、低有效、带唤醒** |
| 唤醒路由 | `GPE0_DW2_14` |
| HID 描述符寄存器 | **`0x20`** |
| **复位 GPIO** | ❌ **未声明** |
| **使能/电源 GPIO** | ❌ 未声明（无 `has_power_resource`） |

### 2.2 主线 DTS：Lenovo ThinkBook 16（`x1p42100`，Snapdragon X）

```dts
/* arch/arm64/boot/dts/qcom/x1p42100-lenovo-thinkbook-16.dts */
/* GXTP5100 */
touchpad@5d {
    compatible = "hid-over-i2c";
    reg = <0x5d>;
    hid-descr-addr = <0x1>;
    interrupts-extended = <&tlmm 3 IRQ_TYPE_LEVEL_LOW>;
    vdd-supply  = <&vreg_misc_3p3>;     /* 3.3 V */
    vddl-supply = <&vreg_l12b_1p2>;     /* 1.2 V */
    wakeup-source;
};
```

该 DTS 同时列了 4 个候选触控板节点（ELAN06FA@0x15 · CIRQ1080/SYNA2BA6@0x2c · FTCS0038@0x38 · **GXTP5100@0x5d**），实际只贴一颗；pinctrl 里 INT 脚 `gpio3` = `bias-pull-up`。

### 2.3 ★★ 三台机器横向对比（⇒ 本轮最有用的三条推论）

| 项 | **本机** ThinkBook 14 G6+（MTL-H） | Brya/pujjolo（ADL Chromebook） | ThinkBook 16（Snapdragon X） |
|---|---|---|---|
| 主机总线 | `\_SB.PC00.I2C0`（I²C0） | I2C5 | i2c2（QCOM） |
| **从地址** | **`1`** | **`0x2C`** | **`0x5D`** |
| 中断 | GPIO **pad 182** 低有效、电平 | `GPP_F14` 低有效、电平 | `tlmm gpio3` 低有效 |
| 描述符寄存器 | `0x20` | `0x20` | `0x1` |
| **复位脚** | 未在 DSDT 暴露 | **无** | **无** |
| 电源 | 整模组由 EC 门控（本机 `F8`） | 无 power resource | 3.3 V + 1.2 V 双轨 |

> **推论 A（★★）**：**两个独立平台都没有把 reset 做成主机可见的 GPIO** ⇒ 支持「GT7868Q 的复位由内部 POR / 供电域控制，主机侧无复位线」。这与本机既有结论（整模组由 EC 门控上下电、`F8` 开关）**方向一致**，并解释了"主机侧拿不到复位权"。
> **推论 B（★★）**：**从地址是板级设计变量**（`1` / `0x2C` / `0x5D` 三种都出现过）⇒ 本项目反复在主机侧探 `0x2C` 这件事本身没有错，但它**不能**用来推断"GT7868Q 在不在那条总线上"。
> **推论 C（★）**：**存在低压电源轨**（该平台 `1.2 V`；目录件标 `DVDD 1.8 V`）⇒ 拆机量线时除 3.3 V 外，应能找到一条 **1.2 或 1.8 V** 的轨；GT7868Q 是**双电源域**器件，只量到 3.3 V 不等于它已上电。

## 四、仍然拿不到的，以及为什么

| 想要的 | 状态 | 原因 |
|---|---|---|
| **GT7868Q 88 脚的引脚分配表** | ❌ | 无公开手册；官方开源只到**主机侧**（重新扫过 `gtx8_driver_linux` 44 文件 + `goodix_advance_touch_platform` 36 文件：`pinmux`/`ball`/`BGA`/`pad_map` **0 命中**） |
| 芯片内部 GPIO/引脚复用配置 | ❌ | 固件相关区段非代码（载荷 A 已解出但非代码）；官方 Windows 组件（`GdixTouchpadService.exe`、`goodix-fw-tool.exe`）只有通用 API 串，无引脚表 |
| BIOS/EC 里的板级引脚表 | ❌ | 已扫 31.57 MB BIOS 明文 + EC dump：只有 `GoodixTouchpadUpdate` DXE 的升级逻辑与 ACPI `TPAD` 子树，**无数引脚配置表** |
| 从 DSDT 拿复位/使能脚 | ❌ | 本机 DSDT 的 `TPAD` 只有 I²C 资源 + `GpioInt`；**与上面两个平台一致 —— 本来就没有** |

## 五、本轮的净收益（可执行结论）

1. **引脚表死路已二次独立确认**（不是搜得不够，是它不公开）⇒ 不要再在这上面花时间。
2. **量线时多一条判据**：除 3.3 V 外要找到 **1.2/1.8 V 低压轨** —— 两轨都在才算真上电（推论 C）。
3. **别再把"没有 reset 脚"当成异常**（推论 A）：两个平台的官方板级配置里都没有它，这与"整模组被 EC 门控"的既有结论自洽。
4. **从地址是可变量**（推论 B）：`1`(本机) / `0x2C`(Chromebook) / `0x5D`(ThinkBook 16) —— 再次说明主机侧扫不到 `0x2C` 不构成任何否证。
5. **GT7868Q 无固件上传**（HID-over-I2C 标准设备）⇒ 主机侧不需要"先下固件才能工作"这一步，**本机"主机侧碰不到硬件"的结论不受此影响**。

## 五之二、第二轮深挖（2026-10-04 晚追加）

### 5b.1 ★★★ 官方两次明说"不公开"——边界最终闭合（一手原文）

| 机型/芯片 | 提问 | Goodix 管理员回复原文 |
|---|---|---|
| **GT7863** | "官网没有这款 IC 的手册…资料中并没有阐述应该如何读取 Report Desc！另外 **Cmd 寄存器只是提了一嘴，加了 wakeup, sleep 还有 reset 指令**，另外的指令能提供么？" | **"触控产品调试对专业性要求较高…触控产品相关资料不公开对外提供，烦请您直接同您的购买方联系以获取支持。"** |
| **GT7868Q** | "是否有驱动可以调整触控板的压力阈值…ThinkBook 14+ 上按压压力阈值过大" | **"本社区暂不支持触控产品的技术服务…"** |

**⇒ 结论（可定案）**：**GT7868Q 的引脚表/寄存器手册属 NDA 专属件，公开渠道不存在**。这不是搜索姿势问题，官方已两次书面回复。

**★ 但这条回复本身泄漏了两条有用信息：**
1. 手册里**确实有一张 `Cmd` 寄存器表**，至少含 **`wakeup` / `sleep` / `reset`** 三条指令 ⇒ 即 **HID-over-I2C 标准命令集**（`SET_POWER(0x00/0x08)`、`RESET(0x01)`）。⇒ 主机侧若拿到 I²C 通道，**协议层有"复位/休眠"这类标准动作可用**（与 §19.33.19 的 `RSTN` 硬复位是两条不同路径）。
2. **手册没有说明"如何读 Report Descriptor"** ⇒ 这正是所有第三方驱动都要做 `report_fixup`（偏移 607）的原因 —— 反证了我们的修复认知是对的。

### 5b.2 ★★ 同族对照：GT7863 的完整参数（与 GT7868Q 出自同一份官方字段表）

| 项 | **GT7863**（同族、蓝莓那台） | **GT7868Q（本机）** |
|---|---|---|
| 封装 | **QFN60**（JLCPCB 库亦为 `QFN-60_6x6mm`，**两源一致**） | **QFN88** |
| 尺寸 | **6 × 6 × 0.6 mm** | **10 × 10 × 0.75 mm** |
| 供电 | **AVDD 2.8 / 3.0 / 3.3 V**（**单域**） | **AVDD 2.8/3.0/3.3 V + DVDD 1.8 V（双域）** |
| 接口 | I²C / **PS2** | I²C |
| DOME 按键 | 支持 | 支持 |

**⇒ 推论 D（★★）**：GT7868Q 比 GT7863 **多 28 脚、面积大 2.8 倍，且多出一个 `DVDD 1.8V` 电源域**。
⇒ **88 脚 ≈ 传感通道（Tx/Rx）+ 电源域（AVDD/DVDD/GND）+ 主机接口（SDA/SCL/INT/RST/VDDIO）+ 力检测/音频等专用脚**。
⇒ **"必须同时找到 3.3 V 与 1.2/1.8 V 两轨"这条判据（推论 C）现在有三处互相印证**：目录件（DVDD 1.8V）、ThinkBook 16 DTS（`vddl 1.2V`）、GT7863 只有单域（反衬出双域是 GT7868Q 的特征）。

### 5b.3 ★ 官方 GT786 系列文案（DirectIndustry 官方条目，一手）

- 触控板控制器：报点率 **≤ 143 Hz @ 5 指**、尺寸 **≤ 180 × 100 mm**（⚠️ 与官网另一页的"240 Hz / 160×100"口径不同，前者更像该系列实测值、后者是"最高支持"）
- **Supports dome keys**
- **★ `Integrated force detection channel`（集成力检测通道）** —— GT786 系列**自带力检测通道**
- 模组：Windows HLK / Chrome AVL 认证；工艺支持 OSP / ENIG

⇒ **对本机架构的意义**：芯片**自身**有力检测通道，但本机把力交给独立 MCU（TF100A）⇒ 说明**本机走的是"分离式"方案**（成本/抗噪考量），**不矛盾**；同时提示 88 脚里**可能有力检测相关的模拟输入脚**。

### 5b.4 ★ 第三个 PID：ThinkPad L14 Gen 3 也在用（一手 dmesg）

| 机型 | 设备名 | VID:PID | 总线 |
|---|---|---|---|
| **ThinkPad L14 Gen 3（21C1）** | `GXTP5100:00` | **27C6:`01E0`** | `i2c-13`（Intel LPSS `0000:00:19.1`） |

⇒ 已知 PID 家族：**`0x01E0`（L14 Gen3）· `0x01E8` · `0x01E9`（本机）· `0x01F0`（旧 hid-ids）** —— 与主线修复覆盖 `01E8/01E9` 不冲突。

### 5b.5 ⚠️ 一条"存在但有风险"的路径：ROG Ally 完整图纸

- **ASUS ROG Ally（RC71L，2023，主板 `NR2301L` Rev2.1）的原理图（55 页 PDF）+ BoardView（CAD）在图纸站有流通**。
- ★ 但**两点未确认**：① Ally 是否真的用 GT7868Q（iFixit 的 "Chip ID" 拆解页已 404，无法证实；TouchI2cDxe 作者后来把 Ally X 更正为 Novatek `NVTK0603`）；② 这些图纸站多为**付费/来源灰色**，免费站点的文件**有捆绑风险**。
- ⇒ **建议**：仅作为"最后手段"知晓其存在；**不要从未知站点下载可执行文件**。若确要走，先设法确认 Ally 上真有 GT7868Q（例如查 Ally 的 Linux dmesg 存档）。

### 5b.6 官方文档中心核实（一手）

`goodix.com/en/document/center` 的**产品分类只有 Health Sensors / Smart Amplifiers / Bluetooth LE** —— **触控产品线零公开文档**（GR551x 这类 BLE 产品才有公开手册）。⇒ 与 5b.1 的官方回复互相印证。
