## 二、★★★★★ 完整可执行的"让 AW86927 震"规格（源码实证，非推测）

### 2.1 寄存器（全部来自源码 `#define`）

```
0x00 RSTCFG       ← 写 0xAA = 软复位
0x02 SYSINT / 0x03 SYSINTM
0x06 PLAYCFG1     ← BST_MODE / BST_VOUT_VREFSET
0x07 PLAYCFG2     ← ★ GAIN（增益）
0x08 PLAYCFG3     ← AUTO_BST / STOP_MODE / BRK_EN / ★ PLAY_MODE[1:0]
0x09 PLAYCFG4     ← ★ STOP(bit1) / ★ GO(bit0)
0x0A-0x12 WAVCFG1..9  ← ★ WAVSEQ1..(选波形) / WAVCFG9 SEQ1LOOP
0x18-0x24 CONTCFG1..13
0x2D BASEADDRH / 0x2E BASEADDRL   ← SRAM 基址
0x3F GLBRD5       ← ★ GLB_STATE[3:0]（STANDBY/CONT/RAM/RTP/TRIG/BRAKE）
0x40 RAMADDRH / 0x41 RAMADDRL     ← SRAM 写指针
0x42 RAMDATA      ← ★ 连续写入口（写这个寄存器会自动递增地址）
0x45 SYSCTRL3     ← EN_RAMINIT(bit2) / STANDBY(bit5)
0x46 SYSCTRL4     ← ★ WAVDAT_MODE[6:5]（24K） / INT_EDGE / INT_MODE
0x48-0x4B PWMCFG
0x4C VBAT_CTRL
0x4D DETCFG1 / 0x4E DETCFG2   ← F0 检测序列
0x57/0x58 CHIPIDH/L           ← CHIPID = 0x9270
0x5B TMCFG                    ← UNLOCK = 0x7D
0x70-0x75 ANACFG
```

### 2.2 ★ SRAM 波形数据结构（源码实证）

```c
#define AW86927_RAM_BASE_ADDR   0x800      // SRAM 基址
#define AW86927_BASEADDRH_VAL   0x08       // → 0x0800
#define AW86927_BASEADDRL_VAL   0x00

struct aw86927_sram_waveform_header {
    u8 version;          // = 0x01
    __be16 start_address;// = 0x0800 + 5 = 0x0805
    __be16 end_address;  // = 0x0805 + len(waveform) - 1
} __packed;              // 共 5 字节
```
★ 数据手册 Figure 10 补充：**SRAM 里可以放多条波形**（header 里是 `Waveform #1..#N` 的 start/end 地址对），
外加一块 **RTP FIFO**（最大 4 KB）；采样率 **8k/12k/24k/48k** 可选。

### 2.3 ★ SRAM 上传序列（`aw86927_ram_init()` 逐行）

```
1) 轮询 0x3F(GLBRD5) 直到 GLB_STATE = STANDBY
2) SYSCTRL3(0x45) |= EN_RAMINIT            ← 开 SRAM 初始化
3) BASEADDRH(0x2D) = 0x08 ; BASEADDRL(0x2E) = 0x00
4) RAMADDRH(0x40)  = 0x08 ; RAMADDRL(0x41)  = 0x00
5) ← 连续写 RAMDATA(0x42)：5 字节波形头
6) ← 连续写 RAMDATA(0x42)：N 字节波形数据
7) DETCFG2(0x4E) 选择检测序列0 = VBAT
8) DETCFG1(0x4D) DET_GO = 检测序列0 → 启动
9) usleep(3.0~3.5 ms)
10) DETCFG1(0x4D) DET_GO = NA            ← 收尾
11) SYSCTRL3(0x45) &= ~EN_RAMINIT        ← 关 SRAM 初始化
```

### 2.4 ★★★ 播放序列（`aw86927_play_sine()` 逐行）——**这几行就是"震"本身**

```
aw86927_stop()                    → PLAYCFG4(0x09) = STOP
aw86927_play_mode(RAM_MODE)       → PLAYCFG3(0x08).PLAY_MODE[1:0] = 0 (RAM)
PLAYCFG3(0x08).AUTO_BST = 1
WAVCFG1(0x0A).WAVSEQ1  = 1        ← ★ 选第 1 条波形
WAVCFG2(0x0B).WAVSEQ2  = 0
WAVCFG9(0x12).SEQ1LOOP = 0x0F     ← 无限循环
PLAYCFG2(0x07) = 0x7C             ← ★ 增益（<0x80 防失真；v4 起改为 level*0x80/0xffff）
PLAYCFG4(0x09).GO = 1             ← ★★ 开播
```
★ 另有 **RTP 模式**（实时写 FIFO）、**TRIG 模式**（3 根硬件引脚，可覆盖 PLAY_MODE）、**CONT 模式**、
以及**一线式（one-wire）触发**播放。

### 2.5 现成可用的波形

```c
/* 正弦波，幅度 84，二进制补码；注释原文 round(84 * sin(x / 16.25)) */

```

## 三、★★★★★ 所以"下别人固件来拿波形"这条路**可以收了**

理由（本轮实证）：

| 我们原本想从别人固件里拿到什么 | 现在从哪拿 | 还要不要挖固件 |
|---|---|---|
| AW86927 的**寄存器映射** | ✅ 数据手册 + 源码 `#define` 全有 | 不要 |
| **SRAM 波形格式**（头/多条波形/采样率） | ✅ 源码 `struct` + 手册 Figure 10 | 不要 |
| **SRAM 上传序列** | ✅ `aw86927_ram_init()` 逐行 | 不要 |
| **播放序列（怎么让它震）** | ✅ `aw86927_play_sine()` 逐行 | 不要 |
| **波形数据本身** | ✅ 主线驱动自带正弦波；艾为有 GUI 可自造任意波形 | 不要 |
| **增益/强度映射** | ✅ v4 patch：`level*0x80/0xffff` → `PLAYCFG2(0x07)` | 不要 |
| 原厂**用了哪几条波形** | ⚠️ 只有这个真的需要抓总线 / 挖固件 | **可选，且不影响"能不能震"** |

**⇒ 结论：波形、格式、时序、强度映射，全部是我们自己能造的。**
**"原厂长什么样"变成纯粹的**锦上添花**，而不是前提。**

### ⚠️ 附带实测：别人的固件**基本是加密的**
- 戴尔 `DigitalTouchpadUpdate_Hellcat` 包 → `.data` 段**熵 7.913**（= 加密）
- 本机的 `NJME*.exe` → 3.12 MB 加密
- ⇒ **"厂商发布加密固件"是常态**，不是本机特有。**期望从别人的包里挖出明文波形，期望值低。**

### ⚠️ 本机 BIOS 里的定向搜索（本轮做的，结论是负的）
在 19.2 MB 明文 `isflash.bin` 里搜：
`SRAM 头 01 08 05` → **0 命中**；连续序列 `40 08 41 00 42`（RAMADDR/RAMDATA 上传签名）→ **0 命中**。
⇒ **AW86927 的初始化和上传代码不在 BIOS 里**（与"主机侧没有任何组件知道它存在"一致）。
⚠️ **但注意脆点：BIOS 的 FV 模块是 LZMA 压缩的，搜不到不等于不存在。**

## 四、⇒ 唯一剩下的问题，一句话

> **从 Windows 主机，有没有一条物理路径够到 I²C 从地址 `0x5A`（AW86927）？**

**支持"有"的新证据（上一轮）**：蓝莓用同一条 I²C 访问了小米那台的触控 IC（`0x2C`）**和马达（`0x50`）**
⇒ 这类模组里，**触控 IC 与马达 IC 共享同一条对外 I²C 排线**。

**若答案是"有"**：
```
补 DSDT / 装一个 SPB 客户端驱动  →  主机直接对 0x5A 写 SRAM + 拉 GO
```
—— 上面 §2.3 / §2.4 的序列**可以照着抄**，全程纯软件。

**若答案是"没有"**（马达只在 GT7868Q 的私有总线上）：那就只剩"让 GT7868Q 转发"或"接管硬件"。
