### 1.1.2 CPU 架构 —— ★ 双核混合

| 区域 | 架构 | 规模 | 判据 |
|---|---|---|---|
| 头部 `0x00000` 起 | **8051（Turbo51）** | **约 4.6 KB** | ARM 指纹 ×0.0 |
| `0x19A00–0x2775C` | **ARM Cortex-M4F Thumb-2** | **约 55 KB / 约 130 个函数** | `F2xx` 富集 ×17–26 · 宽指令占比 0.35–0.41 · `c2 f2` 位置 mod2 = **558:1** · `PUSH{...,LR}`×133 与 `BX LR`/`POP{PC}` 配对 |

**架构本身**：芯片核 = **Turbo51**（8051 二进制兼容，Goodix 自研双核 M/S）
（证据来自官方源码 `xdata` / `FLASH_BUFFER_ADDR` / 16 位地址 + 数据手册框图 + IEEE 论文，**与固件明文无关**）

**尾区 ARM 代码内容**：`printf` 运行库 · 浮点库 · **ADC1(`0x40012400`) 驱动** · **FLASH(`0x40022000`) 驱动** · **UART 驱动**

**❌ 架构线上的已作废结论**
| 曾经的结论 | 现状 |
|---|---|
| 「`0x1E000` 是 8051 代码 + 数据表混合区」 | ❌ **是标准 ARM Thumb-2 代码** |
| 「`c2 f2` = 8051 的 `CLR F0`」 | ❌ **是 ARM Thumb-2 `MOVT` 的第二半字**（`0xF2C2`）；558/559 落在偶数地址；8051 真代码里 0 次 |
| 「`\|rel\|≤8` 是 8051 代码判据」 | ❌ **判据不专一**：ARM 代码实测 0.238–0.286、8051 代码 0.558、数据 0.067 ⇒ 只能分「代码/数据」 |
| 「`0x1E000` 与 `0x00000` 同源（Turbo51）」 | ❌ ARM 与 8051 是两个不同架构 |
| 「`0x26500` 附近有 `0x08xxxxxx` 函数指针表」 | ❌ 对齐率仅 **25%**（真指针应 >99%）⇒ 是 ARM 指令被按 u32 误读 |
| 「架构 = Turbo51 ⇒ 固件是 8051 代码」 | ❌ **核兼容某指令集 ≠ 固件就是该指令集代码** |

**❌ 三种加扰/加密模型的否证**

| 模型 | 否证方式 | 结果 |
|---|---|---|
| `C = P XOR T[i mod 1024]` | XOR 解密后 mod-1024 列众数占比 | **×25 → ×26，纹丝不动** ⇒ 周期不来自加扰 |
| 整块加密 | 97 个整块里只有 1 种重复 | 最多解释 0.17%，实测 7.16% ⇒ **差 42 倍** |
| ECB 模式 | 16 字节块重复 13.42% + 周期 8/16/32/64 类内熵显著低 | ⚠️ **证据不足**：16 字节块重复**不能区分** ECB 与弱加扰；众数占比标定显示**保留了明文逐位置分布** ⇒ 是弱加扰。**且第 19 轮自我更正"周期 1024"是小样本偏差** |

**★ 三重定量结案（否定"密文"）**

| 判据 | 实测值 | 随机基线 | 结论 |
|---|---|---|---|
| 真压缩器可压比 | **0.8797** | `os.urandom` 1.0004 · 真 Thumb 码 0.4719 · 文本 0.0088 | 偏离随机 |
| 条件熵 H1−H0 | 低于随机 **0.36 bit** | 随机 7.4576 vs 本区 7.1009 | 偏离随机 |
| lag1 自相关 | **0.01149 = 2.94×** | 随机 0.00381 | 偏离随机 |

⇒ **密码学密文应使三项全部落在随机基线上；实测三项全部偏离，且偏离很弱**
⇒ 该区 = **表 + 填充 + 约 12% 块级重复的结构化数据**

**★ 压缩假设排除（阳性对照标定）**：埋藏真 zlib 流**能被抓出** ⇒ 判据灵敏；固件区 6 种算法 × 2 步长 **全 0 命中**

**★ 「为什么当年两个 agent 都说有加密」的根因**
> **零阶熵 `H0 ≈ 8.0` 是"非特异判据"** —— 白化 / 压缩 / 加扰 / 密文 / 真随机 **全都**给 ~8.0。
> 它**不能**用来判定"这是密文"。

**★ 由此沉淀的纪律**

| 寄存器空间 `0x00–0x80` | 私有封装 `[0E 20 ...]` + 地址 `0x1800/0x3800/0x96F8/0x4014/0x4160` | ❌ **完全不同** |

### 1.3.5 业界标准用法（一手资料：Fairphone + Linux 主线）

**Fairphone 5 设备树**
```dts

    compatible = "awinic,aw86927";

    interrupts-extended = <&tlmm 101 IRQ_TYPE_EDGE_FALLING>;
    reset-gpios = <&tlmm 100 GPIO_ACTIVE_LOW>;
};
```
⇒ **标准形态：挂在 SoC 普通 I²C 上的从设备 + reset GPIO + 中断 GPIO**

**★ 身份标识（一手）**
```c
#define AW86927_CHIPIDH (0x57)
#define AW86927_CHIPIDL (0x58)
#define AW86927_CHIPID  (0x9270)
```
⇒ **读 `0x57`(高)/`0x58`(低) == `0x92 0x70` ⇒ 确认是 AW86927**（前提：主机够得到它）

**★ 完整控制流程（`aw86927.c` 摘要）**
```
硬复位(reset 拉高1ms→释放→等8ms) → 软复位(0x00=0xAA,3ms) → 验身份(0x57/0x58)
→ 初始化(TMCFG 0x5B=0x7D 解锁 → ANACFG11/12/13/15/16, CONTCFG1/5/10/13,
          PWMCFG1/3/4, DETCFG2, PLAYCFG1 BST=8500mV → 锁定)
→ SRAM 初始化 + 下波形(BASEADDR 0x2D/0x2E=0x0800；RAMDATA 0x42 连写 头+数据)
→ ▶ 播放: 写 0x09 PLAYCFG4 = 0x01 (GO)
→ ■ 停止: 写 0x09 PLAYCFG4 = 0x02 (STOP)
```
**参考波形**：驱动内置 106 字节 sine（`round(84*sin(x/16.25))`，双补码）

### 1.3.6 ★ 三条"可直接用于硬件判定"的手册原文（2026-10-04 补）

> 来源：`AW86927FCR.pdf` V0.9（2021-06，本地）逐页核对。
> **这三条把"下一步该量哪根线"从模糊猜测变成了二元判据。**

**(1) `TRIG1/2/3` 未使用时必须接 GND** —— 引脚定义原文：`Must connect to GND when not used`

⇒ 拆机量线时的**二元判据**：

- 量到**接 GND** ⇒ 模组**没有**走硬件触发路（`GT7868Q` / `TF100A` 都没用它）
- 量到**有线接到某颗主控** ⇒ **存在一条完全不经过 I²C 的播放通道**（见下面 (3)）

**(2) `AD`(9) 直接决定 I²C 从地址** —— Table 3 原文：

| `AD` 电平 | 7 位从地址 |
|---|---|
| `0` | `0x5A` |
| `1` | `0x5B` |

⇒ 量一下 `AD`(9) 的电平即可把从址**定死**，不必再在 `0x5A` / `0x5B` 之间奇偶交替盲探
（§19.33.19 / §19.33.20 的 140 轮与 40 轮探测，一直是在两个地址之间轮着试的）。

**(3) 单线（one-wire）播放的完整编码** —— 手册 `One wire Mode` + Figure 15 原文：

- **`TRIG1` 就是那条线**；一次传 **15 bit**：**低 8 bit = 增益、高 7 bit = 波形序号**，**从最低位开始发**
- 时序：`IDLE 10~20 µs`、bit 脉宽 `45~55 µs`；两次协议之间间隔须 **> 3 ms + 波形时长**
- 前置条件：`0x3A` 的 `TRG_ONEWIRE = 1`；**波形库必须已初始化**

**(4) 补充：TRIG 模式可配**（寄存器 `0x33 ~ 0x3A`）

每个 TRIG 脚可配 `posedge` / `negedge` / `both-edge` / `level`
（`TRGx_LEV`、`TRGx_POLAR`、`TRGx_POS` / `TRGx_NEG`、`TRGxSEQ_P` / `TRGxSEQ_N`）。

> ### ⚠️ 这三条**不改变**当前卡点，但改变了卡点的"落点"
>
> `TRIG` / one-wire 的前提仍然是：**芯片已被上电（`RSTN` 高）+ 已被某个 I²C 主机预置**
> （`0x3A` 置位、8 KB 波形库已下发）。
> ⇒ 它**绕不开**"谁是模组内的 I²C 主机"这个问题。
> ⇒ 但它把入口从"在主机侧继续找软件通路"变成 —— **在模组上夹 `SDA`(18) / `SCL`(19)（外加 `RSTN`(1)），
> 一次把「配置 + 波形 + 播放时序」全抓下来**：不需要任何驱动，也不需要先知道命令语义。
