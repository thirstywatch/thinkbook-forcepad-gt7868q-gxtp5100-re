# BIOS 宿主侧触控板协议 + FMP 包格式（2026-09-28 反汇编实测）

> 目标：`GoodixTpDxe`（宿主侧驱动）与另两个触控板相关模块的全量反汇编理解。
> 结论：**GoodixTpDxe 做完了**（寄存器协议 + FMP 包格式带字段名）；另两个模块**字符串层无锚点**，价值低；TF100A 的 I2C 收发候选**经复核不是代码**（见 §4，属更正）。

---

## 1. ★ 宿主侧寄存器访问协议（`GoodixTpDxe`）

三个基础函数（全部实测）：

| 函数 | 签名 | 作用 |
|---|---|---|
| `0x18bc` | `(cx=寄存器号, rdx=缓冲, r8d=长度)` | **写寄存器** |
| `0x161c` | `(cx=寄存器号, rdx=缓冲, r8d=长度)` | **读寄存器** |
| `0x11d8` | `(ecx=毫秒)` | 延时 |

调用形态（反汇编原文）：

```asm
mov  r8d, 0x11          ; 长度 = 17
lea  rdx, [rsp+0x68]    ; 缓冲
mov  cx, 0x100          ; 寄存器
call 0x18bc             ; → 写
```

### 寄存器与用途（实测站点）

| 寄存器 | 方向 | 长度 | 用途 |
|---|---|---|---|
| **`0x100`** | 写 | **0x11（17）** | **命令包**（包内 `[0] = 1`；某重试流程里为 `2`） |
| **`0x200`** | 写 | **变长 = 长度字节 + 1** | **数据块**，末字节是校验（`call 0x4e5c` 算校验，长度取自包内 `+0x45`） |
| **`0x300`** | 读 | **5** | **状态/响应** |
| **`0x303`** | 写 | **0x11（17）** | 第二命令包（升级流程里与 `0x100` 交替出现） |

**实测到的时序（一次完整的"发命令→读状态"）**：
```
写 0x303 (17B, buf[0]=1) → 延时 70ms → 写 0x100 (17B) → 延时 100ms → 读 0x300 (5B) → 判状态
（失败时分别返回 0xFFFFFFFE / 0xFFFFFFFD / 0xFFFFFFFB / 0xFFFFFFFA / 0xFFFFFFF8 / 0xFFFFFFF7 等错误码）
另有循环 `for i in 0..3`：buf[0]=2 → 写 0x100 → 读 0x300（重试/多步流程）
```

**⇒ 与项目此前结论一致，并新增三点**：① `0x303` 是第二个 17 字节命令寄存器；② 数据块长度字段在包内偏移 `+0x45`、末字节为校验；③ 一整套错误码（`0xFFFFFFF**`）可作为判读依据。

## 2. ★★ FMP 固件包格式（带字段名，日志字符串逐一对上）

解析函数在 `0x3A20`–`0x3D70`，日志串与偏移一一对应：

| 偏移 | 类型 | 字段 | 日志原文 |
|---|---|---|---|
| `0x00` | u32 | **包总大小** | `Firmware size:%u` |
| `0x0F..0x12` | 4×u8 | **PID** | `Fimware PID:%x%x%x%x` |
| `0x17..0x1A` | 4×u8 | **VID** | `Fimware VID:%02X%02X%02X%02x` |
| `0x1B` | u8 | **子系统数量**（校验 `≤0x1C` = 28，否则 `Bad firmware, invalid subsys num: %d`） | `Firmware subsystem num:%u` |
| `0x1C` | u8 | **芯片型号** | `Firmware chip type:%02X` |
| `0x1D` | u8 | **协议版本** | `Firmware package protocol: V%u` |
| `0x20 + i*8` | — | **子系统表**，每项 8 字节 | `Index:%d` |
| 　`+0` | u8 | 　子系统类型 | `Subsystem type:%02X` |
| 　`+1` | u32 | 　子系统大小 | `Subsystem size:%u` |
| 　`+5` | u16 | 　烧写地址 | `Subsystem flash_addr:%08X` |
| **`0x100`** | — | **载荷起点**；第 i 个子系统数据指针 = `包基址 + 0x100 + Σ(前 i 个子系统大小)` | `Subsystem Ptr:%p` |

**边界检查**：累计偏移超过包总大小 → `Sybsys offset exceed Firmware size`。

⇒ **这份包格式是"从 capsule 里解析触控板固件"的完整规格**（此前只知道有 PID/VID/chip/subsystem 这些词）。

## 3. 另外三个模块：字符串层无锚点，价值低

| 模块 | 大小 | 字符串 | 判读 |
|---|---|---|---|
| `FmpDxeY750` | 0x52AE | 82 条，**几乎全是代码字节的假串** | 无锚点，只能逐函数反汇编；功能是通用 FMP 框架（Cirque 共用） |
| `I2cTouchPanelDxe` | 0x4692 | 28 条，其中还有 `___AUTOPAD___`（Insyde 构建填充） | 通用 I2C-HID 传输管道，无触控板专属逻辑 |
| `SynaReflash` | 0xE14E | 100 条，同样是假串 | Synaptics 升级流程（本机不是 Synaptics 面板） |

**⇒ ④ 的结果：`GoodixTpDxe` 有实质收获；另三个即使反汇编，预期也只是通用管道代码，性价比低。**

## 4. ⚠️ 更正：TF100A 的"I2C 收发候选"经复核**不是代码**

我之前用"同时有写 DR(+0x10) 与读 SR(+0x14)"的粗启发式，报了两个候选（`0x080109DC`、`0x08012154`）。
本日复核：
- `0x080109DC` 实为**"外设基址 → 时钟索引"分发器**（一长串 `cmp <基址>` + `movw r0,#0x400+n`）
- **`0x08012154` 反汇编出来是乱码**（`stc2` / `vfma` / 错位指令）⇒ **该地址及其附近不是有效代码**（位于镜像尾部区域，很可能是 rodata/数据）

**⇒ ① 的现状修正**：I2C 层（`I2C_Init`@`0x0800FA20`、总线复位 `0x08008A4C`、引脚/字段层 `0x0800FC20/FC44/FC80`）**已定位**，但**真正的收发函数尚未确认**；下一步应改为：**只在"能连续解码、且函数边界自洽"的地址范围内**，搜索 `SR1` 位轮询（`bit 1 (ADDR) / bit 7 (TXE) / bit 6 (RXNE)` 形态）的循环，而不是继续用寄存器对启发式。

## 5. ② 的最终判定（本日两次复核后）

- `0x0800D6F5`（TIM3 回调）= **纯计数器**（`[0x20004010]++`）
- 三处"bit0 使能对"= RAM 标志（`0x200042E8`/`0x200042EC`）与 **RCC 时钟配置**（`0x40021000` 区）
- 未找到"开一段 PWM 通道"的运行时站点
**⇒ 结论：TF100A 侧只有载波参数（200/400 Hz、~35% 占空比）；包络/pattern 极可能由加密的 TP 侧经链路逐次下发 ⇒ 单靠 TF100A 拿不到手感数据。**
