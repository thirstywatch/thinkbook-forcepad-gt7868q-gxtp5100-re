# 追加三十 —— 路线 A③ 的模型判别：**1 KiB 周期是"位置型变换"，但缺锚点 ⇒ 打不开**

> 日期：2026-09-30 · 触发：用户选定「路线 A③：离线破 1 KiB 变换」
> 方式：**全离线、纯统计**，零设备操作。
> 本文**部分修订** `追加二十九` §〇 的一条提醒（见 §五），并**否证** `追加二十三` §七 的"整块加密"模型解释。

---

## 〇、一句话

> ## **周期精确 = 1024（不是 1084、不是 3236）。**
> ## **两个替代模型都被实验否证 ⇒ 变换确实是【周期 1024 的位置型变换】**
> ## ⇒ `追加二十八` 的「攻击面只有 1024 字节」**成立**。
> ## **但位置型 XOR 下，两份密文差分会把密钥消掉 ⇒ 必须有【绝对已知明文锚点】。**
> ## **本轮找了 4 条锚点路，全部干净排除 ⇒ A③ 在现有资产下打不开。**

---

## 一、周期精确测定（细扫）

对加扰区 `0x1400–0x19800`（99,328 B）扫 L，看 `C[i] == C[i+L]` 的比例：

| L | 匹配率 | 相对基线 0.0039 |
|---|---|---|
| **1024** | ## **0.071889** | ## **18.43×** |
| 2048 | 0.056600 | 14.51× |
| 3072 | 0.053160 | 13.63× |
| 4096 | 0.047915 | 12.29× |
| **1023** | 0.006948 | **1.78×** |
| **1025** | 0.006704 | **1.72×** |
| 1280 | 0.006772 | 1.74× |
| 1600 | 0.006559 | 1.68× |
| 768 | 0.005722 | 1.47× |
| 809 | 0.003776 | **0.97×** |
| 1618 | 0.003797 | **0.97×** |
| 3236 | 0.003174 | **0.81×** |

**L=1023/1025 立刻掉回基线附近 ⇒ 周期是【精确的 1024】，不是"附近某个值"。**
1024 的整数倍（2048/3072/4096）同步衰减，是典型的"周期＋其倍数"结构。

## 二、★★ 模型判别（本轮最关键的一步）

"密文在 1024 处出现尖峰"**本身不能区分**下面两类模型 —— 必须用别的判据。

| 模型 | 预测 | 实测 | 判定 |
|---|---|---|---|
| **A. 内容寻址的【整块】加密**（`追加二十三` §七 的解释："内容相同的区块 → 密文相同"） | 密文出现整块重复；且字节相等率的上限由整块重复贡献 | 97 个整块里**只有 1 种重复**（出现 4 次）⇒ 整块相同最多贡献 **0.0017**，而实测 0.0716（**差 42 倍**） | ## **❌ 否证** |
| **B. 16 字节 ECB** | 单字节相等率 ≈ 16 字节相等率（同块才可能相等） | ℓ=1 → **0.0719**，ℓ=16 → **0.0483**，不相等 | ## **❌ 否证** |
| **C. 周期 1024 的【位置型】变换**（stream/XOR/逐位置置换） | 匹配率随 ℓ 平滑衰减；`C[i]=C[i+1024] ⟺ P[i]=P[i+1024]` | ℓ 从 1 到 1024 **平滑衰减**（0.0719 → 0.0350），无任何台阶 | ## **✅ 唯一存活** |

### 2.1 匹配长度谱（stride 1024）

| ℓ | 匹配率 | ℓ | 匹配率 |
|---|---|---|---|
| 1 | **0.071889** | 64 | 0.045236 |
| 2 | 0.056478 | 128 | 0.043788 |
| 4 | 0.053112 | 256 | 0.042540 |
| 8 | 0.050612 | 512 | 0.040034 |
| 16 | 0.048276 | **1024** | **0.034981** |
| 32 | 0.047175 | | |

**平滑衰减 = 位置型变换的指纹。** 若是整块/ECB 加密，ℓ≥2 会立刻塌到基线；实际只从 7.19% 缓降到 3.50%。

### 2.2 整块重复计数（直接否证模型 A）

```
stride 1 KiB : 3 对整块逐字节全同  （共  96 对可比）
stride 2 KiB : 2 对                （共  95 对）
stride 3 KiB : 1 对                （共  94 对）
stride 4 KiB : 0 对                （共  93 对）
stride 8 KiB : 0 对                （共  89 对）

97 个整块 → 94 种不同整块；出现 4 次的 1 种，出现 1 次的 93 种
```

> **⇒ 那 3 对全同整块，只能解释 0.17% 的字节相等率。7.16% 的绝大部分必须由"位置型"变换解释。**

## 三、★ 一个必须解决的矛盾：`追加二十三` 的 δ=0xCA4

`追加二十三` §七 用 `YELSTO` 对齐本机与 2020 版样本，得 **delta = 0xCA4 = 3236**，
并观测到 **32,877 字节逐字节相同**。

**3236 的因子只有 `1, 2, 4, 809, 1618, 3236`**（3236 = 2² × 809，809 是素数）。
若变换是"位置型 + 周期 1024"，则 δ=3236 对齐下密文相同**必须**要求 `1024 | 3236` —— **不成立**。
实测 809 / 1618 / 3236 三个因子的匹配率分别是 **0.97× / 0.97× / 0.81×**（全在基线）。

**⇒ 推论（未验证，但排他性最强）：密钥流的相位不是以【文件开头】为基准，而是以【加扰区/子系统开头】为基准。**
两个文件的加密区起点在文件内的偏移不同 ⇒ 两者加密区之间的有效 δ 与 3236 无关。

> ★ **这条同时给出一把钥匙**：将来拿到第二份密文时，可用
> "**使 `C1[i] ^ C2[i+s]` 的零率最大化**" 来搜出正确的相对相位 s（若两份明文在同一段相同，则正确 s 处 XOR 为 0）。

## 四、锚点搜索：四条路，全部干净排除

| # | 锚点候选 | 检验 | 结果 |
|---|---|---|---|
| 1 | 容器是否只是 `cap_payload.bin` 的切片（那样可从 capsule 结构推出别的拷贝） | 容器头 32 B 在 `cap_payload.bin` 中搜索 | ❌ **未命中** |
| 2 | `cap_payload.bin` 里是否有同一固件的第二份（哪怕加密） | `YELSTO` 全 payload 搜索 = **0 处**；`7868`=0 处；4 条 16 B 明文特征串各 0 处 | ❌ **无第二份** |
| 3 | X9-15 那份容器（用于差分） | `x9bios` 全目录搜 `YELSTO` = **0 处**；工区 130–200 KB 的 `.bin` 只有本机那两份（md5 相同） | ❌ **不在手头** |
| 4 | ★ `x9bios\iso_fat\Flash_B06D0.PAT`（**99,328 B，与加扰区长度完全一致**） | 强判据：`X = C ^ PAT` 是否呈 1024 周期 | ## **❌ 干净排除**（最高 0.004435 = **1.1× 基线**，异或后熵 7.998，等于什么也没发生） |

**第 4 条的判据值得记住**：不是"看着像不像"，而是"**异或之后是否出现 1024 周期**"。
无关文件异或之后周期一致性会停在基线，**有信号就是有信号，不会模棱两可**。

> 顺带记录：`Flash_B06D0/1.PAT` 自带一个头部（`01 00 00 00` / `1A 00 00 00` / 日期样字节 /
> `D0 83 01 00`=0x183D0 / `00 84 01 00`=0x18400=文件大小 / `A0 03 00 00` / `07 00 05 00`），
> 是从 X9-15 BIOS 里带出来的**独立容器**，与触控固件无关。

## 六、A③ 的诚实结论

### 6.1 为什么打不开 —— 一条代数事实

```
若 C[i] = P[i] ^ K[i mod 1024]     （位置型，本轮已确证）

则两份密文的差分：  C1[i] ^ C2[j] = P1[i] ^ P2[j]
                    ↑ K 被完全消掉 ⇒ 差分【永远给不出绝对明文】
```

**推论：A③ 成败 100% 取决于能否拿到"绝对已知明文锚点"，而不是取决于算法多难。**
本轮确认：手头资产里**没有**任何锚点。

### 6.2 唯一有效量的锚点形式（给后续会话）

> ## **只需要【1024 字节连续已知明文，且与 keystream 相位对齐】即可恢复 K，从而解开全镜像。**

可行来源（按可行性）：

| 来源 | 说明 |
|---|---|
| **2020 版 MS Update Catalog 样本**（`GOODIXTOUCHPADCAPSULE_22001E0D.Cap`） | ★ **差分能给出"版本差异"，但仍给不出绝对明文**（K 消掉）。价值在于**验证 §三 的相位假说** |
| ★★ **同一芯片的"明文孪生"固件**（fwupd / linux-firmware / 其他 OEM 包 / `goodix_advance_touch_platform` 的 `goodix_firmware.bin`） | **这是唯一能真正解开的路**。只要有一段与相位对齐的明文即可 |
| 物理路线（读芯片 flash 原始内容） | 见 `追加二十九` §六：厂商 16 位窗口**不含固件** ⇒ 需换接口（路线 B / 片上调试） |

❌ **不要再做的**：盲扫候选周期；对 `cap_payload.bin` / `x9bios` 再做重复搜索；把 `.PAT`、`device_fw_*` 当锚点。
