# 角度项目 · 读那 4 KB 的执行手册

- 时间：2026-09-27 · 机器：ThinkBook 14 G6+ IMH（21LD）
- **目标地址**：物理 `0xFE0B0400`，长度 `0x1000`（4096 字节）—— 即 ACPI 里的 `OperationRegion(ECMM, SystemMemory, 0xFE0B0400, 0x1000)`
- **要回答的唯一问题**：这 4 KB 里，除了 `0x856.1` 的 `LIDF`，**还有没有字节跟随屏幕角度连续变化？**
- 配套工具：`ecram_diff.py`（给两个以上快照，逐字节 diff 并标注字段名）

---

## 零、先立三条纪律（比操作本身重要）

| # | 纪律 | 为什么 |
|---|---|---|
| **1** | **绝不让屏幕接近闭合**。用"小幅摆动"（约 90°↔100°，或 90°↔75°） | 合盖会触发 Modern Standby，读内存的操作会被挂起；而**合盖/待机正是 bug 218771 的高发场景**（EC 状态机崩 → 硬关机）。**本机在"合盖"这条路径上已有一个独立故障源（NVIDIA 0x9F），不要叠加** |
| **2** | **先做静止基线**，再动屏幕 | EC RAM 里**本来就有一直在变的字节**（时间戳、温度、计数器）。不先建立"自己会变的清单"，会把噪声当成角度 |
| **3** | **只读，绝不写** | 往那 4 KB 写一个字节可能直接改掉电源/风扇策略 |

## 一、实验设计（受控对照，四步）

| 步 | 做什么 | 采几个快照 | 目的 |
|---|---|---|---|
| **A 基线** | 机器静止、屏幕不动、你不碰它 | **读 2–3 次，间隔 1 分钟** | 得到"**自己就会变**"的字节白名单（噪声清单） |
| **B 只改目标量** | **只**小幅摆动屏幕（90°↔100° 来回，慢，每次停 2 秒） | 读 **5–8 次**，每次记下大致角度 | 找"跟随角度"的字节 |
| **C 恢复** | 停止摆动，屏幕停在 90°，人不动 | 读 2 次 | 验证 B 中找到的字节是否回稳 |
| **D 干扰对照**（可选） | 屏幕不动，但**人走开再回来** | 读 2 次 | 排除"人体存在传感器"之类的影响 |

**判读判据（三条都要满足）**：

```
① 在 B 里变化
② 在 A 和 C 里不变
③ 变化方向与屏幕角度单调相关（而不是随机跳）
```

**只有同时满足①②③的字节，才可能是角度。** 这是跨项目一直用的 A/B/C/D 受控对照法。

## 二、路线 A：Windows + RWEverything（快，但要临时关两道防护）

### A.1 准备（一次性，之后要关回去）

1. 下载 RWEverything（`rw-everything.com`，免费，v1.7）
2. **关闭内存完整性**：Windows 安全中心 → 设备安全性 → 内核隔离 → **内存完整性 = 关**
3. **关闭易受攻击驱动封锁列表**：
   - GUI：Windows 安全中心 → 设备安全性 → 内核隔离详细信息 → **Microsoft 易受攻击的驱动程序封锁列表 = 关**
   - 或注册表：`HKLM\SYSTEM\CurrentControlSet\Control\CI\Config` → `VulnerableDriverBlocklistEnable` = `0`
   - **两者缺一不可**：只改注册表、内存完整性还开着的话，封锁列表仍会强制执行
4. **重启**

> ⚠️ 这一步会**临时降低系统防护**。做完实验请把两项都开回去。

### A.2 读取与采集（照抄这个顺序）

1. 以**管理员**运行 `Rw.exe`
2. 点工具栏 **Memory** 图标
3. 地址框输入 **`FE0B0400`**，回车；滚到覆盖 `FE0B0400..FE0B13FF`（4 KB）
4. **按下面的顺序采集，每采一次就存一份**：

| 编号 | 条件 | 说明 |
|---|---|---|
| **A1** | 机器静止、屏幕不动、人不碰 | 基线 |
| **A2** | 与 A1 完全相同，**60 秒后**再读一次 | ★ 用来识别"本来就会变的字节"（时间戳/温度/计数器） |
| **B1–B5** | **手扶屏幕在 90°±10° 小幅来回摆**，每次停下 2 秒后读一次 | ★ **绝不接近闭合**；每次记下大致角度 |
| **C1** | 停止摆动、回到 90°、静止 30 秒后读一次 | 验证 B 里找到的字节是否回稳 |

5. **导出方式（任选其一，脚本都能吃）**：
   - **存文件**：右键 / 工具栏找 **Save to File** → 存 `.bin`（首选，命名 `ec-A1.bin`、`ec-B1.bin` …）
   - **复制文本**：在 Memory 窗口里 **Ctrl+A → Ctrl+C**，粘进记事本存成 `.txt`
   - **截图**：实在不行就截图，**我按图逐字节读**

6. **采完立刻把 A.1 里那两道防护开回去**（内存完整性 + 易受攻击驱动封锁列表），然后重启。

> ⚠️ **只读，一个字都不要写。** RWEverything 能写，别碰。

### A.3 比对

把快照放到同一目录，跑：

```
<HOME>\miniconda3\python.exe ecram_diff.py ec-A1.bin ec-A2.bin ec-B1.bin ec-B2.bin ec-C1.bin
```

- **`.bin` 和文本 dump 都能吃**（自动识别），不必先转换
- 输出：**每个被改动的字节偏移 + 该偏移属于哪个 ACPI 字段名**（120 个字段的对照表已内嵌在脚本里），附结论提示

**怎么读结果**：

| 输出 | 含义 |
|---|---|
| `0x84E CTMP` 之类在 **A1/A2 之间**就变 | 噪声（温度/计数器），**先剔掉** |
| **只有 `0x856`（LIDF）在 B 里变** | ★ **结案**：盖子就是二元标志，**这台机器没有角度** |
| **某未命名字节在 B 里单调变，且 A/C 不变** | ★ **找到角度了** —— 把那个偏移告诉我 |
| 什么都没变（连 0x856 都不动） | 说明摆动幅度不够或没真动到；重来一次，摆动幅度稍大一点 |

## 三、路线 B：Linux Live USB（推荐，不动系统）

### B.1 准备

| 项 | 做法 |
|---|---|
| U 盘 | 8 GB 以上 |
| 镜像 | Ubuntu LTS 或 Fedora Live（挑**支持 Secure Boot** 的，省一步） |
| 写入 | **Ventoy**（推荐，直接拖 ISO）或 Rufus |
| Secure Boot | 若 Live 起不来，进 BIOS **临时关掉**（本机 BIOS 里 `SecureBoot = Enable`） |
| 退路 | Live 会话里触控板能用；**仍建议插一个 USB 鼠标** |

### B.2 启动并加内核参数

1. 插 U 盘 → 开机按 **F12 / Novo** → 选 U 盘
2. 在 GRUB 菜单高亮 Live 项，按 **`e`** 编辑
3. 找到以 `linux` 开头那一行，**在行尾加**：

```
iomem=relaxed
```

4. **Ctrl-X** 启动

> `iomem=relaxed` 是必须的 —— 现代内核默认 `CONFIG_STRICT_DEVMEM=y`，会挡住对非保留物理地址的访问。

### B.3 采集

```bash
# 看一眼 /dev/mem 在不在
ls -l /dev/mem

# 读一次（4096 字节）
sudo dd if=/dev/mem bs=4096 skip=$((0xFE0B0400/4096)) count=1 of=/tmp/ec-A1.bin

# 校验长度必须是 4096
stat -c%s /tmp/ec-A1.bin

# 顺手确认 LIDF 位：偏移 0x856，bit1
od -An -tx1 -j $((0x856)) -N 1 /tmp/ec-A1.bin
```

然后按 A/B/C/D 步骤重复，命名 `ec-A1/A2/B1..B8/C1/C2.bin`。

**先做阴性对照**：机器完全不动，连读两次，`cmp` 一下 —— 若完全相同，说明读取稳定；若不同，差异就是"天然噪声"，先记下来。

```bash
cmp -l /tmp/ec-A1.bin /tmp/ec-A2.bin | head
```

### B.4 比对

方式一（Linux 里直接跑）：
```bash
python3 ecram_diff.py /tmp/ec-A1.bin /tmp/ec-A2.bin /tmp/ec-B1.bin /tmp/ec-B2.bin /tmp/ec-C1.bin
```

方式二（把 `.bin` 拷回 Windows，用同一个脚本跑）—— 推荐，方便留档。

### B.5 若 `/dev/mem` 仍被拒（备用）

```bash
# 看一眼内核有没有挡住
dmesg | grep -i -E "devmem|STRICT"
# 若参数没生效，回 GRUB 确认 iomem=relaxed 确实在 linux 行尾
```

再不行就用 `busybox devmem` 逐字读几个关注点（如 `0x856`），或写一个 `ioremap` 小模块（需装 `linux-headers-$(uname -r)` + gcc，Live 里能装但要多几步）。

## 四、判读表（把结果对到结论）

| 观察 | 结论 | 后续 |
|---|---|---|
| **A/B/C 三次快照完全一致**（含 0x856） | 读取方式有问题，或 LIDF 在未实际改变状态时不刷新 | 检查是否真的动了屏幕；确认地址对不对 |
| **只有 `0x856` 在变，且只在 B 里变** | **永久结案**：盖子就是二元标志，**这台机器没有角度** | 角度项目收束，把精力转到触控板/别的目标 |
| **有未命名字节在 B 里单调变化，A/C 不变** | ★ **找到角度了** | 记下偏移；再测几个已知角度做线性拟合，定出单位与范围 |
| **有很多字节在 A 里就在变** | 那些是噪声（时间戳/温度/计数器），先剔掉再判 | 用真正的 A/B 差分 |
| **`0x853`（`DPOT`）变化** | 有传感器状态位翻转（对应 `_Q20`） | 顺带记录，与 `_Q20` 的位掩码对照 |

**字段名速查（完整 120 项在 `EC-RAM地图与读取路线.md`）**：

| 偏移 | 字段 | 含义 |
|---|---|---|
| **0x856.1** | **`LIDF`** | **盖子状态（1 bit）** |
| 0x841.7 | `ADPT` | 适配器在位 |
| 0x842 | `PWAK…TWAK` | 各类唤醒源 |
| 0x844 | `S3ST/S3RM/S4ST/S4RM/S5ST/S5RM/CSST/CSRM` | 睡眠/关机状态与恢复标志 |
| 0x848 / 0x84E / 0x84F | `TCNL` / `CTMP` / `CTML` | 温度（当前/限值）—— **典型的噪声源** |
| 0x84B | `FSSN/FANU` | 风扇档位 |
| 0x853 | `DPOT` | 传感器变化位掩码（`_Q20` 读它） |
| 0x857 | `BRTS` | 背光亮度 |
| 0x879 | `ORRF` | 未定 |

## 附：两条已排除的平台问题

| 平台 | 为什么不行 |
|---|---|
| **WSL2** | 它跑在 Hyper-V 虚拟机里，`/dev/mem` 拿到的是**虚拟机自己的物理地址空间**。`0xFE0B0400` 这个 MMIO 窗口在 guest 里**根本不存在**（不是权限问题）。自编译 WSL2 内核仍在 VM 里 |
| **WSL1** | 没有 `/dev/mem`，不能装内核模块 |
| Windows 用户态 | 读物理内存需要 ring0。除 RWEverything 外，也可考虑联想自家签名驱动（`LnvMSRIO.sys` 提供 I/O 端口 + MSR，**不含物理内存**；`AcpiVpc.sys` 未查），但需先逆向其 IOCTL —— 工作量大于直接开 RWEverything |
