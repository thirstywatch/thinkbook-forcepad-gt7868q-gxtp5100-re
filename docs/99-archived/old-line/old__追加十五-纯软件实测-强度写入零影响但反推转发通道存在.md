# 追加十五 —— 纯软件路线实测：强度写入对可读窗口零影响 ⇒ 但反推出「转发通道存在」

> 日期：2026-09-28 · 真机只读 + 4 次合法 feature 写入 · 全部前台、单发、活性门、失败即回写
> 目的：回答「64 KB 可读窗口里到底有没有触觉控制面」，以及顺带纠正我自己两处说法。

---

## §0 一句话

**写 `Col02` feature `rid=9`（Haptic Intensity）到 0 / 10 / 100 —— 两个已证稳定的窗口（共 384 字节）完全不动（0/128 与 0/64，连噪声基线也是 0）。**
**⇒ 这两个窗口不是触觉控制面。**
**★ 但由此反推出一个正向结论：那个强度值既然确实改变了触觉行为、又不在可读窗口里，那么它必然被 GT7868Q 转发给了 TF100A ⇒ 「GT7868Q → TF100A 的转发通道是存在的」。**

---

## §1 实验设计与实测结果

### 1.1 设计（脚本：`poc/intensity-probe.ps1`）

| 步 | 写 `rid=9` | 读窗口 |
|---|---|---|
| 1 | **10**（项目已知良好值 = 基线） | `0x4000`(256 B) + `0x5B80`(128 B) |
| 2 | **0** | 同上 |
| 3 | **100**（已知 = 反馈关闭） | 同上 |
| 4 | **10**（回写复原） | 同上 |

- 自变量换成**我们亲手写、离散可控**的 intensity（不像压力那样连续变化）
- 观测窗口只用**已证秒级稳定**的两段（`diff-A` vs `diff-A1` = 0 变化）
- **内置噪声基线**：步 1 vs 步 4（同为 10、不同时刻）
- 总帧数 ≈ 28 读 + 4 写；活性门在每次写之后；任何失败立即回写 10

### 1.2 原始结果

写入（4/4 成功，全部 `err=0`）：
```
step 1: intensity = 10   SetFeature(rid=9, len=2) -> True err=0
step 2: intensity = 0    SetFeature(rid=9, len=2) -> True err=0
step 3: intensity = 100  SetFeature(rid=9, len=2) -> True err=0
step 4: intensity = 10   SetFeature(rid=9, len=2) -> True err=0
```

差分（16 位单元）：

| 对比 | `0x4000` | `0x5B80` |
|---|---|---|
| 10 vs 0 | **0/128** | **0/64** |
| 10 vs 100 | **0/128** | **0/64** |
| 0 vs 100 | **0/128** | **0/64** |
| ★ **10 vs 10（噪声基线）** | **0/128** | **0/64** |

收入体检（收尾）：
```
readMem(0x4000,16) -> A7 E0 ED B1 F4 9D DC  ✓ 与历史一致
readMem(0x5B8E,16) -> 5A 00 50 00 30 00 30  ✓
```
**⇒ 设备全程正常；方法可靠（噪声基线 0）；结果是干净的负结果。**

## §2 结论一：这两个窗口**不是**触觉控制面

- `0x4000`（含 `YELSTO`/`7869` 标识 + 后面一大段配置）**完全不随 intensity 变**
- `0x5B80`（含 `5A 00 50 00 30 00 30 00 46 00 …` 这类字串）**完全不随 intensity 变**
- ⇒ 那个强度值**没有落在**这两个窗口的 384 字节里

**⇒ 所以「在稳定窗口里找触觉寄存器」这条路，对这两个窗口已关闭。**
（想继续找，只能扫全部 64 KB —— 那是 4,372 次读，量级太大且项目有打挂史；除非先用"只扫非零稳定地址"筛一遍。）

---

## §3 ★ 结论二（派生，且是正向的）：那个值必然被**转发**给了 TF100A

推理链：

```
① 写 rid=9 = 100  ⇒  点击反馈消失                    ← 已实测（用户体感验证）
   ⇒ 这个值**确实到达了触觉子系统**
② 而触觉在 TF100A 里（TIM2/TIM3 在 TF100A 内部驱动 LRA）
③ 本次实测：这个值**不在** GT7868Q 的可读 64 KB 窗口里（至少不在这两个稳定窗口）
④ ⇒ 那它只能是被 GT7868Q **通过某条链路送给了 TF100A**
⑤ 而 GT7868Q ↔ TF100A 的链路 = **I2C1**（TF100A 作从机，地址 0x2C —— 我们已解出）
```

> ## **⇒ 「GT7868Q → TF100A 的转发通道存在」这件事，现在有了一个间接但相当强的证据。**

**⚠️ 但有一个必须守住的分界：**

| | 来源 | 是否已证转发 |
|---|---|---|
| `rid=9`（Haptic Intensity） | **Col02**（标准 PTP 集合） | ★ **强证据表明会转发** |
| `0xA0`/`0xA1` 那 39 条命令 | **Col04**（厂商集合） | **仍然未知** —— 两条来源在 GT7868Q 里很可能是**不同的代码路径** |

**⇒ 所以这个推论不能直接推广到 Col04。**
**⇒ 但它给了一个明确的、可验证的预测：**
> **如果 GT7868Q 会转发触觉参数给 TF100A，那它是走 I2C1 发的 ⇒ 逻辑分析仪夹 `PB6/PB7`，在"点按 / 写 intensity"时就一定能抓到帧流。**

**⇒ 这把「验证转发」从"可选"提升为"关键且有了明确观测目标"。**

## §4 纠正我自己两处说法

| 我说过 | 更正 |
|---|---|
| 「那次'写强度会不会触发震动'的实验，因为写入长度写成 `len=1`（`err=203`）而无效」 | ❌ **不成立**。我核对了 `ColProbe.SetFeat` 实现：`buf.Length = 1 + payload.Length`，两个脚本**都是 `len=2`**。差异只在 `err=203` vs `err=0`，那不是长度问题 |
| 「这个假设从没被正确测试过」 | ❌ **过重**。项目 `WHY-NOT-VIBRATE.md` §3 已记录结论：连写 6 个强度值（5/40/75/15/60/90），**力度确实随之改变（阳性对照成立），但不产生震动（阴性）** ⇒ **"把音量旋钮当播放键"这条路早已被否掉** |

**⇒ 所以本次实验的真正新价值只有两条：**
1. 排除了"这两个稳定窗口是触觉控制面"（新）
2. **反推出"转发通道存在"这个正向推论**（新，且重要）

## §5 纯软件路线的现状（更新后的判定表）

| 通道 | 判据 | 结论 |
|---|---|---|
| 标准 HID（Col02） | `OutputReportByteLength = 0`、usage page `0x0E` 只有 `Intensity` | **无触发入口**（描述符级事实） |
| 厂商通道（Col04） | 39/39 命令全覆盖，无一条接马达；定时器引用闭包封闭 | **无马达入口**；**是否转发仍未知（见 §3）** |
| feature 通道（`rid=9`） | 可写、确实到达触觉；但**不触发震动**，且**不落入可读窗口** | **只影响"强度"，不能当播放键** |
| 可读窗口（`0x4000`/`0x5B80`） | 本次实测：对 intensity 零响应 | **不是触觉控制面** |
| **I2C1 上的实际帧流** | **从未观测过** | ★ **唯一还没有被排除的观测面** |
