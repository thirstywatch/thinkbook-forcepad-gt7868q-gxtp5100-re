## 一、为什么必须是 Linux（本轮新增的关键前提）

| 问题 | 答案 |
|---|---|
| 为什么需要 Linux？ | **唯一目的**：读物理地址 `0xFE0B0400` 那 4 KB。需要物理内存访问 → Linux 有 `/dev/mem`（配 `iomem=relaxed`），或写小模块 `ioremap()` |
| **WSL 行不行？** | **不行，原理上不行。** WSL2 是 Hyper-V 虚拟机，`/dev/mem` 拿到的是**虚拟机自己的物理地址空间**，`0xFE0B0400` 这个 MMIO 窗口在 guest 里**根本不存在**（不是权限问题）。WSL2 自编译内核仍在 VM 里；WSL1 没有 `/dev/mem`、不能装模块 |
| 有 Windows 替代吗？ | 有 —— **RWEverything**（Memory 页读 `FE0B0400` × `1000`），代价是**要临时关"内存完整性" + "易受攻击的驱动程序封锁列表"** |
| 结论 | 两条路线二选一：**A. RWEverything（快，但要动防护设置）· B. Linux Live USB（推荐，不动系统，拔盘即复原）** |

> Linux Live USB 另有一个附带好处：**触控板项目里"Windows 做不到的三件事"（`hidraw` 写 feature、裸 I2C）也一并能做。**

### 3.4 ⚠️ 需复核的一条

`lid-probe` **N1**：「BIOS 镜像 `NJCN67WW_FWUpdate.bin`（4.34 MB，Intel FPT）全镜像 0 个 `Goodix`/`GXTP`/`TB14P`/`7868`、0 个固件 GUID ⇒ 联想 BIOS 里没有 Goodix 代码 ⇒ 平台固件是死路」

**实测**：该文件 `offset 0x10` 是 **`$FPT`**（Flash Partition Table），同目录配 `FWUpdLcl64.exe` + `FLASH_me.BAT`
（内容 `FWUpdLcl64.exe -F NJCN67WW_FWUpdate.bin -forcereset -allowsv`）→ **它是 Intel CSME 固件，不是 BIOS**。
ME 固件里当然没有 Goodix 代码。**→ 这条结论必须在真 BIOS（`NJCN67WW.exe`）上重做。**
（报告同时提到 Insyde `pgrm.met` 明文，说明当时可能也碰过真 BIOS，但**文件命名与归属是混的** → 定性"需复核"。）
