## §2 ★★ 三条高危「维护/升级」命令（完整证据）

### 2.1 `0xA0/0x0100` = **擦/写 flash + 软复位**（20 行，全文读完）

```asm
08006F98  movs r0, #0xaa ; strb r0,[sp,#3]      ; 局部常量 0xAA（未使用）
08006FA0  ldrb r0,[msg]  ; cmp r0, #1 ; bne 结束
08006FA8  r0 = 0x08004C00                        ; ★ flash 目标地址
08006FB0  bl 0x0800F49C                          ; ★ flash 操作
08006FB4  bl 0x0800A6A0                          ; ★ 软复位
```

`0x0800F49C(addr)` 展开：
```asm
0800F4A2  bl 0x0800F634            ; ← flash 解锁（KEYR）
0800F4A6  r0 = 0x307 ; bl 0x0800F4C4   ; ← 置 FLASH 寄存器位
0800F4B0  r0 = addr   ; bl 0x0800F4FC   ; ← 对目标地址做操作（擦/写）
0800F4B6  r0 = 0x307 ; bl 0x0800F4C4
0800F4BC  bl 0x0800F4E8            ; ← 收尾（等 BSY / 清位）
```
而 `0x0800F4C4(bit)`：`reg = 0x40022000 区（FLASH）`、`bit = arg & 0x1f`、`reg_offset = arg >> 6` ⇒ **对 STM32F1 FLASH 寄存器做位置位**。

`0x0800A6A0` 展开：
```asm
0800A6A4  r1 = 0xE000ED0C          ; ★ SCB->AIRCR
0800A6B2  r2 = 0x05FA0004          ; ★ VECTKEY(0x05FA) | SYSRESETREQ(bit2)
0800A6BA  [r1] = r0 | r2
0800A6C0  b .                      ; 死循环等复位
```

> **⇒ 判定：`0xA0/0x0100` 在 `msg[0]==1` 时 = 「擦/写 flash `0x08004C00` → 触发 Cortex-M 系统复位」。**
> **⇒ 这是"写入并重启"—— 典型的配置/固件更新收尾动作。危险等级：极高。**

### 2.2 `0xA0/0x0500` = **带序号与累加和校验的数据块下载**（387 行）

逐段实读：

```asm
0800669C  r1 = msg[1] ; [0x20004958] = L        ; 块长度
080066AA  if (L == 0x11) → 特殊分支 0x08006984  ; ★ 与"开始更新"同值
080066BE  for (i=0;i<L;i++) buf[0x100+i] = msg[4+i]      ; 拷载荷
08006706  bl 0x08010078(0x2000602A, 0x20003F60, 0x10)
0800671E  bl 0x0800FFE0(0x2000602A, buf+0x100, 0x3A)
08006724  [0x20004950] = rev32(buf[0x100])      ; ★ 首 4 B 大端 = 序号
0800673E  bl 0x080110BC(0x08011A40, [0x20004950])
08006742  for (i=0;i<L-4;i++) [0x20004948] += buf[0x100+i]   ; ★ 累加和
080067A6  [0x2000494C] = rev32(buf[L-4])        ; ★ 末 4 B 大端 = 校验和
080067BE  if ([0x20004948] != [0x2000494C]) → 失败分支 0x08006982
080067D0  [0x20004948] = 0                       ; 校验通过，清零
08006826  [0x20004956] += (L-8)/4                ; ★ 写入计数
0800684E  循环 (L-8)/4 次，按 4 字节条带化写入目标结构
```

`L == 0x11` 分支（只拷 8 字节）：
```asm
080069FA  [0x20004950] = rev32(buf[0x100])
08006A02  if ([0x20004950] == 0x111) → 0x08006A5A     ; 特殊魔数
08006A1C  否则把 2 个 dword 写进 0x200044EC[...]
```

> **⇒ 判定：`0xA0/0x0500` = 「数据块下载」：有序号（首 4 B 大端）、有累加和校验（末 4 B 大端）、有写入计数、有条带化落位；`L==0x11` 是特殊 8 字节控制包（魔数 `0x111`）。**
> **⇒ `L==0x11` 与项目红线「刷机三连 `00 11`」同值域 ⇒ 这是升级流程的"开始更新"环节。**
> **⇒ 危险等级：极高（升级通道）。**

### 2.3 `0xA0/0x3300` = **纯软复位**（全文 3 行）

```asm
08006F68  push {r7,lr}
08006F6A  bl   0x0800A6A0     ; ★ 就是上面那个 AIRCR/SYSRESETREQ
08006F6E  pop  {r7,pc}
```

> **⇒ 判定：`0xA0/0x3300` = 「复位芯片」。**
> **单独看无害（设备重启），但在 `0x0500` 写到一半时发它，会把 flash 停在半更新状态 ⇒ 危险等级：高。**

**⇒ 三条合起来构成一对完整的维护链**：`0x0500`（收数据块 + 校验）→ `0x0100`（写入 + 复位）→ `0x3300`（随时复位）。

## §3 ★ 新发现：一块**从未被逆向**的 flash（20 KB），其中含可被命令擦写的配置扇区

### 3.1 推理链

1. 反汇编文件的**首行地址是 `0x08005000`**，而那段明文以**合法 Cortex-M 向量表**开头（Initial SP = `0x200076C8`，Reset = `0x08005164`；未用 IRQ 全指向 `0x0800517F`）。
2. `0xA0/0x0100` 的 flash 目标常量是 **`0x08004C00`** —— 它落在 `0x08005000` **之前**。
3. **⇒ 说明 `0x08000000–0x08004FFF`（20 KB）也是一块真实的 flash 区域**，只是不在我们手里的这份 dump 里。
4. 而 `0x08004C00` 距 dump 起点只差 `0x400`（1 KB）⇒ 很像一个**紧贴应用之前的配置扇区**（1 KB 页 4×256 B）。
5. 反证：若这段明文其实是从 `0x08000000` 加载（即 dump 标号偏高 `0x5000`），那么 `0x08004C00` 就落在**应用代码内部**——而"自写自己正在运行的代码区"是不合理的设计。**⇒ 这条反证支持"dump 标号正确、应用起于 `0x08005000`、其下另有一段"**。
   （这也与我之前用 `0x40e8` 引用完整性、函数入口自洽性得出的"dump 地址基准是对的"结论一致。）

### 3.2 ⇒ 结论

| 地址 | 大小 | 状态 |
|---|---|---|
| `0x08000000–0x08004BFF` | 19 KB | **从未逆向**（很可能是引导/启动代码） |
| **`0x08004C00–0x08004FFF`** | **1 KB** | **★ 可被 `0xA0/0x0100` 擦写的配置扇区** |
| `0x08005000–0x08012C9F` | 56,480 B | ✅ 已完整反汇编（20,314 行） |

**⇒ 这块 20 KB 从哪里拿？** 候选：① 另一份同族固件容器；② 设备侧若有办法读 TF100A flash（**目前没有** —— 32 位读已判否，见 `追加十`）；③ GT7868Q 容器里的加密块（但那 97 KB 已判定"不是代码"）。**⇒ 暂时拿不到，如实记录。**

## §6 红线更新

**原有全部不变。新增三条"绝不发送"**：

| 命令 | 理由 |
|---|---|
| **`0xA0/0x0100`** | 擦/写 flash `0x08004C00` **并立即软复位** |
| **`0xA0/0x0500`** | **升级/配置数据块下载**（`msg[1]==0x11` 分支 = "开始更新"） |
| **`0xA0/0x3300`** | 纯软复位（在半更新状态下发它会留下坏固件） |

**⇒ 于是"绝不发送"清单现在是**四条**：`0xA0/0x0100` · `0xA0/0x0500` · `0xA0/0x3300` · 以及原来的刷机三连 `00 10 / 00 11 / 0E 12`。**
**⇒ 反过来，"最安全的探测命令"也更明确了：`0xA1` 全族（22 条，纯读 + 回复），首选 `0xA1/0x0A00`（`A2 11`）。**
