## 一、一句话结论

**这块触控板（Goodix GT7868Q + 钛方 TF100A）的震动，主机侧永远无法主动触发。**
**唯一确定可行的路 = 拆底盖，在 `HDP`/`HDN` 焊盘外挂驱动直接驱动 LRA。**

## 二、五个"封死"（各自独立，互相不依赖）

| # | 面 | 结论 | 决定性证据 |
|---|---|---|---|
| **1** | **HID 标准接口层** | 无主机发起触觉的接口 | 描述符未声明 Manual Trigger OUTPUT 报表；微软 Haptic Touchpad 规范；Linux 上游 RFC；真机实测——**四重** |
| **2** | **厂商通道 Col04** | 主机无法到达 TF100A | `class` 全扫：`0x00`–`0x0D` 有应答，**`0x0E`/`0x0F`/`0x14`–`0x2F` 连续 28 个全 `err=122`**；发 `A1` 帧无 `0xA2` 应答（§6.9）；**门在 GT7868Q 侧**——它没实现 `0xA0`/`0xA1` 分区 |
| **2b** | **★「写波形缓冲」`0xA0/0x0B00`**（2026-09-28 深夜追加，见 `剩余可推进项` **追加七**） | ★ **即使写成功也不产生振动** | **引用完整性检查**：`0x200040E8` 全镜像（20,314 行）**只有 2 处引用** —— `0xA0/0x0B00` 写（`0x0800D8EE`）+ `0xA1/0x0B00` 读回（`0x0800D894`，组 `A2` 回复并拉 PA3）。**无第三处消费者**，未接 TIM2/TIM3、未接播放回调 `ctx+0x14` ⇒ 该表只是"主机写/主机读"的收发寄存器组 |
| **3** | **固件加密区（100 KB）** | 🔵🔵🔵 **整条前提已作废 —— 固件根本没有加密**（2026-09-30 第二十–二十一轮） | **原三条证据（无密钥字段 / 工具无实现 / 明文内存写）只说明"主机侧无加解密"，不能推出"设备侧有加密"。** 现由**三个带随机基线的独立量**结案：真压缩器可压比 **0.8797**（随机 1.0004 / 真 Thumb 码 0.4719）· 条件熵**低于随机 0.36 bit** · lag1 自相关 **2.94×** ⇒ **弱相关的结构化数据**。⚠️「密钥在芯片 OTP/eFuse」**随之作废**。「两个 agent 说有加密」的根因 = **零阶熵 H0≈8.0 是非特异判据**。出处 `追加三十七` §23.6 |
| **4** | **固件内部（TF100A 明文段）** | **波形/手感不在明文段**（09-28 晚修正，见下） | 播放器 `0x0800D704` **在 main 里被无条件调 2 次**（TIM2/TIM3），参数**全硬编码**、无取波形路径；回调 `0x0800D6F5` **只是计数器** |
| **5** | **触觉驱动的上层来源** | 包络/模式由 TP 侧下发 | `0x0800D6F5`（TIM3 回调）只是计数；三处"bit0 使能对"= RAM 标志 + RCC 时钟；TF100A 侧只有常量，没有 pattern 表。⚠️ 原表述中的"**加密的** TP 侧"已更正为"TP 侧"（固件无加密） |

### 2.0 ★ 第 4 条的修正（2026-09-28 晚，追加六实测）

原表述「播放函数零调用者 ⇒ 测试固件」**定性有偏差**，修正后：

| 项 | 原表述 | 修正后 |
|---|---|---|
| `0x0800D628` | "启动 TIM3 的播放函数" | 零调用者的**"就绪后手动触发一次回调"入口**（真身见`追加六`§4） |
| **真正的播放器** | 未识别 | **`0x0800D704`** —— 2 个调用者（`0x0800E03E`/`0x0800E784`），**在 `main()` 里被无条件调用** |
| 「测试固件」证据强度 | 强 | **减弱** —— 零调用者≠死代码，本镜像已有 ISR 先例（`0x08008978` 也零调用者） |

**⇒ 结论方向不变（波形确实不在明文段），但"零调用者"这条论据不能再用。**

**全链（`追加六`实锤）**：
```
main() 0x0800FA20
  ├─ 0x0800FD7C → 0x0800DFE8 → 0x0800D704 → TIM2 = 200 Hz
  ├─ 0x0800FD80 → 0x0800E750 → 0x0800D704 → TIM3 = 400 Hz  (+回调槽 [ctx+0x14])
  └─ 主循环 { 0x0800E1C0 命令分派器 … }
```


### 2.1 关于第 2 条，本轮（09-28）新增的两点认识

1. **为什么"一条条试"不可行（收口测试）**：GT7868Q 已实现 `0x00`–`0x0D` 这 **14 个连续 class**，
   而触觉在 `0xA0`/`0xA1` 分区。要逐条试需 ~`60/1 × 23 ≈ 1,380` 帧；
   但 `0x30` 那个 **ABORT 证明扫到约 47 帧设备就会被拖住**。两个数字不在一个量级
   ⇒ **这不是"还没试到"，是"结构上试不到"**。
2. **为什么"就算转发也命中不了"（静因机制）**：TF100A 的收包路径已完整解出 ——
   `wire[0]` 被单独取走存进 `ctx+0x104` 作命名空间，其余字节从 `ctx+0` 起顺序落
   ⇒ **子命令在 `wire[3]/wire[4]`，不在 `wire[2]/wire[3]`**。
   这条更正了项目文档里"永远不相等"那句的**理由**（原来把它归因于字节序，实际是
   **把 Col04 报文的字段偏移当成了 TF100A 内部缓冲的偏移**）——但**结论（路封死）不变**。

### 2.2 ⚠️ 一处证据性质的澄清（2026-09-28 两轮复核后的定稿）

**"主机经 Col04 触达 TF100A" 这条，证据是"实测 + 结构"两条，而不是"推断"一条。**

| 证据 | 复核结论 |
|---|---|
| 09-14 真机测试 | 实际做了**两次**：**11:15** 用 `0x000F`（表外，无效）；**23:40** 用 **`0x0B00`（表内合法）**，结果 send=True 但 6 种长度读取全 `err=122`、无 `A2` |
| 子命令偏移归属 | **两种封装假设，结论一致**：① 若子命令在 `pkt[2]/pkt[3]`（GT7868Q 结构化重组）⇒ **23:40 是一次有效的实测封死**；② 若在 `pkt[4]/pkt[5]`（原样转发）⇒ 该帧表外，但 TF100A 的 **37/38 条子命令低字节恒为 `0x00`**，而这位置在 Col04 协议里是**长度字段** ⇒ 主机**结构上难以构造合法帧** |
| 「GT7868Q 只实现 `0x00–0x0D`」 | ⚠️ **此说法已不准确**（`追加九` §2）：`opcode-sweep-log.txt` + `sweep-ops.ps1` 显示脚本**有意跳过** `0x10–0x13`、`0x20`，而这 5 个 class **是能应答的** ⇒ 已实现的是**分段集合** `0x00–0x0D` + `0x10–0x13` + `0x20`（≥19 个），**不是连续区间** |
| ⇒ 因此「收口测试」那句"结构上试不到" | ⚠️ **失去依据**。正确的说法是：`0x30–0x7F`/`0x80`/`0xA0`/`0xA1` **未测**；而"**不能大规模扫描**"这一条**仍然成立**（日志显示：0x30 尚未发送前，连已知有效的 `readMem` 就已 `err=122` ⇒ 累积流量会拖垮通道） |
| 反向补充证据 | TF100A 主循环里有任务**持续上报**（`0x0800767C`），而 Col04 IN 通道 **180 秒 0 报文**（监听用 `ReadFile` 异步，未踩红线）⇒ **GT7868Q 不把 TF100A 的上报转出主机** |

**⇒ 结论方向不变**（主机侧确实没有可用入口），**但"实测封死"与"不能扫描"必须分开表述**。
要彻底定案，只有**料板**或**逻辑分析仪夹 I2C1**（纯监听、零注入）。
**红线不变：真机上不要再发任何 `0xA0`/`0xA1` 帧。** 详见 `追加八` §8、`追加九` §1–§2。

## 三、★ 唯一可行路线：方案③（HDP/HDN 焊盘旁路）

### 3.1 为什么是它
- 不依赖任何主机侧接口 ⇒ 前面五个"封死"**一个都不影响它**
- 焊盘已实证：模组背面找到 **`HDP`/`HDN`** = 原装 LRA 的两根驱动线，且**从金属支架开口处露出 ⇒ 拆底盖即可接触**（不必拆开模组本体）

### 3.2 ★ 完整驱动规格（已从 TF100A 反汇编提取，可直接照做）

| 项 | 值 | 来源 |
|---|---|---|
| **主模式频率** | **200 Hz**（TIM2：PSC=119 / ARR=1999，÷120 → 2000 计数） | `0x0800E038` ✅实锤 |
| 第二模式频率 | **400 Hz**（TIM3：PSC=119 / ARR=999） | `0x0800E76C` ✅实锤 |
| 占空比 | **35%**（CCR = `0x2BC` = 700 / 2000） | `0x0800D76E` ✅实锤 |
| 通道 | **通道 1（CC1E）**，位掩码 `1` | `0x0800D760` ✅实锤 |
| 拓扑 | **支持互补输出（CCxNE/CCxNP 可配），但未设死区（无 BDTR 写入）** | `0x080105AC` case 1/2/3 |
| 谁驱动 | **MCU 自己的定时器直接 PWM**，**无外部驱动 IC**（无 SPI、无额外 I2C 从机） | 全外设清单 |
| 运行时调制 | **1 个通道配置函数 `0x080105AC`，3 个 case，各覆盖 TIM1/TIM8** | 09-28 晚修正 |

**200 Hz 正好落在 LRA 谐振带（170–235 Hz）⇒ 这是刻意设计，不是巧合。**

**"播放"的组织方式（追加六实锤）**：不是一个"波形播放函数"，而是
`main()` 无条件初始化两个定时器 → 每个定时器各配一段硬编码参数 → 定时器自己跑。
**没有"从主机接收波形"的路径** ⇒ 手感不来自主机。

⚠️ **"单端 PWM"要更正为"支持互补但未设死区"**：`0x080105AC` 的 case 1/2/3 明确在写
CCxNE/CCxNP。STM32F1 允许开互补输出而不设死区（DTG=0）。

### 3.3 还没定的（只剩两个）
| 项 | 怎么定 |
|---|---|
| **振幅（驱动电压）** | 示波器在 HDP/HDN 上**空载实测**实际驱动电压与波形 → 再定功放规格 |
| **LRA 型号与实测谐振频率** | 验证 200 Hz 假设；拆下模组看丝印或用阻抗法扫频 |

### 3.4 接线建议
- MCU 是单端 PWM ⇒ 两端之间需外部器件才能形成交流
- 建议：**小功率 H 桥 / 差分驱动器** 接 HDP/HDN；或信号发生器 + 功放
- 与原生驱动的互斥：建议加**模拟开关**，避免两个源同时驱动 LRA

## 五、红线（一条不动）
