## 二、★ 核心发现：EC 窗口只实现 768 字节

**全盘扫描 `0xFE000000 – 0xFEFFFFFF`（16 MB，28 秒，65,536 个 256B 块）**，
EC 相关只有这几块有内容：

| 物理地址 | 非 00/FF 字节 | 判定 |
|---|---|---|
| **`0xFE0B0400`** | 91 | **活**（窗口偏移 0x000–0x0FF） |
| `0xFE0B0500` | 73 | **活**（0x100–0x1FF） |
| `0xFE0B0600` | 26 | **活**（0x200–0x2FF） |
| `0xFE0B0700` – `0xFE0B0EFF` | 0 | **全 `FF`（未实现）** |
| `0xFE0B0F00` | 12 | 基本全零（EFAN / LA3M 窗口） |
| `0xFE0B1000` – `0xFE0FFFFF` | 0 | **全 `FF`** |

**⇒ `OperationRegion(ECMM, SystemMemory, 0xFE0B0400, 0x1000)` 这个 4 KB 窗口，
实际只映射 `0x000–0x2FF`（768 字节）；`0x300` 起全部读到 `0xFF`。**

**⇒ `LIDF` 在窗口偏移 `0x856` —— 落在未实现区，读到 `0xFF`。**

### 但基址和字段偏移是对的（交叉验证）

| ACPI 字段 | 窗口偏移 | 实测 |
|---|---|---|
| `LESR` / `LSRN` | 0x002 | ✅ 在变 |
| `EST1`–`EST6` | 0x0E4–0x0E9 | ✅ 在变（0x0E9 = EST2） |
| `WLIS` / `APSB` / `TCAD` | 0x0EA | ✅ 在变 |

**⇒ "字段偏移 = 窗口偏移"成立，`0xFE0B0400` 没找错。问题只在窗口的**实现长度**。**

### DSDT 里 EC 的 MMIO 窗口只有这三处（跨全部 32 张表确认）

| 区域 | 物理地址 | 长度 |
|---|---|---|
| `ECMM` | `0xFE0B0400` | 0x1000 |
| `PECM` | `0xFE0B0400` | 0x1000 |
| `ECCD` | `0xFE0B0400` | 0x1000 |
| （未命名） | `0xFE0B0640` | 0x30 |
| `LA3M` | `0xFE0B0F00` | 0xFF |
| `EFAN` | `0xFE0B0F00` | 0x1000 |

**没有第四个候选窗口。**

## 三、A/B/C 摆动实验：跑了，但**结论无效**

- 采样文件 `ecram_live_samples.bin`（336 样本 × 4096 B，80 秒）
- 可读区（0x000–0x2FF）内 **26 个字节发生变化**
- 其中"只在 B 相（摆动）变化"的**只有 1 个：`0x0E9`（EST2）**
  - 但看它的值序列 —— 前 24 个样本全是 `1C`，只在某处跳了一次；
  - 静止基线里它本来就是 `1B → 1C` 缓慢漂移
  - **⇒ 伪阳性，不是角度**

### 但这个"没有结果"**不能算证伪**

```
LIDF（0x856）在未实现区  ⇒  盖子状态即使变了，也不会在可读的 768 字节里留下痕迹
```

**⇒ 这个实验在设计上就回答不了问题。** 同理，可读区里那 ~530 个未命名字节虽然热闹，
但它们只是 EC 的时基/计数器（`0x0F8`、`0x103`、`0x12A`、`0x12C` 成片递减，是定时器）。

## 六、补充：I/O 端口通道也挖通了（同日晚）

### 6.1 `RwDrv.sys` 的完整 IOCTL 表（反汇编 + 交叉印证）

反汇编其 IOCTL 分发器（`0x113B` 起的比较链）得到 9 个码；与已知的 fwexpl 源码（TrickBot 用过的那份）
交叉印证后确认：

| IOCTL | 功能 | 分发器位置 |
|---|---|---|
| `0x222808` | 读物理内存 | `je 0x129D` |
| `0x22280C` | 写物理内存 | `je 0x1211` |
| **`0x222810`** | **读 I/O 端口 8 位** | `je 0x11FD`（`in al,dx`） |
| `0x222814` | 写 I/O 端口 8 位 | `je 0x11F1`（`out dx,al`） |
| `0x222818` | 读 I/O 端口 16 位 | `je 0x11E6`（`in ax,dx`） |
| `0x22281C` | 写 I/O 端口 16 位 | `je 0x11D8` |
| `0x222820` | 读 I/O 端口 32 位 | `je 0x11D2`（`in eax,dx`） |
| `0x222824` | 写 I/O 端口 32 位 | — |
| `0x22282C` | 索引/数据对写（两次 `out`） | `je 0x133A` |
| `0x222830` / `0x222858` / `0x22285C` / `0x222880` / `0x222884` / `0x22288C` / `0x22289C` | PCI / MSR / SMBus 等其它功能 | 分发链各分支 |

**端口 I/O 的结构体**（从 `0x11FD` 等处反汇编得出，8 字节，返回 8 字节）：

```c
struct PortIo { u16 Port; u16 pad; u32 Value; };   // Value = 读出值 / 待写值
```

**实测验证**（只读无害端口）：
```
port 0x61 -> 0x20      （NMI 状态）
port 0x71 -> 0x26      （CMOS 数据，合理）
port 0x80 -> 0x00      （POST 码）
port 0x66 -> 0x08 持续 （EC 状态口：IBF=0 OBF=0，接口空闲）
```

### 6.2 ❌ ACPI EC 只读协议：**EC 不响应**

按标准 ACPI EC 读时序尝试读取 EC RAM 偏移 `0x00–0x07`：

```
wait IBF=0 → 写 0x80 到 0x66（READ_EC）→ wait IBF=0 → 写偏移到 0x62 → wait OBF=1 → 读 0x62
```

**结果：8 次全部 `TIMEOUT`（OBF 始终不置位，50 ms 超时）。**

**⇒ 这条代机器上，裸端口访问 EC 不被响应**（可能原因：EC 接口由 ACPI 驱动独占/授权、或该代 EC 只认 eSPI 侧的封装时序）。
**没有重试** —— 每次尝试都是对 EC 的流量，按红线"不碰"。

### 6.3 由此产生的两条结论

1. **端口读通道本身可用**（`0x222810` 已验证），只是 EC 不响应裸命令
2. **MMIO 是唯一能读到 EC 内容的通道，而它只给 768 字节**

## 七、角度项目 · 主机侧收官判定

把所有证据串起来：

| # | 证据 | 结论 |
|---|---|---|
| 1 | 25 个 `_Qxx` 全反编译 | 与盖子相关的**只有 `_Q15`**；它读的 `LIDF` 位于 **MMIO 未实现区** |
| 2 | EC MMIO 可读 768 字节（0x000–0x2FF） | A/B/C 实测（336 样本 / 80 秒）：**其中没有任何随屏幕角度变化的字节** |
| 3 | DSDT 的 `Field(ECMM)` 120 个字段 | **无角度/铰链字段**；与盖子有关的只有 `LIDF` 1 bit |
| 4 | 传感器上报通道 `_Q20` + `DPOT` | 只有 5 个槽位（bit3–7），**全部是温度传感器** |
| 5 | 官方 HMM 的 FRU 表 | 机身侧 22 个 FRU **无任何传感器件**；唯一的"传感器板"在屏幕顶部（ALS/摄像头） |
| 6 | ACPI EC 端口只读协议 | **EC 不响应**，此路不通 |

### 最终判定

> **在这台机器上，主机侧能看到的范围内——不存在盖子角度量。**
>
> - **已证实**：768 字节可读 EC 窗口内无角度字节；DSDT 字段表无角度字段；事件表无角度事件；传感器通道无角度槽位。
> - **未证实（但也没有任何证据支持）**：MMIO 窗口 `0x300–0xFFF`（含 `LIDF`）不可读，因此无法直接排除"那儿藏着角度"。但**它连盖子状态位都读不出来**，说明这一段大概率是**厂商 DSDT 的通用样板**，在本机型上并未实现。
> - **最合理的解释**：开盖检测由 **EC 固件内部完成**（EC 自己驱动睡眠），`LIDF` / `ECMM` 高位字段是跨机型的模板代码，本机未用。

### 主机侧只剩两条路，都不在"只读软件"范围内

| 路线 | 说明 | 需要 |
|---|---|---|
| **A** | **EC 固件静态逆向** | 解包 `NJCN67WW.exe` → 提取 EC 固件 → Ghidra 反汇编，找角度运算/阈值比较。**仍然不用拆机** |
| B | 读 EC 内部 RAM 的运行时值 | SWD / JTAG，或 EC 固件补丁 —— **要动硬件/固件** |

**⇒ 下一步应该走 A：解包 BIOS 拿 EC 固件。** 这也是最早那份清单里就列着、一直没做的一项。
