## 〇、三句话

1. **逆向侧已实质收口**：不是"还没找到"，而是**用证据证明路不存在**。主机侧 6 条注入面全部判定为结构上不成立。
2. **唯一可行路线（方案③ HDP/HDN 焊盘旁路）逻辑上与前 6 条完全解耦**，所以它是一个**不会因后续更正而翻案**的结论。

## 二、核心逻辑：一条并联的"注入面穷举"（不是串联试错）

需求 = 让 LRA（线性谐振马达）动。任何方案都必须存在一条 **主机 → LRA** 的驱动通路。
把"通路"拆成 6 个可能入口后，结论不是"5 条里都没走通"，而是"**5 条各自被独立判定为结构上不存在**，第 6 条**不依赖前 5 条中的任何一条**"。

```
        ┌────────────────────────────────────────────────────┐
        │ 主机侧注入面（5 条 · 各自独立判定为不存在）          │
        │  ① HID 标准接口层       ✕ 无 Manual Trigger 报表    │
        │  ② 厂商通道 Col04       ✕ class ≥0x0E 连续 28 未处理│
        │  ②b 写波形缓冲 0xA0/0B00 ✕ 目标表无消费者（补强②）  │      ┌─────────┐
        │  ③ 固件加密区 100 KB    ✕ 密钥在芯片 OTP/eFuse     │ ───▶ │   LRA   │
        │  ④ TF100A 明文段        ✕ 参数硬编码、无波形输入    │      │  马达   │
        │  ⑤ 包络的上层来源       ✕ 由加密侧下发（推断）      │      └─────────┘
        └────────────────────────────────────────────────────┘           ▲
                                                                         │
        硬件旁路 · 方案③：拆底盖 → HDP/HDN 引线 → H 桥/差分驱动 ──────────┘
        ✔ 不经过 MCU / 固件 / HID / EC 的任何一层
        ✔ 因此上面 6 条判决对它全部无效
        ✔ 反汇编副产品（封死④的过程）正好提供了它需要的 6 条驱动规格
```

### 为什么这张图就是全部逻辑关系

| 关系 | 内容 | 工程含义 |
|---|---|---|
| **并联独立（AND）** | ①~⑤ 互不依赖，每条有自己的证据链 | **不存在"再试一条就能翻案"的余地**，也没有"找到关键那一条"的剧情 |
| **补强（冗余证据）** | ②b 对 ②：② 说"门打不开"，②b 说"**就算打开了门后也没有房间**" | 双保险；且 ②b 让"字节序卡点"这条研究线**定案也无用** |
| **副产品（封死→产出）** | 封死 ④ 的过程产出了方案③ 需要的 6 条规格 | "这条路封死了" ≠ "这轮白做了" |
| **单向推断依赖（软肋）** | ⑤ 是 6 条里唯一强度不足的（推断） | 它若被推翻，只影响"手感从哪来"的叙事，**不动摇任何决策** |
| **替换（更正）** | 同一位置旧结论被整体替换 | 替换 ≠ 推翻方向（见 §四） |
| **收敛（可做项归零）** | 可推进项 9 → 1 中 + 2 低 | 关键动作是"**判死**"，不是"推进" |

## 三、六道闸门：判决与决定性证据

### ① HID 标准接口层 —— 没有主机发起触觉的接口
- **决定性证据（四重独立）**：描述符未声明 Manual Trigger OUTPUT 报表；微软 Haptic Touchpad 规范要求该报表；Linux 上游 RFC 同样无此通路；真机实测确认。
- **判读**：约束来自**设备描述符**，不在 Windows 驱动栈的任意层 —— 换驱动、换系统都不改变。

### ② 厂商通道 Col04 —— 门在 GT7868Q 侧，它没实现那片分区
- **实测**：`pkt[1]` = `0x00`–`0x0D` 正常应答；`0x0E`/`0x0F`/`0x14`–`0x2F` **连续 28 个 class 全部 `err=122`**（未处理类的默认应答）。
- **不转发**：发 `A1` 帧无 `0xA2` 应答 ⇒ **H1 判否**。
- **收口测试（关键判据）**：已实现 14 个连续 class，触觉在 `0xA0`/`0xA1` 分区 ⇒ 逐条试需约 `60/1×23 ≈ 1380` 帧；而 `0x30` 的 ABORT 证明**扫到约 47 帧设备就会被拖住**。两个数不在一个量级 ⇒ **这不是"还没试到"，是"结构上试不到"**。

### ②b 写波形缓冲 `0xA0/0x0B00` —— 即使写进去也不产生振动【补强】
- **反汇编实读**：`0x0800D8C0`（`A0/0x0B00`）= 逐字节 `msg[4..] → 0x200040E8`，无其它副作用；
  `0x0800D868`（`A1/0x0B00`）= 组 `A2 <n> <data>` 回包 + `GPIOA->BRR = 1<<3`（拉低 PA3 握手线）。
- **引用完整性检查**：全镜像扫 `0x40e8` **恰好 2 处**（`0x0800D894` 读 / `0x0800D8E6` 写）。
  ⇒ 完整生命周期 = 「主机写进来」+「主机读回去」，未接 TIM2/TIM3、未接播放回调 `ctx+0x14`。
- **逻辑升级**：从"门打不开"升级为"门后没有房间" ⇒ "字节序卡点"这条线降级为**仅记录**。
- **副作用解释**：正好解释项目当年"写 `rid=9` 力度变但不震" —— 参数确实收下了，但没有东西把它变成驱动。
- **顺带更正**：处理函数旧记 `0x080088C0`/`0x08008868`，实为 **`0x0800D8C0`/`0x0800D868`**（两个地址在镜像里都存在，写岔一位）。

### ③ 固件加密区（100 KB）—— 密钥不在主机侧
- **三证独立**：容器格式（汇顶在 fwupd 已开源）无密钥字段；两个主机侧工具无加解密实现；Dell 刷写器写入路径是明文内存写。
- **结构特征**：128 位分组 / ECB 式 / 跨 4 年同密钥。
- **后果**：差分攻击需第二份同族固件，且解开后还要过"值语义"关 ⇒ 价值低。

### ④ TF100A 明文段 —— 波形/手感不在里面【方向不变，论据已换】
- **完整链**：`main() 0x0800FA20` → `0x0800FD7C → 0x0800DFE8 → 0x0800D704`（TIM2 = 200 Hz）；
  `0x0800FD80 → 0x0800E750 → 0x0800D704`（TIM3 = 400 Hz）；随后进入无限主循环（命令分派器 + 7 任务）。
- **无接收波形路径**：两个包装函数参数全硬编码、无分支 ⇒ 是两段固定波形。
- **回调只是计数器**：`0x0800D6F5` 仅做 `[0x20004010]++`。
- ⚠ **旧论据作废**：「播放函数 `0x0800D628` 零调用者 ⇒ 测试固件」——本镜像已有 ISR 先例（`0x08008978` 也零调用者）。**零调用者 ≠ 死代码**。
- **方向反而更硬**：真播放器 `0x0800D704` 有 2 个调用者且在 `main` 里被无条件调用。

### ⑤ 手感/包络的上层来源 —— 包络由加密的 TP 侧下发【推断 · 唯一软肋】
- **支持**：明文段里只有常量、无 pattern 表；分派器 39 条 handler 无一接 TIM2/TIM3。
- **未排除**：① 由 TF100A 自己的加密区产生；② 由 GT7868Q 侧产生。
- **为什么不构成风险**：它只回答"手感从哪来"；④ 已独立证明"明文段里没有波形"，所以⑤ 成立与否都不改变决策级结论。
- **要闭合它**：只能靠硬件接入去"观测"LRA 何时被驱动（用测量代替逆向）。

| # | 旧结论 | 更正后 | 根因类别 |
|---|---|---|---|
| 1 | BIOS 里没有 Goodix 代码 | 解压后有 `GoodixTpDxe`（48,590 B，源码来自 edk2-platforms `GtpUpdate`） | 搜索范围错 + 在压缩态搜字符串 |

## 八、红线（一条不动）

1. 禁止对 `Col04` 做后台轮询；嗅探只能前台、≤30 秒、间隔 ≥200 ms
