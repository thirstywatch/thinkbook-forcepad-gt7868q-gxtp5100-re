# 追加二十一 —— ★ 更正一个长期推测：「华为的滑动跟随震动」不存在

> 日期：2026-09-28 · 五条一手证据（华为官网 / 荣耀官网 / V2EX 两代用户实测 / 微软 2026 规范）
> **本文推翻 `DESIGN.md` §2.6 第 217 行一个标注为"大概率"、但从未验证的推测。**

---

## §0 一句话

> **矛盾不存在 —— 因为「华为用主机触发震动来做滑动跟随」这个前提本身就是错的。**
> **华为做的是两件**互不耦合**的事：① 用户态手势（电脑管家）调音量/亮度；② device-initiated 的按压触觉（强度低/中/高 = `0x0E/0x23`，与本机同一个旋钮）。**
> **⇒ 汇顶没有扳机 / 华为没做主机触发 —— 两个事实完全自洽。**

---

## §1 被推翻的那句话（原文）

`DESIGN.md` §2.6（关键）第 217 行：

> 「2. **华为的震动是"设备自主触觉的强度可调"（低/中/高）**，与我们从描述符测到的 `Haptic Intensity`（Report ID 9）是同一个旋钮；**滑动过程中的逐格震动则大概率来自「他们那块板子支持主机发起触觉」**（本机不支持，见 §2.5）——这正好落在 Phase 3 的证伪条件上。」

**⇒ 前半句（强度旋钮 = `0x0E/0x23`）是对的；后半句（滑动逐格震动来自主机发起触觉）是**未验证的推测**，而且**现在被推翻**。**

## §2 五条一手证据

### 2.1 华为官方支持页（[原文](https://consumer.huawei.com/cn/support/content/zh-cn15908056/)）

官方把设置分成三组，**井水不犯河水**：

| 分组 | 内容 |
|---|---|
| **触控板设置** | 调节按压灵敏度、**振感强度（低、中、高三个等级）** |
| 指关节手势 | 截屏、录屏 开关 |
| **边缘手势** | 调节亮度、调节音量、视频快进快退、最小化窗口、关闭窗口 **开关** |

**⇒ 「振感强度」在**触控板设置**里；「边缘手势」是**独立的一组开关**。**
**⇒ 全文没有任何一句说"边缘滑动时会有震动"。**

**★ 而且「振感强度 低/中/高」= `0x0E/0x23 Haptic Intensity`（0–100 的旋钮）—— 与本机 Col02 的 Feature RID 9 是同一个东西。**

### 2.2 V2EX 实测：MateBook X Pro 2024 用户（两代都用过）

[原帖](https://global.v2ex.co/t/1034727)（2024-04，7,734 次浏览，68 条回复）：

> 「**一直在加边缘滑动调亮度，音量，视频进度，指关节截屏，录频这种功能。核心体验上，这一代震动马达硬件缩水，驱动也毫无改进。**」

**⇒ 他把"边缘滑动"与"震动"明确描述为两件独立的事。**

### 2.3 同帖 68 条回复：讨论震动的全在讲"按压反馈"

| 回复 | 原话 |
|---|---|
| OP | 「**震动反馈全都在掌托**，反而触控板上的反馈很弱」 |
| OP | 「外加那个**糟糕的力反馈**，我甚至感受不到按键已经被放开了」 |
| #9 datasone | 「今年估计是为了卡 1kg 内，**把电机砍成单马达**了……**震动强度最好是中**，因为调成强之后不但震动反馈没多好，反而延迟明显增加了」 |
| #15 ghostwwg | 「花厂的触控板已经算上乘的了，可惜**只有一个马达**」 |
| #31 datasone | 「按下拖拽之后松开力度，**已经能感受到松开力度后的回弹**，并且反复按下、松开的时候也能感受到和正常点击一样的力度反馈」 |

**⇒ 全部在描述「按下/松开的触觉反馈」= device-initiated。**
**⇒ 68 条里**无一条**提到"沿边缘滑动时触控板会震"。**

### 2.4 荣耀官方支持页：振动被当作"点击反馈强度"处理

标题即 [《荣耀MagicBook Art 14系列笔记本触控板振动太强或太弱》](https://www.honor.com/cn/support/content/zh-cn15864330/)（另有[英文版](https://www.honor.com/uk/support/content/en-us15864330/)）

**⇒ 官方只把"振动"当成一个**可调的点击反馈强度**来处理，从不把它与手势关联。**

### 2.5 华为/荣耀官方：边缘手势是**用户态**功能

- 华为：「此功能**集成在华为电脑管家**，使用时请保持华为电脑管家为运行状态」；「要求华为电脑管家版本在 **13.0.2.300** 及以上」
- **⇒ 手势是软件功能（可开关、随版本解锁），不是固件魔法**
- **⇒ 与震动（固件内的 device-initiated 触觉）在完全不同的层**

## §3 ★★ 更重要的正向发现：「逐格震动」是 **2026 年微软刚定义的新交互**

来自微软《[Implement haptic feedback in Windows apps](https://learn.microsoft.com/en-us/windows/apps/develop/input/haptics)》（最后更新 2026-08）：

> ### Sliders
> "Haptics improve slider interactions by anchoring feedback to meaningful positions. Always tie feedback to visible markers the user can understand — tick marks, named values, or range boundaries.
> **When to fire:** **Fire haptics as the thumb crosses each tick mark.** Avoid continuous feedback between ticks, which can feel distracting."

—— 用的波形是 **`KnownSimpleHapticsControllerWaveforms.Step`**。

**★ 而且微软还专门写了"意图检测"的做法**（速度滤波 / 50 ms 定时器防抖），因为"在快速移动时逐格触发会淹没用户"。

> ## **⇒ 「手指滑动跨过刻度 → 震一下」正是微软 2026 年定义的交互，官方叫 Sliders + Step 波形。**
> ## **⇒ 但它**需要设备支持 host-initiated**（`0x0E/0x21 Manual Trigger`）。**
> ## **⇒ 官方支持设备列表（2026-06）：触控板只有 `Surface Laptop 8` —— 第一个做这件事的。**

## §4 ⇒ 结论：我们一直在对标一个**并不存在**的"华为方案"

| 我们以为的 | 实际 |
|---|---|
| 华为用某种主机→触控板的震动指令，实现了"边缘滑动逐格震动" | ❌ **华为没做这个**。边缘滑动只是用户态调音量/亮度，震动是独立的按压反馈 |
| 华为那块板（GT7863）应该有"扳机" | ❌ 项目早已确认其描述符**同样没有 `0x0E/0x21`** —— 与"华为没做主机触发"完全自洽 |
| 我们比华为"低一档" | ❌ **不存在这个落差**。华为能调的（强度低/中/高）**本机也能调**（`0x0E/0x23`） |

**⇒ 而"移动时逐格震动"这个真需求，是 **2026 年微软新规范**里的东西，第一个落地的是 Surface Laptop 8。**

## §5 目标重新校准（诚实版）

| 目标 | 状态 |
|---|---|
| **A · 更多功能**（边缘滑动调音量/亮度、指关节手势…） | ✅ **纯软件可实现，与华为同构（都是用户态）**；本机已验证与华为做法同层 |
| **B · 震动反馈** | 拆成两问：<br>**B1 · 调"按压反馈强度"** ⇒ ✅ **本机可做**（`0x0E/0x23`，与华为同一个旋钮）<br>**B2 · 按我们的时机触发（逐格震动）** ⇒ ❌ **本机做不到**（缺 `0x0E/0x21` 等六条）—— 而**华为也做不到** |
| **C · 通用** | ✅ 用 `haptic-capability/` 的**能力探测 + 分级支持**：<br>A 级（如 Surface Laptop 8）⇒ 走 `InputHapticsManager`，逐格震动可实现<br>B 级（本机 / 华为 MateBook）⇒ 强度调节<br>C 级 ⇒ 无 |

**⇒ 所以对着"华为"这个标杆追"滑动震动"，追的是一个**不存在的功能**。**
**⇒ 真正可对标的新标杆是 **Surface Laptop 8（2026）+ 微软 Sliders/Step 规范** —— 而它要求的正是那块我们缺的扳机。**
