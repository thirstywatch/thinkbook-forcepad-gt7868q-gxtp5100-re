## 一、角度项目（lid）

### 1.1 ★★★ LIDF 实证成功（里程碑）

连拍 236 帧 × 768 B（纯只读），用户做两轮合盖 → **LIDF 位两段翻转与动作逐次对应**：

| 事件 | 帧号 | `0x0B8` |
|---|---|---|
| 合盖 1 / 开盖 1 | 30 / 39 | `00→02` / `02→00` |
| 合盖 2 / 开盖 2 | 64 / 78 | `00→02` / `02→00` |

**严格特异性检验**（768 B × 8 位 = 6144 位逐个求"置位帧集合"）：**只有 `0x0B8.1` 与 LIDF 完全一致**，真子集 0 个 ⇒ **零假阳性**。
配套：`0x00B.2` 是伴随位（超集，24 帧 vs 23 帧）；温度/风扇/电池类候选全部排除。

**产物**：`lid-probe/ec-re/实证-LIDF位确认.md` · `scripts-ec/lidf_capture.py` · `ec-lid-snaps/capture-20260927-212353/`（236 帧）

**方法论教训（已写入技能）**：用户发消息到工具执行有 ~50 秒延迟 ⇒ 动作指令必须**放在同一条消息里、紧跟工具调用**，且连拍时长放宽、动作做两轮。

### 1.2 ★★ EC 命令协议解出（`ERCD`）

DSDT 里的 `ERCD` = EC 命令收发器：`ECMD`+`EDT1-5` → `ECTB/ECTE` → 轮询 → `ERN1-8`。
命令表：**`0xB0` 任意地址读** / `0xB1` 任意地址写 / `0x5B` 16 位地址操作 / `0x45` 风扇与功率。

### 1.3 ★★★ EC 端口协议完全解出（本日最深的技术成果）

从 BIOS 内 `IhisiServicesSmm` 反汇编得到**权威协议**：

| 操作 | 时序 |
|---|---|
| 读 | `out 0xD01=地址高` → `out 0xD02=地址低` → `in 0xD03` |
| 写 | 同上 + `out 0xD03=数据` → 重设地址 → `in 0xD03` 回读校验（≤100 次重试）|
| 收尾 | 恢复 `0xD01`/`0xD02` 原值 |

**地址空间 = `0xC400 + 窗口偏移(0x000–0x2FF)`**：签名 `0xC620/0xC621` = `5A/A5`，与内存窗口 `0xFE0B0400 + off` 完全对齐 ✅

**⇒ 更正**：2026-09-27 我判"端口路径从 OS 侧不可用"是**错的** —— 实测时地址该用 `0xC4xx`（我用了 `0x00xx`）。**端口路径可用，且固件自带校验/重试/原值恢复。**

### 1.4 首次涉足 IHISI（Insyde SMI 服务）

- `IhisiSmm`(37 KB) / `IhisiServicesSmm`(94 KB) 存在；SMM 里的 EC 读写原语（`0xE204` 读 / `0xE0B8` 写）已解；SMM 还自备一套 ECMD/EDT/ERN 收发（与 ACPI `ERCD` 同款）
- `IhisiServicesSmm` 的 `0x5418` = **电池状态服务**（读 EC `0xCE` 容量、`0xDA` 充电标志）⇒ 证明 IHISI 服务按**绝对 EC 地址**读写
- `IhisiSmm` 的 13 条目函数指针表（`.reloc` 精确命中 13 个、间距 8）逐条反汇编后判为 **SMM 内部服务/协议包装层**（GUID 比对 + 调用全局函数指针），**不是 OS→服务号分派表** ⇒ 继续挖性价比下降
- **两个项目此前都没提过 IHISI**

**为什么"直控 I2C 控制器"被判不必要且更危险**（有证据的五条）：
① Intel LPSS I2C 由 `iaLPSS2_I2C` 持有并已初始化 → **一台状态机两个主人**；

**且有更安全等价路径**：Linux `i2c-dev`（内核仲裁）或 ESP32 直挂 I2C。

## 二·补 ★★ 下午收口：TF100A 收包路径完整解出（20:0x 归档）

### 1) 完整调用链
```
I2C1_EV_IRQHandler = 0x08008978   ← 全镜像无代码引用（grep 零命中）⇒ 向量表入口
  ├ 0x05010109 → 0x08008B30   ADDR：清计数器（事务起点）
  ├ 0x05060109 → 0x08008A70 ★ RxNE：收字节（唯一收包路径）
  ├ 0x05040109 → 0x08008A4C   PE-toggle 总线复位
  ├ 0x05070109 → 0x08008AE4   TxE：发字节
  └ 0x050?010A → 0x08008A1C   另一事件
```

**新工具：事件码解码**（`0x0800FC80` 测位 / `0x0800FC20` 置位，同一编码）
| 位域 | 含义 |
|---|---|
| `code[15:6]` / `code[4:0]` | 寄存器字节偏移 / 该寄存器内 bit 号 |
| `code[31:22]` / `code[20:16]` | 第二个寄存器偏移 / 第二个 bit 号 |

⇒ `0x0109` = `CR2 bit9` = **DMAEN**；高半 `0x0506` = `SR1 bit6` = **RxNE**
⇒ 读懂初始化 `0x08008B68`：**`CR2 |= DMAEN`**、**`CR1 |= PE`**
⇒ **收包函数的触发条件由固件自己置上 ⇒ 在执行通路上，非死代码**（区别于 TIM3 那个零调用者的例子）

### 2) ctx 结构（由访问偏移反推）
`rx_buf[0x80]@+0x00` · `tx_buf[0x80]@+0x80` · `tx_idx@+0x100` · `rx_idx@+0x102` · `ns@+0x104` · `ctrl@+0x106` · `state@+0x107`
（两侧溢出阈值同为 `cmp ...,#0x7f` ⇒ 两个 0x80 缓冲并列，自洽；句柄 `0x20004134 = [0x20004128]+0xC`）

### 3) ★★ 字节落位（本轮定案）
| wire | 落点 |
|---|---|
| **wire[0]** | **ctx+0x104**（被单独取走作命名空间） |
| wire[1] / wire[2] | ctx+0 / ctx+1 |
| **wire[3] / wire[4]** | **ctx+2 / ctx+3** ← 子命令低/高字节 |

⇒ 子命令 = `wire[3] | wire[4]<<8`，**不是** `wire[2]/wire[3]`
**独立交叉验证**：发包编码器 `0x0800BDE0` 基址是 `0x20004128`，`[r1+0x8C]=ctx+0x80`
⇒ 发送帧 = `[0x80][len=4][type=2][lo][hi]`（带独立长度/类型字段）⇒ 接收帧对称 ✔

## 二·补二 ★★★ 20:3x 触觉播放通路完整解出（原「下一步 2」已执行）

**做了什么**：写静态调用图工具 `fw-touchpad/callgraph.py`，从 21 处 CCER 读写点回溯，
完整解出「触觉播放」的组织方式。**纯离线，零风险，已全部归档。**

### 核心结论

**「播放」不是一个函数** —— 是 `main()` 里**无条件初始化**的两个定时器：

```
main() 0x0800FA20
  ├─ 0x0800FD7C → 0x0800DFE8 → 0x0800D704 → TIM2 = 200 Hz
  ├─ 0x0800FD80 → 0x0800E750 → 0x0800D704 → TIM3 = 400 Hz  (+回调槽 [ctx+0x14])
  └─ 主循环 0x0800FDF4 { 0x0800E1C0 命令分派器 + 7 个任务 }
```

### 三条更正（都是对既有结论的修正）

| # | 原结论 | 更正后 |
|---|---|---|
| 1 | 「TIM1/TIM8 CCER ×21 处、散落全镜像」 | **全在同一个函数 `0x080105AC` 内**，是它的 3 个 case |
| 2 | 「单端 PWM、无互补输出」 | **支持互补（CCxNE/CCxNP 可配），只是未设死区** |
| 3 | 「`0x0800D628` 播放函数零调用者 ⇒ 测试固件」 | **论据作废** —— 它零调用者≠死代码（已有 ISR 先例）；真正的播放器是 `0x0800D704`，**有 2 个调用者且在 main 里** |

### 新增 6 条可直接照抄的驱动规格（方案③ 直接受益）

| 项 | 值 | 实锤地址 |
|---|---|---|
| 频率 | 200 Hz / 400 Hz | `0x0800E038` / `0x0800E76C` |
| 占空比 | **35%**（CCR = 0x2BC = 700 / 2000） | `0x0800D76E` |
| 通道 | **通道 1（CC1E）**，位掩码 1 | `0x0800D760` |
| 互补输出 | 支持，未设死区 | `0x080105AC` case 1/2/3 |

### 关键判断

- **波形/手感确实不在 TF100A 明文段**（包装函数参数全硬编码，回调只是计数器）→ 支持项目预判
- ⚠️ 但**不等于已证实"由 TP 侧下发"**：另有两种可能未排除（TF100A 加密段 / GT7868Q 侧）
- **本项处置：降级但不作废**（确认预判 + 净赚 6 条规格）
- **方案③ 剩余缺口仍只有 2 个**：**振幅** + **LRA 型号/谐振频率**
