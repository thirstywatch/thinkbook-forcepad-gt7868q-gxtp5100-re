## §1 任务 3：`ctx+0x1691` / `+0x1692` 全解 —— ★ 新链路

### 1.1 `ctx+0x1690` 邻域的完整地图（`ctx` = `0x2000495E`）

| 偏移 | 绝对地址 | 名称 | 语义 |
|---|---|---|---|
| `+0x1690` | `0x20005FEE` | **`armed`** | 待处理标志（`A0/0x0D00` 置 1，主循环任务消费）—— 已解 |
| **`+0x1691`** | **`0x20005FEF`** | ★ **采样窗口开** | `=1` 表示"正在累积" |
| **`+0x1692`** | **`0x20005FF0`** | ★ **累积完成待取走** | `=1` 表示"结果就绪" |
| `+0x1694` | `0x20005FF2` | （不是标志） | 它是**长度** `0x1694 = 5780`，出现在 `A0/0x0D00` 的 `memset` 参数里 |

**全部访问点**（`asmq.mjs grep '#0x169[0-9]'` 机械提取）：

| 地址 | 操作 | 所属 | 说明 |
|---|---|---|---|
| `0x08009A16` | **写 `+0x1691` = 1** | 函数 **`0x080099EC`** | ★ **开采样窗口** |
| `0x08005BC6` | 读 `+0x1691`，要求 `==1` | **主循环任务 `0x08005BB8`** | 门控 |
| `0x08005C44` | **写 `+0x1691` = 0** | 同上 | 累积满 **300** 次后关窗口 |
| `0x08005C4E` | **写 `+0x1692` = 1** | 同上 | 置"结果就绪" |
| `0x08008794` / `0x080087AC` | 读 `+0x1692`，`==1` 则**清 0** | 函数 **`0x08008784`** | ★ **取走结果 + 回 `A2 10 <16B>`** |
| `0x0800630E` | 写 `+0x1691` | `0x080062xx`（**USART 侧**） | 另一条链路也参与同一状态机 |
| `0x08006360` / `0x08006384` | 读/清 `+0x1692` | 同上 | 同上 |

### 1.2 完整链路（逐条实读）

```
① 0xA0/0x2000  → 块 0x0800E2CE → 0x080099EC
      若 msg[0] == 1  ⇒  ctx+0x1691 = 1              ★ 开采样窗口
② 主循环任务 0x08005BB8(ctx=0x2000495E, flags=0x2000403C)  每轮：
      if (ctx+0x1691 != 1) return;                    ; 窗口未开 → 什么都不做
      if (flags[0] & 1) {                             ; 有一位"新数据"位
          flags[0] &= ~1;
          for (i=0;i<4;i++)
              0x2000405C[4i] += *(u16*)(flags + 2 + 2i);   ; ★ 4 通道 → 4 个 32 位累加器
          0x20004058++;                                    ; 采样计数
          if (0x20004058 >= 300) {                         ; ★ 阈值 = 300
              ctx+0x1691 = 0;                              ; 关窗口
              ctx+0x1692 = 1;                              ; ★ 结果就绪
          }
      }
③ 0xA1/0x0400  → 块 0x0800E54A → 0x08008784
      若 ctx+0x1692 == 1  ⇒  ctx+0x1692 = 0
                            ⇒ 构造 buf[0]=0xA2, buf[1]=0x10 (16 字节)  ; ★ 取走结果
                            ⇒ 从 0x2000602A 结构取数据填入 + 拉 PA3
④ 0xA1/0x2B00  → 块 0x0800E5A2 → 0x080099A4
      回 A2 01 <[0x20004945]>
      清 0x20004948、清 0x20004954（16 位）            ; 复位累加/计数
      拉 PA3
```

### 1.3 ⇒ 净结论

- **这是一套「主机开窗口 → TF100A 累积 300 次 4 通道采样 → 主机取结果」的完整闭环**，此前**两个项目都不知道**。
- **它给出了第三个"主机命令能改变 TF100A 行为"的实例**（前两个：模式字节 1/2/3/4、`armed`）。
  具体命令：**`0xA0/0x2000`（开窗口）**、**`0xA1/0x0400`（取结果）**、**`0xA1/0x2B00`（复位）**。
- **两条链路（I2C1 与 USART1）共用这套状态机** —— 这也修正了 `追加八` §5.2 里"USART1 不承载命令协议"的说法需要**加一句限定**：USART1 不承载那 39 条命令，但它**参与同一个力采样状态机**。
- ⚠️ **仍然不接马达**：整条链都在数据处理簇（`0x0800A0xx` / `0x08005Bxx`），不在 `追加八` §7 的定时器引用闭包内。

## §2 任务 2：三方比对**前提不成立**（附根因与修法）

### 2.1 我做了什么、为什么失败

用 `poc/xref_mem_vs_container.mjs` 把设备 64 KB 窗口与本地容器做 8 字节高熵锚点比对，得到一堆**"阶梯状"假匹配**（delta 每级相差 `0x43C = 1084`）—— 那是**容器内周期性重复结构**造成的，不是真实对应。
**该比对结论作废。**

### 2.2 ★ 根因：这个通道的**返回字节序随请求起始地址变化**

受控实验（同一秒、同一函数、同一段稳定内容 `YELSTO` 区）：

| 请求起始地址 | 覆盖绝对地址 `0x4000..0x4003` 的 4 字节 | 判定 |
|---|---|---|
| `0x3F80` / `0x3FC0` / `0x3FE0` / `0x3FF0` / `0x3FF4` / `0x3FF8` / `0x3FFC` | `B1 ED E0 A7` | **组内反序** |
| **`0x4000`** | **`A7 E0 ED B1`** | **正序** |

- **地址↔偏移映射是正确的**：已验证 `read(0x3FFC)` 的每一组都等于 `read(0x4000)` 对应地址那 4 字节的**逐字节反转**（含 ASCII：`read(0x4000)` 处读作 `YELSTO`，`read(0x3FFC)` 处读作 `SLEY`）。
- **可复现、与顺序无关**：交错连读 `0x3FFC → 0x4000 → 0x3FFC → 0x4000`，结果每次一致（`....SL` / `YELSTO` / `....SL` / `YELSTO`）⇒ **是地址的函数，不是状态残留**。
- **规律未定**：试了 **8 个起始地址**，只有 `0x4000` 得到正序。mod 4 / mod 8 / mod 16 / mod 0x40 / `0x100` 页边界**都不能解释**（`0x3FF0` 与 `0x4000` 都是 16 的倍数，前者却反序）。

### 2.3 ⇒ 后果与修法

| 后果 | 说明 |
|---|---|
| ⚠️ **`mem-scan-16bit.txt` 不能用于任何跨地址/跨块的结构分析** | 它由 **60 字节步长的 1093 个块**拼成；每块的字节序取决于该块自己的起始地址 ⇒ **文件内部的字节序一致性无法保证**。（已确认：其 `0x3FFC` 块与实时 `read(0x3FFC)` 逐字节一致 ⇒ 扫的是"设备当时返回的东西"，但"返回的东西"本身不统一。） |
| ✅ **`mem-now.txt` 可信** | 它用的是少量、点对点的读取；本次已与实时读在 `0x4000` / `0x1800` / `0x5B80` **逐条对上**（0x4000 处含 `YELSTO`/`7869`） |
| ✅ **可以做的一条确定结论** | 窗口 `0x4018` = `YELSTO`、`0x4020` = `7869`；容器 `0x1142` = `YELSTO`、`0x114B` = `7868Q`、`0x19ECC` = `TF100A`（= 明文段 `0x19ABC` + `0x410`）⇒ **窗口确实暴露了与容器同源的 GT7868Q 标识数据**；但"对应容器哪一段"**仍无结论** |

**修好的扫描方法（要重扫时按这个来）**：
1. **每次只读一个 4 字节组**，且**起始地址就是目标地址**（或用 4 字节对齐的定长块、并对每块独立做字节序自检）；
2. 或**保留原步长，但对每块加一次"字节序自检"**：用一个已知锚点（如 `0x4000` 的 `A7 E0 ED B1`）在每块内定位并判定该块的正/反序，再归一化；
3. **必须**在扫描文件头部记录扫描参数与自检结果。
