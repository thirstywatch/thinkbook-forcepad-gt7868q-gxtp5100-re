## 〇、对 `追加二十四` 的三处更正（必须先读）

| 追加二十四 的说法 | 更正 | 依据 |
|---|---|---|
| ①「判据 `\|基线−当前\| > 40`（`0x28`）是震动灵敏度，改它就能滑动震动」 | ❌ **错**。`0x080059E0` 那条链是「检测压力变化 → 采集 19 点波形 → **打包上报给 GT7868Q**」，改 `0x28` 只改变**上报的数据**，**不产生震动** | 该链终点是 `0x08005E38`（把 10 槽环形缓冲展开成 4 通道 × 20 时间点）→ `0x080110BC`（通用上报派发） |
| ②「TIM2 200 Hz / TIM3 400 Hz = LRA 驱动」 | ❌ **错**。它们是**软件时基**：TIM3 回调 `0x0800D6F4` 仅 `[0x200040D0+0x10]++`（纯计数器）；TIM2 回调 `0x0800F0B5` 是 **SysTick 忙等延时**；CCR/ARR 运行期恒不变 | 见 §三 |
| ③「往上报数据注入振荡可实现滑动震动」 | ❌ **错**。实测证明**震动阈值 = 点击阈值 = 140**，注入振荡必然产生**假点击** | 见 §一 |

**⇒ 追加二十四 的价值只剩两处：`0x080059E0` 判据链的完整解出、以及 PWM 层的参数确认（均在本文更正后仍成立为"事实描述"）。**

## 一、★★★ 新实测：震动是「两次」，且与点击状态机的两个跳变沿同源

**用户口述现象**：按下时震一次、抬手时再震一次。

**报文级验证（`press-log.txt`，2760 条 40 字节报文）：**

```
0→1（按下）沿: n=5   压力全部 = 140      ← 零抖动
1→0（抬起）沿: n=4   压力 = [0, 98, 98, 0]

抬起前压力序列（示例）:
  事件2: 126,122,120,116,113,108,106,104,102,100, 98 → 翻转 → 0,0
  事件3: 113,112,111,110,110,108,107,105,103,101, 98 → 翻转 → 0,0
```

**⇒ 两个阈值：按下 **140** / 抬起 **98**（滞回带 98–140）。**

**★ 而"两次震动"= 点击状态机的**两个跳变沿**各触发一次 —— 即**模拟机械按键的"咔哒 + 回弹"两声**。**

### 附带否掉的实验（"震动是否早于点击"）

若震动阈值低于点击阈值，压力信号里应出现 LRA 的机械耦合振荡。实测：

```
压力在 100..139（未点击）区间时，相邻帧差分:
  n=271   平均|Δ|=0.77   中位=1   最大=3   |Δ|≥10 的比例 = 0.0%
```

**⇒ 完全平滑、零振荡 ⇒ 震动**不在** 140 之前。**

**⇒ ⇒ 推论：任何"让 GT7868Q 更频繁震动"的手段，都会同时产生**真实点击上报** ⇒ 注入振荡 = 制造假点击 ⇒ **此路判死**。**

## 二、分工定案（谁管什么）

| | **TF100A（钛方）** | **GT7868Q（汇顶）** |
|---|---|---|
| 定位 | **压力前端 + 数据打包器** | **主控 / 触控控制器** |
| 采集 | ✅ **自己的 ADC1（`0x40012400`）采 4 路模拟压力**，引脚经 GPIOA/GPIOB 配置（`0x08005CD4`） | 电容坐标、多指 |
| 算法 | 基线跟踪 → 突变检测（`\|Δ\|>40`）→ 采 19 点 → 打包 4×20 | 收压力 → **判定点击（按下 140 / 抬起 98）** → HID 上报 |
| 对外 | I2C1 **从机**（`0x2C`）+ **USART1 @460800** | I2C1 **主机** + HID（Col01–04） |
| 定时器 | TIM2/TIM3 = **软件时基**（纯计数器 / SysTick 忙等） | 未知（加密） |
| **驱动 LRA** | ❌ **否**（四条否定证据，见 §三） | ✅ **推断是**（唯一剩余可能） |
| 固件 | **明文**（已反汇编 20,314 行） | **分组密码 ECB** |

## 三、TF100A 不驱动 LRA —— 四条否定证据

1. **PWM 在上电初始化时即启动**：`0x0800FD64` 那一串触觉模块序列**没有任何 `bl` 调用者**（它调用的 `0x0800A430`/`0x0800E074`/`0x0800E798` 也都只被它调用一次）⇒ 经启动表进入的初始化。
2. **CCR/ARR 运行期恒不变**：写 CCR 的 HAL `0x08010908` **全固件只有 1 个调用者**（`0x0800D772`，在初始化内）；且全固件 51 处 `0x4000xxxx` 构造里，**没有任何一处是 TIM2/TIM3 的 `0x34/0x434/0x2C/0x428/0x20/0x420`**。
3. **GPIO 无马达使能**：`0x0800F7FC`(BSRR 置位) / `0x0800F80C`(BRR 复位) 的全部调用点，掩码几乎都是 `0x8` = **PA3 门铃**（与项目"`A2` 回复统一拉 PA3"一致）。
4. **39 条 I2C1 命令无马达入口**（项目 `追加十四`）。

**⇒ 若 TF100A 驱动 LRA，它会一直震。实际不是 ⇒ 它不驱动。**

**★ "200 Hz 落在 LRA 谐振带（170–235 Hz）"是巧合：200/400 恰为 2 倍，是采样时基的典型特征。**

### ❗ 一个仍未排除的软件侧疑点

**`USART1 @460800`（TF100A 的第二条链路）—— 从未追踪过它上面是否存在"播放"命令帧。**
**若震动命令走这条路，则"改 TF100A"重新成立。定位方法：夹 USART1（PA9/PA10）逻辑分析仪，在点击瞬间看有无命令帧。**

## 四、★★★ GT7868Q 固件的加密性质判定：**分组密码 + ECB 模式**

### 4.1 判据一：重复 16 字节块

```
本机容器 0x1000..0x18000（94,208 B）:
  16 字节块总数 = 5888
  ★ 重复块 = 790 / 5888 = 13.42%        ← 真随机下应为 0（2^128 空间）
  不同块数 = 5227
```

### 4.2 判据二：按周期分组的类内熵（小周期处超出统计偏差）

| P | 类内样本数 | 均匀分布下的**期望**测量熵 | 实测 | 判定 |
|---|---|---|---|---|
| 8 | 11776 | ≈8.00 | **7.9003** | ★ 真结构 |
| 16 | 5888 | ≈7.99 | **7.8283** | ★ 真结构 |
| 32 | 2944 | ≈7.97 | **7.6951** | ★★ |
| 64 | 1472 | ≈7.94 | **7.4721** | ★★★ |
| 256 | 360 | ≈7.49 | 6.6561 | 偏差主导（**不可用**） |
| 1024 | 90 | ≈5.96 | 5.2619 | 偏差主导（**不可用**） |

**⚠️ 方法学警告（本文自我更正）：大周期的熵下降**几乎全是小样本偏差**（Miller-Madow 效应），**不能据此推断密钥周期**。作者最初据此得出"周期 1024"是错的。**

**⇒ 综合两条：块长 16 字节 + ECB 式重复 ⇒ **分组密码 ECB**（或等价的分块变换），**不是流密码、不是固定异或**（后者会保留明文的统计形状，而我们观测到 256/256 值均匀）。**

**★ 这也解释了两份固件那 32,877 字节逐字节相同（相同明文块 → 相同密文块）。**

## 五、★★★ 准确回答：「解密出来就能震吗？」

### 5.1 官方源码给出的决定性事实：**主机侧零变换**

```c
/* goodix_gtx8_update.c —— 灌 ISP：数据原样写 */
goodix_reg_write_confirm(ts_dev, HW_REG_ISP_ADDR, (u8 *)fw_isp->data, fw_isp->size);

/* 组包：只拼地址，数据原样 memcpy */
pkt[2] = (flash_addr >> 16) & 0xff;
pkt[3] = (flash_addr >> 8)  & 0xff;
memcpy(&pkt[4], data, len);                    // ★ 零变换

/* 刷 flash */
goodix_format_fw_packet(fw_packet, subsys_base_addr + offset, ..., data_size);
```

**⇒ 官方刷机工具是**搬运工**：不解密也不加密。**

**⇒ 加扰发生在**更早**（厂商编译打包阶段）；算法在**厂商内部工具**里，公开源码只有 `HW_REG_SCRAMBLE` 一个寄存器。**

### 5.2 所以这条链断在哪

| 步骤 | 能不能 |
|---|---|
| 解密 ⇒ **看懂**判定逻辑、**定位**要改的字节 | ✅ 能（确定的收益） |
| 解密 ⇒ **改**（离线） | ✅ 能 |
| 改完 ⇒ **刷回去** | ❌ **不能** —— 需要把明文**重新加扰**成芯片可接受的格式，而**算法不在公开源码里** |

**⇒ 准确结论：「解密 ⇒ 能震」**不成立**，它断在**"重新加扰"**这一步。**

### 5.3 唯一的理论通路

> **拿到一份**未加扰 / 已解密**的镜像**（设备 dump、或泄露的工程版本）⇒ 因为**刷写路径零变换**，就能直接改、直接刷。

**这正是项目一直说的"等一份明文 gtx8 镜像"。**

## 七、★★★ GT7936L 被证实为**明文** —— 更正项目原判

### 7.1 原判与更正

**`HANDOVER.md:226` 原文：**
> GT7936L 样本本身 | ✗ **无用**。不同芯片 + 不同容器代（魔数 `BERLIN`+`7936L`）+ 其载荷**不是可读的 Thumb 代码**：`push {…,lr}` 半字数 **0**（对照本机镜像 **125**），全文件熵 6.6–7.0 ⇒ **加密或压缩**

**更正：它是**明文 RISC-V 固件**。原判错在用 **ARM Thumb** 的判据（`push {…,lr}`）去测 **RISC-V** 代码。**

**证据：**
```
明文 ASCII 串（固件内）：
  D:/msys64/home/SYSTEM/new_pulpino_x64/gmsis/toolchains/pulpino/pulpino_tools/riscv-gcc/libgcc/config/riscv\save-restore.S
  D:\msys64\home\SYSTEM\new_pulpino_x64\gmsis\toolchains\pulpino\...\riscv32-unknown-elf\rv32imcxpulpv2\ilp32\libgcc
```

## 八、★★★ 准确回答：「只要是汇顶的都应该可以吧？」

## **不一定 —— 必须**同代同芯片**的明文镜像**

| 条件 | GT7936L | 我们的镜像 |
|---|---|---|
| 架构 | **RISC-V**（rv32imcxpulpy2） | **ARM Thumb** |

### ★ 但这次发现带来了一个**真正的新线索**

**汇顶并非全线加密：**

```
同厂 · 同一套分区表语义 · 同一套容器家族
   ├── BERLIN / poseidon        → 【明文】
   └── Yellowstone / GT7868Q    → 【加密】
```

**⇒ Yellowstone 族存在明文版本（工程样机 / 早期版本 / 某次未加密发布）的可能性**并非零**。**

### 明文镜像的**快速判据**（本文建立，已验证可用）

| 判据 | 明文特征 | 加密特征 |
|---|---|---|
| **全零段** | 有（≥1 KB） | **无** |

## 十、震动线是否闭环 —— 分层结论

| 层 | 状态 | 依据 |
|---|---|---|
| 主机 → 设备（标准 HID） | ✅ **闭环：不可能** | 描述符缺 `0x0E/0x21`，`Col02 Out=0` |
| 主机 → 设备（厂商 Col04） | ✅ **闭环：无入口** | 39 条全表 + 定时器引用闭包 |
| 震动 ↔ 点击状态机 | ✅ **闭环：同源** | 按下 140 / 抬起 98，两次震动 = 两个跳变沿 |
| TF100A → LRA | ✅ **闭环：不驱动** | 四条否定证据（§三） |
| **谁物理驱动线圈** | ❌ **未观测，仅推断** | 由四条否定证据**推出**是 GT7868Q |
| **USART1 是否有播放命令** | ❌ **未追踪** | 唯一还开着的**软件侧**疑点 |
| GT7868Q 固件改写 | ❌ **闭环：不可行** | 分组密码 ECB + 无法重新加扰 |

**⇒ 软件与协议这条线**已闭合到底**；剩两步都是**观测类**：**
1. **示波器测 `HDP`/`HDN`** ⇒ 钉死物理驱动源（若发现是 200/400 Hz，则 TF100A 结论翻转、改固件路复活）
2. **逻辑分析仪夹 `PA9/PA10`（USART1）** ⇒ 排除"播放命令走 USART1"

## 十一、方法学（本轮新增）

1. **架构判据必须匹配**：用 ARM 的 `push {…,lr}` 密度去判 RISC-V 代码 ⇒ 得出"不是代码"的**错误结论**。判代码前先确认指令集。
2. **熵 vs 样本数**：类内熵随分组数下降**大部分是小样本偏差**（Miller-Madow），必须先算"均匀分布下的期望测量熵"再判断。
3. **ECB 指纹 = 重复块率**：压缩会**消除**重复；若观察到高比例重复 16 字节块 ⇒ 是 ECB 分组密码。
4. **明文/密文的四联判据**：全零段 + ASCII 路径串 + 低块重复率 + 熵<7.5。
5. **"只有一个调用者"判据**：HAL 写寄存器函数若全固件仅 1 个调用者 ⇒ 该寄存器只在该处被写。

## 十二、一句话总结

> **震动是点击状态机两个跳变沿的产物（140 按下 / 98 抬起）；LRA 不在 TF100A 侧（物理驱动源仍待示波器钉死）；GT7868Q 固件是分组密码 ECB，"解密⇒能震"断在**无法重新加扰**；而 GT7936L 被证实为**明文 RISC-V**（代号 `poseidon`），说明汇顶**并非全线加密** —— 所以"找明文镜像"这条路在技术上仍然成立，但目标必须精确到 **Yellowstone / GT7868Q 族**。**
