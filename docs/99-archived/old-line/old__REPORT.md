# TF100A / GT7868Q 容器内 TF100A 明文固件 — I²C 主机传输路径独立审计

分析对象
- 反汇编：`touchpad_TF100A_thumb.asm.txt`（20,314 行，0x08005000–0x08012342）
- 原始容器：`touchpad_GT7868Q_fw.bin`（161,628 B = 0x2775C）
- 映射核验：`文件偏移 = 地址 - 0x08005000 + 0x19ABC`；`TF100A_Test_FW` @ 文件 0x19ECC = 地址 0x08005410 ✓
- 明文段 0x19ABC..0x2775B（56,480 B）**正好是容器尾部**（0x19ABC+56480 = 0x2775C = 文件大小）→ 段后无残余数据
- 固件版本字符串 `5.21.01.23007`，构建 `Nov 28 2023 19:10:59`
- 反汇编尾部未覆盖 0x08012342–0x08012C9F（约 2.4 KB）；本文用原始字节级扫描补全
- 所有脚本在 `verify-A/a01..a18_*.py`

## 结论

**不存在任何发起 I²C 主机传输的代码路径。** 全镜像唯一的 I²C 是 I2C1 @ 0x40005400，被配置为**从机**：程序化自身地址（OAR1）、使能 I2C1_EV/ER 的 NVIC 中断、按 ADDR/RxNE/STOPF/TxE/AF 组织状态机、PB6/PB7 配成 AF 开漏。STM32F1 主机模式所必需的 `CR1.START (bit8)` 与 `CR1.STOP (bit9)` **从未被写过**，`SR1.SB (bit0)` 与 `SR2.MSL (bit0)` **从未被检测**，`I2C2 (0x40005800)` 从未出现。

## 寄存器映射与依据

`I2C1_BASE = 0x40005400`，寄存器映射 = 标准 STM32F1 I²C：
CR1 0x00 / CR2 0x04 / OAR1 0x08 / OAR2 0x0C / DR 0x10 / SR1 0x14 / SR2 0x18 / CCR 0x1C / TRISE 0x20

依据（五条独立证据）：
1. **地址映射自洽**：同镜像另用 0x40010800=GPIOA、0x40010C00=GPIOB、0x40012400=ADC1、0x40000400=TIM3、0x40013800=USART1、0x40003000=IWDG、0x40006C00=BKP、0x40007000=PWR——全部落在标准 F1 表上，该表 `I2C1_BASE=0x40005400`。
2. **寄存器偏移逐一对上，且带语义**：`0x0800FA20` 的时钟初始化做 `CR2.FREQ[5:0]=(APB MHz)`、`CCR=ccu/(2*speed)`、`TRISE=(freq_MHz*300)/1000+1`（快速模式）、`CCR.F/S(bit15)`、`CCR.DUTY(bit14)`——这是 ST `I2C_Init` 的算法，非 I²C 不可能。
3. **向量表**：表基址 0x08005000（Reset=0x08005164，默认处理子 0x0800517E）。idx47 (off 0xBC) `I2C1_EV`=0x08008979→0x08008978；idx48 (off 0xC0) `I2C1_ER`=0x0800894D→0x0800894C，**正好指向访问 0x40005400 的代码**。同表 USART1@idx53、TIM3@idx45、DMA1_Ch1@idx27 亦符合 F1 IRQ 编号。
4. **NVIC**：`0x0800FE3C(IRQn, prio, subprio)` 写 `NVIC_IPR`(0xE000E400) 与 `NVIC_ISER`(0xE000E100)。I²C 初始化例程以 **IRQn=0x1F(31) 与 0x20(32)** 调用它两次，即 F1 的 `I2C1_EV_IRQn`/`I2C1_ER_IRQn`。
5. **引脚**：`GPIO_Init(GPIOB, GPIO_Mode=0x1C(AF_OD), Speed=3(50MHz), Pin=0x40/0x80)` → **PB6=SCL, PB7=SDA**，硬件 I²C（非模拟）。

**假阳性排除**
- `0x080064F4 movw r1,#0x5400` + `movt r1,#0x800` → `0x08005400`（flash 取常量），非 I²C。
- `0x08010AB6 movw r1,#0x5400` + `movt r1,#0x4001` → `0x40015400` = **TIM11**。该站点位于 0x080109E6–0x08010AC2 的 `base==X` 分派链中，链内条目为 TIM2/3/4/5/6/7/12/13/14/1/8/9/10/11，**完全没有 I²C 项** → 代码自身也证明 0x40015400 ≠ I²C1。
- 0x40005800 (I2C2)：整个 56,480 B 段内 **0 次**出现。
- 其它易混外设：0x40006C00 = BKP（`[0x40006C04] |= 0x100` 写 BKP_DR1，持久标志）、0x40003000 = IWDG（写 0x5555 解锁）、0x40007000 = PWR。`0x0800EF20` 的 `[base+4] |= 0x100 / |= 0x400` 只在 0x08005D1E/0x08005D2C 被调用，base = **ADC1 (0x40012400)**，是 ADC_CR2，不是 I²C CR2。

## 全部写操作清单

穷举方法：对整段（含反汇编未覆盖的 2.4 KB）做**指令编码级**扫描（movw 掩码 `(hw0&0xFBF0)==0xF240`，movt `==0xF2C0`），解出 1,295 个 movw / 1,124 个 movt；再对 0x400054xx 做寄存器数据流跟踪（含 `str [rBase,rIdx]` 索引寻址）。
结果：**materializing 0x400054xx 的站点只有 12 个**，全部落在 0x0800894E–0x08008BC6 一个簇内；**以 r0∈0x400054xx 发起的 `bl` 也只有 12 个**，同样全在该簇内。索引寻址无任何一处命中 I²C 块。

| 5575 | 0x08008BBE | ACK(base,1) | | `CR1.ACK(10)=1` | 从机接收需 ACK |

辅助函数内部等价于外设写：
- `0x0800FC20(base,desc)`：`reg[(uint16)desc>>6] |= 1<<(desc&0x1F)`（desc 0x0109 → `CR2.ITEVTEN`）
- `0x0800FC0C(base)`：`CR1 |= 1`（PE）
- `0x0800F9CC(base,en)`：`CR1.ACK` 置/清
- `0x0800F9F8(base,en)`：`CR1.POS` 置/清（实参 en=1 → 清除）
- `0x0800FBF8(base,byte)`：`DR = byte`
- `0x0800FD24`：`CR1 &= ~SMBUS`、`OAR1 = arg & 0x3FF`
- `0x0800FA20`：`CR2.FREQ`、`CCR`、`TRISE`

### C. 直接内存写

仅一处：`0x08008A6C  str r1,[r0]`（r0=0x40005400），前两条为 `ldr r1,[r0,#0x14]`(读 SR1)、`ldr r1,[r0]`(读 CR1)。
⇒ 这是手册要求的 **STOPF 清除序列"读 SR1 后写 CR1"**，写回的是原 CR1 值（恒等 RMW），不改变任何位。

### D. 从未出现的写（关键否定）

- `CR1.START (bit8, 0x0100)` — **全镜像 0 次**
- `CR1.STOP (bit9, 0x0200)` — **全镜像 0 次**
- `CR2.ITERREN (bit8)` — 0 次（因此 ER 中断条件永假）
- `CR2.ITBUFEN (bit10)` — 0 次（因此 RxNE/TxE 中断条件永假）
- `OAR2 (0x0C)`、`SR1/SR2` 的位写入（除清标志）

（全局交叉验证：镜像内所有 `orr #0x100` 只有 4 处——0x0800EC94 `[struct+8]`、0x0800EF40 `[ADC1+4]`、0x0800FF7E `[PWR_CR]`、0x0800FFD6 `[PWR_CSR]`——无一指向 I²C；所有 `movs/mov #0x100` 6 处，均非 I²C CR1。）

## 中断向量的处理集合

| 向量 | idx/off | 入口 | 检测的状态位 |
|---|---|---|---|
| `I2C1_EV` | 47 / 0xBC | **0x08008978**（单函数，0x08008978–0x08008A1B，0xA4 B）| 顺序检测 `ADDR` → `RxNE` → `STOPF` → `TxE`；每项前置 `CR2.ITEVTEN`，RxNE/TxE 另需 `CR2.ITBUFEN`（**未置位 ⇒ 恒假，死分支**）|
| `I2C1_ER` | 48 / 0xC0 | **0x0800894C**（0x0800894C–0x08008976）| 仅 `AF`，前置 `CR2.ITERREN`（**未置位 ⇒ 恒假，死分支**）|
| `I2C2_EV/ER` | 49/50 | 0x0800517F（默认处理子）| 无 |

各分支动作：
- `ADDR` → `0x08008B30`：`drv->0x100=0`、清 `drv->0x107` 低 2 位、`drv->0x106 |= 0x10`、回调 `drv->[0x114]`，随后 `读 SR1 → 读 SR2`（ADDR 清除序列；**返回值被丢弃，从不检查 MSL/TRA**）
- `STOPF` → `0x08008A4C`：`drv->0x106 |= 0x20`、回调 `drv->[0x118]`、`读 SR1 → 写 CR1`（清 STOPF）
- `RxNE` → `0x08008A70`：读 `DR`，按 `drv->0x107` 状态机写入 `drv+0x80` 起的 128 字节缓冲（`cmp #0x7f` 上限）
- `TxE` → `0x08008AE4`：`DR = drv->buf[drv->0x100++]`；`idx > 0x7F` 时 `DR = 0x55`
- `AF` → `0x08008A1C`：清 `drv->0x106` 位 6、回调 `drv->[0x11C]`（参数取 flags 位 6）、`SR1 &= ~AF`

**`SR1.SB (bit0)` 与 `SR2.MSL (bit0)`：从未被检测。** SR1 被检测过的位集合 = {ADDR(1), STOPF(4), RxNE(6), TxE(7), AF(10)}（由 5 个描述符形式化解出）；SR2 只在 0x0800FC5A–FC60 与 0x08008B62 被**读出以完成 ADDR 清除**，从不做位判别。SB/MSL 是主机状态机的核心抓手，二者缺席 ⇒ 无主机状态机。

## 运行上下文（补充证据）

- 驱动实例 `drv = 0x20004134`（= 0x20004128 + 0x0C）。初始化 `0x0800DA4C`：
  - `GPIO_Init(GPIOA, Out_PP, 50MHz, Pin=8)` 然后 `GPIOA->BSRR = 8`（`0x800F80C(port,val)` = `*(port+0x10)=val`）→ **PA3 输出置高**
  - `drv->[0x110] = 0x00061A80 = 400000`（400 kHz）
  - `drv->[0x10C] = 0x58`（写入 OAR1 的地址值）
  - `drv->[0x114/0x118/0x11C] = 0x0800DB39 / 0x0800DB5D / 0x0800DADD`（三个回调）
  - `drv->[0x108..0x10B] = 0`（IRQ31/32 的抢占/子优先级，0 = 最高）
  - `bl 0x08008B68`（I²C 初始化）
- ADDR 回调 `0x0800DB38`：置 `*(0x20004128) |= 2`，并 `GPIOA->BSRR = 8`（再次拉高 PA3）→ **被主机寻址时驱动一条 GPIO 握手线**（典型从机行为）
- STOPF 回调 `0x0800DB5C`：`flag &= ~2`，`flag |= 4`
- AF/错误回调 `0x0800DADC`：按参数置/清 `flag` 位 1
- 该初始化被 `0x0800FD64` 起的启动初始化链调用（`0x800FD78 bl 0x800DA4C`），即开机执行
- 静态调用图：`0x0800894C`、`0x08008978` 的静态入度 = 0（仅向量表可达）；`0x08008B68` 入度 = 1（0x0800DAC4）。**驱动除 init 外无任何对外 API，没有任何"传入目标地址并启动传输"的函数**

## 反证 / 不确定性

1. **最强的反向证据**：`CCR(0x1C)` 与 `TRISE(0x20)` 被按主机时序公式编程（400 kHz 快速模式，F/S=1）。手册把 TRISE 描述为"仅主机模式"。但 (a) 只有当速度 >400 kHz 才会走到的分支里还写了 `[0x40005490]=1`，该偏移在 F1 I²C 块中不存在，说明`0x800FA20`是通用/移植来的时钟代码；(b) 配置主机时序 ≠ 发起主机传输：没有 START 写入，硬件不可能产生任何主机事务。故不构成反例，但确实说明该驱动被当成"双向通用 I²C 驱动"来写。
2. **数据通路是死的**：`CR2.ITBUFEN` 与 `CR2.ITERREN` 从未置位 ⇒ EV 处理子里的 RxNE/TxE 分支与整个 ER 处理子恒不触发。因此该从机实际只能"响应地址匹配 + 检测 STOP（并拉 PA3）"，不能真正收发字节。这更像**残留/未完成的驱动**，而非在用功能。这不产生主机路径，但削弱了"从机正在工作"的力度。
3. **OAR1 语义歧义**：写入 `OAR1 = 0x58 & 0x3FF`，未置 `bit14`（F1 要求"软件保持为 1"），也未置 `ADDMODE(bit15)`。严格按 F1 解释，`ADDR[7:1]=0x2C`（7 位地址 0x2C，总线写地址字节 0x58）；若该 MCU 是容错克隆/或用 10 位解释，则地址可能是 0x58。无法从代码唯一确定。
4. **0x40005490 写**：仅出现在 `>400kHz` 分支（本固件传 400000 ⇒ 不 >400000 ⇒ 该分支不可达）。可能是克隆特有寄存器，不影响结论，但它提示该 I²C 块可能非 100% F1 兼容。
5. **覆盖边界**：我只审计了 TF100A 明文段（0x08005000–0x08012C9F）。容器前 105,148 B（0x0–0x19ABB）不属于该段（属 GT7868Q/容器头部区域），未审计；**若该区域含另一份可执行镜像，本次结论不覆盖它**。
6. 地址 0x08005000–0x0800517F 的向量表/字面量池按题设不当代码；我对其只做数据（向量）读取，未当指令解释。
7. 未排除 ROM bootloader 行为（与固件本体无关，且不属"固件里的代码路径"）。

## 置信度

**高。**
理由：(a) `0x40005400 = I2C1` 由"标准 F1 地址表 + 与 ST `I2C_Init` 完全一致的 FREQ/CCR/TRISE 算法 + 向量表 I2C1_EV/ER 槽位指向同一段代码 + NVIC 使能 IRQ31/32 + PB6/PB7 AF_OD"五条相互独立的证据闭合；(b) 主机模式的充要抓手 `CR1.START` 在全镜像（含反汇编未覆盖的 2.4 KB，用指令编码级扫描）**零出现**，`SR1.SB`/`SR2.MSL` 零检测；(c) 地址常量层面的穷举（1,295 movw / 1,124 movt）显示访问 I²C 块的代码只有 12 个站点、12 个调用，全部读完并逐条定性；(d) 从机身份有独立的正面证据（OAR1 编程 + NVIC 双中断 + ADDR 清算 + 128 字节接收缓冲 + 地址匹配拉 PA3）。

不降到"极高"的原因：上述第 1–5 条不确定性（尤其 CCR/TRISE 的存在、数据通路被 ITBUFEN/ITERREN 关闭、以及只审计了明文段这一覆盖边界）。
