# 追加十三 —— 硬件接入执行手册（图纸 → 定义 → 连 MCU → 验证）

> 缘起：2026-09-28，喆转述"蓝莓"的意见 —— **"笔记本图纸找定义，连 MCU，自己摸协议，完事。"**
> **本文结论：这个路线是对的，而且是我们唯一还没走的那条。**
> **但有一个重要差异：「摸协议」这一步我们不需要了 —— 协议已经全部解完（39 条命令全表 + 帧格式 + 三个状态标志 + 采样链）。**
> **所以 MCU 接入的用途变成两件更省事的事：① 定案唯一还开着的那条推断；② 实测 LRA 波形（方案③ 的最后缺口）。**
> 全部参数由反汇编直接抠出，**不依赖图纸也能开工**；图纸只用来"少拆一点"。

## §1 ★ 接口定义总表（从反汇编直接抠出，带出处）

### 1.1 `main()` 的上电初始化时序（`0x0800FD64` 起）

```
0800FD64  bl 0x080064B4        ; ①
0800FD68  bl 0x0800BD7C        ; ②  疑似发包编码器相关
0800FD6C  bl 0x0800DF14        ; ③
0800FD70  bl 0x0800DF48        ; ④
0800FD74  bl 0x0800CF10        ; ⑤
0800FD78  bl 0x0800DA4C        ; ⑥ ★ I2C1：填句柄 + 初始化（400 kHz / OAR / GPIOB）
0800FD7C  bl 0x0800DFE8        ; ⑦ ★ TIM2 = 200 Hz（触觉 A）
0800FD80  bl 0x0800E750        ; ⑧ ★ TIM3 = 400 Hz（触觉 B）
0800FD84  bl 0x0800E798        ; ⑨ ★ USART1：460800 bps
0800FD88  bl 0x0800E7FC        ; ⑩
0800FD8C  bl 0x0800E074        ; ⑪
0800FD90  bl 0x0800A430        ; ⑫
0800FD94  bl 0x0800E7D4        ; ⑬
          然后进入无限主循环（命令分派器 + 8 个任务）
```

### 1.2 接口清单

| 接口 | 参数 | 出处 | 用途 |
|---|---|---|---|
| **I2C1** | **400 kHz**（`[ctx+0x110] = 0x061A80`）· 寄存器 `0x40005400` | `0x0800DA4C` 写 `[0x20004128+0x11C] = 0x61A80` | ★ **39 条命令协议**（TF100A 作 **从机**） |
| ↑ 从机地址 | **`OAR1 = 0x58`** ⇒ 按 `OAR1 = addr7<<1` 解释，**7 位地址 = `0x2C`** | `0x0800FD24`（`I2C_OwnAddress1Config`）：`bfc r3,#0xa,#0x16` → `str r0,[I2C1+8]` | 自己当主机时的目标地址 |
| ↑ 引脚 | **GPIOB**（`0x40010C00`）⇒ STM32F1 上 I2C1 默认 **PB6 = SCL / PB7 = SDA** | `0x08008BF0`/`0x08008BFE` 两次 `0x0800F81C(GPIOB, 0x1C, 3, 0x40/0x80)` | 逻辑分析仪的夹点 |
| ↑ 其它 | `CR2 |= DMAEN`（bit9）· `CR1 |= PE` · 门铃回调 `0x0800DB39/0x0800DB5D` | `0x08008BAA`/`0x08008BB4` | — |
| **USART1** | **460,800 bps**（`[struct+0x108] = 0x70800`）· 结构基址 `0x200061B4` · `[struct+0x104] = 4` | `0x0800E798` 写 `[0x200061B4+0x108] = 0x70800` → `0x0800DF4C` 用它算 BRR | ★ **第二条链路**（参与力采样状态机；**不承载这 39 条命令**） |
| ↑ 引脚 | STM32F1 上 USART1 默认 **PA9 = TX / PA10 = RX** | 未在本镜像里显式重映射（`0x0800DF4C` 只配了 GPIO 复用） | 第二个夹点选择 |
| **TIM2** | 200 Hz · PSC=119 / ARR=1999 · 通道 1 · CCR=700 ⇒ **35%** | `0x0800E034`/`0x0800E038`/`0x0800D76E` | ★ 驱动 LRA（触觉 A） |
| **TIM3** | 400 Hz · PSC=119 / ARR=999 | `0x0800E768`/`0x0800E76C` | 触觉 B |
| **HDP / HDN** | 模组背面裸露焊盘 = 原装 LRA 两根驱动线 | 项目实物照片 + HMM | ★ **方案③ 接入点** |
| **GPIOA** | **PA3** 被 `BRR` 拉低 ⇒ 对主机的"敲门"握手 | `0x0800F7FC` = `str rN,[rM,#0x14]`；A2 回复末尾都调它 | 观测"固件在回复"的最简信号 |
| **片间帧格式** | `[class][b1][b2][sub_lo][sub_hi][payload…]`；小端；双向同构 | `追加八` §6（TX/RX 两侧独立证实） | 分析仪解码用 |

> ⚠️ **I2C1 与 USART1 同时存在，是两条独立链路**。项目 `STATUS.md §20` 说的「USART1、~460800 baud」**波特率是对的**（本次反汇编证实），但它把「39 条命令」和 USART1 绑错了 —— 39 条命令在 I2C1 上（`追加八` §5）。**⇒ 上分析仪时，两条都要夹，先夹 I2C1。**

## §2 图纸 / Boardview 上要找什么

**本机板名**：DMI 里是 `LNVNB161216`；LCFC 板号形如 `NM-xxxx`（同代已流出的有 NM-E021 / NM-E561 / NM-E661 / LA-K061P）。
**检索姿势**：`"ThinkBook 14 G6+ IMH" boardview` 或 `"NM-xxxx" schematic`（`方法总谱` §3.6 列了分发站）。查看器用 **OpenBoardView**（免费）。

按优先级找这 6 项：

| # | 找什么 | 找到了有什么用 |
|---|---|---|
| **1** | **触控板 FPC 连接器**（Jxxxx）的 pin 表 | 拿到 **I2C0（主机↔GT7868Q）** 的 SCL/SDA/INT/RST + 供电 —— 夹这里的价值是"看主机侧协议"，**优先级低于第 2 项** |
| **2** | ★ **模组侧 GT7868Q↔TF100A 的连线**：在模组 FPC 或主板上找 **TF100A 的 I2C1（PB6/PB7）与 USART1（PA9/PA10）是否引到测试点** | ★ **这是全案最关键的一处**：能直接决定"夹哪两根线就能看见 39 条命令流" |
| **3** | **TEST / TXD / RXD / TPxx 丝印** | 产线调试口 ⇒ **零焊接**接入 |
| **4** | **HDP / HDN 的主板侧来源**（TIM 通道引脚 → 驱动电路或直连） | 确认"MCU 定时器直驱、无外部驱动 IC"这个反汇编结论 |
| **5** | **TF100A 供电与复位**（3.3V？1.8V？RESET 引脚） | 自己当主机/单独供电时必须知道电平 |
| **6** | 模组型号丝印 → 模组厂 FPC 定义 | 有时模组规格书直接给出内部连线 |

**⚠️ 现实提醒**：这类模组的**片间连线通常走在模组内部 PCB 上**，主板上只到 FPC 座的 I2C0。**⇒ 第 2 项很可能找不到 ⇒ 那时唯一办法是"夹模组上的测试点"或"拆模组、在模组这一侧引线"。**
**⇒ 所以不要把希望全押在图纸上；本次抠出的引脚定义（PB6/PB7、PA9/PA10、0x2C、460800）已经足够直接开工。**

## §3 路线 A：**纯监听**（零注入，首选，先做这个）

| 项 | 内容 |
|---|---|
| 器件 | 逻辑分析仪 8ch，≥24 MHz（¥30–100）—— 400 kHz I2C 与 460800 UART 都够 |
| 夹点 | **I2C1：PB6(SCL) / PB7(SDA)**；同时留两路给 **USART1：PA9/PA10**；**GND 必须共地** |
| 触发 | 上电 → 手指在触控板上滑动/轻按（最好同时做一次真正的震动触发动作） |
| 解码 | I2C 解码器（地址 **0x2C**）+ 自定义帧解码 `[class][b1][b2][sub_lo][sub_hi]` |
| **判据一** | 抓到 `class ∈ {0x80, 0xA0, 0xA1}` 的帧 ⇒ **链路归属定案** |
| **判据二** | ★ 抓到 **`class=0xA0, sub=0x0D00`**（或 `0xA1/0x0B00`）⇒ **GT7868Q 确实在转发主机厂商帧 ⇒ `追加九` §1 的两种假设立刻否掉一半，主机侧"封死"的结论要重估** |
| **判据三** | 抓到 TF100A 回的 `A2 …` ⇒ 确认回复方向与门铃 PA3 时序 |
| 风险 | **零**（不注入任何信号，只监听） |

**⇒ 这一步做完，"主机能否触达 TF100A"这个悬了 15 天的问题就**永久定案**，不管答案是哪个。**

## §4 路线 B：**自己当主机**（需要拆模组 / 单独供电）

### 4.1 为什么不能直接在线挂

TF100A 是**从机**（由 ISR 结构判断：RxNE 收、TxE 发、ADDR 清计数器），GT7868Q 是主机。
**⇒ 你在同一对 SCL/SDA 上再挂一个主机，会与 GT7868Q 抢总线（多主仲裁失败可能拉死总线）。**
**⇒ 正确做法：把模组从笔记本上取下，单独给 TF100A 供电，用你的 MCU 当唯一主机。**

### 4.2 接线（拆下模组后）

| 你的 MCU | 接到 TF100A |
|---|---|
| 3.3V + GND | 模组 VCC / GND（**先确认电平**；若模组是 1.8V，必须加电平转换） |
| SCL / SDA（上拉 4.7 kΩ 到 3.3V） | 模组侧 I2C1（SCL/SDA） |
| （可选）UART TX/RX | USART1（460800 bps） |

### 4.3 注入顺序（**从只读命令开始，逐级放行**）

**我们这个顺序的好处：`0xA1` 是只读族（22/22 只读 + 回复），所以前两步天生安全。**

| 步 | 发什么 | 期望 | 判据 |
|---|---|---|---|
| **1** | `0xA1 / 0x0A00`：`0E A1 00 00 00 0A …`（子命令在 `pkt[4]/pkt[5]`，见 `追加九` §5） | **`A2 11 <17 字节>`** | ★ 收到 ⇒ **协议跑通、地址正确、帧格式定案** |
| **2** | `0xA1 / 0x0400` | `A2 10 <16 字节>` | 若第 1 步通过，这步必通 |
| **3** | `0xA0 / 0x2000` + `msg[0]=1` ⇒ 开采样窗口，再用 `0xA1/0x0400` 取 | `A2 10` 里能看到累积值变化 | ★ **验证「采样窗口」链路是真的** |
| **4** | `0xA1 / 0x2800`、`0x2900`、`0x2C00`、`0x1600` | 48–60 字节表数据 | ★ **验证 4 条"按索引读表"命令**（表长上限 609） |
| **5** | `0xA0 / 0x0E00` / `0x1100` / `0x1F00` | 模式字节变化（用 `0xA1/0x0700` 读回） | 验证模式状态机 |
| **6** | 波形相关（`0xA0/0x0D00` 清零+arm 等） | 观察 PA3 / 回复 | ⚠️ **此时再决定**；`0xA0/0x0500` **永不发** |
| ❌ | **`0xA0/0x0500`** | — | 387 行、含 `msg[1]==0x11` 分支，**疑升级状态机 ⇒ 列入"绝不发送"** |

**⇒ 关键点：我们不是"摸协议"，是"逐条验证一张已经画好的表"。工作量比从零小一个数量级。**

## §5 路线 C：方案③（HDP/HDN 外挂驱动）—— 顺手一起做

在**同一次拆模组**里可以把 C 也做掉，因为接入点（HDP/HDN）和 B 的接线在同一个模组上。

| 已定规格（可直接照抄） | 值 |
|---|---|
| 主模式频率 | **200 Hz**（TIM2 PSC=119/ARR=1999） |
| 第二模式 | 400 Hz（TIM3 ARR=999） |
| 占空比 | **35%**（CCR = 0x2BC = 700 / 2000） |
| 通道 | 通道 1（CC1E） |
| 拓扑 | 支持互补输出，**未设死区**；**MCU 定时器直驱，无外部驱动 IC** |
| **仍缺（只有示波器能补）** | **振幅/驱动电压** · **LRA 型号与实测谐振频率** |

**互斥**：外挂驱动与原生驱动**必须互斥**（模拟开关），否则两个源同时推 LRA 可能烧。

## §6 不要做什么

1. **不要在线并挂第二个 I2C 主机**（总线争用）—— 必须拆模组或确保 GT7868Q 让出总线
2. **不要发 `0xA0/0x0500`**（疑升级状态机；与红线 `00 11` 同值域）
3. **不要发刷机三连** `00 10 / 00 11 / 0E 12`
4. **不要在真机上**用"表内合法帧"去补测 `0xA0`/`0xA1`（`追加九` §1 的结论：两种假设都指向封死，不值得用唯一指点设备去赌）
5. 模组单独供电前**先确认电平**，别把 3.3 V 灌进 1.8 V 的片子

## §8 与既有结论的关系

| 既有结论 | 硬件接入后的变化 |
|---|---|
| 「主机侧到不了马达」 | **路线 A 判据二**会把它彻底定案（或推翻一半）。在此之前，`追加九` §1 的"两种假设都指向封死"已经给了它结构性支撑 |
| 「包络/手感不在 TF100A 明文段」 | **路线 B 步 3–4** 能直接看到 TF100A 对外报什么；**路线 C 的示波器**能拿到真实波形 |
| 「加密 97 KB 不是代码」 | 路线 B 若能把 TF100A 当从机跑起来，就**不需要**动 GT7868Q 的加密区 |
| 「唯一可行 = 方案③」 | 不变；而路线 A/B 与它**共用同一次拆机** |

## §9 一句话

> **蓝莓说的对：图纸找定义 → 连 MCU。**
