## §0 判定（一句话）

> **这块触控板的震动马达，主机永远无法主动触发它。** 不是"没找到方法"，而是**接口、固件、硅片三层都不通**。
> 想要"滑动跟随震动"，**唯一可行的是在触控板之外加一个自己控制的执行器**。

---

## §1 第一环：这是块什么板子（拓扑）

1. 系统里触控板**只有一条设备节点**：`ACPI\GXTP5100`（compatible `PNP0C50` = HID over I2C，服务 `hidi2c`），
   父设备 = Intel Serial IO I2C 控制器 `PCI\VEN_8086&DEV_7E78`。【实测】
2. 它暴露 **4 个 HID 集合**：`Col01` 鼠标 · **`Col02` PTP**（in=40 / **out=0** / feat=737）· `Col03` mtconfig · **`Col04` 厂商**（in=65 / out=65 / feat=0）。【实测】
3. `Col02` 声明了 **7 个 feature usage**，其中与触觉有关的**只有一个**：
   - **`rid=9`，usage page `0x0E`（Haptics）/ usage `0x23` = Intensity**，1 字节；【实测】
   - 另有厂商 feature：`rid=11`(66 数据字节) / `rid=12`(736) / `rid=6`(256) / `rid=13`(4)。【实测】
4. **模组里有两颗芯片**（★ 2026-09-14 晚间修正此处表述）：
   - **左侧**（覆盖 DataMatrix 二维码）：`8SST61M69932` / `SLE0141701V1` = **汇顶 GT7868Q**（触摸控制器，固件 **AES 加密** 100,608 B）【实测】
   - **右侧**：`TF100A` / `TB0V200` / `0001-2311-JW` = **北京钛方科技（Taifang）的 TF100A**（力度感应 + 触觉控制，固件**明文** 56,480 B，**非汇顶芯片**）【实测】+【网络】
   > 原句把两颗芯片的信息混写在同一句（"丝印 TF100A…（QR 解出 8SST61M69932…）"），照读会误以为那个 QR 属于 TF100A。详见 `SESSION-2026-09-14-PM.md` §1.3。
5. **EC 不在数据通路上**（`ACPI` 下无任何独立触觉设备；震动在没有任何主机软件时也发生）。【实测】

**⇒ 第一环结论：主机与触控板之间的"输入方向"很宽（3 个集合在上报），"输出方向"极窄（只有一个 1 字节的强度控件）。**

## §2 第二环：震动是**模组内部闭环**（谁决定"何时"、谁负责"怎么"）

**证据 A【实测·最硬】**：**BIOS Setup 里触控板可用，且点按会震。**
BIOS 阶段没有 Windows、没有驱动、没有任何主机软件 ⇒ **震动不需要主机**。

**因此链路是：**
```
手指按下 → 压力传感器 → 压力 > 阈值(约 141/97，原始域 70/48)
   → 【GT7868Q】判定"该震"          ← 决定"何时震"（加密固件 100,608 B）
   → 【TF100A】取波形、TIM3/PWM 驱动 → 【LRA】震一下   ← 决定"怎么震"（明文固件 56,480 B）
   → （副作用）给主机发一条"按键按下"报文  ← 主机收到时，震动早已发生
```
- 【反汇编】TF100A 明文固件里：LRA 配置**振幅 119、周期 999 / 1999**（全镜像只有两处 ⇒ **编译期常量**）；
  PWM 配置 ARR=700/CCR=96 与 ARR=1999/CCR=119；🔴 **2026-10-02 更正：不应读作 LRA 驱动参数**（TF100A 无 PWM 输出路径，只是采样节拍定时器）；🔴 **2026-10-02 更正：不应读作 LRA 驱动参数**（TF100A 无 PWM 输出路径，只是采样节拍定时器）；🔴 **2026-10-02 更正：不应读作 LRA 驱动参数**（TF100A 无 PWM 输出路径，只是采样节拍定时器）；"播放"包装 `0x08008628` 在 600 条边的调用图里**0 个调用者**。
- 【实测】点击阈值：按下 HID 140–149（中位 **141**）、松手 95–99。
- 【实测】`GetInputReport` 通路下的**主机侧监听**：180 秒、45 次触摸事件，**厂商通道 `reports=0`** ⇒ 点按时主机**一个报文都不发**。

**⇒ 第二环结论：这是"设备自主触发（device-initiated）"，主机只是旁观者。**
（学术名词与上游说法见 §3。）

## §3 第三环：**接口层**——主机侧没有"播放键"

【实测】**`Col02 OutputReportByteLength = 0`**：PTP 集合上一个输出报表都没有 ⇒ 主机连一句"震一下"都无处可写。

【规范】微软《Input Device Haptics Implementation Guide》：主机要能触发震动，设备**必须**同时声明
`Manual Trigger (0x0E/0x21)` 的**输出**报表 + `Waveform List (0x0E/0x10)` / `Duration List (0x0E/0x11)`。
**本机这三条全部没有，只有 `Intensity`** ⇒ 按规范这**就是** device-initiated 设备。

【上游】Linux 上游 RFC（2026-06-16，Rong Zhang 发起；input 维护者 Dmitry Torokhov、libinput 维护者 Peter Hutterer 参与）原话：
> "device-initiated ones are currently **not configurable at all**" / "…since **there's no way to initiate a force feedback from the host**, the device is not a true FF device"

【社区】一份**真在 Windows 上跑起来**的触觉触控板项目，其描述符**恰好声明了**上述几条 usage ⇒ **别人有、我们没有**；同族 **GT7863** 的描述符里**也没有**。

### 而且我们**直接问过它**【实测·有阳性对照】
连写 6 个不同强度值（5/40/75/15/60/90，间隔 4 秒）：
- **点击反馈的力度确实随之改变** ⇒ 写入**真的到达设备**（阳性对照成立，不是空跑）；
- **但没有任何一次产生震动** ⇒ 阴性。
- 强度语义：**1–10 最强、50 变轻、100 = 关闭**。

**⇒ 第三环结论：主机对这颗马达有"音量旋钮"，没有"播放键"。而且"音量旋钮"实测调不出震动。**

## §4 第四环：**固件层**——就算主机能下发，固件里也没人接

【反汇编】把明文镜像（TF100A，56 KB，STM32F1 级内核）逆完：
- 命令分发表**共 39 条，全部取得并逐条分析**；
- **无一**读写触觉上下文（`ctx+0x14`）、**无一**碰 TIM2/TIM3；
- 全镜像**没有** `vib`/`motor`/`haptic`/`cmd`/`AT+` 之类字符串；唯一"人话"是 `TF100A_Test_FW`、编译时间 `Nov 28 2023 19:10:59`、内部版本 `5.21.01.23007`。

【实测】厂商命令通道（`Col04` OUT/IN，report ID `0x0E`）：
- 帧：读 `0E 20 00 00 05 01 <addr16BE> <size16BE>`；写 `0E 20 00 00 <len+5> 00 <addr16BE> <len16BE> <data…>`（★`[4]=len+5`）；
- **唯一有价值**的命令是 `0x20`（内存读写，可读整个 64 KB 窗口）；
- opcode 扫描（约 35 条后中止）：`0x00`–`0x0D` 全部只回**同一个空 ACK**、**未引发任何震动**；**`0x0E` 起应答通道死亡**（其后全部 `err=122`）。
- 【今天补证】`fwupd/plugins/goodix-tp`（**Goodix 原厂署名**）给出该族的命令族：`0x20` 内存读写、`0x00/0x03/0x0E` = **固件更新/复位**（`0E 12` 烧 flash、`0E 13` 软复位、`00 10` 切 Bootloader、`00 11` 开始更新）
  ⇒ **`0x0E` 打断通道的真因**：那是更新命令族，误发会把芯片送进 Bootloader。

**⇒ 第四环结论："主机侧没有入口（描述符不声明）+ 固件侧没有出口（命令表不碰马达）"= 双层缺失。**

## §5 第五环：**硅片层**——"改固件"是一条**单程门**

- 【实测】容器 `TB14P_GT7868Q_14030522_20240202.BIN` = `1084 头 + 96×1084 加密块 + 56,480 明文镜像` = 161,628；
  密文块熵 ~7.82（zlib/lzma/gzip 全解不开 ⇒ 真加密）⇒ **GT7868Q 的固件（决定"何时震"的那颗）读不到**。
- 【实测/规范】官方刷机由 **BIOS 在启动时**执行（`goodixtouchpad.inf` → `UEFI\RES_{b6ae105a-…}`，ESRT 名 "Goodix Update **UEFI**"），
  Windows 只把 `.BIN` 放进 `C:\Windows\Firmware`：
  1. 已装版本 `0x14030522` **正好等于**设备当前版本 ⇒ **无待刷更新**；
  2. 自己造包 ⇒ 破坏 `Goodixtouchpad.cat` 签名 ⇒ Windows 拒绝安装；
  3. 让 BIOS 接受改过的镜像 ⇒ 容器加密 + **eFuse 验签**（汇顶文档：密钥在 eFuse，`Security Mode` 开启后不可关闭）。
- ⇒ **刷不进去；就算刷进去，也没有退路。而触控板是本机唯一的指点设备。**

**⇒ 第五环结论：想做"加一条 `if (在滑动) 也震`"这种几十字节的改动 —— 技术上通，工程上等于赌上唯一指针设备。**

## §6 综合：三层封死 ⇒ "主机不能触发"是**结构性事实**

| 层 | 缺什么 | 证据 |
|---|---|---|
| 接口 | 输出报表 `out=0`；Haptics 页只有 `Intensity` | 【实测】+【规范】+【上游】+【社区】 |
| 固件 | 39 条命令无一碰马达；播放入口不可达 | 【反汇编】 |
| 硅片 | 加密 + eFuse 验签 + 无自助刷回 | 【实测】+【规范】 |

⇒ 这也**反向解释了厂商为什么这么做**：局部反射 ~1–5 ms，绕到 Windows 再回来 10–30 ms；
**点击手感全在延迟上**，所以厂商宁可写死在固件里，也不走主机。

## §7 证据链的独立性（为什么这不是"我们没想到办法"）

五条**互相独立**的证据同时指向同一结论，任何一条单独都不足以定案，合起来构成闭合：

1. **本机描述符**（硬件事实）—— `out=0`，只有 Intensity；
2. **微软规范**（标准要求）—— 主机触发必须有 Manual Trigger OUTPUT + Waveform/Duration List；
3. **Linux 上游 RFC**（独立的操作系统社区）—— device-initiated 无法由主机发起；
4. **阳性对照实测**（本机行为）—— 强度写入到位、力度确实变化，但**一次都没震**；
5. **固件逆向**（设备内部视角）—— 命令表与马达之间**没有边**。

## §9 失效形态与安全边界（运维知识，务必分清）

| 形态 | 能移动 | 点按震动 | 诱因 | 恢复 |
|---|---|---|---|---|
| **输入挂起（轻度）** | ✗ | **✓** | 类 0x20 **高频读取**（683 次 / 50–75 s） | **杀进程 + 等 1–2 分钟**（两次都自愈） |
| **永久 latch（重度）** | ✗ | **✓** | 厂商命令枚举（`0x0E` 等） | **只有彻底断电**（EC 复位流程） |
| **模组未运行** | ✗ | **✗** | 未上电 / 停在 Bootloader / 驱动层禁用 | 视情形；完整断电兜底 |

- **剂量红线**：类 0x20 读 **单轮 ≤80 次、≤3 次/秒、轮间 ≥3 分钟**，前后各一次体检（90 次 @≤10/s 安全；683 次 @9–13/s 三次中两次冻结）。【实测】
- **禁令**：**禁止枚举 class `0x00` / `0x03` / `0x0E`**（固件更新/复位命令族 = 历史"IC 挂死"真因）。
- **处置顺序**：① 杀掉所有后台任务 → ② 等 1–2 分钟 → ③（已装驱动时）按两次 `F8`【今天实测：按 F8 = 不能移动 + 不震；**再按是否恢复未验证**】→ ④ 完整断电 EC 复位（关机 → 拔充电器 → 长按电源 20–30 s → 等 1 分钟 → 开机）。热重启无效。

## §11 结论与路线

### 已判定不可行的（六条）
| 路线 | 结论 |
|---|---|
| HID 主机触发接口 | ❌ 不存在 |
| 厂商命令空间 | ⚠️ **此结论已作废（2026-09-14 PM）** —— 历史探测方法有误（子命令位置恒 0），**扩展空间 `0x80`/`0xA0`/`0xA1` 从未被探测过**，其中 `0xA0-0x0B`/`0xA0-0x0D` 直通触觉波形缓冲 ⇒ **★ 已升级为最高优先级路径**（改用「在台面样机上探」的方式，规避真机风险）|
| 改配置/阈值/波形 | ❌ 参数在 MCU 侧（编译期常量） |
| 改固件 | ❌ 单程门（加密 + eFuse 验签 + 无退路） |
| 拆机嗅探总线 | ❌ 只能确认"主机没发"，而这点描述符已证明 |
| 让 OEM 加功能 | ⚠️ 理论可行，**不可自助** |

### ~~唯一可行（方案 A）~~ —— ★ 2026-09-14 PM 已降级

> **降级原因**：用户明确要「**触控板本体震 + 连贯**」（不是单次震动，也不是外壳震）。外置执行器只能装在掌托/底盖，**手指在触控板上滑动时感受不到** ⇒ 方案 A 满足不了该需求。
> **当前优先级**：① 在台面样机上探 Col04 扩展命令空间 → ② 拆机 SWD 读固件 + 路线 ② 内层注入。详见 `SESSION-2026-09-14-PM.md` §5。

**以下为方案 A 原设计（保留备查）：**
- **软件**：复用已验证可用的 `RawTouchProbe`（Raw Input 读 `Col02` 的 40 字节报表）识别边缘滑动，
  按固定距离产出"震动节拍"；
- **硬件**：ESP32 + LRA 驱动板（如 DRV2605L）+ 方形 LRA，**¥40–65**，串口一行一条指令；
- **风险**：**零**（完全不碰触控板，原生点按触觉保持原样）；
- **诚实预期**：**震动时机**可做到与华为同级（完全由我们决定）；**震动质感**打折扣
  （外置 LRA 无法等效于"贴在玻璃下方的原装马达"）。
- 附注【社区】：华为 MateBook X 用的是**压电陶瓷（PZT）**，与本机 **LRA 是不同技术路线** —— "华为那种效果"在硬件层面就不同源。

### 若只想"不改硬件"（零成本、可立即做）
保留原生点按触觉不动，手势软件照做，**滑动时用屏幕/声音/光标反馈**替代震动，直到接上外置马达。

## §13 ★ MCU 路线评估（用户提问："我现在要用 MCU 破解？"）

### 13.0 先纠正一个用词：**不是"破解"，是"信号级重放"**

要拿**原装 LRA**随滑震，**不需要**：破容器加密、过 eFuse 验签、改固件、刷机。
需要的只是：**在模组内部那条链路上，把"播放"这一帧照抄下来，再重放出去。**

| 障碍 | 在本路线中是否挡路 |
|---|---|
| GT7868Q 固件加密（100,608 B） | ❌ 不挡 —— 我们不去读它，只在**线上**抓它发出的帧 |
| eFuse 验签 / 无自助刷回 | ❌ 不挡 —— 不写 flash，不刷固件 |
| 主机 HID 接口没有"播放键" | ❌ 不挡 —— 我们**绕过主机**，从模组内部那侧下令 |
| 模组拆解 / 焊接 | ✅ **这才是真正的成本与风险** |

### 13.1 两种"用 MCU"的方式，别混为一谈

| | **A. MCU 做外置执行器** | **B. MCU 进模组内总线（嗅探 + 注入）** |
|---|---|---|
| 接在哪 | **模组之外**（掌托/底盖内），自己带一个 LRA | **GT7868Q ↔ TF100A 之间的内部链路**（模组内） |
| 震动源 | 外置 LRA（质感打折） | ★ **原装 LRA**（质感 = 原生点击） |
| 要不要拆机 | 只拆底盖（不碰触控板） | **要拆触控板模组**（唯一指针设备） |
| 风险 | **零** | 拆坏 = 失去唯一指针；链路电平/时序错 = 打挂（可断电恢复） |
| 成本 | **¥40–65** | ¥50–150 器件 + **以周计的逆向工时** |
| 成功率 | 100%（一定能做出来） | **中等偏上**（取决于链路类型与可注入窗口），但**不保证** |
| 能达到的"灵魂" | 时机 100% 可控；质感打折 | **时机 100% 可控 + 原装质感** |

### 13.2 ★ 修正项目旧文档的一处推理（route 4 的否定只对"主机侧总线"成立）

`WHY-NOT-VIBRATE.md` §5 路 4 的否决理由是：
> 「嗅探回答的是"**主机发了什么**"，而这个问题看描述符就有答案（`Col02 out=0`）；固件的决策逻辑在芯片内部，总线看不到。」

**这条对"主机 ↔ 触控板"那条 I2C-HID 链路是对的，但**没有覆盖模组内部链路**：
- 【已确立】模组里**有两颗芯片**（丝印 `TF100A`）；
- 【已确立】**GT7868Q 决定"何时震"、TF100A 决定"怎么震"**；
- ⇒ 那么"**播放**"这个动作，必然是 GT7868Q 通过**内部链路**告诉 TF100A 的 —— **这条报文主机永远看不到，而它正是我们唯一需要的东西。**
- ⇒ 因此 **route 4 的正确形态不是"嗅探主机总线"，而是"嗅探模组内链路"** —— 这是**尚未被否证**的一条路。

（旁证：明文固件里唯一的非空 IRQ 是 **USART1**、且**载频镜像缺失的尾部正好含 USART1 接收 ISR**（量级：**下界 837 B**，~~原写 5,141 B 已推翻~~）⇒ 内部链路很可能是 **UART**，而 UART 点对点链路**天然适合被动嗅探与空闲注入**。）

### 13.3 可行性推演（技术细节）

| 环节 | 说明 | 难度 |
|---|---|---|
| 1. 找测试点 | 模组 PCB 上 GT7868Q 与 TF100A 之间的走线/TX-RX 对（UART 通常 2 线，或 I2C1 的 SDA/SCL） | 中（需显微/放大镜 + 万用表） |
| 2. 电平确认 | TF100A 是 STM32F1 级 ⇒ 大概率 3.3V（也可能是 1.8V，**必须先量**） | 低 |
| 3. **被动嗅探**（不动手，只听） | 用一个 UART 接收脚听 TX，记录"点按瞬间"的字节流 ⇒ **拿到播放帧** | 低–中 |
| 4. 注入 | ESP32 的**三个 UART** 天然适合做 MITM 桥：透传 GT7868Q↔TF100A，**在空闲窗口插入一帧播放命令** | 中 |
| 5. 与主机软件联动 | 手势软件（Raw Input 读 `Col02`）→ 串口 → ESP32 → 注入 ⇒ **随滑随震** | 低（本项目已有可用探针） |

**⇒ 架构会长这样**（这套架构里，**主机侧仍然零驱动、零风险**）：
```
Windows 手势软件（Raw Input 读 Col02，识别边缘滑动）
        │ USB 串口
        ▼
ESP32（MITM：透传内部链路 + 空闲注入"播放"帧）
        │ 焊在模组内 TX/RX（或 SDA/SCL）
        ▼
TF100A → TIM3/PWM → ★ 原装 LRA  ⇒ 滑动时逐格震动
```

### 13.4 ★ 强烈建议的第一步：**先买一块同型号触控板做"台面样机"**

理由：**模组是唯一的指针设备**。若在真机上拆焊失败，损失远大于收益。
- 二手/拆机的 **ThinkBook 14 G6+ 触控板模组**（或同型 GXTP5100 模组）通常几十元；
- 台面上：可以慢慢找测试点、量电平、**反复试错**，真机保持完好；
- 台面样机验证通过后，再把**已验证的接线与固件**搬到真机上做一次。

### 13.5 决策建议（按"要不要原装 LRA"分叉）

| 你的偏好 | 推荐 |
|---|---|
| 只想**尽快**有"随滑随震"，手感差一点能接受 | **做方案 A**（外置 LRA + 手势软件，¥40–65，今天就能开始） |
| **必须是原装马达的手感**，且愿意投入以周计的逆向 | **走 §13.3**，但**先买台面样机**，把真机风险降到最低 |
| 两者都想要 | **先做 A**（立刻可用，软件层与手势识别并**完全复用**），再慢慢做 B；B 成功后只需把输出从"外置马达"切到"注入"即可 |

### 13.6 安全边界（B 路线尤其要守）

- 注入前**必须**先做纯被动嗅探（只听不发），确认链路类型、波特率/时钟、空闲窗口；
- 电平不确认**绝不**接线；**禁止**在链路活跃时强推电平；
- 一旦触控板异常：**杀进程 → 等 1–2 分钟 → 按两次 F8（已装驱动时）→ 完整断电 EC 复位**（见 §9）；
- **不要碰** `0x00/0x03/0x0E` 那几个类（更新/复位族）；B 路线的注入只做**已抓到的"播放"帧**，不做枚举。
