# 最终结论：AW86927 触觉改造 · 纯软件路终止

> 日期：2026-10-01
> 状态：**纯软件路线关闭**（经用户确认）。本文是最终收口，供后续会话直接接手，**不必重跑实验**。
> ⚠️ 本文结论全部有实测支撑，凡未验证的一律标注。

## 〇、一句话

> **主机侧不存在"触发震动"的接口，设备也不监听主机。**
> 震动由模组内部自治产生（TF100A 测压力 → 驱动 LRA），
> **主机拿到 I²C 也改变不了这一点** —— 因为原厂设计里就没有让主机触发的那条命令。

---

## 一、★ 决定性实测（本次新增，且是终局判据）

**在 Linux live USB 里（触控板完全没驱动）：**

| 观察 | 含义 |
|---|---|
| 触控板**指针完全不能用** | 主机**没有在跟触控板通信**（`i2c-hid` 未工作） |
| 但**点按照样震动** | ★ **震动完全不依赖主机** |

⇒ **结论**：
1. 震动是**模组内部自治**的（按压 → TF100A 测压力 → 阈值判定 → 驱动 LRA）
2. **主机侧的"能不能说话"根本不影响它震**
3. ⇒ **"拿到 I²C 话语权" ≠ "能让它震"** —— 这是两道独立的门
4. ⇒ 原厂**从设计上就没有**"主机触发震动"这条通路

**这一条独立地、决定性地关闭了纯软件路。** 与老线 `追加十九`（蓝莓项目）的结论完全一致：

> **主机没有"发送震动"的指令 —— 一条都没有。**

## 二、本次会话确认的事实（全部实测）

### 2.1 硬件 / 拓扑

| 项 | 值 | 强度 |
|---|---|---|
| 触控板 | Goodix **GXTP5100 / GT7868Q**，`27C6:01E9`，`ACPI\GXTP5100\1` | ✅ |
| 总线 | I²C，`Intel Serial IO 7E78`，ACPI 路径 `\_SB.PC00.I2C0.TPAD`，从地址 `1` | ✅ |
| 触觉驱动 IC | **AW86927FCR**（丝印 `CA4F`），艾为 | ✅ |
| LRA 驱动线 | `HDP`/`HDN` = AW86927 的 **pin 7 / pin 5**（差分输出） | ✅ |

### 2.2 ★ AW86927 的业界标准用法（一手来源）

**Fairphone 5 设备树 + Linux 主线驱动**（[补丁组](https://patchew.org/linux/20250806-aw86927-v1-0-23d8a6d0f2b2@fairphone.com/)）：

```dts
vibrator@5a {
    compatible = "awinic,aw86927";
    reg = <0x5a>;                                        /* 从地址 0x5A */
    interrupts-extended = <&tlmm 101 IRQ_TYPE_EDGE_FALLING>;
    reset-gpios = <&tlmm 100 GPIO_ACTIVE_LOW>;
};
```

⇒ **它就是"标准 I²C 从设备 + reset + 中断"**，挂在 SoC 的普通 I²C 上。

**★ 身份标识（可直接用来探测）**：
```
读寄存器 0x57(高) / 0x58(低) == 0x92 0x70  ⇒ 确认是 AW86927
```

**★ 完整控制流程（`aw86927.c` 逐行）**：
```
硬复位(reset 拉高1ms→释放→等8ms) → 软复位(0x00=0xAA,3ms) → 验身份(0x57/0x58)
→ 初始化(0x5B TMCFG=0x7D 解锁 → ANACFG/CONTCFG/PWMCFG → 锁定)
→ 下波形(BASEADDR 0x2D/0x2E=0x0800；RAMDATA 0x42 连写 头+数据)
→ ▶ 播放: 写 0x09 PLAYCFG4 = 0x01 (GO)
→ ■ 停止: 写 0x09 PLAYCFG4 = 0x02 (STOP)
```

### 2.3 ❌ AW86927 不在 PCH SMBus 上（**强结论**）

用 PawnIO 签名模块 `SmbusI801.bin` 实测：

```
[3] 控制器身份: type = i801, IO base = 0xEFA0, PCI IDs = 0x382717AA7E228086  (7E22 ✓)
[4] 三种协议交叉扫描 0x03..0x77 → 仅 1 个地址应答: 0x44
[5] 0x44 dump: reg00-0F = 00 00 00 03 00 00 00 00 00 24 49 00 04 01 10 26，其余全 00
[6] 0x5A / 0x5B: 无应答 (STATUS_NO_SUCH_DEVICE = 0x800701B1)
```

**为什么可信**：有**阳性对照**（`0x44` 应答，很可能是电池/电源器件）+ 用对了协议（`BYTE_DATA`）+ 控制器身份确认为 `7E22`。

### 2.4 ❌ ACPI 里没有任何触觉通路（**强结论**）

**全 32 张 ACPI 表 / 761,859 字节 / 反编译后 100,645 行 ASL**：

| 关键词 | 命中 |
|---|---|
| `LRA` · `HAPTIC` · `VIBR` · `MOTOR` · `AW869` · `CA4F` · `Awinic` | **全部 0** |
| `Trig` | 40 处，**全是** `FundamentalDeviceResetTriggeredOnD3ToD0`（PCIe 复位） |

**曾被怀疑的 `MLR1`/`MOFD` 已归因到 EC 功耗/热管理**：
```asl
OperationRegion (LA3M, SystemMemory, 0xFE0B0F00, 0xFF)
Field (LA3M, ByteAcc, Lock, Preserve) {
    Offset (0xBD), MLR0, 8, MLR1, 8, MLR2, 8, MLR3, 8,
    Offset (0xD0), PL1V, 8, PL2V, 16, ...,
    Offset (0xDE), MPL1, 1, MPL2, 1, ..., MOFD, 1
}
Method (_Q47, 0) { ... WMI5.LPWR = MLR1; Notify(WMI5, 0xD0) ... }
```
⇒ `PL1V`/`PL2V`（Intel PL1/PL2 功耗限制）紧邻 `MLR1` ⇒ **这是 DPTF 电源/热管理，与触觉无关**。

### 2.5 ❌ EC 与触觉无关联证据

用 PawnIO `LpcACPIEC.bin` 读 EC RAM（84% 偏移可读，含温度块 `0x12–0x17` 与 ASCII `2023`）：

```
[3] 交互期 25 个偏移"变化"
[4] 静置 10 秒后与基线相比: 93 个偏移不同   ← 读数噪声大
[5] 关键偏移:
    EC[0xBD] base=0x7A  snapshots=0x7A 0x7A 0x7A   ← 静止
    EC[0xBE] base=0x02  snapshots=0x02 0x02 0x02   ← 静止
    EC[0xD0] base=0x00  snapshots=0x00 0x00 0x00   ← 静止
```
⇒ 唯一可信的变化是温度块**单调下降**（时间漂移），**不是触控引起的**。
⇒ **没有证据支持"EC 管触觉"。**

### 2.6 ❌ Windows 上的两条路都已关闭

| 路 | 关闭原因 |
|---|---|
| **RWE 扫 I²C** | ❌ `RwDrv.sys` 被微软吊销名单拦截（事件 3023: *"blocked ... revoked by Microsoft"*）；且 RWE **`Access` 菜单里没有原生 I²C 入口**，只有 SMBus + EC ⇒ 够不到 `7E78` |
| **再挂一个并列 SPB 客户端驱动** | ❌ 微软文档明示：*"Only one driver can hold an open logical connection to an SPB-connected peripheral device at a time"*；`hidi2c` 已占用。且用 `ACPI\GXTP5100` 做 HWID 安装会**顶掉 `hidi2c`**（触控板当场失灵） |

### 2.7 ❌ Linux 上扫描 designware 控制器不安全

```
i2c-4  → i2c_designware.4: i2c_dw_handle_tx_abort: lost arbitration ×4
       → i2cdetect exited with irqs disabled → 内核崩溃 / killed
i2c-15 → 用户报告卡死
```
⇒ Intel Serial IO I²C（`i2c-designware`）**对 `i2cdetect -r` 快速探测不稳定，会卡死内核**。
⇒ **触控板正挂在这类控制器上 ⇒ Linux 这条路也无法安全走完。**

### 2.8 Linux 实测观察

```
i2c-0 … i2c-5:  基本全空
i2c-5:  0x44 出现在表格中  → 与 Windows 侧 PCH SMBus 的 0x44 一致
i2c-0:  0x28 / 0x51 显示 UU（驱动已占用，非空闲设备）
i2c-16…: 后期编号，用户确认是显卡相关（DDC/EDID）总线
```
⚠️ 有一张表出现整片 `50 51 52 … 5f` 连续"应答" —— **属可疑回显，不作为证据**。

## 三、❌ 本次会话中我犯了并已撤回的错误

| 我说过 | 状态 | 否证依据 |
|---|---|---|
| "`MLR1`/`MLR2` = LRA #1/#2，这是触觉控制面" | ❌ **撤回** | 反编译后是 EC RAM 字节，邻居是 `PL1V/PL2V`（功耗） |
| "`Q47 trigger` 是触发震动" | ❌ **撤回** | 它把 EC 寄存器转发给 `WMI5.LPWR` 并发 `Notify(D0)` |
| "UMP45 完全正确（EC 控制震动）" | ❌ **撤回** | 本机 ACPI/EC 均无触觉证据 |
| "Windows 没有 `IOCTL_ACPI_READ_EC` 是我写错候选码" | ✅ 修正 | 查 WDK `acpiioct.h` 确认：Windows **确实没有**该 IOCTL（那是 Linux 的） |
| "`0x0B` 电池读不到 ⇒ SMBus 通道坏了" | ❌ **撤回** | 笔记本电池常走 EC 而非 PCH SMBus；后经 `0x44` 阳性对照证明通道正常 |
| "RWE 被拦 ⇒ 完全不可用" | ⚠️ 修正 | 关掉 HVCI+黑名单后 `RwDrv` 实际**能加载**；RWE 出局的真因是**没有原生 I²C 入口** |

**教训（与项目既有纪律一致）**：
> 在二进制/AML 里"看到一个像缩写的名字"，**不是证据**。
> 必须反编译到 `OperationRegion`/`Field`/调用点，看清邻居和值域。

## 四、⇒ 结论：纯软件路终止，只剩硬件路

```
纯软件 + 不拆机   →   ✗ 不可能
```

**必须放弃"纯软件"或"不拆机"其中一条。**

### 剩余两条路（都需要拆机）

| | 路线 | 能达成 | 难度 | 依据 |
|---|---|---|---|---|
| **C1** | **`HDP`/`HDN` 焊盘外挂驱动** | ✅ **一定成功**，可编程，滑动时可震 | ★★ 中 | 焊盘已实证：模组背面找到 `HDP`/`HDN`，**从金属支架开口处露出 ⇒ 拆底盖即可接触，不必拆开模组本体** |
| **C2** | **改 TF100A 固件** | ⚠️ 能让它"手势也震"，但**拿不到"主机触发"** | ★★★★ 高 | TF100A 是**唯一明文固件 + 有片上自写代码**的芯片；但写入通路被 `hidi2c` 挡 |

### C1 的关键前置（**值得先做，成本极低**）

> 老线 `追加二十七` §十四之二：**用万用表测 `PA3` 是否连通到 AW86927 的 `TRIG1`（pin 4）**

- **若连通** ⇒ **在那一根线上发个 ≥1 µs 脉冲就能播放波形** —— 连 H 桥都不用做，C1 大幅简化
- **若不连通** ⇒ 引 `HDP`/`HDN`，接小功率 H 桥/差分驱动器

**附带收获**：AW86927 有 **8 KB SRAM 波形库 + TRIG 触发**，若能从模组内读出原厂波形，**震动手感可复刻原厂**。

### 5.2 可复用技巧

**① 零权限拿完整 ACPI**（不需要管理员！）
```
HKLM\HARDWARE\ACPI\<表键>\<OEMID>\<OEMTABLEID>\<REV>  →  值名 "00000000" = REG_BINARY
★ SSD1..SSDS 是【平级表键】，不是 SSDT 的子键 —— 只走 DSDT/SSDT 会漏掉 30 张表
```

**② iasl 反编译正确用法**
```bash
iasl -e <31 张 SSDT> -d <DSDT.bin>     # .dsl 自动落在输入旁
# ❌ 反编译模式不能用 -o <path>（报 "Option requires a single-character suboption: -o"）
```

**③ PawnIO 用法**（签名驱动，可绕开吊销名单）
```
pawnio_open → pawnio_load(blob) → pawnio_execute(handle, "ioctl_xxx", in, out)
module 放同目录；pawnio_open 需要管理员（0x80070005 = 权限不足）
★ 模块 .bin 从 GitHub release 取（release_0_2_11.zip 仅 69 KB）
```

**④ PowerShell 脚本喂给 `powershell.exe` v5.1 必须带 UTF-8 BOM**
否则中文按 GBK 解码、全角标点会吃掉引号导致语法崩。
**最稳做法：脚本输出纯 ASCII。**

## 六、给未来会话的三句话

1. **别再找"主机侧触发"了** —— Linux 实测证明：触控板无驱动、指针不动时**点按照样震**，主机根本没参与。
2. **AW86927 不在 PCH SMBus 上**（有阳性对照的强结论）；它更可能在触控板那条 `i2c-designware` 总线上，而那条总线**用 `i2cdetect` 会卡死内核**。
3. **想继续只有一条确定能成的路**：拆底盖 → 万用表测 `PA3` 是否连 `TRIG1` → 引 `HDP`/`HDN` 外挂驱动。
