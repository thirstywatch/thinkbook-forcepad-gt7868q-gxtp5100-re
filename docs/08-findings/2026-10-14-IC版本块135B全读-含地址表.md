# IC 版本块 135 B 全读：**自描述长度 + 两层 YS 校验 + 块尾一张地址表**（2026-10-14）

> 性质：**纯只读厂商通道**（`gxmem.py read`，5 次 ≤32 B、间隔 800 ms）。
> 触发：**A#42**（核对 `0x4020`/`0x4032`）。结果比预期大：**A#42 解决，并额外发现一条可读的地址表**。

## §1 一句话

> `0x4014` 起的版本块 = **135 字节**，**首两个字节就是它自己的长度**（BE16 = `0x0087` = 135）；
> 块内**有两层 YS 校验**（内层 32 B 子记录 + 整块 135 B）；
> 块尾是一张 **16 位地址表**，其中 **`0x86B8` / `0x8E38` / `0x8078`** 与《§19.64》里 **DLL 分支 2（本机 Yellowstone）的 A1/A2/A3 逐字命中**。

### 3.1 两层校验的算术验证（可复算）

```
内层（32 B）: sum(bytes[+0x00..+0x1D]) = 0x0375 == BE16(+0x1E,+0x1F) = 0x0375   ✅
整块（135 B）: sum(bytes[+0x00..+0x82]) = 0x1554 == BE16(+0x83,+0x84) = 0x1554  ✅  ← 见下方注
```

> 规则：`checksum_u8_ys(data, n) = sum(data[0..n-3]) - BE16(data[n-2..n-1]) == 0`（厂商 `gtx8drv_goodix_ts_core.h:579`）。
> 即 **末 2 字节 = 前 n−2 字节之和**；135 B 时 n−2 = 133，故为 `+0x00..+0x84` 之和。

## §6 ★ 对「改版本骗 BIOS 重刷」的机制意义（B48 / §19.66）

版本块**自带两层校验**（内层 32 B + 整块 135 B），且厂商驱动读回后会**先校验再解析**（`gtx8drv_goodix_ts_i2c.c:731`）。
⇒ **任何"改版本号"的尝试都必须同时重算这两层校验尾**，否则块自身不自洽；这给 §19.66 的纪律 161（**不要靠改版本字段骗重刷**）提供了机制层支撑。
