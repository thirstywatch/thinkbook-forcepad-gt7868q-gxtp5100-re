# 两处归属错误的实测裁定 + 全链证据分级

> 日期：2026-10-01
> 触发：用户指出「1.1.2 把 `0x19A00–0x2775C` 算成 GT7868Q 的双核混合」与「TF100A 地址基址不统一（差 `0x5000`）」
> 方法：**对本机胶囊 + 反汇编做算术与指纹实测**
> 结果：**两处都成立，且第 2 处比指出的更彻底**

---

## 一、★★★ 裁定 1：`0x19A00–0x2775C` 那段 ARM 代码**全部是 TF100A**

### 1.1 算术核对（决定性）

```
载荷 B 起点 0x19ABC + 56,480 B (0xDCA0) = 0x2775C
文件总长                                = 0x2775C
⇒ 相等 ✅
```

| 区间 | 归属 | 长度 |
|---|---|---|
| `0x00000..0x0113C` | 头部/目录 | 4,412 B |
| `0x0113C..0x19ABC` | **载荷 A**（7868Q 侧） | **100,736 B** |
| `0x19ABC..0x2775C` | **载荷 B**（TF100A 侧） | **56,480 B** |

⇒ **`0x19A00..0x19ABC` 这 188 B 属于载荷 A 尾部**；**`0x19ABC..0x2775C` 全部是载荷 B。**
⇒ 用户指的"`0x19A00–0x2775C` 那段 ARM 代码"**就是 TF100A 镜像**。

### 1.2 ★ ARM Thumb-2 指纹实测

| 区域 | 长度 | `0xF2xx` | **`c2 f2`（MOVT）** | `push{..lr}` |
|---|---|---|---|---|
| **载荷 A**（7868Q） | 100,736 B | 2.0/KB | **0 个（0.0/KB）** | 2.0/KB |
| **载荷 B**（TF100A） | 56,480 B | 0.3/KB | **888 个（16.1/KB）** | 2.5/KB |
| 随机对照 | — | 1.6/KB | — | — |

**⇒ ARM Thumb-2 特征【只存在于载荷 B】。载荷 A 一个 `MOVT` 都没有。**

### 1.3 ★ 载荷 A 不是任何代码

| 指标 | 载荷 A |
|---|---|
| 熵 | **7.9966** |
| 非零字节 | 99.33% |
| 零字节 | 0.67% |
| **8051 常见操作码命中率** | **23.7%** |
| 随机基线 | **23.4%** |
| 对照：载荷 B | 43.1% |

**⇒ 载荷 A 的操作码分布 ≈ 随机 ⇒ 它不是 8051 代码（也不是 ARM 代码）。**

### 1.4 ⇒ 结论

> ## **"GT7868Q = 8051 + ARM Cortex-M4F 双核混合"这个结论【整条作废】**
> **原因：那段 ARM 代码是 TF100A 的，被误算到 GT7868Q 头上。**
> **而 M4F 本身又是早已更正过的错误标签**（TF100A 是 STM32F1 类 = **Cortex-M3**，无 FPU）。
> **⇒ GT7868Q 的 CPU 架构在软件层面【无任何证据】。**

## 二、★★★ 裁定 2：TF100A 加载基址 = **`0x08005000`**（不是 `0x08000000`）

### 2.1 三重交叉验证

| # | 证据 | 结果 |
|---|---|---|
| 1 | 反汇编文件**首行地址** = `0x08005000` | ✅ |
| 2 | 向量表位于 **file `0x19ABC`**（载荷 B 起点），表项 `SP=0x200076C8` · `Reset=0x08005165` | ✅ |
| 3 | **反向检验**：若 base = `0x08000000`，则 `Reset=0x08005165` 应落在 file `0x1EC21` | ❌ 那里是普通指令 |
| 3' | 若 base = **`0x08005000`**，则 `Reset` 落在 **file `0x19C21`**（= 向量表 + 4） | ✅ **正是函数入口**（旧文档 §3.3 的 `abs()`，字节 `f2 5a 22 fb`） |
| 4 | 向量表有效表项 42 个，跨度 `0x08005165..0x0800DFE5` = 36,480 B | ✅ ≤ 56,480（base=`0x08000000` 则 57,316 > 56,480 ⇒ ❌） |

> ## **⇒ 正确基址 = `0x08005000`**
> ## **⇒ 映射式：`运行地址 = 0x08005000 + (file偏移 − 0x19ABC)`**

### 2.2 分派器地址的正确值

| 口径 | 地址 | 判定 |
|---|---|---|
| **旧口径**（base `0x08000000`） | `0x080091C0` | ❌ **错**（本镜像内不存在该地址的有效入口） |
| **正确**（base `0x08005000`） | **`0x0800E1C0`** | ✅ **与反汇编实测一致**（`push {r7,lr}` + 唯一调用者 `0x0800FDFA`） |

**⇒ `0x080091C0`（旧）与 `0x0800E1C0`（新）不是"两种基址约定"，是【一个新一个旧】。**
**⇒ 全线应统一为 `0x0800E1C0`。**

## 三、★★★ 顺带查出的第 3 处（比前两处更根本）

### 3.1 `0x22C7C`（"GT7868Q 内部分派器"）**不在 TF100A 里，也不在文件里**

`ROUND23` / `追加八` 说 TF100A 里有一个"16 条命令的分派器 `0x22C7C`"。
按 TF100A 的基址换算：

```
0x22C7C 作为「file 偏移」        ⇒ file 0x22C7C 在载荷 B 内，但落在【未反汇编尾部】
0x22C7C 作为「运行地址」+ base 0x08005000 ⇒ file = 0x19ABC + (0x22C7C−0x08005000) 
                                          = 0x19ABC + (负数) ⇒ ❌ 不可能
```

### 3.2 反汇编覆盖范围（实测）

```
反汇编覆盖: 0x08005000 .. 0x08012342   （20,314 条）
载荷 B 运行地址上限: 0x08012CA0
⇒ 未反汇编尾部 = 0x08012342..0x08012CA0 = 2,398 B
⇒ 该尾部内容: ff 01 01 ff 01 01 …（周期 3 的填充图案）+ 浮点常量块
```

**⇒ 尾部是数据，不是代码 ⇒ TF100A 里没有 `0x22C7C` 那个分派器。**

### 3.3 ⇒ `0x22C7C` 的真实出处

`ROUND23` 的口径原文是：
> 固件：`TB14P_GT7868Q_...BIN`（161,628 B，**文件偏移 0 ↔ 运行地址 `0x08000000`**）

**⇒ 那是旧线对【GT7868Q 侧（已解密镜像）】的口径**，
用的是 `raw = GT7868Q_native_fw.bin`（161,628 B，与胶囊等长）的**独立地址空间**。

> ## **⇒ TF100A 与 GT7868Q 是【两个独立程序】，各有自己的加载基址与地址空间。**
> ## **把 `0x22C7C`（GT7868Q 侧 file 偏移）与 TF100A 的 `0x0800E1C0` 混在一张表里，就是 5.4 节那处"四个命令表"混淆的根源。**

## 五、★ 全链证据分级（按用户给的表，逐格核对后定级）

> 分级定义：
> **【已确认】** 有本机实测或一手规范原文
> **【半确认】** 有实测但缺一个关键环节，或只有间接证据
> **【推断】** 由排除法或旁证得出，无直接证据
> **【无证据】** 完全没有材料

| 环节 | 用户给的状态 | **裁定后** | 依据与疑点 |
|---|---|---|---|
| 主机 → GT7868Q | 已确认 | ✅ **【已确认】** | `PCI 7E78` · `I2C0.TPAD` · 400 kHz · 从地址 `1` · Col04 实测可读写 |
| GT7868Q → TF100A | 半确认 | ⚠️ **【半确认】** | **确**：TF100A 作为载荷 B 随胶囊下发（算术已证）；TF100A 从机 `0x2C`（`OAR1=0x58`）；PA3 门铃 + A2 回复（实测）<br>**缺**：`ITBUFEN`/`ITERREN` 从未置位 ⇒ 走 I²C1 还是 USART1 **未定**；**PA3 对端未证** |

## 六、★ 对关键疑点 1 的专门更正（我此前的错误）

**全书 1.5 原文（错）：**
> 「由 AW86927 规格导出的关键推论：…⇒ 只能是 GXTP5100 / GT7868Q（**但该结论的前提"波形必须经 I²C 下载"在本镜像内找不到 I²C 驱动 ⇒ 前提已削弱**，见 6.3）」

**❌ 错在**：把"**TF100A 镜像里没有 I²C 主机驱动**"当成了"**GT7868Q 也没有**"。
**载荷 A 不可反汇编 ⇒ 对它一无所知 ⇒ 不能用来削弱这个前提。**

**✅ 正确表述：**
> AW86927 的 8 KB 波形库掉电即失 ⇒ 每次上电必须有主控下载。
> TF100A **从不产生 START**（实测：`CR1.START` 全镜像 0 次）⇒ 不是它。
> ⇒ **唯一候选是 GT7868Q**（或一个尚未发现的主机）。
> **⇒ 这条线索【仍然指向 GT7868Q】，前提未被削弱。**

## 七、方法学

| # | 要点 |
|---|---|
| 1 | **归属判断必须做算术** —— `0x19ABC + 56,480 = 0x2775C = 文件长` 这一步就能定案，成本几乎为零 |
| 2 | **架构指纹要按区域分别统计** —— 全域统计会把两段不同性质的载荷平均掉 |
| 3 | **基址要用镜像自身要素交叉验证**（向量表位置 + 反汇编首行 + 表项跨度上界），不要沿用旧文档口径 |
| 4 | **不同程序的地址空间不能混表** —— TF100A（load `0x08005000`）与 GT7868Q（load `0x08000000`，独立空间）混在一张"四张命令表"里，是混淆的根源 |
| 5 | **"零引用/无驱动"结论要声明搜的是哪个镜像** —— 否则会跨程序得出过强结论（本轮疑点 1 的错误即由此产生） |
