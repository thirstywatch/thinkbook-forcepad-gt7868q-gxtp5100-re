> # ⚠️ 非触控板项目文档（「开盖角度 / LID」项目）
>
> 本文属于**另一个项目**（屏幕开盖角度传感器），与触控板震动改造**无关**。
> 它被放在同一工区是为了复用底层方法（EC / ACPI / BIOS 反汇编），**但它的结论不能用在触控板上。**
>
> ## ★ 本文有一处会误导触控板工作的错误
>
> > §60：「用 RwDrv 读 PCI 配置空间……以其寄存器……以 **从机地址 0x2C** 直接读写**触控板**寄存器」
>
> ❌ **错**。`0x2C` 是 **GT7868Q ↔ TF100A 之间的 I²C1 从机地址**（TF100A 的），
> 不是主机侧访问触控板的地址。`0x2C` 只是 DSDT `TPID` 表里 Goodix 的**默认值**。
>
> **⇒ 主机侧访问触控板必须用 `1`**（ACPI `_ADR` / SPB 连接资源为权威）。
>
> ```
> 主机 ──[I²C0, 从地址 = 1]──▶ GT7868Q（触控主控）
> GT7868Q ──[I²C1, 从机 0x2C]──▶ TF100A（压力 MCU）
> ```
>

## 一、本轮新增的硬参数（DSDT `TPAD` 设备）

触控板在 DSDT 里叫 **`TPAD`**，是**五厂商共用节点**（同一块板可装不同厂商触控板），`_CRS` 会按实际厂商回填：

| 条目索引 | HID 字符串 | **I2C 从机地址** | **HID 描述符寄存器** | CID |
|---|---|---|---|---|
| 1 | SYNA2BA6（Synaptics） | 0x2C | 0x20 | PNP0C50 |
| 2 | ELAN06FA（义隆） | **0x15** | 0x01 | PNP0C50 |
| 3 | CIRQ1080（Cirque） | 0x2C | 0x20 | PNP0C50 |
| **4** | **GXTP5100（汇顶，本机）** | **0x2C** | **0x20** | PNP0C50 |
| 0xFF | XXXX0001（占位） | 0xFF | 0xFF | — |

- **交叉验证**：ELAN 条目 = **0x15**，与行业已知的 ELAN 触控板 I2C 地址一致 ⇒ 解读正确
- 总线 = **`\_SB.PC00.I2C0`**（I2C 控制器 0）；中断走 **`\_SB.GPI0`** 的 GpioInt 描述符（`SBFG`）
- `_DSM` 使用**标准 I2C-HID 规范 GUID** `3CDFF6F7-4267-4555-AD05-B30A3D8938DE`（fn=1 返回 HID 描述符寄存器地址）
- `_CRS` 按 `OSYS` 分派：`OSYS >= 0x7DC`（Windows 10+）走 `SBFI`，否则走 `SBFG`
- Linux 侧 ty2 驱动按 HID VID/PID（`27C6:01E9`）匹配，**地址由 ACPI 提供** ⇒ 与本表一致

**⇒ 意义：现在有了"直接与触控板对话"所需的全部寻址参数**（总线、从机地址、描述符寄存器）。这在之前是缺的。

## 二、角度清单（按价值/代价排序）

### ★ A1. Windows 下绕过 HID 栈，直接驱动 I2C 控制器
- **做什么**：用 RwDrv 读 PCI 配置空间（I/O 端口 0xCF8/0xCFC）拿到 `I2C0` 控制器的 BAR（Intel LPSS / DesignWare I2C），再按其寄存器（`IC_CON`/`IC_TAR`/`IC_DATA_CMD`/`IC_ENABLE`）以 **从机地址 0x2C** 直接读写触控板寄存器
- **能拿到什么**：
  1. **原始 HID report descriptor**（读描述符寄存器 0x20）—— 这是 Windows 这侧拿不到的东西
  2. **Col02 那 737 字节 feature 的等价数据**（不经过被独占的 HID 接口）
  3. **不受 Col04 只读限制的 vendor 命令面**（直接写寄存器）
  4. 可能读到**触控板固件版本/配置/校准区**
- **代价**：中高（要正确驱动 I2C 控制器）；需要临时关闭 VBS/驱动黑名单加载 RwDrv
- **风险**：中 —— 控制器同时被 Intel I2C 驱动占用，需只读起步、单次、失败即停
- **判断**：**最值得做的一条**，因为它一次性解锁"描述符 + 寄存器级命令面"

### ★ A2. Linux live USB（更省事，但要重启）
- **做什么**：U 盘启动 Linux，用 `hidraw`（`HIDIOCGRDESC` 读原始描述符）+ `i2c-dev`（`i2cget`/`i2cset` 直接访问 0x2C）+ `hid-multitouch`
- **优势**：hidraw **不排斥**驱动占用 ⇒ Col02/Col03 feature 直接可读；i2c-dev 一行命令就能读寄存器
- **代价**：低（协议全部由内核提供）；需要一次 U 盘重启
- **风险**：低（Linux 不写固件就没事）
- **判断**：**性价比最高**，前提是你接受重启进 U 盘

### ★ B. I2C 总线监听（用测量替代逆向）
- **做什么**：逻辑分析仪 / I2C sniffer（$10 级）夹在 **主机↔触控板** 或 **TP↔TF** 的 SCL/SDA 上，边用触控板边记流量
- **能拿到什么**：**真实的触觉命令流**（哪种操作让 TP 给 TF 发"播放"命令）—— 这是加密固件里读不到、但总线上一定出现的东西
- **代价**：中（要拆机接线，触控板排线/焊点）
- **风险**：低（纯监听，不驱动）
- **判断**：**直接回答项目原始问题**的最快路径

### C. BIOS `I2cTouchPanelDxe` / `GoodixTpDxe` 反汇编
- **拿什么**：固件侧初始化时序（含描述符寄存器地址、I2C 速率、复位/中断 GPIO）、固件更新的 pass-through 模式与包结构
- **代价**：低（离线，产物已在 `bios-re/`）
- **判断**：可与 A1 配合（先知道固件侧怎么写，再照做）

### D. 汇顶同族驱动/上游资料对照
- **现状**：搜到的是 **GT9xx（触摸屏）** 系列定义（16 位寄存器：`0x8040` sleep / `0x8047` config / `0x8140` version / `0x814A` sensor id / `0x814E` status；从机地址 0x5D）
- **价值**：只作**同族模板**参考（命令寄存器语义、固件更新流程、校验方式）；**不能直接套到 GT7868Q**（地址与寄存器空间都不同）
- **判断**：低，除非找到 GT78xx 专门的公开资料

### E. 厂商配置工具 record & replay
- **做什么**：找到 Goodix/Lenovo 的触控板配置或校准工具（Windows 版），抓其 HID/I2C 报文
- **代价**：取决于工具是否存在（先搜到工具再谈）
- **判断**：若有 → 价值最高（一次拿到完整命令集）

### F. 其他弱路径
- FCC/认证文档（触控板模块基本不单独认证）· Lenovo 授权服务工具（不对外）· 加密区差分（需第二份同族固件）
