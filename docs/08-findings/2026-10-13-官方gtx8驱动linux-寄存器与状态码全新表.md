## 0. 一句话

> **在本机家族的官方 Linux 驱动里，flash 结果码是：`0xAA` = 就绪/正在写、`0xBB` = 成功、`0xCC` = 错误、`0xDD` = 校验错误。**
> **而本项目当前用的是【借自 GTX9 家族】的定义：`0xAA` = 成功、`0xBB` = 校验和错误。**
> **⇒ 两套定义【方向相反】** —— 但**地址空间不同**，因此**这是"必须实机核对的高优先级判据冲突"，不是可直接套用的新结论**。

## 1. ★★★★★ 全新的 `HW_REG_*` 寄存器表（本机家族 Linux 驱动）

```c
#define HW_REG_CPU_CTRL          0x2180
#define HW_REG_DSP_MCU_POWER     0x2010
#define HW_REG_RESET             0x2184
#define HW_REG_SCRAMBLE          0x2218   /* ★★★ 解扰 */
#define HW_REG_BANK_SELECT       0x2048
#define HW_REG_ACCESS_PATCH0     0x204D   /* ★ 访问 patch0 */
#define HW_REG_EC_SRM_START      0x204F
#define HW_REG_GIO_YS            0x2014   /* YS = Yellowstone = 本机 IC 类型 */
#define HW_REG_ESD_KEY_EN        0x2318
#define HW_REG_ESD_KEY_DIS       0x2324
#define HW_REG_CPU_RUN_FROM      0x4506   /* 注释：for nor_L is 0x4006 */
#define HW_REG_CPU_RUN_FROM_YS   0x4000   /* ★★★ Yellowstone 专用的 CPU 运行来源 */
#define HW_REG_ISP_RUN_FLAG      0x6006   /* ★★★ ISP 运行标志 */
#define HW_REG_ISP_ADDR          0xC000   /* ★★★ ISP 地址 = 0xC000（= flash 缓冲） */
#define HW_REG_ISP_BUFFER        0x6100
#define HW_REG_SUBSYS_TYPE       0x6020
#define HW_REG_FLASH_FLAG        0x6022   /* ★★ flash 标志 */
#define HW_REG_CACHE             0x204B
#define HW_REG_WTD_TIMER         0x20B0
```

**★ 三条立即可用的定性**
1. ★★★ **`HW_REG_SCRAMBLE = 0x2218`** ⇒ **本项目 §「路线A①只读 `0x2218`」那条一直"只探过、未定性"的地址，现在定性了 = 解扰（scramble）寄存器**
2. ★★ **`HW_REG_ISP_ADDR = 0xC000`** ⇒ 与 `FLASH_BUFFER_ADDR = 0xC000`（`gt_update.h`）**同址** ⇒ **`0xC000` 既是 ISP 加载地址、又是 flash 缓冲** ⇒ **印证 B30（写 flash 前必须先完整覆盖 `0xC000`）**
3. ★★ **`HW_REG_CPU_RUN_FROM_YS = 0x4000`** ⇒ **Yellowstone（本机）专用的 CPU 运行来源寄存器**，且**与 gtx9_i2c 的 `0x10000` 完全不同**

## 2. ★★★★★ 全新的状态码表（**与本项目判据方向相反**）

```c
#define ISP_STAT_IDLE           0xFF
#define ISP_STAT_READY          0xAA    /* ← 0xAA = 就绪 */
#define ISP_STAT_WRITING        0xAA    /* ← 0xAA = 正在写 */
#define ISP_FLASH_SUCCESS       0xBB    /* ★★★★★ 0xBB = 成功 */
#define ISP_FLASH_ERROR         0xCC
#define ISP_FLASH_CHECK_ERROR   0xDD
#define ISP_CMD_PREPARE         0x55
#define ISP_CMD_FLASH           0xAA
```

**使用点（源码第 709–729 行，逐条）**：
```c
if (reg_val[0] == ISP_STAT_WRITING  /* 0xAA */ && reg_val[1] == ISP_STAT_WRITING) { ... }   /* 正在写 */
if (reg_val[0] == ISP_FLASH_SUCCESS /* 0xBB */ && reg_val[1] == ISP_FLASH_SUCCESS) { ... }   /* 成功 */
if (reg_val[0] == ISP_FLASH_ERROR      /* 0xCC */ && ...) { ... }
if (reg_val[0] == ISP_FLASH_CHECK_ERROR /* 0xDD */) { ... }
```
⇒ ★★ **判据是【两个字节都等于同一个值】**（`reg_val[0]` 与 `reg_val[1]`）

### 与本项目判据的冲突对照

| 值 | **本项目当前用**（借自 **GTX9/Marseille**） | **本机家族官方 Linux 驱动**（`gtx8_driver_linux`） |
|---|---|---|
| `0xAA` | **成功** | **就绪 / 正在写** |
| `0xBB` | **校验和错误** | ★ **成功** |
| `0xCC` | — | 错误 |
| `0xDD` | — | 校验错误 |
| `0xFF` | 空闲 | 空闲 ✅ |

⇒ **两套定义方向相反。**

## 3. ⚠️ 但**不能直接套用** —— 三条限制

| # | 限制 |
|---|---|
| 1 | **地址空间不同**：本文件里 **grep `0x5095` / `0x5096` = 0 次**，**`0x4160` / `0x96F8` / `0x60CC` / `0x60DC` 也都是 0 次**<br>⇒ 这份驱动用的是 `0x2010`–`0x6006` 那一组地址，**与本项目实测的地址集【又】不同** |
| 2 | 它的 flash 运行标志在 **`0x6006`（`HW_REG_ISP_RUN_FLAG`）**，而本项目读的是 **`0x5095` / `0x5096`** ⇒ **不是同一寄存器** |
| 3 | ⇒ 严格说：**「本项目 `0x5096` 的语义」仍未由这份驱动直接确认** |

⇒ ★ **所以这是"第三个家族的地址+状态集"** ⇒ **正是纪律 148 的情形（多套并存，不得跨条外推）**。

## 4. ★★★★ 用本项目【已有实测】做裁决（不碰设备）

本项目有两条关键实测可以**直接检验三套定义**：

| 实测 | 条件 | 结果 | 设备状态 |
|---|---|---|---|
| 2026-10-12 **15:25** | 写**原样** cfg 到 `0x1E000` | **`0x5096 = 0xAA`** | ✅ **完全正常** |
| 2026-10-12 **15:11** | 写 `0x19000` | `0xAA` | 🔴 退化 |
| 2026-10-10 | 写 `idx1` 第 1 块 | **`0x5096 = 0xBB`** | 🔴 退化 |

**裁决**：

| 判据集 | 15:25（正常，`0xAA`） | 10-10（退化，`0xBB`） | 与实测吻合？ |
|---|---|---|---|
| **本项目当前用**（GTX9：`0xAA`=成功 / `0xBB`=校验错） | `0xAA` = 成功 ✅ 合理 | `0xBB` = 校验错 ✅ 合理 | ✅ **吻合** |
| **gtx8 Linux 驱动**（`0xAA`=就绪写中 / `0xBB`=成功） | `0xAA` = 就绪 ⇒ **"成功"从未被确认** | `0xBB` = 成功 ⇒ **但设备退化了** | 🔴 **不吻合** |

> ### ⇒ ★★★★ **结论：三套定义里，只有"借自 GTX9 的那套"与本项目实测吻合。**
> ### ⇒ **本项目当前判据的【方向】是对的**（这一点得到加强）。
> ### ⇒ **但"为什么 gtx8 官方驱动给的是相反的定义"是一个【新问题】** ——
> ### 最可能的解释：**那份驱动的 `reg_val[0]`/`reg_val[1]` 读的是【另一个寄存器】**（`0x6006` 一路），不是本项目的 `0x5095`/`0x5096`。

⇒ **⇒ 可检验的推论（纯离线）**：若 `0x5096` 真是"派生自 `0x6006` 或同族寄存器"，则本项目此前读到的**稳定值分布**（`0x75` / `0xC8` / `0xAA` / `0xBB`）应当能在这份驱动的状态机里找到解释。**目前找不到** ⇒ **支持"两者不是同一寄存器"**。

## 6. ★★ `0xAA` 的**第四个**语义（进一步说明"不能把某个字节值当成功码"）

| 出处 | `0xAA` 的含义 |
|---|---|
| `gtx8_driver_linux/goodix_ts_core.h` | **`GOODIX_ESD_TICK_WRITE_DATA`（ESD 心跳写入值）** |
| `gtx8_driver_linux/goodix_gtx8_update.c` | `ISP_STAT_READY` / `ISP_STAT_WRITING` / `ISP_CMD_FLASH` |
| `gtx9_i2c_update.cpp` | `FLASH_CMD_TYPE_READ`（命令类型） |
| 本项目（借用 GTX9 HID） | "写成功" |

⇒ **同一个字节值在四处置含义不同** ⇒ **强化 B32 的精神：单一字节值不能作为跨上下文的成功判据。**

## 8. 新增纪律

| 条 | 内容 |
|---|---|
| **149** | **同一个字节值（如 `0xAA` / `0xBB`）在不同家族、不同通道、不同寄存器里含义可能【相反】。**<br>**判据的跨家族借用必须标注来源，并在本家族源码里寻找反证**；若本家族源码给出**相反**定义，则该判据必须**实机重新裁决**，不得沿用。 |
