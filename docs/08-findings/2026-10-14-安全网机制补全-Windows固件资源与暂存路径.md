# 安全网机制【补全】：Windows 固件资源暂存路径 = BIOS 自动重刷（2026-10-14）

> 承 §19.45（BIOS 自动重刷恢复路径）与 §20.11「B 部·前置」。
> 档案此前只知道"方向是 ESRT"；本轮把**整条链补到可执行**，并给出一个**确定性恢复原语**。
> 性质：**纯只读系统查询**（注册表 / INF / 文件哈希），零设备操作。

---

## §1 一句话

> 项目的"安全网"**不是运气**，而是**标准 Windows/UEFI 固件更新路径**：
> `Class=Firmware` 的驱动包（`goodixtouchpad.inf`）把厂商 BIN 拷到 **`%SystemRoot%\Firmware`**，
> 并在 **`HKLM\SYSTEM\CurrentControlSet\Control\FirmwareResources\{b6ae105a-…}`** 登记 {版本, 文件名}；
> **下次启动由 BIOS（`FmpDxe` + `GoodixTpDxe`）按 ESRT 资源把该镜像刷进触控板**。
> ⇒ **该路径可以【主动触发】= 一个确定性的官方恢复原语（R8）。**

---

## §2 六条新证据（全部可复核）

### 2.1 INF 原文（`C:\Windows\INF\oem87.inf` = `GoodixTouchpad.inf`，Goodix，Class=Firmware）

```ini
DriverVer=02/02/2024,0.0.2.8                     ; 与 REPRODUCE.md 记的版本一致
[Firmware.NTamd64]
%FirmwareDesc% = Firmware_Install, UEFI\RES_{b6ae105a-ba93-4fc8-aa28-e63903ffedde}   ; ★ ESRT 资源设备
[Firmware_CopyFiles]
TB14P_GT7868Q_14030522_20240202.BIN
[Firmware_AddReg]
HKR,,FirmwareId,,{b6ae105a-ba93-4fc8-aa28-e63903ffedde}
HKR,,FirmwareVersion,%REG_DWORD%,0x14030522       ; ★ 版本号字面量
HKR,,FirmwareFilename,,TB14P_GT7868Q_14030522_20240202.BIN
[DestinationDirs]
DefaultDestDir = 10,Firmware                       ; = %SystemRoot%\Firmware
```

### 2.2 注册表实况（`FirmwareResources\{b6ae105a-…}`）

| 值 | 数据 | 含义 |
|---|---|---|
| `Version` | **335742242 = `0x14030522`** | 该固件资源的版本（与 INF 字面量一致） |
| `Filename` | `TB14P_GT7868Q_14030522_20240202.BIN` | 暂存镜像名 |
| `Phase` | `2` | 资源阶段（**语义未定**，见 §6） |
| `LastAttemptVersion` | `335742242` | 上次尝试的版本 |
| **`LastAttemptStatus`** | **`0`** | ★ **上次刷写【成功】**（= §19.45 那次恢复留下的痕迹） |

### 2.3 暂存目录实况（`%SystemRoot%\Firmware`）

```
TB14P_GT7868Q_14030522_20240202.BIN                    161,628 B   ← FILE（触控板镜像，时间戳 = 2024-02-02）
{652d4eee-b41c-4809-80e7-ef22561db51e}\5B11M67497.CAP   2,113,472 B ← FILE（★ 另一台设备：见 §2.7）
```

### 2.7 ★ ESRT 资源全景（本机共 **11** 条 `UEFI\RES_*`）

| ESRT 资源 GUID | `FriendlyName` | 备注 |
|---|---|---|
| **`{B6AE105A-BA93-4FC8-AA28-E63903FFEDDE}`** | **Goodix Update UEFI** | ★ **触控板固件资源**（本项目关注的那条） |
| `{652D4EEE-B41C-4809-80E7-EF22561DB51E}` | **Lenovo Battery Firmware 258.5** | 上面那个 2.1 MB `.CAP` 属于它（`oem88.inf` = `5b11m67497.inf`，`FirmwareVersion = 0x01020005`） |
| `{6B791D8C-9286-4800-91D9-929DC2F23053}` | **系统固件** | = **BIOS**（与项目 §10.7.2 的 ESRT 分析同源） |
| 另 8 条 | 「设备固件」 | `{3B8A509D…}` `{C725E332…}` `{E196AD37…}` `{A9898AFA…}` `{993BD1CE…}` `{F224E838…}` `{B9C68CC2…}` `{978B4CEA…}` |

⇒ **这张表就是 `FmpDxe` 构建/维护的 ESRT**（§10.7.2 的结论在此得到**运行期实况**印证：Type=2 设备固件、每条一个资源）。
⇒ 也说明**只有触控板这条被 Windows 驱动包暂存过**（`FirmwareResources` 下**只有** `{b6ae105a-…}` 一个键）。

### 2.4 ★ 负载哈希：与项目逆向的那份**完全一致**

| 位置 | sha256 |
|---|---|
| `%SystemRoot%\Firmware\TB14P_GT7868Q_14030522_20240202.BIN` | **`0033d075fae88f0048544696c8941ed7dcca4269beaa84af76323ef5bbdcee72`** |
| `DriverStore\FileRepository\goodixtouchpad.inf_amd64_dd57a59bc9759d61\…BIN` | **`0033d075…`（同）** |

⇒ **安全网刷的就是 §2.1 里那份 161,628 B 的镜像** —— 也就是项目全书 §2.1 / REPRODUCE P0 采集、并被完整逆向（容器 + K 加扰 + TF100A 明文）的**同一份字节**。
⇒ 因此：**项目的逆向结论可直接用于"安全网会写什么"的预测**（例如 `0x1E000` cfg 区、TF100A 段位置），这解释了为什么 §19.45 的恢复是"逐字节回到基线"。

### 2.5 权限（决定 R8 可行性）

| 主体 | 权限 |
|---|---|
| `BUILTIN\Administrators` | **FullControl**（可写） |
| `NT AUTHORITY\SYSTEM` | FullControl |
| `BUILTIN\Users` | **ReadKey**（只读） |

⇒ **R8（主动重暂存）需要管理员**；只读复现任何人都能做。

### 2.6 ESRT 本身的读取

`GetFirmwareEnvironmentVariable("ESRT", …)` 返回 **0 / err=1314（ERROR_PRIVILEGE_NOT_HELD）** ⇒ **需管理员 + `SeSystemEnvironmentPrivilege`** 才能直读 UEFI ESRT 变量（本轮未提权，故未读）。

## §4 ★ 可执行的恢复原语 **R8**（建议并入 `docs/09-safety/RECOVERY.md`）

> **前提**：仅用于**恢复**（把设备刷回官方镜像），**不是**改固件的通道。
> **需要管理员**。执行前先读 RED-LINES 与 R1–R7。

```powershell
# R8：主动重暂存官方固件 ⇒ 下次启动由 BIOS 重刷（确定性的"安全网"）
# 1) 确认镜像在位且哈希正确（应 = 0033d075…）
$bin = "$env:SystemRoot\Firmware\TB14P_GT7868Q_14030522_20240202.BIN"
Get-FileHash $bin -Algorithm SHA256
#    若缺失：从驱动包取回（不要用其它来源的镜像）
$pkg = (Get-ChildItem "$env:SystemRoot\System32\DriverStore\FileRepository" -Directory -Filter "goodixtouchpad.inf_amd64_*" | Select-Object -First 1).FullName
Copy-Item "$pkg\TB14P_GT7868Q_14030522_20240202.BIN" "$env:SystemRoot\Firmware\" -Force
# 2) 确认固件资源键（版本 0x14030522 / 文件名一致）
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\FirmwareResources\{b6ae105a-ba93-4fc8-aa28-e63903ffedde}"
# 3) 重启 ⇒ BIOS 在启动阶段对比并重刷（会看到"类似升级 BIOS 的界面"）
# 4) 恢复后核验（只读）：0x96F8[0:5] = 22 01 1B 00 3E · 0x5096 = 75 · 点按震/滑动正常
```

| 判据 | 期望 |
|---|---|
| 刷写成功 | `FirmwareResources\{…}\LastAttemptVersion = 0x14030522` 且 `LastAttemptStatus = 0` |
| 设备恢复 | `0x96F8[0:5] = 22 01 1B 00 3E`（基线，见 §19.45.1 的恢复后实测表） |
| ⚠️ 失败面 | 若镜像不在位/版本键损坏 ⇒ BIOS **不会**触发 ⇒ 仍需 R1–R4（重启/断电/EC reset） |

## §5 对"触发条件"的收窄（本轮结论）

1. **机制**：Windows 暂存 + BIOS 下次启动应用（ESRT 资源 + 版本比对），**与 `FmpDxe` = ESRT 构建器这一既有结论闭环**。
2. **版本**：资源侧版本 = **`0x14030522`**；`LastAttemptStatus = 0` 说明**至少成功刷过一次**（与 2026-10-11 的恢复吻合）。
3. **子系统**：按 REPRODUCE.md 的 `GTPCheckTFUpdate`，**TP（主控）与 TF（力芯片）分别比对版本、分别刷写** ⇒
   ⇒ ★ **"写坏 TF100A" 这类操作若要靠安全网恢复，必须先让 TF 的版本字段变化**（§19.45.3 的警告由此获得机制解释）。
4. **对实验安全性的意义**：`0E 12` 写坏的是 **TP 侧 cfg/flash** ⇒ 属于该路径覆盖范围 ⇒ 安全网**大概率有效**；
   但**不能**把"安全网存在"当成"改 TF 固件的许可"。
