# 二、★ 根本性混淆（4 处，这是乱的根源）

## 混淆 1 ★★★★★ **TF100A 与 GT7868Q 的命令表被混为一谈**

| | **TF100A**（钛方压力 MCU） | **GT7868Q**（汇顶触控主控） |
|---|---|---|
| 明文固件 | ✅ 全明文（54 KB / 20,314 行） | ❌ 主体高熵 |
| **内部分派器地址** | **`0x0800E1C0`** | **`0x22C7C`** |
| **类结构** | **`0x80` ×1 · `0xA0` ×16 · `0xA1` ×22** | **16 条命令号 `0x0100`–`0x3500`** |
| **「39 条命令」** | ★ **就是这个**（1+16+22 = 39） | ❌ 不是它 |
| 链路 | I²C1 从机 `0x2C` | 主机 |

**★ 证据：两份固件里的命令号完全一致**
```
0x0100  0x0500  0x0B00  0x0D00  0x0E00  0x1100  0x1200  0x1400
0x1700  0x1F00  0x2000  0x2400  0x2600  0x3200  0x3300  0x3500   ← 16 条
```
- TF100A 侧：`COL04-BOUNDARY.md` §2.2 的 16 条表
- GT7868Q 侧：`ROUND23` §3.2 的 16 条表
⇒ **两条工作线各自解出同一张表，却以为是两个器件各自的命令表。**

**★ 真相（我的判断，需验证）**：
> 这 **16 条命令是 TF100A 的内部命令空间**；
> **GT7868Q 固件在 `0x22C7C` 也有一份，说明 GT7868Q 是把同一条 I²C 帧转发给 TF100A 的"中继"**
> ⇒ 主机发到 GT7868Q 的命令，**本质上是发给 TF100A 的**。

**★ 影响**：所有"GT7868Q 有 16 条命令"的表述都应改为"**TF100A 的 16 条命令，GT7868Q 侧有一份中继副本**"。

## 混淆 4 ★★★ **`0xA2` 是"同步应答"还是"异步产物"**

| 文档 | 说法 |
|---|---|
| `COL04-BOUNDARY.md` §2.4 | 「`0xA2` 是**回复类**，固件自己发，主机禁发」（暗示：发命令 → 收 `A2`） |
| `H1修正-主循环状态机与A2异步应答.md` | ★★★ **`0xA2` 是主循环状态机的异步产物，不是命令的同步应答** |
| `追加八` / `追加九` | 「发 `A1` 帧后未收到 `0xA2` ⇒ H1 否」 |

**★ `H1修正` 那份是**后出且更硬**的**（有完整主循环反汇编 + 模式字节机制）：
```
主循环：先跑分发器 → 再依次调三个模式处理器（各自按模式字节自证身份）
0xA2 在【模式 3 处理器】里产生：
    清 armed → 紧接着 movs r0,#0xA2 开始构造回复
而 A0/0x0D00 设的是【模式 4】⇒ 路径不对 ⇒ 当然收不到 A2
```
⇒ **「未收到 `A2`」不能证明设备拒绝**。**H1 判否的验收方式已被推翻。**

⚠️ 但 `追加八`/`追加九` **仍在用这个验收方式**，且 `docs-触控板/00-触控板结论总表.md` 也保留了"H1 实测判否"。

## 矛盾 1 ★★★★★ **"Linux 能任意读写触控板寄存器"** —— 被当作结论，但依据是错的

| 文档 | 说法 |
|---|---|
| `goodix-tool/ROUND61-67` §8 方案 A | 「依据 `github.com/ty2/goodix-gt7868q-linux-driver`……**Linux 的 `i2c-hid` 完整透传 GET/SET_FEATURE**（不像 Windows 会拦截）」
「装上该内核模块后，`hid-multitouch` 接管设备，**hidraw 节点可用**」
「官方工具 `gdixupdate -d /dev/hidrawX` 可直接跑，**我们能自己发 `_I2C_DIRECT_RW` 读写参数区**」 |
| `goodix-tool/00-★交接文档` 决策 3 | 「Linux 的 `i2c-hid` **完整透传**」 |

**★ 但 `ty2/goodix-gt7868q-linux-driver` 全仓库只有 1,663 字节**：
```c
static const __u8 *goodix_gt7868q_report_fixup(...)
{ if (rdesc[607] == 0x15) { rdesc[607] = 0x25; } return rdesc; }
```
- 它是 **`hid-multitouch` 的一个 report descriptor 修补**（改 1 个字节）
- **不是 I²C 驱动、不碰寄存器、不做任何总线透传**
- `local-overrides.quirks` 全文也只有 `AttrPressureRange=2:0` + 掌压阈值

**★ 而且这个说法本身有内部矛盾**：
```
「i2c-hid 完整透传 GET/SET_FEATURE」
  ⟷ 同时又说「需要装 ty2 那个内核模块」
如果 i2c-hid 本身就透传，为什么还需要第三方模块？
```

**★ 真实状态**（本项目实测）：
- **Linux 下触控板完全不能用**（指针不动）⇒ 说明 Linux 侧驱动**没工作**
- 但**点按照样震动** ⇒ 震动与主机通信无关

⇒ **「Linux 是出路」这条判断，其依据（ty2 驱动 + i2c-hid 透传）站不住。**
⚠️ **这条如果不修正，会直接导致"装个 Linux 就能读写参数区"的错误行动。**

| # | 名称 | 出处 | 条数 | 层 |

| 3 | **GT7868Q 官方命令集** | `CMD_ADDR 0x4160` | **约 10 条**（`0x32/0x33/0x34/0x80/0x83/0x7D` + `00 10`/`00 11`/`0E 13`/`0E 12`） | 主机↔器件 |

## 矛盾 5 ★★★ **分区表编码：官方定义 vs 我们解出的** ✅ **已在第四轮实测裁定（见文末附录四）**

## 新增矛盾 1 ★★★★ **`5A A5` 同步字被两份文档判给了不同芯片**（真矛盾）

### 双方说法

| 出处 | 说法 |
|---|---|
| `touchpad-lab\COL04-BOUNDARY.md` | 「窗口里没有任何可读的方案字符串：**`5A A5`（TF100A 发送帧同步字）0 处**」 |
| `goodix-tool\ROUND23`（已归档） | 「主机报文协议：**`5A A5` 魔数** + 类型 + 长度 + CRC-8，入口 GT7868Q 的 `0x1ACEC`」 |

### ★ 判定：**ROUND23 对，COL04-BOUNDARY 那句归属写错了**

**证据（ROUND23 的逐指令反汇编，地址在 GT7868Q 固件里）**
```asm
0x1AD5C  cmp r0,#0x5a      ; 魔数低字节 == 0x5A
0x1AD6C  cmp r0,#0xa5      ; 魔数高字节 == 0xA5
0x1AD28  rsb r0,r0,r0,lsl #8  ; 长度大端合成
0x1B6E0  bl → CRC-8（多项式 0xA1）
```
⇒ `5A A5` 是 **GT7868Q 的【主机 → 触控主控】报文魔数**，**不是 TF100A 发送帧的同步字**。

### ⇒ 正确的分层

| 协议 | 魔数 / 帧头 | 谁跟谁说话 |
|---|---|---|
| **GT7868Q 主机报文** | **`5A A5`** + 类型 + 长度 + CRC-8（poly `0xA1`） | **主机 → GT7868Q** |
| **TF100A 帧** | `[class][b1][b2][sub_lo][sub_hi][payload]`（**5 B 头，小端，无魔数**） | GT7868Q → TF100A（I²C1） |

### ★ 为什么这条重要

**它会直接改变一个结论的解读**：
- 若 `5A A5` = TF100A 的同步字 ⇒ "窗口里 0 处命中" ⇒ **TF100A 不向主机发帧**（当时很可能就是这么推的）
- 真相：`5A A5` 属 GT7868Q 主机层 ⇒ **"窗口里 0 处命中"只能说明"那个 40KB 窗口里没有 GT7868Q 主机报文"，跟 TF100A 无关**

⚠️ **需要重新确认的推论**：凡是用"`5A A5` 0 命中"来论证"**TF100A 与主机之间没有通路**"的地方，论证依据都不成立（**结论本身可能仍然对，但依据要换**）。

## 新增矛盾 6 ★★★ **GT7868Q 的 I²C 从地址：`1` 还是 `0x2C`**

### 双方说法

| 出处 | 说法 |
|---|---|
| `ANGLES-2026-09-28-其他角度评估.md` §60 | 「按其寄存器……以 **从机地址 0x2C** 直接读写**触控板**寄存器」 |
| `DELTA-2026-09-29d` §135 | 「命中第 4 条 → **地址 0x2C** · 描述符寄存器 0x20 · HID "GXTP5100"」 |
| `DELTA-2026-09-28p` §81 | 「GT7868Q ↔ TF100A 的链路 = I²C1（**TF100A 作从机，地址 0x2C**）」 |
| **全书 / 统一入口 / 全景报告** | GT7868Q 主机侧从地址 = **`1`**（ACPI `_ADR` 权威） |

### ★ 判定：**两条总线，两个地址，不矛盾 —— 但表述必须分清**

```
主机 ──[I²C0, 从地址 = 1]──▶ GT7868Q（触控主控）
GT7868Q ──[I²C1, 从机 0x2C]──▶ TF100A（压力 MCU）
```

| 地址 | 属于哪条总线 | 权威来源 |
|---|---|---|
| **`1`** | **主机 ↔ GT7868Q** | ACPI `_ADR` / SPB 连接资源 |
| **`0x2C`** | **GT7868Q ↔ TF100A** | TF100A 固件 `OAR1 = 0x58` ⇒ `0x58>>1 = 0x2C`；DSDT `TPID` 表第 4 行也是 `0x2C` |

### ⚠️ 但有一处**确实错了**

`ANGLES-2026-09-28` §60 说「**以从机地址 0x2C 直接读写触控板寄存器**」——
这是**把 `TPID` 表的默认值当成了主机侧的实际运行地址**。
⇒ **主机侧要用 `1`**（ACPI `_ADR` 权威）；用 `0x2C` 会打不到。
⇒ **`0x2C` 是 `TPID` 表里 Goodix 的【默认值】，不是本机 ACPI 实际下发的地址。**

## 四、本轮方法学沉淀

### 4.1 **先哈希去重，再谈矛盾**

```
错误做法：直接读文档找矛盾 → 会在重复副本上浪费大量时间，且误判"两份说法不同"
正确做法：先 MD5 去重 → 只对【唯一内容】做矛盾分析
```
**本轮 19 对重复 = 一份内容被当成两份读了 19 次。**

### 4.2 **"含错误关键词"不能作为"需要更正"的判据**

因为**反驳错误的文档必然包含错误关键词**。
**正确判据 = 顶部有无自我声明。**

### 4.3 **重复是矛盾的温床**

```
同一内容存两份
  → 只改了其中一份
  → 两份开始分叉
  → 变成"矛盾"
```
⇒ **去重不是整洁问题，是防止未来产生矛盾的机制。**（本项目已出现过疑似案例：两份 `追加二十四`）

### 4.4 **"多权威"的具体形态**

| 形态 | 本项目的实例 |
|---|---|
| 多份自称权威 | 4 份都叫"先读这一份" |
| 同名文件跨工区 | 2 份 `00-★交接文档` |
| 同内容多文件名 | 19 对 `追加N` ↔ `DELTA-*` |
| 编号无语义 | `追加八`–`追加三十七`、`DELTA-2026-09-28a`–`z` |

⇒ 四者叠加 ⇒ 206 份 md 里有近 40% 是冗余或重名。

## 一、★★★ 裁定：分区表编码（矛盾 5 结案）

### 1.1 长期有三种说法

| 出处 | 编码 |
|---|---|
| `ROUND60`（官方源码 `gt7868q_update.cpp`） | `type(1B)` + `len(4B 大端)` + `addr(2B 大端) << 8`，每条 8 B |
| `ROUND24`（我们静态解出） | `addr(2B BE) << 8` + `type(1)` + `pad(1)` + `len(2B BE) << 8` + `pad(2)` |
| `追加二十三`（老线） | `type(u8)` + `size(u32 BE)` + `flash_addr(u32 BE 绝对)`，每条 8 B |
| `ROUND60` §1.2 自评 | 「**与 ROUND24 我们的结论一字不差**」← 😑 明显没逐字节对照 |

### 1.2 实测裁定（用本机固件 `TB14P_...BIN`）

**表起点**：`YELSTO @0x1142` ⇒ 表在 **`0x1164`**（= `YELSTO + 0x22`）

**原始字节（前 3 条）**
```
03 00 00 20 00 01 60 00
03 00 00 20 00 00 60 00
03 00 00 20 00 00 80 00
```

**三种假设的解读对比**

| 假设 | #0 解出 | 判定 |
|---|---|---|
| **[A] 官方源码**（type / len4BE / addr2BE<<8） | `type=0x03 len=0x2000 addr=0x016000` | ✅ **全部自洽** |
| **[B] ROUND24**（addr2BE<<8 / type / pad / len2BE<<8 / pad2） | `type=0x00 len=0x0100 addr=0x030000` | ❌ **#1–#4 解出 len=0 与 type=0x00** ⇒ **不成立** |
| **[C] 追加二十三**（type / size4BE / addr4BE 绝对） | `type=0x03 size=0x2000 addr=0x00016000` | ✅ **与 [A] 同值** |

### 1.3 ★ 结论：**[A] 与 [C] 是同一个格式的两种读法**

```
字节布局（8 B/条）:
  [0]     type
  [1..4]  len   大端 32 位
  [5..6]  addr  大端 16 位（高 16 位）
  [7]     恒 0x00（addr 的低 8 位）

[A]  官方源码：len = u32be(bytes[1..4])
[C]  追加二十三：size = u32be(bytes[1..4]);  addr = u32be(bytes[4..7])
```

**⇒ 对 len < 0x10000 的情况，[A] 与 [C] 完全等价**（因为 `bytes[3]=0x00`，且 `addr` 高字节也正好是 0x00）。
**⇒ `addr = u32be(bytes[4..7])` 之所以能对，是因为 `bytes[4]=0x00` 恰好落在 `addr` 的高 8 位**（而真实 addr 是 16 位）——这是**巧合性的等价**。

**★ 唯一能区分 [A] 与 [C] 的情形**：某条记录的 `len` 低 16 位 ≠ 0 且高 16 位 ≠ 0（即 `len > 0xFFFF`），
此时 `[A]` 的 `len` 与 `[C]` 的 `size` 仍相同，但 `[C]` 的 `addr` 会把 `len` 的高字节混进地址。
⇒ **本机表所有记录 `len ∈ {0x1000, 0x2000, 0x3000}`** ⇒ **无法区分 [A] 与 [C]，但两者都能用。**

**[B]（ROUND24）确定作废。**

### 1.4 ⇒ 结案表述（建议统一口径）

```
Goodix GT7868Q 子固件表（每条 8 字节）：
  byte[0]      = type          （0x01 / 0x02 / 0x03）
  byte[1..4]   = length，大端 32 位
  byte[5..6]   = flash_addr 的高 16 位，大端
  byte[7]      = 恒 0x00（flash_addr 的低 8 位）

换算：subsys_base_addr = flash_addr << 8
表位置：本机 YELSTO + 0x22 = 0x1164；条目以全零结束

★ 兼容读法（与官方源码等价，但不严谨）：
   也可读成 type(1) + size(4BE) + addr(4BE) —— 结果相同，
   因为 addr 高字节位置恰好为 0x00。
```

**本机解出的 12 条（与 `追加二十三` 一致）**：type 全为 `0x03`/`0x02`，addr ∈ {`0x00000`,`0x01000`,`0x04000`,`0x06000`,`0x08000`,`0x0A000`,`0x0C000`,`0x0E000`?,`0x10000`,`0x12000`,`0x13000`,`0x16000`,`0x1E000`}，len ∈ {`0x1000`,`0x2000`,`0x3000`}

## 四、本轮方法学沉淀

### 4.1 **矛盾要"裁定"，不是"折中"**

本轮对分区表编码没有和稀泥，而是**拿原始 BIN 用三种假设各解一遍，看哪个自洽**。
结果：**[A]/[C] 对、[B] 错** —— 而且顺手发现 **[A] 与 [C] 是同一格式的两种读法**。

⇒ **纪律**：遇到"两份文档说法不同"，**优先找原始数据实测**，而不是在文档间投票。

### 4.2 **"未闭合"不等于"矛盾"**

```
矛盾   = 有相反说法        ⇒ 必须裁定谁对
未闭合 = 没有说法 / 只有一种 ⇒ 是缺口，不是冲突
```
把两者混在一起统计，会把"已知未知"误报成"项目混乱"。
**本项目：矛盾 18 处（全裁定）；缺口约 15 项（不是矛盾）。**

### 4.3 **"自评一致"要警惕**

`ROUND60` 自己写「与 ROUND24 我们的结论**一字不差**」，
但**逐字节一解就发现 ROUND24 的假设解不通**。
⇒ **"我核对过了"这句话本身不是证据；只有可复现的字节对照才是。**
