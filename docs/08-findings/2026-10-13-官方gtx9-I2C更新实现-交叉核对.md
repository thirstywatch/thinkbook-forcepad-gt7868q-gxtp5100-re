## 1. ★★★★★ 官方"裸 I²C 模式"的完整寄存器地图（`gtx9_i2c_update.cpp`）

```c
#define CLIENT_ADDR 0x5D              /* ★ 裸 I²C 模式的从地址，他从未扫过 */
#define TS_ADDR_LENGTH 4              /* ★ 4 字节寄存器地址（大端） */
#define I2C_MAX_TRANSFER_SIZE 256
```

| 地址 | 操作 | 含义（源码注释为准） |
|---|---|---|
| **`0x3030AABB`** | w 1 B = **`0xCC`** | ★★★ **`switch_i2c_mode()` —— 切换 I²C 模式** |
| `0xD808` | w 1 B = 0 | 软复位（`gdix_soft_reset`） |
| `0xD80B` / `0xD054` | w 1 B | 未注 |
| **`0x10014`** | r | **固件版本块**（自带 U8LE 校验，含 `rom_pid[6]`+`patch_pid[8]`） |
| **`0x10000`** | **w 8 B = `0x55`×8** | ★★★ **注释：`SET BOOT OPTION TO 0X55` / 日志：`Failed set REG_CPU_RUN_FROM flag`** ⇒ **CPU 运行来源（ROM↔Patch）** |
| `0x2000` | r 4 B ×3 | 轮询忙/状态 |
| `0x0002` | w 2 B | 未注 |
| **`0x57000`** | w(ISP) | ★★★ **ISP 程序加载地址** |
| **`0x13400`** | **r/w 16 B** | ★★★ **flash 命令/状态寄存器** |
| **`0x13410`** | w(pkg) | ★★★ **flash 数据寄存器** |

**I²C 传输范式**：`i2c_read/reg` = 4 字节大端地址 + 重复起始读；每块 ≤256；`i2c_write` = 4 字节地址 + 数据（≤252）

## 2. ★★★★★ `gdix_load_isp()` —— "让芯片从 ISP 运行"的官方 4 步 + 权威判据

```
① i2c_write(0x57000, subsys[0].data, subsys[0].size);        // 写 ISP 程序
② reg_val[8] 全填 0x55 ; i2c_write(0x10000, reg_val, 8);     // ★ SET BOOT OPTION / REG_CPU_RUN_FROM
③ gdix_soft_reset(100);                                     // 0xD808 ← 0，等 100 ms
④ gdix_read_version(&v);                                    // 读 0x10014
   if (memcmp(&v.patch_pid[3], "ISP", 3)) → 失败            // ★★★ 权威判据
   GDIX_INFO("ISP running successfully");
```

**★ 三条推论**
- **`subsys[0]` = ISP 程序** ✅ 与他 §19.13.2 的结论一致
- ★★ **这正面证实「ROM + Patch 双段架构」**：`goodix_fw_version` 里 `rom_pid[6]` 与 `patch_pid[8]` **并列**；`0x10000` 那个标志决定 CPU 从哪一段运行
- ★★ **"进 bootloader"有了第二条独立判据**：他（HID 侧）= `0x5095 == 0xDD`；**官方（I²C 侧）= `patch_pid[3..5] == "ISP"`** ⇒ 可互证

## 3. ★★★★ flash 命令的**双字段成功判据 + 4 种失败分类**（`gdix_send_flash_cmd`）

```c
struct goodix_flash_cmd {   /* 16 B */
    u8 status; u8 ack; u8 len; u8 cmd; u8 fw_type; u16 fw_len; u32 fw_addr;
};
/* 收发：i2c_write(0x13400, cmd, 16) → 轮询 i2c_read(0x13400, 16) */
成功 ⇔ ack == 0xEE (FLASH_CMD_ACK_CHK_PASS)  &&  status == 0xEE (FLASH_CMD_W_STATUS_WRITE_OK)
失败分类：
  status 0x22 = CHK_PASS               （"data check pass, but failed get follow-up results"）
  status 0x33 = CHK_FAIL               （"data check failed, please retry"）
  status 0x44 = ADDR_ERR               （"flash target addr error, please check"）
  status 0x55 = WRITE_ERR              （"flash data write err, please retry"）
```

- **`ack` 与 `status` 是两个独立字段**，前者=命令帧校验结果，后者=flash 层结果
- ★★★ **"地址错"有专门码 `0x44`** ⇒ 他写 `0x19000` 时 HID 侧只回 `0xAA`（他记为"被接受"），
  **很可能设备内部是 `0x44`，而 HID 通道没有把 flash 层 status 报回来**

## 4. ★★★★ 分块与校验（直接对应他的 B30）

```c
#define ISP_MAX_BUFFERSIZE 4096
data_size = min(total_size, 4096);
gdix_append_checksum(fw_packet, data_size, CHECKSUM_MODE_U16_LE);   // 追加 4 B
gdix_flash_package(type, fw_packet, addr + offset, data_size + 4);  // 包长 = data + 4
/* 失败重发同一包：retry = 2 */
```
`gdix_append_checksum`：**U8_LE** ⇒ 前 n 字节和（&0xFFFF）小端存 2 B；**U16_LE** ⇒ 16 位小端字和存 **4 B**

⇒ ✅ **B30（unitlen 必须 4096）被官方确认**；★ 新增：**每包追加 4 B u16LE 字和，包长 = data + 4**
⇒ ⚠️ **注意方向**：HID 通道（gtx8/gt7868q）实测用 **u16BE** 字和（`0xF44E`）；这份 I²C 版用 **u16LE** —— **两通道不同，别混**

## 5. ★★★★ 判据核对结果（**我一度差点判错，靠核对家族源码救回来**）

**`0xAA` / `0xBB` 的语义 —— 跨家族核对：**

| 家族/文件 | 有没有 `0xAA`/`0xBB`/`0xCC` 判据 |
|---|---|
| **`gtx8_update.cpp`** / **`gt7868q_update.cpp`** / **`gtx3_update.cpp`**（**他的家族**） | 🔴 **完全没有**（它们是**位标志** `NEED_UPDATE_FW` / `NEED_UPDATE_CONFIG` / `NEED_UPDATE_CONFIG_WITH_ISP`） |
| `gtx9_update.cpp` / `marsei_update.cpp`（GTX9/Marseille，**HID 版**） | ✅ 有，且 **`} else if (ret == 1 && flag == 0xBB) { //checksum error`** ← **官方原文注释** |
| `gtx9_i2c_update.cpp`（GTX9，**I²C 版**） | ✅ 有，但**语义不同**：`FLASH_CMD_TYPE_READ = 0xAA` / `FLASH_CMD_TYPE_WRITE = 0xBB` = **命令类型** |

**⇒ 裁定**：
- ✅ **他"`0xBB` = 校验和错误"的方向是对的**，**有官方注释支撑**
- ⚠️ **但那条注释出自 GTX9/Marseille，不是他的 gtx8/gt7868q** ⇒
  **登记时应降级标注为「借用 GTX9 家族定义，未经本机家族源码确认」**（同登记表 B13 的"需按项分辨"情形）
- ★ **同时发现一个事实**：**同一颗 GTX9 的两条通道（HID vs I²C）状态语义不同** —— HID 里 `0xBB`=checksum error，I²C 里 `0xBB`=WRITE 命令类型

## 8. 对"写固件 / 硬件分析对主机控制有帮助吗"的最终回答

| 问题 | 答案 |
|---|---|
| **写固件** | ★ **它是唯一能创造主机入口的路**；本轮**新增一条从未考虑过的子路**：**如果 GT7868Q 同族有"切 I²C 模式"命令，主机就能把芯片切到裸 I²C，然后用 4 字节地址直接读写 `0x13400`/`0x13410` 发 flash 命令，完全绕开 HID** |
| **硬件分析** | ⚠️ **对主机控制几乎无帮助**。**chip-off 也不适用**（见下） |
| ★★ **chip-off 为什么不算** | 官方明确：**8 位核的小设备，CPU/RAM/Flash 常在同一 die 上，且有 code lock**（`ianhowson` 原文）。**GT7868Q = Turbo51（8 位核）⇒ 极可能是 SoC 单 die ⇒ 没有独立 flash 芯片可拆** |
| **代码在哪（仍是前提）** | 判法不变：进 BL + `0x20` 扫地址空间。**但本轮新增一条判据**：若能从 I²C 侧读到 `0x10014` 的 `rom_pid`/`patch_pid`，可**直接看 ROM 与 Patch 两段的版本** |
