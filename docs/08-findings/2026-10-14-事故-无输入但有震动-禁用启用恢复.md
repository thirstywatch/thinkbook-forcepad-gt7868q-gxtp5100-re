# 事故与恢复：【无输入但按压有震动】—— 判为**输入路径**问题，**禁用→启用**即恢复（2026-10-14）

> 性质：**1 次提权设备重启（诱因）+ 只读抓签名 + 1 次提权禁用/启用（恢复）**。用户全程在场并确认结果。
> 关联：§19.74（提权重枚举实验）· RECOVERY §1 手段 2b/2c · 退化签名表（RECOVERY §2b）。

---

## §1 时间线（真实事故）

| 时刻 | 事件 | 结果 |
|---|---|---|
| T0 | 提权执行 `pnputil /restart-device "ACPI\GXTP5100\1"`（§19.74 的实验） | 退出码 0，「已成功重启设备」；5 节点 `Status=OK` |
| T1 | **用户报告：触控板无法对电脑进行任何输入，但按压有震动** | ⚠️ 设备「看起来健康」但**输入不通** |
| T2 | **立即只读抓退化签名**（见 §2） | **不符合退化签名表** ⇒ 不是固化退化 |
| T3 | 提权 `Disable-PnpDevice` → 等 3 s → `Enable-PnpDevice`（`ACPI\GXTP5100\1`） | 禁用 OK · 启用 OK · 5 节点仍 `OK/CM_PROB_NONE` |
| T4 | **用户确认：已恢复**（正常输入） | ✅ 恢复成功（**未重启电脑**） |

## §3 三条新结论

### 3.1 「无输入但按压有震动」**不等于**固化退化

退化判据**只看** `0x96F8`（`22 01 11…` vs `22 01 1B…`）＋ `0x5096`（`AA/BB` vs `75`）＋ 用户实测（RECOVERY §2b）。
本例两项**都是正常值** ⇒ 归类为 **HID/输入路径未起来**，属**可逆、无需刷固件**的一类。
> ★ 这也解释了为什么"按压有震动"不能当好消息：**震动走 TF100A/执行器，输入走 IC→Col01/02**，两条路是分开的。

### 3.2 ★ 新增恢复手段 **2c：禁用 → 启用**（本轮实测有效）

| 手段 | 本轮效果 |
|---|---|
| `pnputil /restart-device`（2b） | 是**诱因**（T0 之后出现症状）；**未能自愈** |
| **`Disable-PnpDevice` → `Enable-PnpDevice`（2c）** | ✅ **恢复成功**（T3→T4，**未重启电脑**） |
| 完整重启（手段 1） | 未使用（档案记录为"已实测有效"的首选） |

⇒ **`restart-device` 与 `disable/enable` 看似同类，实测效果不同** ⇒ 遇"无输入"先试 **2c**，再考虑重启。

### 3.3 ★ 纪律 **167**

**`Status=OK` / `CM_PROB_NONE` 不能作为「输入可用」的判据** —— 重枚举/电源循环类操作之后**必须让用户实测输入**（或验证输入报表流）。
本例 T0 时设备树**全绿**，但输入已死 ⇒ 只信设备树会漏判。

> **注（进制）**：PowerShell 把该属性渲染为**十六进制数字串** —— 判据：触控板这条 `14030522` 与 `workbuddy` 里 `goodixtouchpad.inf` 的 `FirmwareVersion = 0x14030522` **逐字符相同**。
> 因此上表各值应读作 `0x14030522` / `0x72595067` / `0x1020005` / `0x1131A` / `0xAA4` / `0x267` / `0xCF` / `0x1`。
★ **触控板条目 = `14030522` = `0x14030522`** ⇒ 与 §19.66 的 `FirmwareResources\{b6ae105a-…}\Version` **完全一致**（两个独立来源互证）。

**⚠️ ESRT UEFI 变量直读失败（提权后仍失败）**：`GetFirmwareEnvironmentVariable("ESRT", …)` → `0` 字节、`GetLastError = 1314`（`ERROR_PRIVILEGE_NOT_HELD`）。
⇒ **光提权不够**：该 API 还要求**显式启用 `SeSystemEnvironmentPrivilege`**（`AdjustTokenPrivileges`）。
⇒ 因此**本轮改用 PnP 属性路线**（零提权、零写入）拿到上表；**原始 ESRT 表**若要拿，需按上述方式启用特权（记为 **A#47**，非必需）。
