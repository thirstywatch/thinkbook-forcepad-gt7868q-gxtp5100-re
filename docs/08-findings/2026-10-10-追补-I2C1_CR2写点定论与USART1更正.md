## 1. ★★★★★ `I2C_Init@0800FA6C` 到底写了 CR2 的哪几位

### 1.1 写入方式：读-改-写，只动低 6 位

```
0800FA52  ldr  r0, [sp, #0x1c]    ; r0 = arg0 = I2C1 基址 0x40005400
0800FA54  ldr  r0, [r0, #4]       ; ★ 读 CR2 (base+0x04)
0800FA5A  bic  r0, r0, #0x3f      ; ★ 清【低 6 位】
0800FA64  orrs r0, r1             ; ★ 只把 r1 的值 OR 进低 6 位
0800FA6C  str  r0, [r1, #4]       ; ★ 写回 CR2
```

**STM32F1 的 `I2C_CR2` 位定义**：
| 位 | 名称 | 本次是否被改 |
|---|---|---|
| `[5:0]` | **`FREQ`**（APB1 时钟 MHz，范围 2..36） | ✅ **就是它被改** |
| `[7:6]` | 保留 | ❌ 原样 |
| `[8]` | **`ITERREN`**（错误中断使能） | ❌ **原样保留** |
| `[9]` | **`ITEVTEN`**（事件中断使能） | ❌ **原样保留** |
| `[10]` | **`ITBUFEN`**（缓冲中断使能） | ❌ **原样保留** |
| `[11]` | `DMAEN` | ❌ 原样 |
| `[12]` | `LAST` | ❌ 原样 |

**⇒ `I2C_Init` 只设 `FREQ`，对三个中断使能位【完全不碰】。**

### 1.2 全镜像唯一的 `set_bit` 调用 —— 就是它置了 `ITEVTEN`

先厘清 helper 族（三个都在 `0x0800FC20`–`0x0800FCA0`）：

| 地址 | 语义 | 实现要点 |
|---|---|---|
| `0x0800FC0C` | 写 DR | `str r0,[r1,#0x10]`（在另一函数体内） |
| `0x0800FC20` | **`set_bit(base, desc)`** | `位号 = desc&0x1F`、`字节偏移 = desc>>6`、`ldr` → **`orrs`** → `str` |
| `0x0800FC44` | **`clear_bit(base, desc)`** | 同法，但 **`bics`**（且对 `0x05010109` 有 SR1/SR2 特殊序列） |
| `0x0800FC80` | **`read_bit(base, desc)`** | 同法，只 `lds`/`ands` 返回 |

**调用点统计（全镜像，逐条 grep 得到）**：

| helper | 调用次数 | 说明 |
|---|---|---|
| **`set_bit`** | **★ 1 次** | **`08008BB0`** |
| `clear_bit` | **0 次** | —— |
| `read_bit` | 5 次 | 全在 I2C1 的两个 ISR 里（`0800895E / 0800898A / 080089B2 / 080089DA / 08008A02`） |

**那唯一一次 `set_bit` 的上下文**（I2C1 从机初始化，见 §1.3）：

```
08008BAA  mov       r0, r5          ; r0 = 0x40005400
08008BAC  movw      r1, #0x109      ; desc = 0x0109
08008BB0  bl        #0x800fc20      ; ★ set_bit(0x40005400, 0x0109)
```

**`desc = 0x0109` 解码**（按 helper 的规则）：
- 字节偏移 = `0x0109 >> 6` = **4** ⇒ `[0x40005400 + 4]` = **`I2C1_CR2`** ✓
- 位号 = `0x0109 & 0x1F` = **9** ⇒ **`CR2.bit9` = `ITEVTEN`** ✓

### 1.3 由此串出 **I2C1 从机的完整初始化序列**（6 步）

```
08008B88  movw r5, #0x5400
08008B8C  ldr.w r1, [r4, #0x110]      ; r1 = 400000（来自 ctx+0x110）
08008B90  movt r5, #0x4000            ; r5 = 0x40005400
08008B98  bl   #0x800fa20             ; ① I2C_Init(base, 400000, 0)  ← 设 FREQ/CCR/TRISE
08008B9C  ldrb.w r3, [r4, #0x10c]     ; r3 = ctx+0x10C = 0x58
08008BA6  bl   #0x800fd24             ; ② 写 OAR1 = 0x58 ⇒ 7 位从地址 0x2C
08008BAC  movw r1, #0x109
08008BB0  bl   #0x800fc20             ; ③ ★ set_bit(base,0x0109) = 置 CR2.ITEVTEN
08008BB6  bl   #0x800fc0c             ; ④
08008BBE  bl   #0x800f9cc             ; ④
08008BC6  bl   #0x800f9f8             ; ④
08008BD4  bl   #0x800fe3c  (0x1F, ctx+0x108, ctx+0x109)   ; ⑤ GPIO/pin
08008BE2  bl   #0x800fe3c  (0x20, ctx+0x10A, ctx+0x10B)   ; ⑤ GPIO/pin
```

> ★ 第 ② 步 **独立复现了项目记载的 `OAR1 = 0x58` ⇒ 从地址 `0x2C`**（与 B18 结论一致）。

### 1.4 ★★★ 后果：这精确解释了「`ITBUFEN`/`ITERREN` 从不置位」

| 使能位 | 状态 | 后果 |
|---|---|---|
| **`ITEVTEN`(bit9)** | **✅ 已置位** | **事务级事件中断会触发**：`SB` / `ADDR` / `BTF` / `ADD10` / `STOPF` |
| **`ITBUFEN`(bit10)** | ❌ 从未置位 | **`RXNE` / `TXE` 中断【不产生】** ⇒ 从 `I2C1_DR` 读字节的 128 B 收包环（`0x08008A70`）**在运行时是死代码** |
| **`ITERREN`(bit8)** | ❌ 从未置位 | **`AF`（NACK）中断【不产生】** ⇒ AF 处理（`0x08008A1C`）**也是死代码** |

**⇒ 项目长期纠结的"字节通路未启用"观察是【正确的】，现在有了准确机制：
只开了事务级中断，字节级与错误级中断全关。**

**⚠️ 但由此产生一个新问题（未闭合，如实报告）**：既然 `RXNE` 中断不触发，那 **128 B 收包环靠什么填充？** 两种解释**均未被排除**：
- **(a)** 字节在别处被**轮询**读走（尚未定位该轮询点）
- **(b)** 本镜像**自称 `TF100A_Test_FW`**（`0x19ECC`）⇒ 它是**测试固件，字节通路未接完**

⇒ **验证方法**：在 `0x0800E1C0`（主循环分派器）附近搜"轮询 `I2C1_SR1.RXNE` 并读 DR"的循环；
   若有 ⇒ (a)；若无 ⇒ (b) 成立（测试固件）。

## 2. 🔴 自我更正：USART1 **不是**无关外设，它是一条**活跃的独立协议**

**我在 B18 §4 写的是**："I2C1 有专用中断、USART1 只是轮询 ⇒ **强烈倾向 I2C1**，USART1 无专用中断入口。"
**⇒ 这句话的**后半段是错的**。子代理的实测如下（本人抽查了其中向量表与字节映射，自洽）：

### 2.1 USART1 有**自己的接收中断**

| 项 | 实测 |
|---|---|
| **STM32F1 的 `IRQ37 = USART1`** | 向量表条目（`file 0x19ABC + 4*(16+37) = 0x19B90`）= **`0x0800DEE9` ≠ 0** ⇒ **处理函数已安装** |
| 该 ISR 本体 | `0x0800DEE8 push {r7,lr}` → 查状态位 → `bl 0x800DD74`（读 DR + 状态机） |
| ⚠️ 我在 B18 只核了 IRQ31/IRQ32 非零，**没有核 IRQ37** | ⇒ 这是我的疏漏 |

### 2.2 USART1 有**完整的寄存器级初始化**

```
0800DF88  str r0,[sp,#8]        ; 保存基址
0800DF8A  bl  #0x8010ed8        ; 时钟/复位使能
0800DF96  bl  #0x8010df8        ; ★ 写 BRR（波特率）
0800DF9E  bl  #0x8011064        ; ★ CR1.bit2 = RE（接收使能）
0800DFA6  bl  #0x8011090        ; ★ CR1.bit3 = TE（发送使能）
0800DFC0  bl  #0x8010fe0        ; 中断使能
0800DFC6  bl  #0x8010f90        ; ★ CR1.bit13 = UE（USART 使能）
```
- 波特率来源：`0x0800E7AA str.w r1,[r0,#0x108]`，`r1 = 0x70800` = **460800** ⇒ 与项目记录一致
- 真解引用：`0800DD82 ldr r0,[0x40013804]`（**读 DR**）、`0x8010EC4` 内 `str r0,[r1,#4]`（**写 DR**）

### 2.3 USART1 有**双向帧协议**

- **帧头 = `5A A5`**（`0800DC86/0800DC8A` 写 `0x5A` / `0xA5`），随后 长度(2B, 大端) + type + payload
- 接收侧状态机 `0x0800DD74` 校验 `5A` / `A5` / 长度，累积 payload，回调取 `结构+0x10C`
- 发送侧 `0x0800DC6C` 组帧 → `0x0800DD18` 逐字节写 DR → **自旋等 `SR.bit6 = TC`**（`0800DD4E` 那个"轮询环"等的就是这个）

### 2.4 ⇒ 修正后的结论

> **I2C1 与 USART1 在本固件里【同时活跃】，各自有独立的寄存器级驱动与协议。**
> **"GT7868Q ↔ TF100A 的片间链路走哪一条"—— 仅凭固件内部证据【无法二选一】**，需要外部证据（逻辑分析仪 / 板级走线 / 或 GT7868Q 侧）。

**⚠️ 这对 B18 §4 的连带影响**：B18 里"⇒ 39 条命令的载体是 I2C1（与《全书》§10.2.1 口径一致）"**仍然成立**（子代理已用 39 个 handler 与分派器逐条比对确认），**但理由不能再用"因为 USART1 不是协议"**。

### 4.1 ★ 第 5 条为什么必须更正（三重问题）

1. **那不是"未用区"，那是 K 表所在区** —— 官方容器里 **`file 0x08800` 起有 4 份 K 表**（`0x08800 / 0x08C00 / 0x09000 / 0x09400`），实测 `file 0x08800–0x08C00` 与 `K_gt7868q.bin` **1024/1024 相同**。
2. **我的"近零"测量是在错误对象上做的** —— 熵 1.798 / 零字节 84% 是在 **`GT7868Q_plain.bin`**（已知**失败的解密产物**，C4 已作废、与容器仅 6.62% 相同）上测的 ⇒ **那是解密错误的伪影，不是真实未用区**。
3. **坐标混用（违反纪律 117）** —— `0x08000–0x09FFF` 是**文件偏移**，把它当作"设备写测试地址"本身就是混用。
   ⇒ **正确做法**：设备侧的写沙盒应到 **cfg 空间地址**（如 `0x96F8` 那个 32 B 窗口、`0x9807` 等）里找**未被使用的偏移**，而不是用容器文件偏移。

> **⇒ 结论：第 5 条整体作废。本项目要建"写测试沙盒"，应改为"在 cfg 空间找未用偏移 + 用第 7 步'先读后写'验证"。**

## 5. 第 4 条产出：`lab__r30_session_harden.py`

elgato 的原笔记（`docs/12-method.md` 第 6 步）：

> *"An I2C address that no device acknowledges makes the transfer fail with `EPIPE`. This is the presence test for a bus scan, and **without it every address appears to answer, because the read buffer keeps the previous transfer**. Sweep the bus several times: **about one address per sweep acknowledges spuriously and returns all zeros. Keep only what answers every time.**"*

**与本项目已知病灶精确同型**（第 18 轮："先前看到的 `0E 20 00 00` 是**复用缓冲区残留**，非真实回读"）。

**四条对策（已实现）**：
| 代号 | 做法 | 对治 |
|---|---|---|
| **DRAIN** | 每次事务前把 Input Report 循环读干净（连续 3 次相同即视为空） | 「读缓冲保留上次传输」 |
| **SWEEP** | 同一事务重复 N 轮（默认 4） | 单次偶发假应答 |
| **DROP-Z** | 丢弃全 `0x00` 结果 | 「一个地址返回全零的假应答」 |
| **EXIST** | 本通道无 EPIPE，改用 **「多轮一致 + 非全零 + 长度符合」三者同时成立** 作判据 | 取代 elgato 的 `EPIPE` 存在性判据 |

**已内建的自检计划**（`--plan probe`）刻意包含两个**应当被剔除**的样本作阴性对照：
- `0x9807` —— 项目既往判为「不可读/自相矛盾」⇒ 本工具**应把它剔掉**
- `0x0000` —— 地址 0，预期无有效应答 ⇒ **应被剔掉**

**安全**：默认 **dry**（不加 `--go` 不打开设备）；**只调用 `Gx.read()`，不含任何写路径**；只开 Col04。
**dry 自检已通过**（4 项 × 4 轮的计划打印正确）。
**⚠️ 未执行 `--go`** —— 涉及设备 I/O，等喆明确批准。

## 6. 新增纪律

> **第 119 条**：**判断"某中断是否工作"，必须同时查【使能位】与【触发条件】，不能只看 ISR 是否存在。**
> 本项目 I2C1 案例：ISR 存在且非零（IRQ31/32）、代码通顺、寄存器名正确，但 `ITBUFEN=0` ⇒ 字节级分支**在运行时不触发**。
> **⇒ 推论：凡"固件里有某段处理代码"≠"该路径会运行"；必须找到【使能它】的那一次写入。**

> **第 120 条**：**"某 exti/中断向量非零"这类判据必须【逐个向量核】，不能因为查了两个就下"另一条链路不活跃"的结论。**
> 本次代价：我在 B18 §4 只核了 IRQ31/IRQ32，就断言"USART1 无专用中断入口"；实际 **IRQ37 非零**，USART1 有完整协议。
