## 一、收包路径（完整）

```
I2C1_EV_IRQHandler = 0x08008978     ← 全镜像无代码引用（grep 零命中）⇒ 向量表入口
  ├─ 0x05010109 → 0x08008B30   ADDR：清 ctx+0x100..0x103（= 事务起点），尾部读 SR1→SR2 清 ADDR
  ├─ 0x05060109 → 0x08008A70 ★ RXNE：收字节（唯一收包路径）
  ├─ 0x05040109 → 0x08008A4C   PE-toggle 总线复位
  ├─ 0x05070109 → 0x08008AE4   TXE：发字节
  └─ 0x050?010A → 0x08008A1C   （另一事件）
```

**新工具：事件码解码**（此前未解出，是本次能读通整条链的关键）

`0x0800FC80(base, code)` = 测试位；`0x0800FC20(base, code)` = 置位。同一套编码：

| 位域 | 含义 |
|---|---|
| `code[15:6]` | 寄存器**字节偏移** |
| `code[4:0]` | 该寄存器内的 bit 号 |
| `code[31:22]` | 第二个寄存器字节偏移 |
| `code[20:16]` | 第二个寄存器内 bit 号 |

- `0x0506_0109`：`0x0109>>6=4`→**CR2**、`&0x1F=9`→**bit9 = DMAEN**；高 16 位 `0x0506>>6=0x14`→**SR1**、`=6`→**bit6 = RxNE**
- 特殊分支（`0x0506`/`0x0507`）另要求 `CR2 & 0x400`（LAST）

⇒ 于是能读懂初始化 `0x08008B68`：`bl 0x800fc20`(r1=`0x109`) = **CR2 |= DMAEN**；`bl 0x800fc0c` = **CR1 |= PE**
⇒ **收包函数的触发条件由固件自己置上 ⇒ 在执行通路上，非死代码**（区别于 TIM3 那个零调用者的例子）

## 二、ctx 结构（由访问偏移反推）

```c
struct tf100a_ctx {            // 句柄 = 0x20004134 = [0x20004128] + 0xC
  uint8_t  rx_buf[0x80];  // +0x000  接收缓冲（128 B）
  uint8_t  tx_buf[0x80];  // +0x080  发送缓冲（128 B）
  uint16_t tx_idx;        // +0x100
  uint16_t rx_idx;        // +0x102
  uint8_t  ns;            // +0x104  ← 分派器读命名空间处
  uint8_t  _pad;          // +0x105
  uint8_t  ctrl;          // +0x106
  uint8_t  state;         // +0x107
  uint8_t  addr;          // +0x108
  uint32_t speed;         // +0x110
  void (*cb_done)(void);  // +0x114
  void (*cb_err)(void);   // +0x118
};
```

依据：收包 `strb r1,[r0,rx_idx]`；发送 `ldrb r1,[r4+0x80+tx_idx]`；两侧溢出阈值同为 `cmp ...,#0x7f` ⇒ 两个 0x80 缓冲并列，自洽。

## 三、★ 收包函数 `0x08008A70`（关键 6 条指令）

```asm
08008AA0  ldr   r2,[r1]           ; r1 = 0x40005410 = I2C1_DR；读第 1 字节
08008AA4  strh.w r2,[r0,#0x104]   ; ★★ wire[0] → ctx+0x104（命名空间）
08008AA8  ldr   r1,[r1]           ; 读第 2 字节
08008AB4  strb  r1,[r0,r2]        ; ★★ wire[1] → ctx+rx_idx（rx_idx=0）
08008AD0  strb  r2,[r0,r1]        ; ★  wire[n] → ctx+rx_idx（续收，stb 直存）
```

**全程只有 `strb`/`strh` 直存，无任何字节交换** ⇒ 报文原样拷贝（H1 的"原样"部分成立）。

**rx_idx 初值 = 0** —— 由 ADDR 处理 `0x08008B30` 的 `movs r1,#0; str.w r1,[r0,#0x100]` 决定。

## 四、★★ 字节落位

| wire 索引 | 落点 |
|---|---|
| **wire[0]** | **ctx+0x104**（单独取走作命名空间） |
| wire[1] | ctx+0 |
| wire[2] | ctx+1 |
| **wire[3]** | **ctx+2** ← 子命令低字节 |
| **wire[4]** | **ctx+3** ← 子命令高字节 |
| wire[5..] | ctx+4..（载荷） |

⇒ 分派器 `ldrh r0,[ctx+2]` ⇒ **子命令 = `wire[3] | wire[4]<<8`**

**独立交叉验证（发送侧）**：编码器 `0x0800BDE0` 的基址是 `0x20004128`（**不是 ctx**）：
`[r1+0x8C] = 0x200041B4 = ctx+0x80` ⇒ 发送帧 = `[0x80][len=4][type=2][lo][hi]`
⇒ 协议带独立的**长度/类型**字段 ⇒ 接收帧对称 ⇒ 子命令在 `wire[3]/wire[4]` ✔ 与收包代码独立算出的结果一致。

## 五、★★★ 「永远不相等」作废（理由更正）

`COL04-BOUNDARY.md:166` 原话：工具 `pkt[2]=sub&0xFF; pkt[3]=sub>>8` ⇒ "内部读到的 u16 = `0x000B`，而固件在等 `0x0B00`。**永远不相等**。"

**该推导的隐含前提是 `ctx[i] = pkt[i]` 且子命令在 `pkt[2]/pkt[3]`。按新落位重算：**

| 转发假设 | `ctx[2]` | `ctx[3]` | 子命令 |
|---|---|---|---|
| 报文原样进 wire | `pkt[3]`=0x0B | `pkt[4]`=0x05 | **0x050B** ✗ |
| 剥掉 `pkt[0]=0x0E` 后进 wire | `pkt[4]`=0x05 | `pkt[5]`=0x01 | **0x0105** ✗ |

⇒ **都不是 `0x000B`**。那句"内部读到的 u16 = 0x000B""**本身不成立**（它是"工具代码 + 未验证偏移映射"推出来的，不是从固件读出来的）。

**⇒ 正确表述：这条作废，但原因不是"字节序反了"，而是它把「Col04 报文的字段偏移」直接当成了「TF100A 内部缓冲的偏移」；两者之间隔着一个未知封装层（`0x0E` 前缀 + `len` + `dir`），字段位置不重合。**

**顺带更正**：工具的 `pkt[2]=sub&0xFF; pkt[3]=sub>>8` 是低字节在前，固件 `ldrh` 也是低字节在前 ⇒ **字节序这件事，工具本来就是对的**。
