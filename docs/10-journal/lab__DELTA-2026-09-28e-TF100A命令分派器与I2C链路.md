# TF100A 命令分派器 + I2C 链路（2026-09-28，反汇编实测）

> 本轮把 ① 的链路摸到了"命令分派器 + 处理函数表"这一层，并对 ② 给出了闭合的反向结论。

---

## 一、★ I2C 链路（TF↔TP）的实测参数

| 项 | 值 | 依据 |
|---|---|---|
| 速度 | **400 kHz**（10 进制 400000 = `0x61A80`） | 驱动句柄 `[0x20004128+0x110]`，由 `0x0800DA4C` 填入 |
| 寄存器 | `0x40005400`（**I2C1**） | `0x08008B68` 初始化：`I2C_Init`@0x0800FA20（CR2.FREQ/CCR/TRISE）+ CR1/OAR + 引脚 |
| 引脚 | **GPIOB**（`0x40005400+0xB800` = `0x40010C00`） | `0x0800F81C(GPIOB, 0x1C, 3, 0x40/0x80)` |
| 驱动句柄 | 结构体 `0x20004134`；状态字节 `0x20004128` | `0x08008B68(handle)` 读 `[handle+0x106/0x108-0x10B/0x110/0x114/0x118]` |
| 回调 | `0x0800DB39`（置完成位）/ `0x0800DB5D`（置错误位）/ `0x0800DADD`（状态同步） | `0x0800DA4C` 写入 `[+0x114/+0x118/+0x11C]` |
| 状态位 | `0x20004128` bit1 = 完成、bit2 = 错误、bit3 = 其它 | 三个回调的读改写 |
| 总线复位 | `0x08008A4C`（PE-toggle 恢复法：读 SR1 → 回写 CR1） | 前次已解 |
| 延时 | `0x0800F0B4(ms)`（`0xE000E010` SysTick + 计数 `0x200040B4`） | 与本轮 `0x0800CE78` 的 `[0x200040B4]--` 互相印证 |

**⇒ 从此以后 TF↔TP 链路的物理参数是全的（400 kHz / I2C1 / GPIOB / 回调与状态位）。**

## 二、★★ 命令分派器 `0x0800E1C0` —— 与项目记录的边界**完全一致**

```c
dispatcher(msg):
  if (status & 4) status &= ~4;
  switch (msg[0x104]) {                 // ★ 命名空间
    case 0x80: 0x08006628(msg); break;
    case 0xA0:                          // ★ 16 个子命令
        ns = *(u32*)0x20004940 = msg;
        switch (*(u16*)(ns+2)) { ... }  // ★ 子命令 = [msg+2]（与项目记录一致）
        *(u8*)0x20004946 = 1;
    case 0xA1:                          // ★ 22 个子命令
        同上，另一套 switch
  }
```

**边界与项目 `COL04-BOUNDARY.md` 记载逐项吻合**：`0x80` 1 条 · **`0xA0` 16 条** · **`0xA1` 22 条** ✔

### 2.2 ★ 参数表读写一对

- **写**：`0x0800D8C0`（`0xA0/0x0B00`）= 把报文体 `N` 字节（`N = msg[1]`）拷入 **RAM 表 `0x200040E8`**
- **读回**：`0x0800D868` = 以标签 **`0xA2`** + 长度 + 表内容构造回包（**`0xA2` 正是项目记录的"回复"标签** ✔）
- ⇒ **`0x200040E8` 是一个可由主机写入/读回的字节表** —— 结合前面解出的 LRA 参数，这就是**最像"触觉参数/波形"的内部表**

## 三、★ ② 的闭合结论（本轮决定性）

| 观察 | 说明 |
|---|---|
| `0x0800D628` = 使能 TIM3（`0x40000400`）→ `0x08010D44/0x08010D30` → `0x0800D858`（调用 `[结构+0x14]` 回调） | 这是"**启动 400 Hz PWM**"的完整动作 |
| **「调用 `0x0800D628` 的位置：无」** | ★ **在本镜像里它没有任何调用者** |
| `0x0800D858` 只被 `0x0800D628` 调用 | 同上 |
| TIM3 的中断回调 `0x0800D6F4` 只做 `[0x200040D0+0x10]++`（计数） | 非波形引擎 |

**⇒ 结论：TF100A 的"启动 LRA 驱动"函数在本镜像中是孤立的（零调用者）。**
结合镜像自报 `TF100A_Test_FW` ⇒ **这是一份测试/开发固件，量产版才会把该函数接进命令分派器**。
**⇒ 因此"哪个命令真正触发振动"无法从这份固件闭合成链路** —— 与 ② 先前的降级结论一致，且现在有了**直接证据**（不是推测）。

## 四、顺手修正的旧认识

| 旧认识 | 更正 |
|---|---|
| `0x40020000` 在 STM32F1 上"未知" | **= DMA1**（`0x40020400` = DMA2）；`0x0800F160/0x0800F1EC` 是 **DMA 通道配置**（通道结构 `CCR/CNT/CPAR/CMAR`，步长 0x14） |
| 曾把 `[r1,#0x10]/[r1,#0x14]` 当 DR/SR1 | 实为 **DMA 通道结构体字段**，故"寄存器模式"启发式必然失败 |
| `0x0800CE94` | = 读 TIM3 的**计数**（`[0x200040D0+0x10]`） |
| `0x0800F0B4` | = `delay_ms`（`0xE000E010` SysTick + `0x200040B4` 倒计数） |
