## 1. 原生 BIN 容器格式（新建）

```
0x00000–0x01400   头部/目录区（512 B 周期结构，含板级标签与区域表）
0x01400–0x19A00   加密区（99,840 B，熵 7.998）
0x19ABC–0x2775C   明文 ARM Thumb-2 镜像（56,480 B）—— **含代码 + rodata**
                  （此前项目文档记「到文件末尾」正确；本文补充其中 rodata 段的性质）
```

### 区域表 @0x1160（12 条 × 8 B，实读）

```
03 00 00 20 00 01 60 00     03 00 00 20 00 00 60 00     03 00 00 20 00 00 80 00
03 00 00 20 00 00 A0 00     03 00 00 20 00 00 C0 00     03 00 00 20 00 01 E0 00
03 00 00 20 00 01 00 00     02 00 00 30 00 00 10 00     02 00 00 10 00 00 00 00
03 00 00 20 00 00 40 00     02 00 00 30 00 01 30 00     02 00 00 10 00 01 20 00
```
- 两条字段族：`type=3`（8 条）与 `type=2`（4 条）；地址域呈 **0x4000 步进**（0x4000/0x6000/0x8000/0xA000/0xC000/0xE000/0x10000/0x13000/0x2000/0x1000）
- 表中地址与**本文件偏移无对应关系**（文件只有 0x2775C）⇒ 该表描述的是**器件内部 flash 空间**（以 16 KB 为单位的段），供升级器使用
- 头部字符串：`_7YELSTO`（板级标签）、`7868Q`（芯片）

### 尾部（0x26E00–末尾，2,396 B）
- 前三段是 3 字节周期记录（`01 FF 01` / `19 54 12` / `12 7A 54` 型），非浮点
- 后段含 IEEE-754 浮点**但不是规则参数数组**（按 +0 对齐仅 25.8% 合理值，最长连续段 14 个，无 16/32/48/64 等通道数特征）
- **未被代码引用**（两条独立方法一致，见 §4）⇒ 判为**外部消费者使用的数据**（宿主驱动/另一子系统），不是 TF100A 的参数表

## 2. ★ TF100A 的外设清单（STM32F1 类 Cortex-M3，常量折叠实测）

| 外设 | 基址 | 引用次数 | 判读 |
|---|---|---|---|
| **TIM2** | `0x40000000` | 用于 LRA 驱动 | **PSC=119, ARR=1999** |
| **TIM3** | `0x40000400` | 用于 LRA 驱动 | **PSC=119, ARR=999** |
| TIM4/5/6/7 | 0x40000800 起 | 各 ×2 | 次要定时 |
| **TIM1 / TIM8** | 0x40012C00 / 0x40013400 | 各 ×7（**CCER 读-改-写 ×21**） | 高级定时器，**运行时开关 PWM 通道** |
| I2C1 | 0x40005400 | ×9 | **与宿主触控 IC 通信**（TF↔TP） |
| USART1/2/3 | 0x40013800 起 | ×6/2/2 | 调试口 |
| ADC1 | 0x40012400 | ×3 | 模拟采样（疑 LRA 状态/回授） |
| **GPIOA** | 0x40010800 | **×28（全场最高）** | 主要 IO 口 |
| GPIOB | 0x40010C00 | ×1 | 次要 |
| RCC / FLASH | 0x40021000 / 0x40022000 | ×28 / ×12 | 时钟与选项字节 |

**⇒ 没有任何外部驱动 IC 的迹象**（无 SPI、无额外 I2C 从设备地址表）：**LRA 由 MCU 自己的定时器直接 PWM 驱动。**

## 3. ★ LRA 驱动参数（关键）

驱动通过一个**结构体 + 通用定时器启动器**下发（0x0800D704）：

```
struct {  ... ; +4 = 定时器基址 ; +8 = PSC(119) ; +0xC = ARR ; +0x14 = 中断回调 }

现场 A（0x0800E026）：[+4]=0x40000000 (TIM2)  [+8]=0x77(119)  [+0xC]=0x7CF(1999)  回调=0x0800D6F5
现场 B（0x0800E754）：[+4]=0x40000400 (TIM3)  [+8]=0x77(119)  [+0xC]=0x3E7(999)  回调=0x0800D6F5
```

| 定时器 | 预分频 | 自动重装 | 频率（SYSCLK=48 MHz） | 频率（SYSCLK=72 MHz） |
|---|---|---|---|---|
| **TIM2** | 119（÷120） | 1999 → 2000 计数 | **200 Hz** ★ | 300 Hz |
| **TIM3** | 119（÷120） | 999 → 1000 计数 | **400 Hz** ★ | 600 Hz |

- **200 Hz 正好落在 LRA 谐振带（170–235 Hz）** ⇒ TIM2 = 谐振驱动主模式；TIM3 = 400 Hz（第二模式/短促"咔哒"）
- 启动器内另有 `mov.w r2, #0x2BC`（**700**）与 `movs r2, #0x60`（**96**）两个参数 → 疑为 **CCR 比较值（占空比/幅度）**：700/2000 = **35%**
- **未发现 BDTR（死区寄存器）写入** ⇒ **无互补输出/死区**，属**单端 PWM**（两个通道各自独立，或一通道 PWM + 一通道静态电平）
- 回调 `0x0800D6F5` 是计时器中断服务例程（累加计数），波形包络由上层按 200 Hz 节奏开关 CCER 实现

### 对方案③（HDP/HDN 焊盘接管）的直接含义

1. **要注入的信号 = ~200 Hz 方波/准正弦**（或 400 Hz 的第二模式），占空比约 35%，差分驱动 LRA 两端
2. **不需要外部 H 桥 IC 的线索**（MCU 单端 PWM ⇒ 两端之间需要外部桥或电容耦合才能形成交流）→ 方案③ 建议用**小功率 H 桥 / 差分驱动器**接 HDP/HDN，或用信号发生器 + 功放
3. **振幅未知**（MCU 供电电压决定）；先用示波器在 HDP/HDN 上空载测量**实际驱动电压与波形**，再定功放规格
4. 项目此前记的「LRA 常量振幅 119 周期 999·1999」与本文实测一致（119 = PSC，999/1999 = ARR）

## 4. ⚠️ 更正：我此前那条「代码零引用」的结论无效

**此前在 `触控板固件反汇编-TF100A.md` 里写过**：「折叠 movw/movt 后，指向镜像内串/表的地址常量引用 = 0 → 这些串不被本镜像代码引用」。

**这是错的，是我脚本的 bug**：capstone 输出立即数带 `#` 前缀（如 `movw r3, #0x433`），而我的折叠脚本用 `int(v, 16)` 解析，**抛异常被 `except: pass` 吞掉** ⇒ 折叠静默失败 ⇒ 恒为 0。

**修复后**（`bios-re/peripheral_use.py`，会剥离 `#`）：
- 折叠成功 **1,122 个** 32 位常量（211 个不同值）
- 分布：SRAM `0x2000xxxx` 887 / 外设 `0x4000xxxx` 155 / Flash `0x0800xxxx` 19 / 系统 `0xE000xxxx` 14
- **指向自身 Flash 的 19 个中，0 个指向尾部参数区** → **尾部无引用这个结论仍然成立**（但依据换成了修复后的折叠 + 字面量池扫描两条独立方法）

> **教训（值得进项目规矩）**：`except: pass` 会让"解析失败"伪装成"结果为零"。**任何"零结果"都必须先排除解析失败** —— 加一条 `成功计数 > 0` 的自检。
