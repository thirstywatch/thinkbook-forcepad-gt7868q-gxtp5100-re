## 二、主机报文协议（`0x1ACEC`）

报文解析函数入口 `0x1ACEC`，唯一调用者 `0x248E2`。

### 2.1 报文头结构（解自 `0x1AD02`~`0x1AD58`）

| 偏移 | 含义 | 证据 |
|---|---|---|
| `+0x00` | 魔数低字节，须 `== 0x5A` | `0x1AD5C cmp r0,#0x5a` |
| `+0x01` | 魔数高字节，须 `== 0xA5` | `0x1AD6C cmp r0,#0xa5` |
| `+0x02:4` | **数据长度**（16 位） | `0x1AD28 rsb r0,r0,r0,lsl #8` + `add r0,r2`（大端合成） |
| `+0x04` | **类型**（1~6，见 2.2） | `0x1AD7C subs r0,#1` → `tbb` |
| `+0x05` | 保留/通道 | `strb r0,[r1,#4]` |
| `+0x06` | 数据类型标记（如 `#1`） | `0x1AD94 ldrb r0,[r0,#6]` |
| `+0x08` | **payload 指针** = 报文基址 + 6 | `0x1AD38 adds r0,#6` |
| `+0x0C` | 数据起始（= 基址 + 长度 + 6） | `0x1AD3E`~`0x1AD44` |
| `+0x0D` | **CRC-8 校验**（多项式 `0xA1`） | `bl 0x1B6E0`，`strb r1,[r0,#0xd]` |

### 2.2 类型分派表（`tbb` @ `0x1AD8C`，基址 `0x1AD8C`，单位 2 字节）

| 类型 | case 地址 | 行为 |
|---|---|---|
| 1 | `0x1AD92` | 检查 `[payload+6]==1` → `bl 0x1ABE4`（写 RAM `0x20004090`） |
| 2 | `0x1ADAC` | `bl 0x1AC14` |
| 3 | `0x1ADB2` | 置 `0x2000406C=1`、`0x2000495E+0x1691=1` |
| 4 | `0x1ADCE` | `bl 0x1AC30`（**写 flash 偏移 `0x3800`，8 字节**） |
| 5 | `0x1ADDE` | `r0=[0x2000425C+8]`, `r1=[+2]` → `bl 0x1AC54` |
| 6 | `0x1ADF0` | `r0=[[0x2000425C+8]]`（首字节作命令号）→ `bl 0x1AB90` |

### 2.3 状态结构体 `0x2000425C`（由解析器填充）

| 偏移 | 含义 |
|---|---|
| `+0x00` | 魔数字节 0（`0x5A`） |
| `+0x01` | 魔数字节 1（`0xA5`） |
| `+0x02:4` | 数据长度 |
| `+0x04` | 类型 |
| `+0x08` | payload 指针 |
| `+0x0C` | 数据起始标记 |
| `+0x0D` | CRC-8 |

## 三、命令分派器（`0x22C7C`）—— 16 条命令表

### 3.1 入口条件

```
0x22C7C  push {r7,lr}
0x22C80  str r0,[sp,#0xC]              ; r0 = 报文指针
0x22C82  movw r0,#0x4128 / movt r0,#0x2000
0x22C8A  ldrb r0,[r0] ; lsrs #2 ; lsls #0x1F ; cmp r0,#0
0x22C92  beq.w 0x23206                 ; ★ 协议使能标志 0x20004128 bit2
0x22CAA  ldrb.w r0,[r0,#0x104]         ; 报文类型
0x22CB6  cmp r0,#0x80   -> 0x1B0E4     ; 0x80 = 一类
0x22CC8  cmp r0,#0xA0   -> 命令类      ; ★ 0xA0 = 命令类
0x22CD2  movw r0,#0x4940 / movt r0,#0x2000
0x22CDA  str r1,[r0]                   ; 0x20004940 = 当前报文指针
0x22CDE  ldrh r0,[r0,#2]               ; ★ 命令号 = [报文+2]
0x22CE2  str r1,[sp,#4]
```

| 命令号 | case | 目标函数 | 语义推断 |
|---|---|---|---|

| `0x0500` | `0x22DE6` | `0x1B150` | — |
| `0x0B00` | `0x22E24` | `0x22237C` | — |
| `0x0D00` | `0x22E34` | `0x22170` | — |
| `0x0E00` | `0x22DB0` | `0x208E4(arg=2)` | 通用读写 |
| `0x1100` | `0x22D9C` | `0x208E4(arg=1)` | 通用读写 |
| `0x1200` | `0x22DC4` | `0x1E790` | — |
| `0x1400` | `0x22E78` | `0x1C9EC` | — |
| `0x1700` | `0x22DEE` | `0x1AE68` | ★ **写 flash `0x3800`，8 字节** |
| `0x1F00` | `0x22E0A` | `0x208E4(arg=2)` | 通用读写 |
| `0x2000` | `0x22D8A` | `0x1E4A8` | — |

| `0x3500` | `0x22DCA` | `0x1E4A8` | — |

所有 case 尾均 `b 0x22E80` → `strb 1,[0x20004946]` → `b 0x23202`（统一出口 + 置完成标志）。

### 3.3 关键命令：`0x3200` 写字节 `0x1B`

```
0x22E52  movw r0,#0x4940 / movt r0,#0x2000
0x22E5A  ldr r0,[r0]        ; 当前报文指针
0x22E5C  adds r0,#4         ; r0 = 报文 + 4
0x22E5E  movs r1,#0x1b      ; ★ 要写的字节 = 0x1B
0x22E60  bl 0x1BA7C         ; 写 1 字节到 flash 偏移 0x1800
```

而 `0x1BA7C`：
```
0x1BA7C  push {r7,lr} ; sub sp,#8
0x1BA80  str r0,[sp,#4]  ; buf
0x1BA82  strb.w r1,[sp,#3] ; value = 0x1B
0x1BA8C  mov.w r1,#0x1800  ; ★ 偏移 0x1800
0x1BA90  bl 0x1B874        ; 写入封装
```

## 四、★ 纠错：「28 KB 可写区」的真实性质

### 4.1 我上一轮说错了什么

`ROUND22` 结论原文：

> 「写区间基址 `0x08019000` + 上限 `0x7000` = 28 KB，与第十八轮"结构化区 `0x19000..0x26000`"完全吻合
> ⇒ 这 28 KB 是**划定的自写配置区，不是代码区** ⇒ 改 cfg 不需要重刷整片固件」

### 4.2 错在哪

**判据错误：把"偏移上限"当成了"绝对地址上限"。**

```
0x1B886  ldr.w r0,[sp,#0x414]      ; r0 = addr 参数
0x1B88A  ldrh.w r1,[sp,#0x412]     ; r1 = len
0x1B88E  add  r0, r1
0x1B890  cmp.w r0,#0x7000          ; ★ 在 add 基址之前判！比的是原始 addr
0x1B894  blo  0x1B8A0
0x1B898  movs r0,#1 / strb [sp,#0x41F] / b 0x1B9BE   ; 越界返回 1
0x1B8A0  ...
0x1B8A4  movw r1,#0x9000
0x1B8A8  movt r1,#0x801            ; r1 = 0x08019000
0x1B8AC  add  r0, r1               ; ★ addr += 0x08019000
```

⇒ `addr` 是**相对偏移**，上限 `0x7000` 是对**偏移**的约束。
⇒ 可写窗口 = `0x08019000 + [0, 0x7000)` = **`0x08019000..0x08020000`**（文件偏移 `0x19000..0x20000`），**28 KB 没错**。

**但性质判错了**：

| 我上轮的推断 | 实测 |
|---|---|
| 窗口 = `0x19000..0x26000` | ❌ 实为 `0x19000..0x20000`（`0x26000-0x19000=0x7000` 是**巧合**） |
| 窗口是配置区 | ❌ **是代码段** |

**三条硬证据说明它是代码段**：

1. **写入封装自己就在窗口里**：`0x1B874`（写入）、`0x1B780`（擦页）、`0x1B9C8`（写页）全部落在 `0x1Bxxx` ⊂ 窗口
2. **熵与指令序列**：窗口内熵 5.5~6.5（远低于 `0x19000/0x19400` 两页的 7.79/7.80），可见 `b5 80`(push{lr})、`70 47`(bx lr)、`ff e7`(b.n) 等指令字节对
3. **含子固件标识**：`0x19ECC = "TF100A_Test_FW"`、`0x19EEC = "Nov 28 2023"`、`0x19F0C = "19:10:59"` —— 钛方 TF100A 压力前端固件区

⇒ **结论修正：这 28 KB 是"固件自身可擦写的代码区（含 TF100A 子固件 + 各写入/擦除例程）"，不是参数配置区。**
⇒ **改它等于改代码/子固件 ⇒ 有变砖风险，不能当"只改配置"的安全路线。**

## 五、任务3：`0x1B7B4`（读取函数）的 16 个调用者

`0x1B7B4(dst, off, len)` = 从 `0x08019000 + off` 拷 `len` 字节到 `dst`。

**16 个调用点**：
`0x1ABAA 0x1E5F0 0x1E670 0x1E68A 0x1E6B0 0x1E6CA 0x1E6E6 0x1E6F4 0x1F00E 0x21830 0x22128 0x22B3E 0x22B5C 0x22BDE 0x22BFC 0x232A6`

**读的是什么（抽样）**：

| 调用点 | 偏移 | 长度 | 上下文 |
|---|---|---|---|
| `0x1ABAA` | `0x1800` | `0x1B` | **命令 `0x1B` 处理器** —— 读回 `0x1B` 字节，组报文 `0x1C` 回主机 |
| `0x1E670` | `0x3044` | 1 | 读单字节 |
| `0x1E5F0` | 动态 | 4 | 索引 `[sp+0x20] + r2<<2` |

⇒ 读函数覆盖 `0x1800`、`0x3044` 等偏移，**范围远超 `0x7000`**（写入才限 `0x7000`）
⇒ **读取无 `0x7000` 限制，写入有** ⇒ 说明 `0x7000` 是**写入安全边界**（保护 `0x08020000` 之后的区域不被改写）

## 七、完整调用链（一张图）

```
主机 USB 报文
   ↓
0x1ACEC  协议解析（5A A5 / len / type / CRC-8）
   ↓ tbb
   ├─ type 1..3 → RAM 操作
   ├─ type 4    → 0x1AC30(写 flash 0x3800, 8B)
   ├─ type 5    → 0x1AC54(写 flash 0x1800, varB)
   └─ type 6    → 取 payload[0] 作命令号 → 0x1AB90

0x1AB90  命令 0x1B 处理器（读回）
   ├─ 0x1B7B4 从 0x1800 读 0x1B 字节
   └─ 组报文 0x1C 回复主机

0x22C7C  命令分派器（报文类型 == 0xA0）
   ├─ 命令 0x3200 → 0x1BA7C 写 1B 到 flash 0x1800
   ├─ 命令 0x1700 → 0x1AE68 写 flash 0x3800/0x1800
   └─ ... 共 16 条

0x1B874  写入封装（唯一实际执行 flash 写的函数，9 个调用者）
   ├─ 偏移 ≥ 0x7000 → 拒绝（返回 1）
   ├─ addr += 0x08019000
   ├─ 0x1B82C 读回整页 1 KB → 栈缓冲
   ├─ 0x1B780 擦页（0x23FB8 内联 Erase）
   ├─ 叠加新数据
   └─ 0x1B9C8 写整页（循环 0x24124 内联 Program，4 B/次）

0x23FB8 / 0x24124  内联的 FLASH 控制器操作
   └─ 0x40022000: CR/AR/SR，KEY1=0x45670123
```

## 八、对项目目标的意义

**「能不能回刷？」→ 能，路径已完全解出。**

| 问题 | 答案 |
|---|---|
| 谁执行 flash 写 | `0x1B874`（唯一），9 个调用者 |
| 谁能触发 | ① 主机报文 type 4/5/6（`0x1ACEC`）② 命令分派器 16 条命令（`0x22C7C`） |
| 命令号怎么发 | `5A A5` 报文，类型 `0xA0`，命令号在报文 `+2` |
| 写多少 | 1 字节 ~ 整页 1 KB，按偏移 |
| 写哪里 | 偏移 `[0, 0x7000)` → 绝对 `0x08019000..0x08020000` |
| 危险度 | ⚠️ **高** —— 该窗口是**代码段**（含 TF100A 子固件），改错即变砖 |

**下一步（若继续）**：
1. ★★★★★ 确认命令分派器 `0x22C7C` 是否可由主机直接触发（追 `0x248B6` 的上游到 USB 端点）
2. ★★★★ 解 `0x1800` / `0x3800` 两个偏移存的具体是什么（对比 `tpcfgsid*.cfg` 明文配置）
3. ★★★ 评估"只写 `0x1800` 单字节"这条最窄路径的风险（1 字节 = 最低变砖概率）
4. ★★ 红线复核：刷机三连 `00 10 / 00 11 / 0E 12` 是否与本路径相关（可能是入口）

**红线（不变）**：禁批量轮询 Col04；≤2 往返/秒；刷机三连绝不碰。
