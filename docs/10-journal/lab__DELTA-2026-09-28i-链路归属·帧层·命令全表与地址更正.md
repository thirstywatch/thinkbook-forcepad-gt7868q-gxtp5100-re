## §0 一句话（五条硬结论）

1. ★ **39 条命令的载体是 I2C1，不是 USART1** —— 由三个中断服务程序级别的代码证实；USART1 是**另一条独立链路**（有自己的收发簇），**不承载这套命令**。
2. ★ **帧格式定案**：线上帧 = `[class][b1][b2][sub_lo][sub_hi][payload…]`，5 字节头、小端、**双向同构**（TX 与 RX 两侧独立证实）。
3. ★ **38 条合法子命令全表已机械提取** —— `0xA0` 16 条与旧表 **16/16 全对**；`0xA1` 22 条中 **更正 8 条、补全 7 条**。
4. ★ **`0xA0` 的 4 条命令能改变固件的运行模式**（`0x0E00`/`0x1100`/`0x1F00` → 模式 1/2/3；`0x0D00` → 模式 4），作用点是**主循环的三个任务**。这条链路已完整闭合 —— **但三个任务都不碰任何定时器 ⇒ 仍然到不了马达**（见 §5 的"外设引用闭包"证明）。
5. ⚠️ **"主机侧封死"所依赖的那唯一一次真机测试，用的是一条"表外子命令"** ⇒ 该测试**无效**。当前封死实际依赖的是"GT7868Q 的 class 空间止于 0x0D"这一条**推断**，而 `0x80`/`0xA0`/`0xA1` 这三个 class **从未被扫过**（当时扫的是 `0x00–0x2F`）。

## §1 更正 A：「三项离线分析」的地址体系混杂了两套基准

**事实**：该文档除 `0x0800D628` / `0x0800D6F4` 两处外，其余 `0x0800 8xxx / 9xxx` 段地址**一律偏低 `0x5000`**。
**根因**：反汇编文件的首行地址是 **`0x08005000`**（不是 `0x08000000`）；旧文档沿用了项目 09-14 那批资料的误记。
**影响**：
- **结论不受影响** —— 调用图是平移不变的（`bl` 目标的相对关系不变），本文档的结构判断（599 条 BL 边、22 个 `blx`、0 个落在 handler 可达内、三类命令的边界）**仍然成立**。
- **但文档列出的"下一步"地址全部指向指令中途**，照做会读到垃圾。**这是必须修的一处**（否则后续任何人都会被误导）。

## §2 更正 B（性质更正）：`armed` 的三个"消费者"不是命令处理器，而是**主循环任务**

这是本次最重要的一条更正，它**推翻了「三项分析」§1.5 的推论**。

### 2.1 三个消费者的真实身份

「三项分析」以为 `0x08007470` / `0x08009780` / `0x0800A050` 是**命令处理函数**，并据此提出
「设备要求**先 arm（`A0-0x0D`）→ 再发子命令 1/3/4** 才会走到 0xA2」。**这个假设不成立：**

| 事实 | 证据 |
|---|---|
| 三者**都不是**命令 handler —— 分派器的 38 条 case 里没有它们 | §4 全表（机械提取） |
| 它们**只在 `main()` 里被调用**，位于无限主循环体内 | `0x0800FE06` / `0x0800FE10` / `0x0800FE18`，函数 `0x0800FA20` |
| 它们比较的 `1 / 3 / 4`（`cmp r0,#N`）**不是子命令号**，而是 **`main` 每次读的模式字节 `[0x20004094]`** | `main`：`ldrb r0,[r7,#4]!`（`r7 = 0x20004090`）→ 同一个值连传给三个任务 |

`main` 主循环原文：

```asm
0800FDC8  movw sl, #0x4090 / movt sl, #0x2000     ; sl = 0x20004090
0800FDDC  add.w r4, r0, #0xc                       ; r4 = 0x20004134 = I2C 句柄
0800FDF4  bl 0x08008C64
0800FDFA  bl 0x0800E1C0                            ; ★ 命令分派器(ctx)
0800FDFE  mov  r7, sl
0800FE00  ldrb r0, [r7, #4]!                       ; ★ r7 = 0x20004094, r0 = 模式字节
0800FE04  mov  r1, r5        ; r5 = 0x2000495E
0800FE06  bl   0x08009780                          ; 任务②（要求模式 == 1）
0800FE0A  ldrb r0, [r7]                            ; 再读模式字节
0800FE0C  mov  r1, r6        ; r6 = 0x20005FF4
0800FE0E  mov  r2, r5
0800FE10  bl   0x0800A050                          ; 任务③（要求模式 == 3）
0800FE14  ldrb r0, [r7]
0800FE16  mov  r1, r5
0800FE18  bl   0x08007470                          ; 任务①（要求模式 == 4）
0800FE1C  mov  r0, r7        ; 0x20004094
0800FE1E  mov  r1, r6
0800FE20  bl   0x0800767C
0800FE24  mov  r0, r8        ; 0x200061B4（USART 侧结构）
0800FE26  bl   0x08006230
0800FE2A  mov  r0, r5 ; mov r1, sb
0800FE2E  bl   0x08005BB8
0800FE32  ldrb r0, [r7]
0800FE34  bl   0x08007F7C
0800FE38  b    #0x0800FDF4                         ; 无限循环
```

### 2.2 ⇒ 正确的语义

```
主机命令  ──设置──▶  模式字节 [0x20004094]  ──主循环读取──▶  三个任务之一
                       ▲
                       └── armed 标志 [0x20005FEE] 决定任务是否真的有活干
```
- **模式字节**（`0x20004094`）：选择"跑哪个任务"。
- **armed 标志**（`0x20005FEE` = `0x2000495E + 0x1690`）：任务体内的第一件事就是 `ldrb r0,[ctx+0x1690]; cmp r0,#1; bne <跳过整个任务>`。
- ⇒ 「arm」不是"解锁命令"，而是"**告诉主循环：有一件待处理的事**"。

### 2.3 三个任务做什么（callee 树，全部不碰定时器）

| 任务 | 入口 | 需求模式 | 直接调用的函数 |
|---|---|---|---|
| ① | `0x08007470`（182 行） | **4** | `0x080059E0` |
| ② | `0x08009780`（197 行） | **1** | `0x080059E0` · `0x0800D1C8` |
| ③ | `0x0800A050`（217 行） | **3** | `0x080059E0` · `0x08009D18` · `0x0800D1C8` |

- `0x080059E0` → `0x08005E38` → `0x08005EE0`（**读同一个模式字节 `[0x20004094]` 做门控**）
- `0x0800D1C8` → `0x08005188`（= **取绝对值** `if (r0<0) r0 = -r0`）
- `0x08009D18` → `0x080051F0` / `0x08005396` / `0x080053BC` / `0x08005480` / `0x0800D1C8`
  （`0x080051F0` 是**软浮点库**：`eor r0,r1,r3; lsrs r0,r0,#0x1f; bic ...,#0x80000000` 是浮点符号/规格化处理）
- **⇒ 这三条链全是"数据处理"（含浮点运算），**没有一条进入定时器/PWM 簇**。

## §3 新发现：`0xA0` 的 4 条命令能改变固件运行模式（链路已闭合）

### 3.1 模式字节的写入者（`0x20004094` = `0x20004090 + 4`）

| 写入点 | 写入值 | 来源 | 触发条件 |
|---|---|---|---|
| `0x0800D6B8` | **4** | handler `0xA0/0x0D00` | 无条件 |
| `0x0800BE56` | **1** | `0x0800BE28(sel, ptr)` | `sel==1 && ptr[0]==1` |
| `0x0800BE78` | **2** | 同上 | `sel==1 && ptr[0]==2` |
| `0x0800BE9A` | **3** | 同上 | `sel==2 && ptr[0]==1` |
| `0x0800BEA8` | **0** | 同上 | 其余（复位/默认） |

`0x0800BE28` 的调用者（来自 §4 全表）：

| 命令 | 参数 | 效果 |
|---|---|---|
| `0xA0/0x0E00` | `(1, msg+4)` | 模式 → 1 或 2（看 `msg[4]`） |
| `0xA0/0x1100` | `(1, msg+4)` | 同上 |
| `0xA0/0x1F00` | `(2, msg+4)` | 模式 → 3（`msg[4]==1` 时）否则 0 |

### 3.2 ★ 于是 `0xA0/0x0D00` 的真身被完整读出（比旧描述准确得多）

```asm
0800D6B4  push {r7,lr}
0800D6B8  r1 = 0x20004090 ; r0 = 4 ; strb r0,[r1,#4]      ; ① 模式 = 4
0800D6C4  r0 = 0x2000495E
0800D6CE  r1 = 0x1694      ; bl 0x080051C2                 ; ② zero(0x2000495E, 5780)
0800D6D8  r2 = 0x1690 ; r0 = 1 ; strb r0,[r1,r2]           ; ③ armed = 1
0800D6E0  r0 = 0x2000426C ; r1 = 0x2C ; bl 0x080051C2      ; ④ zero(0x2000426C, 44)
```
- `0x080051C2(r0, r1)` 实测 = **memset(ptr, 0, len)**（`0x080051B4` 是 `strb r2,[r0],#1` 的循环，`0x080051C2` 把填充值固定为 0）。
- ⇒ 项目当年给它起的名字 **"clear/arm" 得到证实**，但动作比"清标志"大得多：**清了 5,780 字节的主上下文 + 44 字节的触觉上下文，把模式设为 4，再置 armed**。
- ⇒ **`0xA0/0x0D00` 是主机侧唯一一条"重置整个 TF100A 上下文并 arm 一个模式 4 任务"的命令。**

### 3.3 这条链路是闭合的，但终点不是马达

```
主机 0xA0/0x0D00  →  模式=4 + armed=1 + 上下文清零
                       ↓ （主循环下一轮）
                  任务① 0x08007470  →  0x080059E0 → 0x08005E38 → 0x08005EE0（数据处理）
```
**⇒ 主机命令确实能改变固件的运行态**（这是本项目此前不知道的），
**但改变之后跑到的是数据处理任务，不是马达。**

| `0x0800D868` | **`0xA1/0x0B00`** | `A2 <n> <0x200040E8 表的 n 字节>` + 拉低 PA3 |
| **`0x0800A2A8`** | **`0xA1/0x0A00`** 与 **`0xA1/0x1300`** | 清 armed → `A2 11 <0x2000426C+0x14 起的 4×u32 之和>` + 拉低 PA3 |
| **`0x0800D65C`** | **`0xA1/0x3200`** | `A2 1C <27 字节记录>`（经 `0x08006CF8(buf, 0x1800, 0x1B)`）+ 拉低 PA3 |

- 三条都往 **`ctx+0x80` = I2C 发送缓冲**写，并拉低 **PA3**（`GPIOA->BRR = 1<<3`，`0x0800F7FC` 实测 = `str rN,[rM,#0x14]`）。
- ⇒ **`A2` 回复是"塞进发送缓冲 + 敲一下 PA3"**；真正上线由 TxE 中断完成（见 §6）。

## §5 链路归属定案：39 条命令跑在 **I2C1** 上

### 5.1 三条 ISR 级证据

| # | 证据 | 位置 |
|---|---|---|
| 1 | **收包**：RxNE 中断从 **I2C1_DR（`0x40005410`）** 读字节，存入 `ctx+0…`，第 1 字节单独存 `ctx+0x104` | `0x08008A70` |
| 2 | **发包**：TxE 中断从 **`ctx+0x80[tx_idx]`** 取字节，交给 `0x0800FBF8` 写 **`[I2C1+0x10]`（DR）** | `0x08008AE4` → `0x0800FBF8` |
| 3 | **分派器的 ctx**：`main` 传 `0x20004128 + 0xC = 0x20004134` —— 正是 I2C 驱动句柄；发送编码器 `0x0800BDE0` 用的基址 `0x20004128 + 0x8C` 也在同一结构 | `0x0800FDF8` / `0x0800BDE8` |

`0x40005400` 的全镜像引用点 = **9 个**（`0x0800894C` / `0x08008978` / `0x08008A1C` / `0x08008A4C` / `0x08008AE4` / `0x08008B68` 等），与项目记的"I2C1 ×9"吻合。

### 5.2 `USART1` 是**另一条独立链路**（不是命令载体）

`0x40013800`（USART1）的引用点 = 6 个，分布在**两个互不相干的簇**：

| 簇 | 函数 | 做什么 |
|---|---|---|
| **A：USART 收发** | `0x0800DD18`（**发送循环**：逐字节 `0x08010EC4(USART1, byte)` 后 `0x08010FA4(USART1, 6)` 等标志）· `0x0800DEE8`（查标志 → `0x0800DD74(0x200061B4)`）· `0x0800DF4C`（**初始化**：置 GPIO 复用 → `0x08010DF8(USART1, baud)` → `0x08011064(USART1, 4)`） | 一条有**运行时可配波特率**（取自 `[arg+0x108]`）的 UART 链路 |
| **B：基址→时钟索引分发** | `0x08010DF8` / `0x08010ED8`（同时引用 USART1/2/3） | HAL 风格的工具函数，不是业务 |

- `0x0800DC6C`（USART 发送包装）**被 11 处调用**，全在 `0x08006098`–`0x08006198` 这一簇（与 `0x200061B4` 结构配套）—— 那是**另一套协议处理器**。
- `0x0800DF4C` 的唯一调用者是 `0x0800E798`，而 `0x0800E798` **只在 `main()` 里被调用**（`0x0800FD84`）—— 即 `main` 依次初始化：TIM2 → TIM3 → **USART1** → …
- **`USART1` 的收发簇里没有任何一处读 `ctx+0x104` / `[ctx+2]`** ⇒ **它不承载这套 39 条命令协议。**

### 5.3 ⇒ 对项目 `STATUS.md §20` 的更正

| 项目原文 | 更正 |
|---|---|
| 「片间链路 = **USART1**、~460800 baud、**39 条命令表已解**」 | **两件事被绑在了一起**：① "39 条命令"确实存在（且与 `0x80`×1+`0xA0`×16+`0xA1`×22 **精确相符**）；② 但**这套命令的载体是 I2C1**（ISR 级证据），USART1 是**并行的另一条链路**，跑的是另一套东西 |

**仍未定（须嗅探或料板）**：GT7868Q ↔ TF100A 的**物理**连线究竟是 I2C1 还是 USART1；
即"主机 Col04 的厂商帧是否被 GT7868Q 转发到 I2C1 上给 TF100A"。**这是 §8 的关键前提。**

## §6 帧层定案

### 6.1 发送路径（TX）—— 完整闭合

```
业务层  0x0800BDE0(value)                 ; 5 字节帧头写进 ctx+0x80
   ├ strb 0x80 → ctx+0x80                 ; class
   ├ strb 0x04 → ctx+0x81                 ; 长度 = 4
   ├ strb 0x02 → ctx+0x82                 ; 类型 = 2
   ├ strb lo   → ctx+0x83
   ├ strb hi   → ctx+0x84
   └ GPIOA->BRR = 1<<3                    ; 敲 PA3

中断层  0x08008AE4（TxE）
   ├ idx = ldrh [ctx+0x100] ; if (idx > 0x7f) → 置错误位
   ├ [ctx+0x106] |= 0x40                  ; 状态位
   ├ [ctx+0x100] = idx+1
   ├ byte = ldrb [ctx + 0x80 + idx]        ; ★ 从 tx_buf 顺序取
   └ b.w 0x0800FBF8                        ; = str byte,[I2C1+0x10]  → 上线
```

### 6.2 接收路径（RX）—— 与 TX 对称

```
中断层  0x08008A70（RxNE）
   ├ wire[0]  → strh → ctx+0x104          ; ★ class 字节被"单独取走"
   ├ wire[1]  → strb → ctx+0x00
   ├ wire[2]  → strb → ctx+0x01
   ├ wire[3]  → strb → ctx+0x02           ; ★ 子命令低字节
   ├ wire[4]  → strb → ctx+0x03           ; ★ 子命令高字节
   └ wire[5…] → ctx+0x04…                 ; 载荷
   （计数器 ctx+0x102，由 ADDR 处理 0x08008B30 清零）
```

### 6.3 ⇒ 线上帧格式（定案）

```
┌────────┬──────┬──────┬──────────┬──────────┬───────────────┐
│ class  │ b1   │ b2   │ sub_lo   │ sub_hi   │ payload …     │
│ 1 字节 │1 字节│1 字节│ 1 字节   │ 1 字节   │ 变长          │
└────────┴──────┴──────┴──────────┴──────────┴───────────────┘
   wire[0]  wire[1] wire[2]  wire[3]   wire[4]      wire[5…]
   →ctx+104 →ctx+0  →ctx+1   →ctx+2    →ctx+3       →ctx+4…
```
- **小端**：子命令 = `wire[3] | wire[4]<<8`（分派器 `ldrh r0,[ctx+2]`）。
- **双向同构**：发送编码器写的也是 `[class][len][type][lo][hi]`（`0x80`/`0x04`/`0x02`/`lo`/`hi`）。
- **class 字节在线上第 1 位**（不是封装层）；`0x80` 类的发送帧里它就是 `0x80`。
- `b1`/`b2` 在发送侧是"长度/类型"；接收侧同样落在 `ctx+0`/`ctx+1`，**语义对称**（追加五 的推断由 TX ISR 独立证实）。

## §7 ★ 外设引用闭包 —— "主机命令到不了马达"升级为闭包级证明

「三项分析」用"39 个 handler 的可达集"证明到不了马达，这依赖"每个 handler 的调用图都算对了"。
**本次换一个更硬的判据：直接枚举所有引用定时器基址的函数。**

### 7.1 全镜像引用 TIM1/TIM2/TIM3/TIM8 的函数 = **只有 6 个**

| 外设 | 引用它的函数 |
|---|---|
| **TIM3** `0x40000400` | `0x0800D628` · `0x0800D704` · `0x0800E750` · `0x080109DC` |
| **TIM2** `0x40000000` | `0x0800D704` · `0x0800DFE8`(`0x0800E02E`) · `0x080109DC` |
| **TIM1/TIM8** `0x40012C00`/`0x40013400` | `0x08010590`（含 `0x080105AC`）· `0x080109DC` |

### 7.2 这 6 个函数的调用者闭包（全部只有一条入口链）

```
main() 0x0800FA20
  ├ 0x0800FD7C → 0x0800DFE8 ─┐
  └ 0x0800FD80 → 0x0800E750 ─┴→ 0x0800D704（播放器）
                                   ├ 0x080105AC（CCER/通道配置）
                                   └ 0x080109DC（TIM1/8 + TIM3 的时基/使能）
0x0800D628（TIM3 就绪入口）        ← ★ 零调用者
0x0800CEA0（FPU + DMA1 + 0x08010590）← ★ 零调用者
```
- `0x0800D704` 的调用者**只有** `0x0800DFE8` / `0x0800E750`；这两个的调用者**只有** `main`。
- `0x080105AC` 的调用者**只有** `0x0800D704`；`0x080109DC` 的调用者**只有** `0x0800D704`；`0x08010590` 的调用者**只有** `0x0800CEA0`（零调用者）。

### 7.3 ⇒ 结论

> **引用定时器的函数集合 { `0x0800D628`, `0x0800D704`, `0x0800DFE8`, `0x0800E750`, `0x08010590`(+`AC`), `0x080109DC`, `0x0800CEA0` } 是一个封闭集合，
> 其唯一入口是 `main()` 的**无条件初始化**（以及两个零调用者入口）。
> 命令分派器 `0x0800E1C0`、38 个 handler、主循环三个任务、全部 `armed` 处理路径 —— 没有一个在其中。**

**⇒ 「主机命令到不了马达」由"39 个 handler 里没有"升级为"定时器引用闭包外没有任何主机可达路径"。**
这条证据形式更强、也更难被"某条 handler 间接调用了"这种质疑推翻。

## §8 ⚠️ 结论链复核：那次真机测试用的是**表外子命令** ⇒ 该测试无效

### 8.1 测试帧与三种可能的落位

09-14 真机发的帧：`0E A1 0F 00 05 01 18 00 00 1B`

| 假设的落位 | class（`wire[0]`） | 子命令（`wire[3] + wire[4]<<8`） | 判定 |
|---|---|---|
| **剥掉首字节 `0x0E`**（最合理的解释：它是封装前缀） | `0xA1` ✅ | `wire[3]=0x05, wire[4]=0x01` → **`0x0105`** | ❌ 不在 `0xA1` 的 22 条内 → **no-op** |
| 整帧原样进 wire | `0x0E` ❌ | `wire[3]=0x00, wire[4]=0x05` → `0x0500` | ❌ **class 不被识别**（分派器只认 `0x80`/`0xA0`/`0xA1`）→ **no-op** |
| 按旧文档的 `pkt[2]/pkt[3]` 读法 | `0xA1` ✅ | `0x000F` | ❌ 不在表内 → **no-op** |

**⇒ 三种落位全部落到 no-op 兜底。**

**无论如何落位，这条帧的子命令都不在合法集合内**（`0xA1` 的 22 条见 §4.3：`0203/0400/0700/0800/0A00/0B00/0F00/1300/1500/1600/1800/1D00/2300/2800/2900/2B00/2C00/2E00/3200/3400/3500/3600`）。
⇒ 它必然落到 `0x0800E740` 的**静默 no-op 兜底** ⇒ **"没收到 `0xA2`"这件事，是由"命令无效"造成的，不能推出"GT7868Q 不转发"。**

### 8.2 那么"主机侧封死"现在靠什么站着？

| 证据 | 强度 |
|---|---|
| HID 标准接口层无 Manual Trigger 输出报表 | **强**（描述符级事实，与本次无关） |
| `0x200040E8` 写波形缓冲无消费者 | **强**（引用完整性，本次不变） |
| **class 全扫 `0x0E`–`0x2F` 无响应** | 中 —— 但**扫描范围是 `0x00–0x2F`，`0x80`/`0xA0`/`0xA1` 从未被扫** |
| 「GT7868Q 只实现 class `0x00–0x0D`，所以不会转发 `0xA0`/`0xA1`」 | **推断**（不是实测：转发行为发生在 GT7868Q 的加密固件里，主机侧看不到） |
| 09-14 发 `A1` 无 `A2` 应答 | **无效**（§8.1 已证子命令表外） |

### 8.3 ⇒ 诚实的结论与建议

> **"主机能否经 Col04 触达 TF100A"这一条，目前建立在"GT7868Q 不转发"的推断上，而不是一次合法实验上。**
> 这是整条结论链里**唯一一处"推断冒充实测"的地方**（其余封死都有独立实测或引用完整性支撑）。

**要把这条彻底关掉，只有三种安全方式**（都不建议在真机上裸试）：
1. **料板**（同型号触控板模组，约 ¥100）—— 用**表内合法子命令**单发一次，看是否出现 `A2`；
2. **逻辑分析仪夹 I2C1**（TF100A 侧的两根线）—— 这是**唯一能"看见"GT7868Q 到底发了什么**的办法，项目早已列入"B 总线嗅探"；
3. 读 GT7868Q 的**加密固件**找转发逻辑（密钥在 OTP ⇒ 目前不可达）。

**红线不变**：真机上**不要**再对 `Col04` 发任何 `0xA0`/`0xA1` 帧。

## §10 红线（不变，并新增一条）

**原有全部不变**：不轮询 `Col04`；不枚举厂商命令空间；只发单发已知安全命令；异常先杀后台任务；触控板是唯一指点设备需备退路；恢复靠"关机+拔电+长按电源 30 秒"；刷机三连 `00 10 / 00 11 / 0E 12` 绝对不碰。
