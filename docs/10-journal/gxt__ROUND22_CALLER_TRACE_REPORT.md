## 一、`0x40003000`：片外 SPI/EEPROM 命令口（**不是**固件通路）

### 1.1 它是 8 个单寄存器命令，不是内存映射器件

`0x40003000` 的 9 个 MOVW/MOVT 装载点，收敛到 `0x2418C` / `0x24288` / `0x24298` / `0x242A8` 四个函数：

```
0x2418C(cmd, data)  —— SPI 命令事务（完整 24 条指令）
   0x24196  movw r0,#0xffff ; movt r0,#0xf     ; 超时计数 0xFFFFF
   0x241A4  r1 = 0x40003000
   0x241AC  movw r0,#0x5555 ; str r0,[r1]      ; ① 写 0x5555
   0x241B4  loop: ldr r0,[0x4000300C] ; and #1 ; 等 bit0
   0x241FC  r1 = 0x40003004 ; str r0(=cmd),[r1] ; ② 写命令字节
   0x24212  loop: ldr r0,[0x4000300C] ; and #2 ; 等 bit1 (busy)
   0x24256  r0 = data ; bfc r0,#0xc,#0x14       ; 16 位截断
   0x2425E  r1 = 0x40003008 ; str r0,[r1]       ; ③ 写 16 位数据
   0x24268  r1 = 0x40003000 ; movw r0,#0xaaaa ; str r0,[r1]  ; ④ 写 0xAAAA

0x24288  → 写 0xAAAA 到 +0x00    （13 条指令，孤立）
0x24298  → 写 0xCCCC 到 +0x00    （孤立）
0x242A8  → 写 0x5555 到 +0x00    （孤立）
```

**寄存器映射**：`+0x00` = 命令寄存器（`0x5555` 解锁 / `0xAAAA` 收尾 / `0xCCCC` 复位）· `+0x04` = 命令字节口 · `+0x08` = 16 位数据口 · `+0x0C` = 状态（bit0 = ready，bit1 = busy）

### 1.2 只有一条业务调用链（决定性）

`0x2418C` **全固件只被调用 1 次**：`0x1D710`。而 `0x1D6F0` 也只被调用 1 次：`0x229FA`。

```
0x229D0()   ← 被 0x24828 调用
   0x229DC  r0 = 0x23A84(1)          ; 读回某 16 位值
   0x229E8  cmp r0, #0xA55A          ; ★ 与测试字比较
   0x229EC  bne 0x229F4
   0x229F2  b   0x22A00              ; == 0xA55A ⇒ 跳过写
   0x229F4  r0 = 2 ; r1 = 0x0F9F
   0x229FA  bl 0x1D6F0               ; → SPI 写 (cmd=2, data=0x0F9F)
```

**判读**：
- `0xA55A` = `0x5AA5` 的字节序镜像，**典型的 OTP/EEPROM 出厂测试字**
- 逻辑 = 「读回 → 若已是 0xA55A 则跳过；否则写一次」= **一次性校准/配置项回写**，**不是固件更新**
- `0x23A84` 本身是一个**查表读函数**（读 `0x40006C00` / `0x40006C14` 两张表，索引 1–10 / 11–42）

⇒ **`0x40003000` 与「cfg → 芯片」的传输通路无关。** 这个头号阻塞点应当**从路线 A 的前沿移出**。

## 二、片上 FLASH：**这才是真正的固件写入通路**（本轮核心发现）

### 2.1 直接 bl 的统计（推翻了上一轮的表述）

| 函数 | 地址 | 直接 bl 次数 | 判定 |
|---|---|---|---|
| `FLASH_Lock` | `0x23FA4` | **4** | ✅ 活跃 |
| `FLASH_Unlock` | `0x240F0` | **4** | ✅ 活跃 |
| `FLASH_WaitBusy` | `0x24074` | 1（来自 `0x24026`，内部） | ✅ 内部 |
| `FLASH_ErasePage` | `0x23FD2` | **0** | ⚠️ 无直接调用者 |
| `FLASH_Program` | `0x24146` | **0** | ⚠️ 无直接调用者 |

> ⚠️ **重要更正**：第二轮报告写「完整 STM32 FLASH 驱动」是对的，但**不能**据此推断「有完整的固件烧写能力」。`ErasePage`/`Program` 的**函数体**存在，但**没有代码直接调用它们**。
> ✅ 然而下一节证明：**功能被内联重实现了**，所以真实写入能力**成立**。

### 2.2 ★★★★★ 真正的写入封装：`0x1B874`

```
0x1B874(r0=src_buf, r1=addr, r2=len)   ; 栈帧 0x420 B
   0x1B890  if (addr + len >= 0x7000) return 1        ; ★ 范围检查上限 = 0x7000 (28 KB)
   0x1B8A0  addr += 0x08019000                        ; ★★ 基址 = 0x08019000
   0x1B8B6  page = addr >> 10                          ; 页号（1 KB/页）
   0x1B8C0  off  = addr & 0x3FF                        ; 页内偏移
   0x1B8CC  room = 0x400 - off                         ; 本页剩余
   0x1B8D4  n    = min(len, room)                      ; 本次写多少
   0x1B8EE  bl 0x1B82C → 把 flash 页读进栈缓冲        ; 读-改-写
   0x1B8FC  bl 0x1B780(page)                           ; ① 擦除该页（仅当需要）
   0x1B90C  for i in range(n): buf[off+i] = src[i]     ; ② 旧数据保留，新数据覆盖
   0x1B944  bl 0x1B9C8(buf, page<<10, 0x400)           ; ③ 写整页 1 KB
   ...（循环处理跨页）
```

**这是教科书级的「flash 读-改-写（read-modify-write）」实现** —— 它必须先读回整页、擦除、再把合并后的 1 KB 写回去。**只有真在刷固件时才需要这样写。**

### 2.3 三个底层原语（内联重实现，不用库函数）

**① `0x1B780(page)` —— 擦一页**
```
0x1B78C  addr = page << 10            ; 页号 × 1KB = 绝对地址
0x1B790  bl 0x240F0                   ; FLASH_Unlock（KEY1/KEY2）
0x1B794  r0 = 0x307 ; bl 0x23F80      ; 置等待周期位 (ACR|=0x307)
0x1B79E  bl 0x23FB8(addr)             ; ★ 内联的 ErasePage
0x1B7A4  r0 = 0x307 ; bl 0x23F80
0x1B7AA  bl 0x23FA4                   ; FLASH_Lock
```
`0x23FB8(addr)` 内部 = `CR|=2(PER)` → `AR=addr` → `CR|=0x40(STRT)` → 等 `0xF0000` → `CR&=~2`
⇒ **与 `FLASH_ErasePage` 的代码一字不差，但它是独立的一份**（`0x23FB8` 自带超时轮询 `0x24018`）

**② `0x1B9C8(buf, addr, len)` —— 写 1 KB**
```
0x1B9D8  words = len >> 2             ; 半字数
0x1B9E0  bl 0x240F0                   ; FLASH_Unlock
0x1B9EA  for i in range(words):
0x1B9F4      r1 = *(buf); buf += 4
0x1B9FE      bl 0x24124(addr, r1)     ; ★ 内联的 Program（且一次写 4 B！）
0x1BA02      addr += 4
0x1BA12  r0 = 0x307 ; bl 0x23F80
0x1BA1A  bl 0x23FA4                   ; FLASH_Lock
```
`0x24124(addr, data)` = `CR|=1(PG)` → `*(addr)=data` → 等 `0xF0000` → `CR&=~1` + 自带 STRT 位
⇒ **与 `FLASH_Program` 完全同构，但独立一份**

**③ `0x1BCA0(addr, data)` —— 写 4 字节（最简形式）**
```
0x1BCA8  bl 0x240F0     ; Unlock
0x1BCB0  bl 0x24124     ; Program
0x1BCB4  r0 = 0x307 ; bl 0x23F80
0x1BCBC  bl 0x23FA4     ; Lock
```

### 2.4 两个辅助函数

| 函数 | 语义 | 证据 |
|---|---|---|
| `0x1B7B4(dst, off, len)` | 从 **`0x08019000+off`** 拷贝 `len` 字节到 `dst`（范围检查 `>= 0x7000` 返回 1） | `movw r2,#0x9000 ; movt r2,#0x801 ; add r1,r2` ⇒ `0x08019000` |
| `0x1B82C(dst, page)` | 从 `page<<10` 拷贝 **0x400 (1 KB)** 字节到 `dst` | `lsls r0,r0,#0xa` + `cmp r0,#0x400` |

### 2.5 `0x1B6E0(buf, len)` = CRC-8 校验

```
0x1B6E8  crc = 0xFF
0x1B704  loop: crc ^= *buf++                 ; XOR 进 CRC
0x1B71E  for 8 bits:
0x1B728      if (crc & 1): crc = (crc>>1) ^ 0xA1   ; ★ 多项式 0xA1, 非常见但存在
0x1B776  return crc
```
⇒ 用于**固件镜像的完整性校验**，被 5 处调用。

### 2.6 完整的调用图

```
0x1B6E0  CRC-8          ← 5 处
0x1B7B4  flash→RAM 拷贝 ← 16 处
0x1B82C  读页(1KB)      ← 1 处（0x1B8F4，在 0x1B874 内）
0x1B780  擦页           ← 1 处（0x1B8FC，在 0x1B874 内）
0x1B9C8  写页(1KB)      ← 1 处（0x1B944，在 0x1B874 内）
0x1BCA0  写 4 字节      ← 0x1BCA8 段自身
0x1B874  读-改-写整页   ← ★★★ 9 处：0x1AC3E 0x1AC84 0x1AEF4 0x1AF0A
                                        0x1BA90 0x1EFFC 0x1F10A 0x2181E 0x2190E
```

**`0x1B874` 的 9 个调用者就是固件写入的真正入口**，它们分布在 `0x1AC00`–`0x21900` 之间，说明这是**全局共用的 flash 写入服务**。

> **⚠️ 纠错（2026-09-30 ROUND23 追加，推翻本节原「关键洞察」）**
>
> 本节原文称该 28 KB 是「可由固件自身擦写的**配置区**，不是代码区」，**该结论错误**。
>
> **错因**：把**偏移上限**当成了**绝对地址上限**。
> ```
> 0x1B890  cmp.w r0, #0x7000    ; ← 此时 r0 还是"原始 addr 参数"（相对偏移）
> 0x1B8AC  add   r0, r1         ; ← 到这里才 add 基址 0x08019000
> ```
> ⇒ 可写窗口 = `0x08019000 + [0, 0x7000)` = **`0x08019000..0x08020000`**，
>    **不是** `0x19000..0x26000`（`0x26000-0x19000=0x7000` 纯属**巧合**）。
>
> **且该窗口是代码段**，三条证据：
> 1. 写封装 `0x1B874`、擦页 `0x1B780`、写页 `0x1B9C8` **自身就落在 `0x1Bxxx` ⊂ 窗口内**
> 2. 窗口内熵 5.5~6.5（对比 `0x19000`/`0x19400` 两页的 7.79/7.80），可见 `b580`(push{lr}) / `7047`(bx lr) / `e7ff`(b.n)
> 3. 含 `0x19ECC "TF100A_Test_FW"`、`0x19EEC "Nov 28 2023"`、`0x19F0C "19:10:59"` —— 钛方 TF100A 子固件区
>
> ⇒ **改这 28 KB = 改代码/子固件 ⇒ 有变砖风险**，**不能**当作"只改配置不改代码"的安全路线。
> ⇒ 完整的命令入口链见 **`ROUND23_COMMAND_ENTRY_REPORT.md`**。
