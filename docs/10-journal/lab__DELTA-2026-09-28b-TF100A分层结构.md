## 一、新增：TF100A 的分层结构（实测）

| 层 | 地址 | 判定依据 |
|---|---|---|
| **引脚/字段访问层** | `0x0800FC20`(set) / `0x0800FC44`(clear) / `0x0800FC80`(get) | handle 编码 = `{ word索引:bits31:22, 位索引:bits20:16, id:bits15:0 }`；对被指向的字做 `\|= 1<<bit` / `&= ~(1<<bit)` / 读位 |
| **I2C 初始化** | `0x0800FA20` | 写 `[base+4]`(CR2.FREQ，`bic #0x3f` 后 OR 入 MHz 值) / `[base+0x1C]`(CCR，含 `0x8000`=F/S、`0x4000`=DUTY 位) / `[base+0x20]`(TRISE)；`umull` 用 0x431BDE83、0x10624DD3 魔数做 1e6/1e3 除法，比较阈值 0xF4240(1e6)、0x61A80(400k)、0x12C(300) |
| **I2C 总线复位** | `0x08008A4C`–`0x08008A6E` | 读 SR1 → 读 CR1 → **回写 CR1**（STM32 官方 PE-toggle 恢复法，专治 I2C 总线挂死）—— 这是"确实在用 I2C"的强证据 |
| **定时器通用启动器** | `0x0800D704` | 按 `[struct+4]` 分支：`cmp 0x40000000`(TIM2) / `cmp 0x40000400`(TIM3)；随后调 HAL 风格函数 0x08010BF0 / 0x080105AC / 0x08010908 / 0x0801087C / 0x08010950 / 0x08010D80 / 0x08010598 / 0x08010BC8 |
| **PWM 通道配置（HAL 风格）** | `0x080105C4` 起 | `tbh [pc, r1, lsl #1]` 按通道号跳转；对 CCER(+0x20) 做 `bic #1/#2/#4/#8/#0x10/#0x20/#0x40/#0x80` 后 OR 入配置；对 CR2(+0x4) 处理 OIS(0x100/0x200)；对 CCMR2(+0x18) 清 OCxM；配置值来自参数结构 `ldrh [cfg+0/2/4/6/8/0xA]` |
| **延时** | `0x0800F0B4` | `0xE000E010` = **SysTick**（`CTRL` bit0 使能 + 轮询计数器变量 `0x200040B4`） |
| **Flash 编程** | `0x0800F668` | `0x40022010` = **FLASH_CR**，写数据后置 PG(bit0)，`bl 0x0800F55C` 等 SR |

**LRA 两档频率的初始化位置**：只在启动初始化序列 `0x0800FD64`–`0x0800FD94`（`bl 0x0800DFE8`=TIM2 / `bl 0x0800E750`=TIM3）里各调一次 ⇒ **是上电时的一次性配置**。

## 二、⚠️ 更正：昨天那条「CCER = 运行时开关波形」判断有误

我在 `DELTA-2026-09-28-LRA驱动规格与自我更正.md` 里写过：
> TIM1/TIM8 的 **CCER 读-改-写 ×21** = 运行时开关 PWM 通道（"放一段波形"）

**实际不是。** 转储 `0x080105C4` 起那段后可见：它是 **HAL 风格的 `PWM_ConfigChannel`** —— 按通道号跳表，把配置结构里的值 OR 进 CCER/CR2/CCMR2。**是配置代码，不是每次振动的开关。**

⇒ **"振动怎么被触发"仍未定位。** 同理，之前把"使能/失能 bit0"的 13 处当成定时器开关也**不成立**：抽查两处分别是 **FLASH_CR.PG**（`0x40022010`）和 **SysTick.CTRL**。

## 三、为什么两个目标都没做完

| 目标 | 卡在哪 |
|---|---|
| ① I2C 帧格式 | 收发函数把**基址走参数 r0**（不出现 `0x40005400` 立即数），所以按"常量扫描"找不到；定位到的两个候选 `0x080109DC` / `0x08012154`（同时有写 DR(+0x10) 与读 SR(+0x14)）**尚未逐个读** |
| ② 波形数据 | 只拿到**载波参数**（PSC/ARR/CCR≈700）；**没有**包络/序列数据，也**没找到触发点**。上一轮"播放包装 0 调用者"的说法我未复验 |

## 四、下一步的三个精确入口（按此顺序即可继续）

1. **读 `0x080109DC` 与 `0x08012154`**（各约 100–200 条指令）→ 确认哪个是 `I2C_Master_Transmit/Receive`，从中取出：从机地址写法、寄存器地址宽度、数据长度、超时与 ACK 处理 ⇒ **① 的帧格式**
2. **反查这两个收发函数的调用者**（BL 图）→ 得到"寄存器级命令表"（哪个寄存器、写什么值）⇒ 这一步会把 **TF↔TP 命令集**列出来
3. **找运行时 CCR 写入点**（+0x34…+0x40 共 17 处，见下表）→ 其中位于"命令处理函数"里的那个 = **振动幅度设定**；再顺藤摸到触发事件

## 五、方法教训（值得进技能）

**"特征寄存器模式"必须看代码，不能只看计数。** CCER 被写 21 次、bit0 被 orr/bic 13 次，两次计数启发式都指向了错误结论（HAL 配置代码 / FLASH / SysTick）。
**修正做法**：先看**周围的常量**再定性 —— 出现 `0xE000E010` 就是 SysTick，出现 `0x40022010` 就是 FLASH_CR，出现 `tbh`(跳表) + `bic #1/#2/#4` 就是 HAL 通道配置。
