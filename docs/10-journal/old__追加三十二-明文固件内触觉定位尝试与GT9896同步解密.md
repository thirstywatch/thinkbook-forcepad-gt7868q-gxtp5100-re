# 追加三十二 — 明文固件内的触觉定位尝试 + GT9896 同步解密

> 2026-09-30 · 纯软件离线 · 零设备操作
> 承接 `追加三十一`（K 恢复）。本文记录"在明文里定位触觉代码"这一后续动作的结果。

---

## 〇 一句话现状

**两件事都做了，都得到"明确但负面"的结论：**

1. **AW86927 引用搜索** —— 做了。但 **GT7868Q 主体经检验不是可反汇编的代码**（详见 §三），字节约束搜索只能给出噪声级结果；而**唯一可反汇编的 TF100A 段不含任何 AW86927 引用**。
2. **与 GT9896 做 diff** —— 做了，而且**顺带把 GT9896 也解开了**（§一，这是本轮最大的意外收获）。但**两份固件的"内容"几乎完全不同**（同偏移相同率 ≈1%，等同于随机），**没有任何可用的公共片段**。

**⇒ "改 GT7868Q 固件实现滑动震动"这条路，卡点从「能不能解密」变成了「解出来的东西不是代码」。**

## 一 ★★ 意外收获：GT9896 也解开了

### 1.1 之前为什么没发现（自我纠正）

`追加三十一` 里我断言「对 GT9896 搜全相位无尖峰」。**那个结论是错的，原因是搜索段选错了：**

```
原搜索段： anchor[0x1200 : 0x1200+0x8000]   ← 32 KiB，上界 0x9200
GT9896 纯区位置：                       0xD900  ← 在搜索段之外！
```

**⇒ 尖峰当然不出现。** 改用**全长**重搜后：

| 相位 | 0x00 计数 | 最长连续 0 段 | 熵 |
|---|---|---|---|
| **256** | **14816** | **8190** | **6.9467** |
| 257 | 1346 | 3 | 7.8654 |
| 704 | 1211 | 1 | 7.6342 |
| 0 | 853 | 2 | 7.4918 |
| （随机期望） | 359 | — | — |

**ph=256 是压倒性唯一尖峰，且正是理论值**：

```
相位 = (Sa - 纯区位置) % 1024 = (0x1200 - 0xD900) % 1024 = 256     ✓ 实测吻合
```

**直接验证**：ph=256 时，`0xD900` 段解出的前 128 字节**全为 0** ✓

### 1.2 GT9896 解码参数（与 GT7868Q 完全同构）

```
纯区   Ma = anchor[0xD900 : 0xD900+1024]        （1024 自相关 = 1.000000）
密钥   K'[j] = Ma[(j - 0xD900) % 1024]          256 = 0xD900 % 1024
解码   P[x] = anchor[x] ^ K'[x % 1024]
产出   GT9896_scramble_key.bin (1024 B) + GT9896_plain.bin (96,512 B)
```

**解密效果**：0x00 比例 **0.37% → 16.03%**；熵 **7.9983 → 6.9514**
**（GT7868Q 对照：0.42% → 14.82%；7.9978 → 7.0156 —— 同一量级）**

### 1.3 这修正了 `追加三十一` §八.1

> 原文：**"K 是否对所有 GTX8 通用？未确证。对 GT9896 全相位搜索无尖峰……"**

**修正为**：**两固件都能用同一套方法解开**（各自用自己的纯区导出密钥）。但两个密钥不是逐字节相同，而是**同一 1024 周期序列的不同循环移位**（差 676 字节），说明**相位基准由各固件自己的纯区位置决定**，不能把一个固件的密钥直接套到另一个上。

## 二 明文头结构（`追加三十一` 未展开的部分）

### 2.1 GT7868Q 头部 = 固件描述符 + 配置表 + 4 个同构块

```
0x0000-0x0028   文件头（块长度字段 0x0000043C 出现 2 次）
0x0028-0x10F0   4 个 0x43C 字节的近似同构块（仅有 70/1084 字节不同）
0x10F0-0x1200   固件描述符 + 地址/长度对表
```

**固件描述符（GT7868Q @0x1138 起）：**
```
88 fa 5f 37 [59 45 4c 53 54 4f] 00 00 06 [37 38 36 38 51] 00 00 00
            └─ "YELSTO" ─┘              └─ "7868Q" ─┘
1c 02 03 05 0d 95 02 03 00 01 00 00 08 00 00 ff 00
03 00 00 20 00 01 60 00  03 00 00 20 00 00 60 00  ...   ← 地址/长度对表
```

**GT9896 同位置（@0x0000 起）：**
```
00 01 78 fa 37 3d [59 45 4c 53 54 4f] 00 00 06 [39 38 39 36] 00 00 00
                  └─ "YELSTO" ─┘              └─ "9896" ─┘
00 03 02 00 0c 0d 95 02 03 00 01 00 00 08 00 00 ff 00
03 00 00 20 00 00 40 00  03 00 00 20 00 00 60 00  ...
```

**⇒ 结构完全同源**（`xx xx xx xx YELSTO 00 00 06 <产品号4B> 00 00 00` + 相同的描述符片段 `0d 95 02 03 00 01 00 00 08 00 00 ff 00` + 相同的 `03 00 00 20 ...` 对表）。差异只在产品号与个别字段值。

### 2.2 头部触觉线索（字节级，仅供参考）

| `0xB4` / `0x5B` / `0xB7` / `0xCA` | — | 0 |

**⇒ 单字节计数噪声过大，不足以判定头部存在 AW86927 引用。** 头部共 4608 字节，16 次 `0x5A` 与随机期望（18 次）无异。

## 三 ★ GT7868Q 主体不是可反汇编的代码（证据链）

这是本轮最重要的（负面）判定。**七条判据全部指向"非代码"：**

### D1 指令特征密度 ≤ 随机

| 样本 | LDR_PC | PUSH | POP | BX LR | MOVW |
|---|---|---|---|---|---|
| GT7868Q 主体 | 20.8 | 6.9 | 3.7 | **0.0** | 0.1 |
| TF100A（真代码） | 12.9 | 4.4 | 8.1 | **2.5** | **15.6** |
| **随机字节** | **31.6** | **8.3** | **8.2** | 0.0 | 0.2 |

（单位：/KB）

**GT7868Q 主体的每一项都 ≤ 随机数据。** 而 TF100A 的 BX LR 是 2.5/KB、MOVW 15.6/KB（典型 Thumb-2）。

### D2 BL / 32 位指令密度 = 随机

| 样本 | BL 高半字 | 32 位指令 |
|---|---|---|
| GT7868Q 主体 | **14.8/KB** | **48.2/KB** |
| TF100A（真代码） | **67.4/KB** | **131.3/KB** |
| 随机字节 | 15.7/KB | 46.7/KB |

**GT7868Q ≈ 随机；TF100A ≈ 4.5× 随机。**

### D3 函数结构缺失

`POP {..,PC}` 之后 12 字节内出现 `PUSH` 的比例：
**GT7868Q 6.9% vs TF100A 22.2%**

### D4 架构扫描：Thumb 最优但优势微弱

对 GT7868Q 主体做 14 种架构反汇编，伪指令率：

| 架构 | 伪指令率 |
|---|---|
| Thumb | 4.3% |
| XCore | 9.0% |
| ARM | 13.2% |
| TRICORE | 24.1% |
| MIPS32BE | 29.8% |
| RISCV32 | 96.9% |
| **TF100A 用 Thumb 的对照** | **0.2%** |

**Thumb 的 4.3% 虽最低，但比 TF100A 的 0.2% 差 20 倍** —— 说明主体里"可解码"并非因为它是代码。

### D5 字节重排无效

试过：16 位字内字节交换 / 32 位字内反转 / 去交织 k=2 与 k=4。
**所有变体的"与随机之比"均在 0.30–0.84 之间（全部 < 1）⇒ 不存在"只差一个重排"的代码。**

### D6 反汇编直验：人眼可判

```
GT7868Q 主体 @0xC200:  strh r7,[r2,#0x24] ; rors r5,r6 ; stm r0!,{r0,r5,r6} ; .byte ... ; ldc2 p3,c7,[sp],#0x1b8
GT7868Q 主体 @0x12000: strh r0,[r7,#0x12] ; bvc ; strh ; .byte ; movs r4,#0xc9 ; ...
TF100A  真代码 @0xBBC6: movs r1,#0xb4 ; movt r1,#0x2000 ; str r0,[r1] ; b ; movw r0,#0x42a0 ; movt r0,#0x2000 ; ldrb r0,[r0] ; cmp r0,#2 ; bne
```

**GT7868Q 是对齐的垃圾；TF100A 是完整可读的初始化流程。**

### D7 缺少地址常量

| 常量 | GT7868Q 主体 | TF100A |
|---|---|---|
| `0x08000000`（Flash） | 3 次 | 有 |
| `0x20000000`（SRAM） | 5 次 | 大量 |
| `0x40010800`（外设基址） | **0 次** | **28 次** |

**若主体是代码，应有大量指向 SRAM/外设的地址常量。实测极少。**

### D8 但"内容"确实有结构（不是噪声）

| 判据 | 实测 | 判定 |
|---|---|---|
| 0x00 填充 | **14.82%**（TF100A 9.38%，随机 0.36%） | 有结构 |
| 最长连续全 0 | **5450 B** | 不可能是随机 |
| 0 段起点 | **聚集在 %128 = 120**（29/49 个） | 有 128 字节尺度结构 |
| 相同 128 字节块 | 存在（最大相邻相等率 **1.0000**） | 定长记录 |
| 128 字节块熵均值 | **5.375**（随机期望 5.64；TF100A 5.027） | 有偏，非纯随机 |
| 标准压缩 | 无魔数；zlib/lzma 解压全失败 | 非标准压缩 |

**⇒ 结论：GT7868Q 主体 = 「高熵结构化数据」（可能是表/非 ARM 代码/仍有内层），而不是可反汇编的程序。**

## 四 AW86927 引用搜索：结果

### 4.1 GT7868Q 主体（字节约束搜索）

| 值 | 出现次数 | 4 KiB 桶分布 |
|---|---|---|
| `0x5A` | 556（1.43× 期望） | 0xA200×53, 0x13200×50, 0x10200×42, 0x11200×40 … |
| `0xB4` | 533（1.37×） | 0xE200×36, 0x10200×32, 0x11200×30 … |
| `0xB5` | 141（0.36×） | 分散 |
| `0xB6` | 109（0.28×） | 分散 |

**`0xB4` / `0x5A` 相对期望偏高约 1.4×，但分布在 10+ 个 4 KiB 桶里（各 30-53 次）—— 是"均匀偏高"，不是"表特征"。**

**判读**：在**不可反汇编的高熵数据**里做字节约束搜索，1.4× 的偏差**不构成证据**（无上下文可验证"这是一个 I²C 地址立即数"）。

### 4.2 TF100A 段（唯一可反汇编区）

| 值 | 次数 |
|---|---|
| `0x5A`（MOVS 立即数） | **1** |
| `0x5B` / `0xB4` / `0xB5` / `0xB6` / `0xB7` | **全部 0** |
| `0x58`（TF100A 自身 OAR1） | 2 |

**⇒ TF100A 的代码里没有 AW86927 的 I²C 地址常量。** 与项目既有结论一致（TF100A 不驱动 AW86927）。

### 4.3 TF100A 段的真正价值：它是可读的真代码

本次反汇编 TF100A（57,180 B）得到 **21,845 条指令**，助记符分布正常（`ldr×2888, b×2231, str×1726, movw×1295, bl×604`）。

**找到真固件字符串（确认身份）：**
```
@0x19ECC  TF100A_Test_FW
@0x19EEC  Nov 28 2023
@0x19F0C  19:10:59
@0x264EE  5.21.01.23007
@0x261C0  0123456789abcdef
```

**⇒ 该段是 `TF100A_Test_FW`（测试固件，构建于 2023-11-28）。**

**外设基址常量 Top：`0x20003F70`(SRAM×50) · `0x20004128`(×36) · `0x40010800`(×28) · …**

**⇒ TF100A 是标准 Cortex-M 芯片，外设基址 `0x40010800`。**

## 五 GT9896 ↔ GT7868Q diff：结果

| 指标 | 结果 |
|---|---|
| 同偏移相同率（4 KiB 分段）最高 | **0x0F000 处 0.2229**（因两边都有 0 填充） |
| 典型段相同率 | **0.010 – 0.020（≈ 1/256 随机水平）** |
| ≥24 B 公共片段 | **全部是长 0 串**（`00 00 …`），无任何有意义片段 |

**⇒ 两份固件的"内容"没有可对齐的共享代码/数据。**

**解释**：GT7868Q 是**触控板**主控、GT9896 是**触屏**主控，两者**算法与配置确实不同**。它们共享的只是"容器格式 / 描述符结构 / 加扰方式"，**不共享程序内容**。

**⇒ 想靠 diff 定位"触控板专属逻辑"这条路，在缺少一个"同型号第二份固件"的前提下走不通。**

## 七 新卡点

**核心问题：GT7868Q 主体在解开外层 K 之后，仍不是可反汇编的代码。**

**三种可能，按可能性排序：**

| # | 假设 | 支持 | 反对 |
|---|---|---|---|
| **1** | 主体是**数据/配置表**（非代码），代码在芯片 ROM | 无地址常量(D7)、无指令特征(D1-D3)、有 128 字节定长结构(D8) | 99840 B 的数据表偏大 |
| **2** | 主体有**内层加密/编码**，K 只解了外层 | 内容熵 7.0-7.5 高于代码基准 6.86（C1） | 0 填充解出真 0（内层加密不该保留 0） |
| **3** | 主体是**非 ARM 的自研 CPU 代码** | 所有 ARM/Thumb/常见架构特征都不匹配 | 无法进一步验证（无公开指令集） |

**⚠️ 关键约束：0 填充区解出"真 0"且密文严格 1024 周期（1.000000，见 `追加三十一` C2）—— 这一条对"假设 2"不利。**

## 十 给下一个会话的提醒

```
① 本轮有两处「自我纠正」，都是有价值的教训：
   - 「GT9896 解不开」是错的 —— 原因是【相位搜索的取样段没覆盖纯区】。
     ★ 教训：搜相位必须用【全长】（或至少覆盖所有已知 0 填充段），不能只取开头几十 KB。
   - 「明文固件 ⇒ 可以反汇编」是错的 —— 解密成功 ≠ 内容是代码。
     ★ 教训：解密后要【先做指令特征密度检验】，再决定是否投入反汇编。

② 用「与兄弟型号 diff」定位逻辑，前提是【同型号】。跨型号（触屏 vs 触控板）
   连一行代码都不共享 —— 本轮已用实测数据证伪（相同率 ≈1%，公共片段全是 0 串）。

③ 判断"是不是代码"，本轮沉淀出一套便宜且硬的判据（见 §三 D1-D3）：
   BL 高半字密度 / 32 位指令密度 / POP 后随 PUSH 比例。
   真代码 = 明显高于随机；数据 ≈ 随机。比"熵"敏感得多。
```
