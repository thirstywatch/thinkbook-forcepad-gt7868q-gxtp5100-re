# AW86927 业界用法调研 —— 上游是一条普通主机 I²C，从地址 0x5A

> 日期：2026-10-01
> 动机：「不能看看网上或者其他厂商是怎么用 AW86927 的吗」
> 结论等级：**一手来源**（Linux 内核补丁原文 + 厂商数据手册 + 设备树）

---

## 〇、一句话

> **AW86927 在业界就是一个"普通 I²C 从设备"**：主机挂在标准的 I²C 控制器上，
> **7 位从地址 `0x5A`**，配一个 reset GPIO 和一个中断 GPIO；
> **波形由主机写进它的 SRAM，播放由主机写一个寄存器位触发。**
> ⇒ **上游 = 主机可见的 I²C 总线，不是私有线、不是 EC。**

### 1.1 设备树（Fairphone 5）

```dts
/* AW86927FCR haptics @ 5a */
vibrator@5a {
    compatible = "awinic,aw86927";
    reg = <0x5a>;                                             // ★ 从地址 0x5A
    interrupts-extended = <&tlmm 101 IRQ_TYPE_EDGE_FALLING>;  // 中断引脚
    reset-gpios = <&tlmm 100 GPIO_ACTIVE_LOW>;                // 复位引脚
};
```

**它在 `&i2c2` 里** —— SoC 的普通主 I²C 控制器。

### 1.2 绑定要求（`awinic,aw86927.yaml`）

```
required: compatible, reg, reset-gpios, interrupts
```

⇒ 上游只需要 **三条线**：**I²C（SDA/SCL）+ reset + 中断**。
⇒ 换句话说：**谁掌握那条 I²C 总线，谁就能驱动它。**

## 二、★★ 芯片有硬性身份标识（可直接用来探测）

驱动里：

```c
#define AW86927_CHIPIDH  (0x57)
#define AW86927_CHIPIDL  (0x58)
#define AW86927_CHIPID   (0x9270)
...
chip_id = be16_to_cpu(read_buf);          // 读 0x57/0x58 两个字节，大端
if (chip_id != AW86927_CHIPID) return -ENODEV;
```

> **读寄存器 `0x57`（高）/ `0x58`（低），得到 `0x92 0x70` ⇒ 100% 确认是 AW86927。**

★ 这比"探 `0x5A`/`0x5B` 有没有 ACK"强得多：

| 方法 | 能回答什么 |
|---|---|
| `i2cdetect` 看 `0x5A` 有无应答 | 该地址上**有**某个设备（可能是别的） |
| **读 `0x57/0x58` == `0x9270`** | **就是 AW86927**，且**主机能碰到它** |

## 三、★ 主机 → 芯片的完整控制流程（可直接照抄）

从 `aw86927.c` 逐行还原：

### 3.1 上电/复位
```c
/* 硬复位 */
reset_gpio = gpiod_get(dev, "reset", GPIOD_OUT_HIGH);
gpiod_set_value(reset_gpio, 1);   // 拉高（有效）
usleep_range(1000, 2000);         // 1ms
gpiod_set_value(reset_gpio, 0);   // 释放
usleep_range(8000, 8500);         // 等 8ms，I²C 才可访问

/* 软复位 */
regmap_write(regmap, 0x00 /*RSTCFG*/, 0xAA /*SOFTRST*/);
usleep_range(3000, 3500);         // 等 ~3ms
```

### 3.2 初始化（关键寄存器）
| 寄存器 | 作用 |
|---|---|
| `0x03 SYSINTM` | 中断掩码（OVP/FIFO/DONE） |
| `0x46 SYSCTRL4` | 波形数据模式 `24K`；**gain bypass**；中断边沿模式 |
| `0x5B TMCFG` | **`0x7D` = 解锁**（写测试寄存器前必须），`0x00` = 锁定 |
| `0x70 ANACFG11` = `0x0F` | |
| `0x71/0x72/0x74/0x75 ANACFG12/13/15/16` | boost 行为 |
| `0x18/0x1C/0x21/0x24 CONTCFG1/5/10/13` | 制动/增益/BEMF |
| `0x48/0x4A/0x4B PWMCFG1/3/4` | PWM 参数 |
| `0x4E DETCFG2` | F0 检测 |
| `0x06 PLAYCFG1` | **BST_VOUT = 8500mV**（升压目标） |

### 3.3 ★ 下发波形到 SRAM
```c
/* 进入 standby */
poll(0x3F GLBRD5, STATE == STANDBY, 2.5ms, 250ms);

regmap_update_bits(0x45 SYSCTRL3, EN_RAMINIT, ON);
regmap_write(0x2D BASEADDRH, 0x08);     // 基址 0x0800
regmap_write(0x2E BASEADDRL, 0x00);
regmap_write(0x40 RAMADDRH, 0x08);      // 写指针 = 基址
regmap_write(0x41 RAMADDRL, 0x00);

/* 波形头：version + [start_addr, end_addr] 大端 */
struct aw86927_sram_waveform_header hdr = {
    .version = 0x01,
    .waveform_address[0] = { start = 0x0800 + sizeof(hdr),
                             end   = 0x0800 + sizeof(hdr) + len - 1 }
};
regmap_noinc_write(0x42 RAMDATA, &hdr, sizeof(hdr));
regmap_noinc_write(0x42 RAMDATA, waveform, len);   // 波形数据，双补码，24K 采样

/* F0 检测 */
UpdateBits(0x4E DETCFG2, DET_SEQ0, VBAT);
UpdateBits(0x4D DETCFG1, DET_GO, DET_SEQ0);
usleep(3000);
UpdateBits(0x4D DETCFG1, DET_GO, NA);

UpdateBits(0x45 SYSCTRL3, EN_RAMINIT, OFF);
```

### 3.4 ★ 播放 / 停止
```c
/* 播放模式 */
UpdateBits(0x08 PLAYCFG3, PLAY_MODE, RAM);        // RAM 模式
UpdateBits(0x06 PLAYCFG1, BST_MODE, BYPASS);
UpdateBits(0x4C VBATCTRL, VBAT_MODE, SW);
UpdateBits(0x08 PLAYCFG3, AUTO_BST, ENABLE);
UpdateBits(0x0A WAVCFG1, WAVSEQ1, 1);             // 波形序号 1
UpdateBits(0x0B WAVCFG2, WAVSEQ2, 0);
UpdateBits(0x12 WAVCFG9, SEQ1LOOP, INFINITELY);   // 无限循环
regmap_write(0x07 PLAYCFG2, 0x7C);                // 增益（<0x80 防失真）

/* ▶ 触发播放 */
regmap_write(0x09 PLAYCFG4, 0x01 /*GO*/);

/* ■ 停止 */
regmap_write(0x09 PLAYCFG4, 0x02 /*STOP*/);
poll(0x3F GLBRD5, STATE == STANDBY);
```

### 3.5 参考波形
驱动内置一条 **sine 波形**（`round(84 * sin(x / 16.25))`，106 字节，双补码）——
**足以产生一次可感知的震动**。⇒ 我们不需要原厂 8 KB 波形库也能先"震一下"验证通路。

## 四、⇒ 对本项目的直接影响

### 4.1 "上游"问题的答案形状变了

原来的问法：「AW86927 的 SDA/SCL 接在谁身上？」
现在的问法（更精确、且可判）：

| 判据 | 含义 |
|---|---|
| 在我们 **16 条 I²C 控制器**的某一条上，地址 `0x5A` 能应答 | 芯片**挂在主机可见总线上** ⇒ **纯软件路成立** |
| 该地址读 `0x57/0x58` == `0x9270` | **确认是 AW86927**（不是别的设备） |
| 以上都不成立 | 芯片在主机看不见的地方（EC 总线 / 模组内私有线）⇒ 只能拆机 |

### 4.2 老线那条"`0x5A` = AW86927 I²C 从地址"是被撤回过的

| 时间 | 结论 |
|---|---|
| 早期 | `0x5A` = AW86927 从地址（从 cfg 明文推出） |
| 第十六轮 | ❌ **撤回**（"不成对、无寄存器语义、频次同参数量级"） |
| 第二十–二十一轮 | ❌ **再次否证**（TF100A 镜像里立即数出现 0 次） |
| **本轮（2025 业界实证）** | ✅ **`0x5A` 确实是 AW86927 的标准从地址**（Fairphone 设备树原文） |

⇒ **当年那次撤回，撤回的是"从 cfg 推出地址"这个推理方式（方式确实不成立），但结论 `0x5A` 恰好是对的。**
⇒ **现在有了独立的一手来源，`0x5A` 重新成为首要嫌疑地址。**

### 4.3 探测方案升级

原方案：`i2cdetect` 看 `0x5A`/`0x5B` 有无应答
**新方案（更强）**：

```
对 16 条 I²C 控制器逐条：
  1) i2cdetect -y <bus>          → 找候选地址（预期 0x5A）
  2) i2cget -y <bus> 0x5A 0x57   → 期望 0x92
     i2cget -y <bus> 0x5A 0x58   → 期望 0x70
  命中 ⇒ 上游就是这条总线 ⇒ 可直接按 §3 的流程驱动
```

⚠️ **注意：`0x57/0x58` 只是普通寄存器读，零风险。**
⚠️ **但在确认身份之前，绝不写 `0x00`(软复位) / `0x5B`(解锁) / `0x09`(GO) 等寄存器。**

## 五、其他厂商用法（补充）

| 项 | 内容 |
|---|---|
| **厂商** | 上海艾为电子（Awinic），产品线「Haptic → Boost haptic」 |
| **型号家族** | `AW86927FCR`（本机丝印 `CA4F`）、`AW86927SNPLR`、`AW86927SAPLR`（同芯片不同封装/批次） |
| **典型形态** | **手机 / 平板里的振动马达驱动**（Fairphone 5 即为实例） |
| **定位** | 11V 升压 · 快速启动 · **F0 检测跟踪** · LRA 触觉驱动 · 8KB SRAM 波形库 |
| **宿主接口** | **标准 I²C 从设备**（7 位地址由 `AD` 脚定，设计上支持 `0x5A`/`0x5B`） |
| **波形来源** | 主机写入 SRAM；生态里有第三方触觉引擎（如 RichTap）提供波形库 |
| **同类参照** | Cirrus `CS40L25`（蓝莓那个项目用的）、TI `DRV26xx` —— **都是"主机 I²C 从设备 + 主机下波形 + 主机触发"** |

★ **业界没有任何一家的用法是"由另一个芯片私有控制、主机碰不到"的。**
这本身就是一条反证：**如果 AW86927 在本机被 GXTP5100 私有控制，那才是异常用法。**
