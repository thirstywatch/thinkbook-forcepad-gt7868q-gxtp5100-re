**★★ 通用纪律（本项目用血换来的）：**
```
1. 短字节模式匹配的命中（如 0x01EA、_BG）必须回看其前后的指令/字符串才能采信
2. "外设/函数被引用" ≠ "被使用" —— 必须追到【调用者】再追到【参数实际取值】
3. 凡"某功能在运行期发生"的断言，必须给出【运行期调用点】证据：
     该函数的调用者是谁 / 调用在初始化还是运行期路径 / 传入参数是什么
   三者缺一，只能写"存在该代码"，不能写"该功能生效"
```

## 四、路线状态总表

| 路线 | 状态 | 依据 |
|---|---|---|
| **标准 HID 触发**（描述符声明 `0x0E/0x21`） | ❌ **封死** | 本机 Col02 只有 `0x0E/0x23` 强度（FEATURE），**无** `0x0E/0x21`；且 `Col02 Out=0` ⇒ 主机无法下发 |
| **伪造/改描述符** | ❌ 封死 | 🔴 **依据已被更正**：「描述符来自设备固件、**主机改不了**」是**错的** —— 内核驱动的 `report_fixup` **可以**改写**主机侧描述符副本**（《全书》§19.30.1，实证针对本机 PID `0x01E9`）。<br>**但判决不变**：改的是主机侧副本，设备侧**仍无接收分支**（`Col02 Out=0`），骗不了设备 |
| **改 TF100A 固件** | ⚠️ **前提具备、但驱动链未坐实** | 固件**明文**、可分析、可改；回刷路径=UEFI capsule + `GoodixTpDxe`（不走 HID）。**但 §18.3/§18.4 推翻了"它在驱动 LRA"** |
| **改 GT7868Q 固件** | ❌ 封死 | 🔴 **依据已被更正**：固件**不是** ECB 加密，是 **1024 B 周期 XOR 位置型加扰**（`plain[x]=raw[x]^K[(x+316)%1024]`），**且已解出**（§19）。<br>**判决仍成立**：软件侧**只有写通路、无读通路** ⇒ 解出来也回刷不了 |
| **注入压力振荡** | ❌ 封死 | 震动与点击**同阈值**（140/98）⇒ 会造假点击 |
| **换 X9-15 模块** | ❌ 封死 | BIOS 白名单 `{0x01E8,0x01E9}` vs 其 `0x01EA` ⇒ Code 10；且 X9-15 **也无主机扳机** |
| **改 BIOS 白名单** | ❌ **不建议** | 理论可行（DXE 不在 IBB 验签范围），实为硬件 SPI 刷写 + 变砖风险，且**只对这一台有效** |
| **厂商命令通道找马达命令** | ⚠️ **唯一还有一丝** | 通道**已打通**（§12），但官方命令表（10 条）**无马达命令**，未知区**无接受判据**且挂起需重启 |
| **降低点击阈值**（滑动时压力波动反复跨阈值） | ⚠️ **基本封闭** | 静态配置区与 `0x5B94–0x5BE4` 均已排除；**全 64 KB 内无 16 位 140** |
| **★ 模组内专用驱动 IC（`CA4F`）** | ❓ **新线索，未探索完** | 实物确认为 LRA 驱动（20 脚、4 路直连马达、带升压电感）。**但它由谁下命令尚未定** |

## 五、★ 下一步：唯一的确定性判据

> ### **问题：`CA4F` 的 I²C 主机是谁？**

**为什么它决定一切：**
```
若主机 = TF100A  ⇒ 命令在【明文固件】里 ⇒ 可读、可改 ⇒ 路是活的
若主机 = GT7868Q ⇒ 命令在【加密固件】里 ⇒ 纯软件路到头
```

**怎么判（不需要任何仪器）：**
```
在 TF100A 固件（touchpad_TF100A_thumb.asm.txt）里查：
   它是否【发起 I²C 主机传输】
   —— 即：追到那套通用 I²C 驱动的【主机发送入口】的调用者
      已知线索：驱动库确实存在（中断驱动、读 I2C1_SR1/SR2、带回调）
               但它主/从两种模式都支持 ⇒ 仅"库存在"不能回答本题
```

**★★ 附：一条物理判据（若能做，最快，一次定案）**
```
万用表通断档：一只表笔固定 HDP 焊盘，另一只依次点 TF100A / GT7868Q 各引脚
   → 响在 TF100A 侧    ⇒ 命令可能来自明文固件 ⇒ 路是活的
   → 响在 GT7868Q 侧   ⇒ 命令在加密固件里 ⇒ 纯软件路到头
（也可以改为量 `CA4F` 那 20 个脚分别连到谁：找它的 I²C 两根线接到哪颗主控）
```

## 七、红线（务必遵守）

1. **不要在未备份的情况下改动任何固件或 BIOS**
   - 参考事故：Win-Raid 论坛一位用户解锁 BIOS 高级设置后**变砖、无 POST**（`Lenovo ThinkBook 16p G5 IRX: SPI Image Creation` 帖）
2. **对设备命令寄存器写未知操作码前，先确认有复位手段**
   - 本项目曾有两次把触控板写到不响应的记录（`0x30`/`0x31`），**重启可完全恢复**（命令寄存器易失、不损伤 flash）
   - **未以管理员权限运行时 `pnputil /restart-device` 不可用 ⇒ 唯一复位手段是重启电脑**
3. **写设备内存前先备份**（例：`poc\backup-5B80-5BF0.json` 的做法）
4. **危险命令清单（官方三条，永不要发）：**
   ```
   {00 10 00 00 01 01}  切到 patch/bootloader
   {00 11 00 00 01 01}  开始更新
   {0E 13 00 00 01 01}  重启
   ```
