> ### 🔴 为什么需要 0b（2026-10-03 实测）
>
> 第 0 步跑完、重启之后，`RwDrv.sys` **仍然加载不了** —— 但错误原因**变了**：
>
> | | 10-01 | 今天（关掉 HVCI+黑名单后） |
> |---|---|---|
> | CodeIntegrity 事件 | `3023` 已被 Microsoft 吊销 | **`3076` 不满足 Authenticode 签名等级 / 违反 CI 策略** |
>
> 实测出来的事实：
> - `RwDrv.sys` 的签名**本身是有效的**（Signer `CN=ChongKim Chan`，由 `GlobalSign CodeSigning CA - G2` 签发）
> - 而字符串 **`ChongKim` 出现在 `C:\Windows\System32\CodeIntegrity\driversipolicy.p7b`** 里
>   （= Microsoft 驱动黑名单策略数据）
> - ⇒ **光关注册表那个黑名单开关，挡不住这个策略**；剩下的拦截来自**内核驱动签名强制本身**
>
> 好在：**本机 Secure Boot 本来就是关的**（`UEFISecureBootEnabled = 0`）
> ⇒ 不需要进 BIOS，`bcdedit` 两条命令就能把 DSE 放松。

## 第 1 步的三种结果怎么读

`step1-scan.bat` 会输出类似：

```
BAR0 (low 32, low 4 bits cleared) = FE0B0000        ← 记下这个
BAR+0x000+0xFC = 44570140                            ← 出现这个 = DW 块在 +0x000
IC_CON    = 65
IC_STATUS = ...
```

| 现象 | 含义 | 下一步 |
|---|---|---|
| 六个候选偏移里**有一个** `= 44570140` | ★ 找到 DesignWare I2C 块了，`+0x000` 最可能 | 做**第 1.5 步**（阳性对照），然后跑交易脚本 |
| **六个都不是 44570140** | BAR 取错了（不是 0:15.0），或 DW 块在别的偏移 | 停下，把输出发我 |
| `BAR0 = 0` | BDF 不对 | 把输出发我 |

## ★ 第 1.5 步：阳性对照（只读，别跳过）

GUI 里 `Access → Memory`，基址填 **`BAR + 0x70`**（`IC_STATUS`），**开自动刷新**（默认 1.5 s），
然后**用手指快速划过触控板**：

- **bit0 或 bit5 有跳动** ⇒ ✅ **确认这条总线就是触控板的** ⇒ 继续
- **完全不动** ⇒ BAR 错了，回上面重查（**不要**继续往下做）

> 这一步是审计新增的（漏洞 3）。没有它，后面"读不到 0x5A"**什么都证明不了**。

## 第 2 步：跑交易脚本（读 `0x5A` 的 CHIPID）

1. 用记事本打开 `poc\rwe-cmd\10-probe.rw`
2. 把第 5 行的 **`LocalK=0x000`** 改成第 1 步里**那个命中的偏移**（如命中 `+0x200` 就写 `0x200`）
3. 运行（管理员）：
   ```
   "<LAB>\touchpad-lab\rwe\Win64\Portable\Rw.exe" ^
       /Command="<LAB>\touchpad-lab\poc\rwe-cmd\10-probe.rw" ^
       /LogFile="%USERPROFILE%\Desktop\probe.txt" /LogDate /LogTime /Stdout
   ```
4. 把 `probe.txt` 发我

### 判读

| 输出 | 结论 |
|---|---|
| `5A/57 value = 92` 且 `5A/58 value = 70` 且 `abort = 0` | ★★★ **AW86927 就在主机 I2C0 上** ⇒ 「隔着 GT7868Q」不存在，路径打通 |
| `abort` 的最低位 = 1 | **该地址没有设备应答**（这才是真的"不在这条总线上"） |
| `value` 有值但 `abort ≠ 0` | 传输被 abort，**不能当结论** ⇒ 先禁用触控板设备再试 |
| `IC_CON` 的 bit5 = 0 | `RESTART_EN` 关着 ⇒ register read 不可靠，告诉我，我换写法 |

## 之后（等第 2 步出结果）

### 若 `0x5A` 在总线上 —— 先做"观测厂商模式"，再谈震

**不要直接猜模式写 GO。** 先在 GUI 里对这三个寄存器开自动刷新，然后**点按触控板**：

| 寄存器 | 看什么 |
|---|---|
| `0x3F` | `GLB_STATE`：0=STANDBY 6=CONT 7=RAM 8=RTP 9=TRIG |
| `0x08` | `PLAY_MODE` = 低 2 位 |
| `0x09` | `STOP`=bit1 / `GO`=bit0 |

- `0x3F` 跳到 **6/7/8/9** ⇒ **那就是厂商用的播放模式**，照抄它
- `0x3F` 全程不动且 `0x08` 一直为 0 ⇒ ⚠️ **点按震动不经过 AW86927 的播放引擎** ⇒ 写 GO 大概率无效，得换思路

### 震一下（在观测之后）

照 `poc\aw86927-操作卡.txt` 的 **v2 第 1 步**（**读-改-写**，别整字节覆盖 `0x08`，
否则会把 `AUTO_BST` 清掉 —— 这是 v1 的错）。
