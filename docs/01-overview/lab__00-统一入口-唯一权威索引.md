## 三、🔴 四件"必须知道，否则会走错路"的事

### 1. ★★★★★ 命令有**四张表**，绝对别混

| # | 名称 | 器件 | 入口 | 条数 |

| **①** | **TF100A 内部分派器** | TF100A | `0x0800E1C0` | **39**（`0x80`×1 + `0xA0`×16 + `0xA1`×22） |
| **②** | GT7868Q 内部分派器 | GT7868Q | `0x22C7C` | **16**（`0x0100`–`0x3500`） |
| **③** | GT7868Q 官方命令集 | GT7868Q | `CMD_ADDR 0x4160` | 约 10 |

### 3. ★★ 红线是**四条**，不是三条

```
00 10  switch to patch   ← 绝不碰
00 11  start update      ← 绝不碰
0E 12  load flash        ← ★ 真正写 flash，绝不碰
0E 13  restart           ← 绝不碰
```
另：禁批量轮询 `Col04` · 单次事务 ≤ 32 B 间隔 ≥ 500 ms · 未获明确同意不动 `bcdedit` ·
不删 `.workbuddy` / `touchpad-lab`

### 4. ★★ 两个"器件层"易混点

| 事项 | 正确口径 |
|---|---|
| **TF100A 架构** | **STM32F1 类 = Cortex-M3**，❌ **不是 M4F**（M3 无 FPU） |
| **型号 7868Q vs 7869** | **两者都对，两个位置**：固件容器标 `7868Q`，芯片实时自报 `7869` |
| **`0xA2` 的性质** | **异步产物**，不是命令的同步应答 ⇒ "没收到 `A2`"不能证明设备拒绝 |

| 符号 | 指什么 | 属于哪条总线 / 哪一层 |
|---|---|---|
| **`0x5A` / `0x5B`** | **AW86927 的 I²C 从地址**（由 `AD` 脚配置） | 器件地址 |
| **`0x5B80` / `0x5B94` / `0x5B96`** | **GT7868Q 的 16 位 RAM 地址**（阈值表所在） | 芯片内部 RAM |
| **`5A A5`** | **GT7868Q 主机报文的魔数**（`0x1AD5C cmp r0,#0x5a`） | 主机 → GT7868Q |
| **`0xC620/0xC621` = `5A/A5`** | **EC 间接读的签名**（**另一个项目**：开盖角度） | EC 协议 |
| **`0x2C`（主机总线）** | **GT7868Q 的 I²C 从地址** —— ACPI `_CRS` 权威（`IICB(ADR0,"\_SB.PC00.I2C0")`，`ADR0=TPID[GXTP5100][1]=0x2C`） | 主机 → GT7868Q |
| **`0x2C`（GT7868Q 片内 I²C1）** | **TF100A 的 I²C 从机地址** | GT7868Q → TF100A |
| **`1`** | ⚠️ **不是 I²C 地址** —— `Name (_ADR, One)` 只是 DSDT 模板遗留（2026-10-03 更正；I²C 子设备地址权威在 `_CRS`） | — |
| **`39` vs `38`** | **同一个东西**：39 = `0x80`×1 + `0xA0`×16 + `0xA1`×22；38 = 后两类子命令之和 | TF100A 命令空间 |
| **`0x1800` / `0x3800`** | ⚠️ **两套**：<br>① GT7868Q **参数区偏移**（27 B / 8 B）<br>② GT7868Q 主机报文**类型 4 的写入目标** | — |

**★ 规律**：项目里**大部分"矛盾"不是结论冲突，而是【同一个符号指了不同的东西】却没加限定词。**
⇒ 修矛盾的正确做法常常不是"选一个"，而是**"给每个符号加上'哪条总线 / 哪一层 / 哪个器件'的限定"**。

## 五、统一口径速查（贴墙用）

```yaml
# 器件层（三颗芯片，别混）
GT7868Q:  汇顶触控主控 · ACPI\GXTP5100\1 · I²C 从地址 1 · ARM Thumb-2
TF100A:   钛方压力/触觉 MCU · I²C1 从机 0x2C · STM32F1 类 = Cortex-M3（非 M4F）
AW86927:  艾为触觉驱动 IC（丝印 CA4F）· 标准 I²C 从设备 · 地址 0x5A/0x5B · 11V H桥

# 固件层（三个不同的东西）
TB14P_...BIN:  联想 UEFI FU 胶囊（内容=ARM 镜像，不符合 Goodix 官方格式）
tpfw_*.bin:    Goodix 官方 GT7863 HID 固件（唯一通过官方校验）
tpcfgsid*.cfg: 人可读导出格式（带元信息头），不是二进制 cfg 载荷

# 命令层（四张表，必须声明是第几层）
① TF100A 内部分派器   0x0800E1C0   39 条
② GT7868Q 内部分派器  0x22C7C      16 条（① 的中继副本）
③ GT7868Q 官方命令集  CMD_ADDR 0x4160   约 10 条
④ GT7868Q 主机报文    0x1ACEC      6 种类型

# 地址层
写入/访问窗口  0x08019000 .. 0x0801FFFF（28 KB）
参数区         0x1800(27B) · 0x2000(1092B) · 0x2C00(1092B) · 0x3800(8B)
单字节标志     0x0444 / 0x2444 / 0x3044
FLASH 控制器   0x40022000  KEY1=0x45670123  KEY2=0xCDEF89AB
TF100A 加载地址 0x08005000（file 0x19ABC）

# 红线层（四条命令）
00 10 / 00 11 / 0E 12 / 0E 13   ← 全部绝不碰

# 三个"不要"
不要以为装 Linux 就能读写参数区
不要把 TF100A 的 39 条当成 GT7868Q 的
不要把 .cfg.txt 直接当 cfg 载荷下发
```
