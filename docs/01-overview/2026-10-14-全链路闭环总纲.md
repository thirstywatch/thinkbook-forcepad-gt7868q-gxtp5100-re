## §0 「闭环」在这里指什么

| 环 | 起点 | 终点 | 判定标准 |
|---|---|---|---|
| **① 输入环** | 手指按/滑 | 主机收到坐标/压力/接触数 | 描述符声明 + 驱动栈通 + 退化可判 |
| **② 触觉环** | 某事件 | LRA 实际震动 | **触发者是谁**可指名，且链路每一跳有证据 |
| **③ 维护环** | 主机读配置 | 改配置 → 落盘/生效 → 可恢复 | 读/写/校验/回复码/恢复手段全通 |

## §1 一页判定

| 环 | 判定 | 强/弱 | 关键缺口 |
|---|---|---|---|
| **① 输入环** | ✅ **闭合** | **强** | 无（可观测层面全通） |
| **② 触觉环** | 🟡 **部分闭合** | **弱** | **触发判据在 IC 固件 / TF100A 内部**；主机侧触发**被描述符排除** |
| **③ 维护环** | 🟡 **部分闭合** | **中** | **flash 无读回通道** ⇒ 落盘内容不可验证 |

**★ 2026-10-14 晚「G2 实战」对判定的补充**（真机实测，非推断）：

| 项 | 实测结论 |
|---|---|
| 实验**前提** | ✅ 活体 cfg == 基线文件（会话态读回 1084 B 逐字节相同） |
| 袋级写入 | ✅ 被接受（`0x7F`）；**但 `0x7D` 后改动仍驻留到断电**（推翻"会话结束即丢弃"） |

## §3 三个闭环的判定与理由

### ① 输入环：✅ **闭合（强）**

描述符（设备原件）声明了 X/Y/压力/接触数/扫描时间，主机驱动栈正常，退化有客观判据 ⇒ **从手指到主机的每一跳都有证据**。

### ② 触觉环：🟡 **部分闭合（弱）—— 这是最大的缺口**

```
[事件] ──?──> [IC 固件判据] ──?> [TF100A] ──?──> [AW86927] ──> [LRA]
   ▲                ▲                                      ▲
   │                │                                      │
   │   主机唯一能写的：RID 9（强度，易失）          主机不可达（5/5 + Linux NACK）
   └── **主机侧没有触发声明**（无 Manual Trigger / Waveform List / Auto Trigger）
```

| 子问题 | 结论 |
|---|---|
| 主机能不能**主动**触发震动？ | ❌ **不能**（描述符层面被排除）——只能**改强度**，不能**拉扳机** |
| 设备**自己**会不会震？ | ✅ 会（点按震、以及 `0x0E/0x20`「交出控制权」式的设备自发波形路径） |
| 那么「滑动震动」能否实现？ | ❌ **在本机不可能由主机侧实现**；除非改 **IC 固件**或经 **TF100A SWD** 改写 |
| 缺口在哪 | **「什么事件触发震动」的判据在 IC 固件 / TF100A 内部**，且 `AW86927` 这条执行链从主机不可观测 |

### ③ 维护环：🟡 **部分闭合（中）**

| 子环节 | 状态 |
|---|---|
| 读配置（`0x96F8` 会话窗口 / 版本块 / 参数区） | ✅ 通 |
| 改配置（合法袋链 + YS 校验 + 官方会话流程） | ✅ 通（拿过 `0x7F`） |
| 落盘（`0E 12`，256 B 对齐页地址，unitlen 4096） | 🟡 **可写但不可读回** ⇒ 落盘结果**无法直接验证** |
| 恢复（安全网 + 2b/2c + 退化判据） | ✅ 通，且**可主动触发** |

## §8 ★ G2 实战记录（2026-10-14，B72–B76）与**当前设备状态**

### 8.1 做了什么（全部只写会话 RAM `0x96F8`，从未落 flash）

| 轮 | 内容 | 结果 |
|---|---|---|
| pass-0 | 协议步骤 1 对照 + bag1/bag3 单点 | `0x7F` 接受；**读回 1084 B == 基线文件**；预演=实机 |
| pass-1 | **27 袋 × fill `0x00`**（+ 1 对照），336 s | `7F`×19 · **`7E 00 03` DATA_ERR ×1（bag 2）** · **无结果 ×8**（自锁成因） |
| 对照重复 | 原样写回 ×5 | **`7E 00 07` ×5（DATA_EQU）** ⇒ **推翻 B72 的"推翻②"** |
| pass-2 | bag 2 探针 37 轮（对照 + 5 填充 + 31 字节逐个清零） | **全部被拒**：`0x4160[0]=0x7D`（寄存器自锁）⇒ 未执行 |

### 8.2 净结论（可引用）

1. ✅ **实验前提成立**：活体 cfg == 基线文件；袋级合法写入被接受；离线预演表与实机逐字节一致。
2. ✅ **cfg 有语义字段**：`bag 2` 全零 ⇒ `DATA_ERR`（首个"IC 会拒绝非法 cfg"的实测证据）。
3. 🔴 **`0x7D` 不丢弃会话写入**（推翻 §19.42b.4）⇒ 回滚必须**显式回写**（纪律 182）。
4. 🔴 **`DATA_EQU` 比较"当前已应用的 cfg"**（不是 flash）—— 同一操作会因活体状态不同而给出 `7F` 或 `7E 00 07`。
5. 🔴 **J1 功效不足**（纪律 184）：人工点按方差 ≥ 效应量 ⇒ **E 面扫描当前不可判定**，既无"某袋改变触觉"证据，也**不能**下穷尽否定。
6. 🔴 **`0x4160` 自锁**（纪律 185）—— 已修工具，但**寄存器仍需一次重枚举/重启**才能解锁。
