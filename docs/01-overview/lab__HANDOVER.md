## ⚠️ 操作红线（2026-09-13 事故后新增，优先级高于一切进度目标）

1. **禁止对 `Col04` 做后台轮询** —— `GetInputReport` 循环不得常驻。嗅探只能**前台、≤30 秒、间隔 ≥200ms**。
2. 嗅探期间**不得同时发厂商命令**（互相抢响应，且可能共同把 IC 打挂）。
3. 后台任务用完**立即** `job_kill`；出现任何异常，第一步是**杀掉所有后台任务**。
4. 判断"IC 还活着吗"只用**单次**只读命令；需要连发就已经是故障征兆。
5. 触控板是本机**唯一指点设备**：任何可能让它停摆的操作，先备好一条不依赖它的退路。
6. **恢复阶梯（2026-09-13 事故实测后的最终版，严格按序）**：
   ① 杀后台任务 → ② 单次只读命令确认 → ③ Fn+F8（**仅 IC 尚能应答时有效**）
   → ④ **关机 → 拔充电器 → 长按电源键 20～30 秒 → 等 1 分钟 → 开机** ← **IC 硬挂死/设备消失时的唯一有效手段（已实测救活 ✓）**
   - *实测教训 1*：IC 硬挂死后 `disable/enable` 会把设备从 `Started` 打成 **Problem 10 / 0xC000009E**；
     `restart-device`（连父级 I2C 控制器）、`scan-devices` 全都救不回来。
   - *实测教训 2*：**热重启 ≠ 断电**。热重启不放触控板供电轨，IC 的挂死状态跨重启存活；BIOS 再次探测失败后
     会把设备从 ACPI 隐藏（`Problem 10` → **`Disconnected`**），连 ESRT 固件资源一起消失。**"设备消失"≠"驱动掉了"**。
   - *实测教训 3*：本机底部的孔是 **Novo 按钮孔**（官方手册底视图：1 进风口 / 2 扬声器 / 3 Novo 按钮孔），
     **只进菜单、不断电**，不要指望它复位硬件。
   事故全过程、核验表与机制结论见 [`STATUS.md`](../08-findings/lab__STATUS.md) **第十三、十四章**。
7. **禁止枚举/批量试探厂商命令空间**。实测：`0x0E`/`0x0F`/`0x99` 会**打断应答通道**（`err=122`），
   而该卡态**会继续恶化成触控板彻底失效**。厂商通道只允许单发、已知安全的命令（当前仅 `0x20` 读）。
8. **厂商通道整体降级为"非必要不用"**：攻坚震动不再依赖它 —— `0x20` 之外没有可用命令（能应答的 `0x00`–`0x0D` 全是同一个空 ACK）。
9. **路线 B（内核 HID 过滤驱动）判定为不值得做**：它依赖"探测命令空间验证隐藏震动触发"，而命令空间既不能安全探测、
   也没有震动触发 ⇒ 成功率趋近 0，不值得付"装 WDK + 关 Secure Boot"的代价。除非出现全新证据，不再讨论。
10. **同一天两次打挂触控板，根因都是"用户态碰厂商通道"**（①后台高频 `GET_REPORT` ②批量试 opcode）
    ⇒ 不再假设"小心一点就没事"，而是**从设计上避开**。

## 一、一页结论

| 问题 | 答案 |
|---|---|
| 能让这块板子"主机主动震一下"吗？ | **不能**。**双层独立证据**：<br>① **描述符层**——微软《Input Device Haptics Implementation Guide》要求主机触发必须有 `Manual Trigger (0x0E/0x21)` **OUTPUT** 报表 + `Waveform List (0x0E/0x10)/Duration List (0x0E/0x11)`；本机 `Col02 out=0`、page 0x0E 下**只有 Intensity**。且群主那份**实际跑在 Windows 上**的触觉描述符正好声明了这几条 usage ⇒ "别人有、我们没有"（见 `VIBRATION-FORENSICS-2.md` §9）。<br>② **固件层**——39 条命令 handler **无一**读写 `ctx+0x14`、**无一**碰 TIM2/TIM3（§8.6）⇒ 即使下发了也没人执行。<br>⇒ 主机下发**没有入口**，固件**没有出口** |
| 能控制震动强度吗？ | **能** ✓（`Col02` feature `rid=9`，写 1–10 强、50 变轻、100 关闭；**用户体感验证**） |
| 能读芯片内部吗？ | **能** ✓（`Col04` OUT→IN + **16 位 GTX8 帧**，稳定读到真数据；已整块测绘 64KB） |
| 能写芯片配置吗？ | ⚠️ **能写进去，但固件不采信**——GTX8 族的帧长度常量必须是 `hidbuf[4] = data_sz + 5`（照搬 Dell/BRLB 族的 `+7` 会被丢弃）✗。改对后经 **Col04 OUT（65 字节）**写入，**回读确实变了**（`0x5B96` 70→25）✓，**但（a）用户手感无变化、（b）重启后客观复测阈值仍是 140–148** ⇒ 那是**影子/易失**位置，不是一个固件会采信的配置写入。详见 `STATUS.md` §12 |
| 写入"强度"本身会不会顺手震一下？ | **不会**（**2026-09-13 实测，测试 A**）——连写 6 个不同的 `rid=9` 值，**点击反馈力度确实随之改变**（阳性对照 ⇒ 写入真的到了设备），**但没有任何一次产生震动** ✗。⇒ 论证链上最后一条缝已焊死。见 `STATUS.md` §十九 |
| 滑动震动的最后一步卡在哪？ | 阈值**不在**传感器配置里。两侧测试（写 25 / 写 200）行为**均无变化** ⇒ 点击判定在 **MCU 侧**（其配置在我们够不到的固件里）✗ |
| 现在还能做什么？ | ① 手势 MVP（`DESIGN.md` 已写好设计，可立即实现）② 内核 HID 过滤驱动（读厂商响应/命令空间）③ 把实测结论发社区 |

## 二、硬件与接口事实（实测）

| 集合 | 驱动 | 能力 | 用户态可访问性 |
|---|---|---|---|
| `Col01` (mouse) | `mouhid` | in=9 | 只写 |
| **`Col02` (PTP)** | 无服务(仅 hidclass) | in=40 / **feat=737 / featVals=7** | **只写**（读被独占 err=32） |
| `Col03` (mtconfig) | `MTConfig` | feat=3（**rid=3 = Input Mode 0–10**） | 读写 ✓ |
| **`Col04` (vendor)** | 无服务 | in=65 / out=65（**rid=14**） | 读写 ✓ |

- Col02 的 feature 报表：`rid=2`(Pad Type+ContactCountMax) · **`rid=9`(Haptics Intensity)** · `rid=6`(256B) · `rid=11`(66B) · `rid=12`(736B) · `rid=13`(4B)，后四者为厂商报表(usage page 0xFF00)。
- **压力/按键位解析（实测报文 40 字节）**：`byte0=报文ID` · `byte1` 低 4 位=按键位、高 4 位=触点ID · `X@2` · `Y@4` · **`压力@6`(0–2000)** · 扫描时间@36 · **`按下位 = byte39.bit0`**
- **点击阈值（实测，n=20+ 次按压）**：按下 **140–149（中位 141）**、松开 **95–99（≈97）**，有回滞。原始域 = HID/2 ⇒ **70 / 48**。

## 三、已打通的能力（含证据）

1. **厂商通道读** ✓ — `Col04` 的 OUT 报表发命令、IN 报表收响应：
   - 读帧：`0E 20 00 00 05 01 <addr16BE> <size16BE>`（**16 位 GTX8 帧**）
   - 响应：`0E 20 <cont> <seq> <len> <data…>`
   - 证据：0x1000 读到配置表、0x4100 读 0x00、0x4000 读到含 `"YELSTO"` 的配置块、整块 64KB 测绘（1093 次读，0 失败）
2. **Col02 feature 写（HID 已声明报表）** ✓ — `rid=9` 写入改变硬件行为（**用户体感**：50→变轻、100→消失、10→恢复）；
   **2026-09-13 测试 A**：连写 6 个不同值**不产生任何震动**（虽然写入确到设备）⇒ 它是**参数**，不是**动作**（`STATUS.md` §十九）
3. **罗塞塔石碑** ✓ — 固件 BIN 的**明文配置记录 0–4** 与芯片内存**逐字节对应**（例：记录 +0x2A4 ↔ 0x5B8E；映射常数随每次重新初始化变化）
4. **Input Mode 读写** ✓ — Col03 `rid=3`（0–10；Windows 用 0/3；4–10 无可见效果）
5. **异常恢复手段**（2026-09-13 **实测救活** ✓）— 杀后台任务 ＞ Fn+F8（**仅 IC 尚活时有效**）＞
   **关机 + 拔充电器 + 长按电源键 20～30 秒 + 等 1 分钟 + 开机**（**IC 硬挂死/设备从 ACPI 消失时的唯一有效手段**）；
   实测无效：`disable/enable`（打成 `Problem 10 / 0xC000009E`）、`restart-device`、`scan-devices`、热重启、Novo 孔。详见第十四章

## 四、已排除/已封锁（不要重走）

| 路径 | 结论 |
|---|---|
| HID 标准触发震动 | **不存在**（官方规范 + 本机描述符双重确认） |
| Col02 读（要读厂商响应） | 被**独占**（err=32）；**禁用 Col03 后仍然独占** ⇒ 持有者不是 MTConfig；自写工具 `WhoHolds.cs` 全系统句柄枚举：**用户态可见进程里找不到持有者** ⇒ 系统/内核组件 |
| Col04 输入报表当响应通道 | 只是"上一条命令的镜像 + 静态块"（4096B 缓冲下两条命令只差地址字节） |
| Col03/Col02 的 GET_FEATURE 取响应 | 小缓冲 err=122；4096B 时返回**同一块共享缓冲**（命令回声） |
| 写芯片内存 | **6 种组合全部"True 但无效"**；raw 模式入口无效；**重启设备后阈值数值完全不变** ⇒ 非"写 flash 需重载" |
| 32 位地址空间（BRLB 帧） | **本芯片未实现**（一律返回 0）⇒ Dell 工具（写 `0x14000`）的命令集**不适用** |
| 固件记录区 5–95 高熵段 | 非标准压缩（zlib/gzip/bz2/xz/zstd 全失败）、非短周期 XOR；明文段内**无任何密码学常量**（AES S-box/Rcon/CRC32/SHA/MD5 全 0）⇒ 疑为**硬件加密 + OTP 密钥**，自行破解无望 |
| 56KB 明文镜像 | **引用越出自己的上界**（向量表 slot 6 → `0x0800DFE5` +837 B；slot 53 = IRQ37 USART1 → `0x0800DEE9` +585 B；代码 `0x08008FF6` 的 `movw/movt` → `0x0800F0B5` **+5,141 B**）⇒ **调用方在镜像指向但未包含的地址空间里**。⚠ **不是"文件缺字节"**：两个声明长度与在场字节**精确相等**（见 §八.4 与 `VIBRATION-FORENSICS-2.md` §5.9）。~~命令分发表静态不可得~~ **该条作废**：分发表已完整取得，见 §五 |
| `5B11M67497.CAP` | 是 Insyde 通用刷写程序，与触控板无关 |
| Input Mode 4–10 | 无可观测效果 |
| 触控板"抽帧" | 成因 = 命令响应未排空、传感器忙于服务主机命令；**停止命令 + 被动读几次即恢复**（F8 无效） |

## 六、恢复与安全（**每次实验前必读**）

**恢复阶梯**（从轻到重）：
1. 触控板"抽帧/卡顿" → **停止发命令**，被动读几次 `Col04` 输入报表排空响应
2. 手势/模式异常 → **Fn+F8**（⚠️ Col03 被禁用时 F8 会失效并切进降级模式）
3. 设备状态异常 → `pnputil /restart-device "ACPI\GXTP5100\1"`（管理员）
4. 仍不行 → 重启电脑（传感器重新初始化）
5. 最坏情况 → 用 `C:\Windows\Firmware\TB14P_GT7868Q_14030522_20240202.BIN` / ESRT 资源重刷固件

**纪律**：
- **命令必须稀疏**；每条命令的响应必须排空
- 安全软件会拦"运行时编译 C# + P/Invoke"（曾报 `Trojan:Win32/Commando.A!ml` **误报**）⇒ 辅助类一律放 `.cs` 文件、用 `Add-Type -Path` 加载（**已在 `WriteHelper.cs` 落实**）
- 设备匹配**必须用完整路径**（`ColProbe.FindPath('&col02')`）；用子串 `'Col02'` 会误命中 Intel 的 `intc816&col02`（**历史重大 bug，曾导致整轮结论错误**）
- 写操作前先读回原值备份（如 `poc/threshold-backup.bin`）

## 九、踩过的坑（后来者请直接跳过）

1. **`EnumPaths('Col02')` 子串匹配** → 打到 Intel `intc816&col02`，导致"写失败 err=87/1"整轮错误结论 ⇒ 必须用完整路径。
2. **帧宽度混淆**：本机是 **16 位 GTX8 帧**；BRLB 的 32 位帧返回全 0。
3. **把 Col03 当侧门**：它能接受任何 report ID 的 SetFeature（返回 True），但**不是真通道** ⇒ 曾据此得出错误结论。
4. **响应不排空 → 触控板"抽帧"**（传感器忙于服务主机命令）。
5. **线性反汇编在数据区失步** → 应从函数入口/向量目标**单独反汇编**；`skipdata` 必须开。
6. **函数边界识别**：函数内部也有 `push {…,lr}` ⇒ 用 `bl` 目标/向量表作为权威起点。
7. **函数指针是 `movw`+`movt` 立即数**，不是 4 字节字面量 ⇒ 搜字面量会漏。
8. **手感不可靠**：所有阈值结论必须用 `press-capture.ps1` 测数值（曾有一次"手感变轻"实为噪声）。
9. **安全软件误报**：运行时编译 C# + P/Invoke 会被判 `Trojan:Win32/Commando.A!ml` ⇒ 辅助类放文件里。

## 十、★ 写入打通（本轮关键突破）与阈值定论

### 10.1 根因：一个字节的族差异
官方开源的 GTX8 实现（[`fwupd/plugins/goodix-tp/fu-goodixtp-gtx8-device.c`](https://github.com/fwupd/fwupd/blob/main/plugins/goodix-tp/fu-goodixtp-gtx8-device.c)，作者 `xulinkun@goodix.com`）明确：

```c
/* GTX8 写包 */
hidbuf[0] = REPORT_ID;            // 0x0E
hidbuf[1] = I2C_DIRECT_RW;        // 0x20
hidbuf[2] = (最后一块) ? 0x00 : 0x01;
hidbuf[3] = i;                    // 分块序号
hidbuf[4] = data_sz + 5;          // ★★ GTX8 = +5（16 位地址）；BRLB = +7（32 位地址）★★
hidbuf[5] = I2C_WRITE_FLAG;       // 0
hidbuf[6..7] = addr16 (BE);
hidbuf[8..9] = data_sz (BE);
hidbuf[10..] = data;
```
我们此前照搬 Dell（BRLB）工具的 `+7` ✗ ⇒ 固件把写包当畸形丢弃（**读一直是对的，因为读包 `hidbuf[4] = 5` ✓**）。
改成 `+5` 后：`Col04 OUT -> True`，**回读立即变化** ✓✓ ⇒ **写通道打通**（且不需要先 raw 模式）。

### 10.2 顺带修好的其他环节
- **raw 模式正确序列**（官方）：`{33 00 CD}` **连写 3 次** → `{35 00 CB}` 确认 → 读 0x60CC 校验 `buf[1]==1`
- **命令包格式**（官方 `send_cmd`，与 Dell 表一致，族间共用 ✓）：`REPORT_ID + <op> 00 00 01 01`
  - `0E 13` = 软复位 · `03 03` = 切回 PTP 模式 · `00 10` = switch to patch · `00 11` = start update · `0E 12` = load flash（带 16 位校验和）
- **地址常量**：`CMD_ADDR 0x60CC` · `BL_STATE 0x5095`(期望 0xDD) · `FLASH_RESULT 0x5096`(期望 0xAA) · `FLASH_BUFFER 0xC000` · `0x60DC`=cfg 版本 · `0x452C`=72 字节 fw info（sum8 必须为 0、偏移 9 为 5 字节 PID）
