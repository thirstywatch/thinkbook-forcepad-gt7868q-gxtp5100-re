## 三、明文镜像 `TF100A`：完整身份

### 3.1 地址映射是怎么解出来的（关键步骤）

三步自洽：

1. **找向量表**：全文件扫 `[SP=0x2000xxxx][Reset=0x08xxxxxx|1]` 成对 → 命中 `@0x019ABC`，`SP=0x200076C8`、`Reset=0x08005165`。
2. **穷举基址**：把代码区里所有像 `0x08xxxxxx` 的 4 字节值取出，对候选 `B` 统计「`V-B` 落在包内」的比例 → `B=0x08000000` 得 91.4%（但该判据偏弱）。
3. **用指针跨度反推（决定性）**：向量表里 35 项有效、24 项都是 `0x0800517F`（默认死循环处理函数），真指针跨度 `0x08005151 → 0x08011A68` = 51,479 B。要求所有指针都落进 54,084 B 的明文区，解得 **镜像基址 `0x08005000`**：

```
映射：flash = 0x08005000 + (file_off − 0x19ABC)
自洽验证：
  Reset 0x08005165  → file 0x19C21  （紧跟向量表之后 ✔）
  最小指针 0x08005151 → file 0x19C0D  ✔
  最大指针 0x08011A68 → file 0x26524  ✔
  49 项有效的向量表起点 0x08005000 == 镜像基址 ✔
```

### 3.2 向量表

```
[ 0] 0x200076C8  SP
[ 1] 0x08005165  Reset
[ 2] 0x0800A679   [ 3] 0x08008895   [ 4] 0x0800A449   [ 5] 0x080053F5
[ 6] 0x0800DFE5   [ 7..10] 0            [11] 0x0800BE25   [12] 0x080053F9
[14] 0x0800B75D   [15] 0x0800CE7D  [16..26] 0x0800517F（默认处理函数）
[27] 0x08006B3D   [28..39] 0x0800517F
```
→ 约 50 项有效（一段 49 项的连续 flash 地址），**IRQ 数量多，符合触控控制器**。

### 3.3 镜像开头 = 标准 ARM 运行库

反汇编一眼可辨（这是"解析正确"的最强佐证）：

| flash 地址 | 代码 | 判定 |
|---|---|---|
| `0x08005188` | `00 28` `00 DA` `40 42` `70 47` → `cmp r0,#0` / `bge` / `rsbs r0,r0,#0` / `bx lr` | **`abs()`**（被调用 **56 次**，全镜像最高频） |
| `0x08005190` | `40 EA 01 03` … `08 C9` `12 1F` `08 C0` `04 2A FA D2` | **`memcpy()`**（ldmia/stmia 字循环 + 字节尾巴） |
| `0x080051B4` | `00 F8 01 2B` `49 1E FB D2` | **`memset()`** |
| `0x080051D8` | `0B 78` `00 F8 01 3B` `03 B1 49 1C` | **`strcpy()`** |

## 四、加密区（100 KB）：定性结论

| 测试 | 结果 |
|---|---|
| 整区熵（99,840 B） | **7.998**（理论上限 8.0；真实 Thumb 代码只有 **6.557**） |
| 32 位 / 16 位字节交换 | 熵不变，Thumb 合理性 60% |
| 位反转 / 半字节交换 | 熵不变，66% / 67% |
| XOR 0x00/0xFF/0x5A/0xA5/0x11/0x0F | 熵不变，60–66% |
| 按偏移的滚动 XOR（两种） | 7.985 / 7.993，63% / 66% |
| **对照：明文字段真实代码** | 熵 6.557，合理性 **73%** |
| 原区（未变换） | 63% |

**⟹ 全部简单变换都落在噪声范围（60–67% vs 真实代码 73%）。该区是加密的（或使用了带密钥的强压缩），不是简单置换。**

> 原理提醒：**熵在双射字节变换下不变**，所以能不能解开不能靠熵判断，只能靠**变换后 Thumb 解码合理性是否跳到真实代码水平**。这次没有跳。

## 五、对触控板项目的意义

1. **良性结论**：这颗触控板的固件**第一次被完整拿到并测绘**了 —— 架构（Cortex-M4F）、运行库、向量表、入口、版本、构建时间、包的划分全部明确。
2. **触觉参数不在可读区**：明文 54 KB 是纯代码，无表、无 haptic 字符串。**触觉逻辑与参数在加密的 100 KB 里。**
3. **`TF100A` 这个名字值得注意**：驱动里 `GoodixTpDxe` 把固件分成 **TP** 与 **TF** 两个子系统分别刷写（`GTPCheckTFUpdate`）。`TF100A_Test_FW` 说明这块明文镜像就是 **TF** 那份 —— 但它自称 **Test_FW**，且不含参数表，更像**框架/驱动层**而非带标定数据的量产件。
4. **要往前走，只剩两条路**：
   - **(a) 拿到解密路径**：`GoodixTpDxe` 的刷写流程里有 `enter pass through mode` → `start updating` → `write flash`，说明**解密大概率发生在板内 bootloader**，主机侧只发密文。要拿到密钥，得看主机侧是否有一段"打包/加密"逻辑（在驱动的 FMP 包解析里），或逆向那 100 KB 的头部找算法标识。
   - **(b) 不再碰固件，改走 vendor 命令通道**：寄存器模型已经拿到（`0x100` 写 17 B 命令 / `0x200` 写数据 / `0x300` 读 5 B 状态，命令包头 `01 A1 <24位参数>`，尾 `0xAA`）。**这条路风险更低、离"触发触觉"更近。**

**我的建议：优先 (b)。** 固件加密区不是短期能啃的，而 vendor 通道是现成的、可实验的，且已经知道报文格式。
