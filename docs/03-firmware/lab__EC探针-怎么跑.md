## 三、跑起来会看到什么（提前知道，不慌）

脚本有 **6 个阶段**，每个阶段会先等 0.9 秒再开始采 6 轮。
**屏幕会倒数提示你要做什么**，跟着做就行：

| 阶段 | 屏幕提示 | 你要做的 | 时长 |
|---|---|---|---|
| P1_IDLE | 「不要碰触控板，保持完全静止」 | **什么都别动** | ~10 秒 |
| P2_TOUCH | 「用一根手指**轻轻放在**触控板上」 | 手指轻放，**不要按** | ~10 秒 |
| P3_LIGHT | 「轻点（力度小于点击阈值）」 | 轻轻点一下 | ~10 秒 |
| P4_HARD | 「**重压**（会触发震动）」 | 用力按下去，**感受震动** | ~10 秒 |
| P5_HOLD | 「保持重压不放（按住 3 秒）」 | 按住别松，**保持震动** | ~10 秒 |
| P6_IDLE2 | 「松开，回到完全静止」 | 松手 | ~10 秒 |

**要点：每个阶段从屏幕出现提示那一刻就开始数 3 秒再动**，这样第一轮采到的才是"已动作"状态。

## 四、结束后看哪里

结果自动存到：
```
touchpad-lab\poc\ec-haptic-<时间戳>.txt
touchpad-lab\poc\ec-haptic-latest.txt     ← 看这个
```

**关键看最后的「判定」段**，会给出三档之一：

| 判定 | 含义 | 下一步 |
|---|---|---|
| **★ A强**（重压+保持都变） | **EC 直接参与震动链路** | EC 线立起来了 ⇒ 值得去解那 3 MB EC 固件 |
| **B中**（只有重压变） | 可能是压力阈值判断或震动状态位 | 有信号，但要再跑一次确认 |
| **C弱**（只有轻触变） | 更可能是接触抖动 | 不算证据 |
| **⚠ 全零** | 按压时 EC RAM 无任何变化 | **EC 线基本可关**，不必解固件 |

---

## 五、如果结果全是"无变化"，怎么读

⚠️ **不等于 EC 一定不参与**。可能是：

| 可能 | 下一步 |
|---|---|
| 采样太稀/动作太弱 | 改参数重跑：`.\ec-haptic-probe.ps1 -Rounds 15 -GapMs 40` |
| P5 改成"按住 5 秒" | 把 `-SettleMs` 调大，让动作贯穿整个采集 |
| EC 不经 RAM 走，直接驱动硬件 | 只能靠抓 HDP/HDN 波形或 I²C 抓包 |

**所以判据是"找到了强信号"而不是"没找到"。** 没找到只说明这条判据不够灵敏。

## 六、脚本的只读保证

| 保证 | 机制 |
|---|---|
| 不写 EC RAM | 只用 `RD_EC`(0x80) 握手读；**没有一条 `0x81`(写 EC) 命令** |
| 不写其他寄存器 | 只碰 `0x62`(数据口) / `0x66`(命令口)，且命令字恒为 `0x80` |
| 不运行刷写程序 | 不碰 `NJME*.exe` |
| 需要管理员 | 只为访问 I/O 端口，不是为了改配置 |

**可自行核对**：打开 `ec-haptic-probe.ps1`，搜 `PioWrite` 的所有调用点 ——
你会看到只有 `0x80`（RD_EC）和偏移值被写，**没有任何写 EC 数据的命令**。
