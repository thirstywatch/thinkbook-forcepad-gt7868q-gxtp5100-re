## 四★★ 本轮做了什么（EC 固件结构定位 —— 有实质进展）

### 4.1 PE 结构已解出

```
NJME01WW.exe / NJME07WW.exe
  Delphi/Pascal 打包器（'This program must be run under Win32' + AnsiChar/Cardinal/NativeInt…）
  PE @0x100, 10 节, SizeOfOptionalHeader = 224(0xE0)
  .text  0x23C00 @0x400   .rsrc 0x3800 @0x28800
  节表结束 = 0x2C000
  ⇒ overlay：NJME01 = 3,132,000 B  /  NJME07 = 3,167,744 B
```

### 4.2 ★ payload 是【加密】，不是压缩 —— 但已定位

| 检查 | 实测 | 判决 |
|---|---|:--:|
| overlay 熵 | **7.999 / 7.999** | 🔴 **加密或强压缩**（真随机 = 8.0）|
| 两版逐字节相同率 | **0.39%** | 🔴 **精确等于随机基线 0.391%** ⇒ **两版明文完全不同** |
| 最长公共前缀 | **仅 6 字节** `7A 6C 62 1A 1A E1` | ⇒ 之后立即分叉 |
| 自相关 lag=1024 / 4096 | 0.38% / 0.43% | ⇒ **无周期性**（不是 §19.2 那种 1024 周期加扰）|
| `.text` 里的解压函数 | **`LZMADecompSmall`** · **`DecompressInto`** · `WriteBuffer` | ⚠️ **说明流程是"解密 → LZMA 解压"** |

**⇒ 判定：overlay = 加密 + LZMA 压缩 两层。**
**⇒ `.text` 里有 `LZMADecompSmall` ⇒ 解密后应该是标准 LZMA stream ⇒ 可解。**
⚠️ 本轮直接对 overlay 试 `lzma.decompress` 全部失败 ⇒ **必须先解密**。

### 4.3 🔴 本轮没做到的事（诚实标注）

| 项 | 状态 |
|---|---|
| 解出 EC 固件 payload | ❌ **未完成** |
| 找到解密算法 | ❌ **未完成**。`LZMADecompSmall` 给了"先解密后解压"的方向，但**具体算法（XOR 密钥？LCG？表驱动？）没定位** |
| EC 固件里有无触觉代码 | ❓ **未知**（取决于上一项）|

**⚠️ 不做的事：**不会去动态调试这个 exe（有 GUI 交互、会写 flash 风险）。

## 五★★★ 下一步（三条，按性价比排序）

### 5.1 ★★★★★ **零风险、零新工具：把 EC RAM 差分实验做完**（最该先做）

**为什么这是最该做的：**`ec_diff.ps1` 已经跑通了，**但差分结果从没被分析过**。
它能直接回答"按压时 EC RAM 有没有变化"，**而这正是 EC 控制震动与否的直接判据。**

```
已有：ec_diff.ps1（基线 3 读多数表决）+ LpcACPIEC 读取能力
待做：
  ① 静置状态读 N轮 → 确认哪些偏移"会自己变"（噪声）
  ② 轻点触控板瞬间 读 N 轮
  ③ 重压（超过点击阈值）瞬间 读 N 轮
  ④ 差分 → 找"只在按压时变、且变il幅度大"的偏移
  ⑤ 对候选偏移做第二次验证（同一偏移、多种按压方式，看是否一致出现）
```

**判据：**
| 观察 | 判决 |
|---|:--:|
| 找到**若干偏移，只在按压时变** | ★★★ **EC 直接参与了按压/震动** ⇒ EC 线立起来 |
| 找不到任何按压相关偏移 | ⚠️ EC 不参与震动（但不能完全排除，需要更多次数/更强激励）|

★ **这一步的价值**：它**不需要解 EC 固件**，只要 8KB EC RAM 的读权限（已具备）。
**成本约 20 分钟。** 而它能一次性决定"要不要去解那 3 MB 的加密 payload"。

### 5.2 ★★★★ 定位 `NJME*.exe` 的解密算法（若 5.1 有信号才做）

**可执行的切入点（本轮已铺好路）：**
```
1. .text 只有 0x23C00 B（145 KB）⇒ 人工可读
2. 已知它是 Delphi + LZMADecompSmall + DecompressInto
3. 入口思路：找调用 LZMADecompSmall 的那个函数 ⇒ 它的上游就是解密循环
4. Delphi 可用工具：Ghidra/IDA 的 Delphi 签名，或直接看调用图
5. 关键：overlay 前 6 字节在两版完全相同 ⇒ 头里很可能有"原始长度/校验"等定值字段
        ⇒ 可用它当已知明文，攻第一层
```

★ **一个更省力的思路**：既然 overlay 是"加密+LZMA"，
**先假设加密是 XOR 类的简单流密码**，用前 6 字节的重复性 + LZMA stream 的头部特征
（首字节通常是 `5D`、随后 4 字节是 dictsize=2^n）当已知明文做频率/异或分析。
（本轮试过直接 LZMA 解压全部失败，说明确实需要先解密。）

### 5.3 ★★★ 用蓝莓那句"振动跟触摸用的两套控制"重新审视旧数据

`追加十五` 有一条**一直没被用起来的实测数据**：
> **"强度写入零影响，但反推转发通道存在"**

★ **"两套控制"这句话，可能正好解释这条旧数据** ——
如果震动是 EC 独立控制的一整套，**那么写 GT7868Q 的 `0x0E/0x23`（touchpad 侧的 intensity）
本来就不该有效果** —— 它压根不是控制震动的那一套。

⚠️ **这条必须实测验证，不能推理**：
```
若 EC 控制震动 ⇒ GT7868Q 的 Intensity 写了没用（符合旧数据）
若 GT7868Q 控制震动 ⇒ Intensity 该有效果（与旧数据矛盾）
⇒ 需要区分"GT7868Q→AW86927"与"EC→LRA/HDP"这两条路是否都存在
   —— 这正是 5.1 的 EC RAM 差分能回答的
```
