# TF100A 固件镜像完整性独立验证报告

> 全部结论从二进制直接验证，未引用任何项目文档结论。目标文件只读、未做任何修改。

## 1. 文件实际大小与分段结构（已验证）
- 目标文件 `TB14P_GT7868Q_14030522_20240202.BIN` = **161,628 字节**（0x2775C）。
- 扫描无 zstd 等压缩帧；全文件仅一处合法 Cortex-M 向量表，位于偏移 **0x19ABC**（105,148）。
- 真实分段：`[0, 0x19ABC)` = 105,148 字节（容器/前导数据）+ `[0x19ABC, EOF)` = **56,480 字节**（TF100A 镜像，因 161,628−105,148 = 56,480，正好等于任务给定"约 56,480"）。
- 与流传"1084+3328+100608+56608"对比：总和虽同为 161,628，但其第 4 段"56608"**多算 128 字节**（把 vtable 前 128 字节零填充也算进镜像）；真正镜像起点是向量表，故为 56,480 而非 56,608。该 128 字节差异可复现。

## 2. 明文载荷头部 / 有无长度字段（已验证）
- 明文 TF100A 载荷 = 文件末尾 56,480 字节，起始即向量表。
- 头部 64 字节：`C8 76 00 20 65 51 00 08 79 A6 00 08 ...`，即初始 SP、复位向量等，**无任何长度字段、分片头、版本号、校验和**。
- vtable 之前 64 字节**全为 0x00**（纯填充/对齐），**没有任何位置声明"镜像总长度"**。（推测：该镜像依赖 flash 容量而非内嵌长度。）

## 3. ★ 镜像末尾字节模式（已验证，关键 dump）
末尾 256 字节**不是** 0xFF/0x00 规律填充，而是真实 Thumb 代码：
```
2774C: 00 20 1C 3B 00 20 70 3F 00 31 00 00 00 00 00 00
```
末 2KB 中 0xFF 仅 3 字节、0x00 仅 23 字节；字节 0x3E 高频出现（末 1KB 187 次）= 大量 `SUBS r6,#imm`。
**结论：镜像在中途代码处断掉，并非自然结尾**（STM32 未用 flash 应为 0xFF，此处没有）。

## 4. 向量表分析（已验证）
- 初始 SP = `0x200076C8`：落在 STM32F1 的 SRAM 范围（0x20000000+），**合理**。
- 复位向量 = `0x08005165`：指向 flash 内、带 Thumb 位，**合理**。
- **越界向量：vec[6]（UsageFault）= `0x0800DFE5`，超出镜像末尾 0xDCA0 共 0x345 = 837 字节**。其余前 16 项（复位/NMI/HardFault 等）均在镜像内；index>16 的"越界"是把后续代码字节误读为向量，非真实向量。

## 5. 独立结论
**该 TF100A 镜像不完整（被截断）。** 依据（全部已验证）：
1. 末尾是代码而非 0xFF 自然结尾；
2. 末尾附近 `0x800D8AE: b #0x800DF5A`，目标超出镜像末尾 698 字节——存在指向不存在字节的分支；
3. vec[6] 指向超出 837 字节处。

**缺多少（已验证下界）：** 至少 **837 字节**（使 vec[6]=0xDFE5 合法），取整到下一边界约 **864 字节**（0xE000=57,344）。
**流传"缺失 5,141 字节"在二进制中无任何支撑**——头部无长度声明，实测越界量仅约 0.8–0.9KB。
**推测：** 原镜像可能按 flash 边界打包（如 64KB 则需补 ~9,056 字节），但无法从二进制唯一确定原始大小。5,141 这一数字应属误判。
