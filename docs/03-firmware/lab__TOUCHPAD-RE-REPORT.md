# 第一部分 · 全貌

## 1.1 需求边界

| 要什么 | 不要什么 |
|---|---|
| 手指沿边缘滑动时**连贯**震动（滑多久、震多久） | 单纯「点按震一下」 |
| **触控板本体**震 | 掌托/底盖震 |
| 在**这台笔记本**上用 | 外接一块独立触控板 |

**需求这一条决定了后面所有取舍**：外置马达（方案 A）隔着模组外壳，手指感受不到 ⇒ 直接出局；要「本体震」就必须碰到模组内部或它的链路。

## 1.2 这件事的本质：一道证明题，不是工程题

这块触控板属于 **device-initiated（设备自主触发）** 的触觉设备：

```
手指按压 → 力传感器 → 芯片内部判断「够不够重」 → 芯片自己驱动 LRA 震
                ↑
        判断发生在设备内部，且发生在数据上报给主机之前
```

主机（Windows）在这条链路上**只是接收方**：
- 设备在 HID 描述符里声明自己有哪些能力，主机**只能在这些能力范围内操作**；
- 这块板的 PTP 集合 `OutputReportByteLength = 0` —— 它明确告诉主机「我不接收下行命令」。

**⇒ 所以「纯软件能不能做到」这个问题，答案由设备决定，不由 Windows 或我们的努力程度决定。** 这也解释了为什么后面所有软件路径都会撞同一堵墙。

## 1.3 系统拓扑（由外到内）

```
笔记本
 └─ Intel I2C 控制器            PCI\VEN_8086&DEV_7E78
     └─ 触控板模组               ACPI\GXTP5100 · VID 27C6 / PID 01E9 · I2C-HID
         ├─ 汇顶 GT7868Q         触摸 + HID 主控          固件【加密】
         ├─ 钛方 TF100A          力度感应 + 触觉控制      固件【明文】
         └─ LRA 线性马达         驱动线 HDP / HDN（焊盘裸露）
```

| 层 | 角色 | 对主机是否可达 |
|---|---|---|
| Intel I2C 控制器 | 总线主机 | 可达（但这层以下全受设备约束） |
| 汇顶 GT7868Q | 触摸、压力上报、HID 主控、**Col04 厂商通道的接收方** | 可达 |
| 钛方 TF100A | 力度判定 + 驱动 LRA | **不可达**（被 GT7868Q 挡在模组内部） |
| LRA | 执行器（振动） | **物理可达**（驱动线焊盘裸露） |

**这张图是全篇的骨架**：所有「某条路走不通」的结论，本质都是「目标对象在这一层够不到」。

## 1.4 触控板对外暴露的四个 HID 集合

| 集合 | 用途 | 输入 | 输出 | 特征 |
|---|---|---|---|---|
| `Col01` | 鼠标兼容接口 | in=9 | — | 监听被拒（`err=5`） |
| `Col02` | **PTP 精确式触控板** | in=40 | **out=0** | 被系统独占（`err=32`）；feat=737 |
| `Col03` | 配置集合（mtconfig） | **in=0** | — | 纯 Feature 集合，**结构上不可能发输入报文** |
| `Col04` | **厂商集合** | in=65 | out=65 | rid=`0x0E`；唯一的下行通道（见 §2.1） |

# 第二部分 · 分层结论（由外到内）

> 每层给出：**结论 → 依据 → 状态**。全部路径均已闭合，无悬而未决的软件路径。

## 2.1 第 1 层：主机软件接口 —— 封死

| 路径 | 结论 | 依据 |
|---|---|---|
| HID 通道触发震动 | **不可能** | ① 实测：`Col02 out=0`，Haptics page `0x0E` 下**只有 `Intensity` 一个控件**；② 微软规范：主机触发**必须**有 `Manual Trigger (0x0E/0x21)` 输出报表，本机没有；③ Linux 上游 Rong Zhang 的 RFC：device-initiated 压力板只暴露 Intensity，**不提供主机主动触发**；④ 阳性对照：连写 6 个强度值，力度确实变化但**一次都没震** |
| `Col04` 厂商通道 | **可见但无出口** | 可读可写（见 §3.5），但可用命令空间里没有震动命令（§2.3） |
| 其它集合 | **无隐藏通道** | `Col01` 拒绝访问、`Col03` 无输入报表、`Col02` 被系统独占（持有者是内核组件，非用户态进程） |

## 2.2 第 2 层：主机侧其它通路 —— 封死

| 路径 | 结论 | 依据 |
|---|---|---|
| ACPI / EC 通路 | **不存在** | 本机 34 个 ACPI 设备全量枚举，无一与触觉/力感相关；EC（`PNP0C09`）存在但**无任何子设备** |
| 驱动栈逐层（应用层 / HID 类驱动 / I2C-HID 传输 / 裸 I2C） | **约束来自设备，不在 Windows** | HID 是「设备描述自己」的协议：描述符里没声明的能力，从应用层到传输层**哪一层都发不进去** |
| BIOS 内取容器解析器 | **不存在** | BIOS 镜像 `NJCN67WW_FWUpdate.bin`（4.34 MB，Intel FPT）全镜像 **0 个** `Goodix/GXTP/TB14P/7868` 字符串、0 个固件 GUID |
| 公开渠道补固件 | **四轮穷尽** | Windows Update Catalog（仅 3 个版本，同构的只有手上那份）· LVFS · 各 OEM 官网 · GitHub · 网页索引 |

## 2.3 第 3 层：设备固件（Col04 命令空间）—— 封死

**先把边界解出来**（对 TF100A 明文固件静态反汇编，未碰设备）：

- 分发器在 `0x080091C0`，由主循环驱动，判定 = **类字节 + 一个 16 位子命令**（取值形如 `0xNN00`）
- 类只有 3 个：`0x80`（疑数据写入）、**`0xA0`（16 个合法值）**、**`0xA1`（22 个合法值）**；`0xA2` 是回复类
- 边界外的值 = 静默 no-op（无害）

**再在真机上打这一发**（用户当场授权）：

| 步骤 | 结果 |
|---|---|
| 发一条 `0xA1` 帧（`0E A1 00 0B 05 01 18 00 00 1B`） | `send = True  err=0`（写被接受） |
| 立刻读 | Col04 全部访问阻塞；恢复后纯读 **六种长度全部 `err=122`**，持续 ≥3 分钟 |
| **有没有 `0xA2` 应答** | **没有** |
| 类 `0x20` 读帧还能用吗 | **能用，数据正常** ⇒ 通道没坏，`122` 只是「当前没有可交付的应答」 |

**关键对照**：工区既有日志显示，**类字节全扫 `0x00–0x2F`** 时，`0x0E`、`0x0F`、`0x14`…`0x2F` **连续 28 个类全部返回 `err=122`**。

> **⇒ `err=122` 是「这个类没被处理」的默认应答，不是 `0xA1` 特有的反应。**
> **⇒ 假设 H1（GT7868Q 会不会把 `0xA1` 转发给 TF100A）判为：否。**
> **⇒ 整条主机侧 Col04 扩展路径作废**，子命令字节序（H2）也不必再打。

## 2.4 第 4 层：加密与容器 —— 封死

（细节见 §3.1–§3.3）结论：

| 问题 | 答案 |
|---|---|
| 固件加密了吗 | ⚠️ **【旧结论，已被推翻】**~~**是**。载荷 100,352 B，熵 8.00，**128 位分组密码 + 位置无关（ECB 式）**~~<br>🔴 **2026-10-02 终审**：它是 **1024 字节周期的位置型 XOR 加扰**（`plain[x]=raw[x]^K[(x+316)%1024]`），**不是分组密码，且已解出**（K 表随仓库公开在 `data/reference/K_gt7868q.bin`）。周期是 **1024**，不是 16。
| 能在主机侧破解吗 | **不能**。无密钥、无 IV、无已知明文对；排除了「16 字节循环 XOR」这种可破形式 |
| 密钥在哪 | **在芯片内**。三路独立证据：容器格式无密钥字段 / 两个主机侧工具都无加解密实现 / Dell 刷写器的写路径是明文内存写 |
| 这对目标有影响吗 | **没有**。加密只挡住「改芯片固件」这条本来也不该走的路 |

## 2.5 第 5 层：硅片与执行器 —— **唯一开着的门**

| 项 | 事实 |
|---|---|
| 执行器 | 模组内**一颗 LRA**（线性谐振马达） |
| 驱动线 | **`HDP` / `HDN` 两个裸露焊盘**，丝印清晰 |
| 可达性 | 焊盘**从金属支架开口朝机内露出** ⇒ **拆底盖即可接触，不必拆开模组本体**（标准无损操作） |
| 已知驱动参数 | 振幅 **119** · 周期 **999 / 1999** · PWM `ARR=700/CCR=96` 与 `ARR=1999/CCR=119`<br>🔴 **2026-10-02 更正**：这些**不应再读作“LRA 驱动参数”** —— TF100A **没有 PWM 输出路径**（20,314 条反汇编里运行期写 `TIMx_CCR/CCER/CR1` = 0 条），它们只是 TF100A 自己的**定时器/采样节拍**配置

**为什么这层是门**：LRA 就是个音圈马达、两根线。接管这两根线之后，**震不震、震多密、震多强完全由自己的驱动电路决定，不受原装固件限制**。

**为什么之前那三条「内层」路线反而不如它**：
- 路线 ①（排线上 MCU 截获报文）：依赖「GT7868Q 会转发」这个未验证前提 —— 已被 H1 判否；
- 路线 ②（GT7868Q ↔ TF100A 之间注入）：同样依赖转发，且需要先知道片间协议（在缺失的固件尾段里）；
- 路线 ③（直接驱动 LRA）：**不需要懂任何协议、不需要破解任何芯片。**

## 3.3 加密强度定案

| 检验 | 结果 | 推论 |
|---|---|---|
| 密文按 16 字节切出重复块，其**字节偏移 mod 16** | 分布 = `[(0, 818)]`，其余 15 个余数**全为 0** | **16 字节分组密码 + 位置无关（ECB 式）**，无 IV/salt |
| 用本机 5,591 个密文块撞 2020/2021 代同族固件 | **15.1% / 14.8%** 命中（按体积 23.8% / 23.6%） | **同一把密钥，跨版本跨板型，四年未换** |
| 各余数类的字节分布偏斜度（K=8/16/32） | 0.7% / 0.9% / 1.3%（随机基线 0.4%） | **排除「短周期 XOR」** ⇒ 是真分组密码 |
| 明文结构是否泄露 | 自相关在 1024/2048/4096/8192/16384/32768 处有峰（5–7%） | 明文的重复格局原样留在密文里（ECB 的特性） |

## 3.5 Col04 读通道的语义与观察方法（逆向工具层面的资产）

- **v1**：`0E 20 00 00 05 01 <addr16BE> <size16BE>`，长度上限 60
- **v2**：`0E 20 00 00 07 01 <addr32BE> <len16BE>`，其中 **`addr32 = (字节偏移 << 16) | 读取字节数`**
- v1 与 v2 是**同一存储的两种取址形式**，结果逐字节一致；长度 0 被拒（`err=122`），>60 封顶
- **★ 观察方法学**：**纯读**（`GetInputReport(0x0E)`，不发任何帧）就能拿到响应寄存器里「上一条应答」的完整内容，**可重复读、不被消耗**
  ⇒ 以后所有「发一条、看回什么」的实验，标准姿势是：**纯读基线 → 发帧 → 恢复后纯读 → 比对**，不再需要并发监听那套易错设计

# 第四部分 · 认知修正史

> 逆向过程里被推翻的判断。**保留这些比保留结论更重要** —— 它们标出了「哪一类推理容易出错」。

| 曾经的判断 | 现状 | 为什么错 |
|---|---|---|
| 「固件缺 5,141 字节」 | **误判**：下界 837 字节，且性质是「镜像引用了地址空间之外的地址」，**文件本身无缺字节** | 那个 5141 来自一处 `movw/movt` 常量，**该常量在镜像里从未被当字面量使用**；且被四层文档转述无人复核 |
| 「解密容器无用 —— 主机接口代码本就在明文段」 | **理由错**：Col04 命令处理在 GT7868Q 的**加密段**里 | 写这句话时还没分清两颗芯片的分工 |
| 「BIOS 区是压缩/加密的」 | **错**：Insyde 自家容器，组件**明文** | 用标准 FFS 特征去搜 Insyde 容器 ⇒ 0 命中被误读成「加密」 |
| 「AES + eFuse 验签，改固件是单程门」 | **验签部分作废** | 依据是汇顶 **GR5xx（BLE SoC 族）** 文档，而该文档的方案是 **PRESENT-128 + ECC P-256**（不是 AES），且明确**不含** GT9xxx 触控控制器。加密本身是真的（实测），验签从未被证实 |
| 「`A1` 帧被处理了，不是 no-op」 | **过度解读** | 后来发现 `err=122` 是**未处理类的默认应答**，几十个类都是这个结果 |
| 「TF100A 是汇顶的芯片」 | **错**：是**北京钛方科技**；那颗二维码属于 GT7868Q | 丝印与型号未核实就下了结论 |
| 「样机实验必须的」 | 用户的判断更对 | H1 那一发在真机上跑完了，代价是几次可自愈的卡顿 —— 而样机（¥100）本来要等好几天 |

## 6.2 方案 ③ 的工程要点（这是接下来真正的活）

| 要点 | 说明 |
|---|---|
| **驱动争抢（必须先解决）** | `HDP`/`HDN` 接在 TF100A 的输出上。自己驱动时若 TF100A 也在驱动，轻则波形互相拉扯，**重则烧驱动** ⇒ 必须用模拟开关/继电器做**互斥切换** |
| 机械空间 | 引线不得妨碍触控板形变（压力靠形变测量），装回后手感与行程不能变 |
| 谐振频率 | LRA 必须按谐振频率驱动才高效 ⇒ **要实测**（这是「连贯」的前提） |
| 连贯节拍 | 每隔多少距离触发一次、间隔多密。注意 LRA 起振/停振约 10–20 ms ⇒ 密度有下限，手感会比华为（压电陶瓷，亚毫秒级）**略粗** |
| 与原生功能共存 | 原生点按震动要保留 ⇒ 切换逻辑要设计好 |
| 试错场地 | **所有试错先在料板（同型号模组，¥100 上下）上做完，真机只做一次已验证的操作** |

## B. 红线（操作纪律）

1. **禁止整段快照**（683 次连发读）—— 这是两次触控板冻结的直接原因
