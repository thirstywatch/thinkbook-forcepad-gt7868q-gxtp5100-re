# TF100A 输出端反向追溯 —— 从"震动"追到引脚（结论：终点是 I²C 回复 + PA3 门铃）

> 触发：用户要求「从输出端反向追：输出写哪个外设/引脚？门控标志有哪些？39 个 handler 里谁能写到？」

## 〇、一句话结论

> ## **那条链的终点不是马达，是【I²C 回复帧 + PA3 门铃】。**
> ## **TF100A 固件里没有任何一条指令写马达/定时器/PWM。**
> ## **`0x0B00` / `0x0D00` 的"触觉"标签，两处都需要改。**

## 一、★ 输出端点：它到底写什么

### 1.1 全线只写这几样（外设写清单，实测）

| 外设 | 写点 | 说明 |
|---|---|---|
| **GPIOA `0x40010800`** | `0x08005D0A` 等（经 HAL）· **`0x0800D8B2` + `bl 0x0800F7FC`** | ★ 引脚操作 |
| I2C1 `0x40005400` | `0x08008B68`（初始化）· `0x08008AE4`（TXE） | 对 GT7868Q 发帧 |
| USART1 `0x40013800` | `0x0800DD40` 等 6 处 | 另一条独立链路 |
| DMA1 `0x40020000` | `0x08006B3C` 等 | 搬运 |
| RCC `0x40021000` | 时钟使能 | — |
| FLASH `0x40022000` | 擦写 | — |

### 1.2 ★★ 门铃那一条（唯一与"输出到引脚"相关的）

```asm
0800D8AE  movw  r0, #0x800
0800D8B2  movt  r0, #0x4001        ; r0 = 0x40010800 = GPIOA
0800D8B6  movs  r1, #8             ; bit3 = PA3
0800D8B8  bl    #0x800f7fc
```
```asm
0800F7FC  sub  sp, #8
0800F7FE  str  r0, [sp, #4]        ; r0 = GPIOA 基址
0800F800  str  r1, [sp]            ; r1 = 0x08
0800F802  ldr  r0, [sp]
0800F804  ldr  r1, [sp, #4]
0800F806  str  r0, [r1, #0x14]     ; ★ GPIOA_BRR = 0x08 ⇒ 拉低 PA3
```

**⇒ 这就是全项目文档里说的「PA3 门铃」。**
**⇒ 它是 TF100A 唯一的"对外引脚动作"，作用是**通知 GT7868Q「我有一帧要给你」**，不是驱动任何执行器。**

### 1.3 ★★★ 没有任何一条指令写马达/定时器/PWM

- 全 asm **没有** `TIMx_CCR` / `TIMx_CCER` / `TIMx_CR1` 的运行期写（TIM3 回调 `0x0800D6F4` 只做 `[0x200040D0+0x10]++`）
- 全 asm **没有**马达/振动相关外设（压电、H 桥、boost）
- **唯一对外输出 = I²C 回复帧 + PA3 门铃**

## 二、★★★ 完整的输出链（逐指令，从头到尾）

### 2.1 链路总览

```
【主机】0xA0/0x0D00 ──▶ 模式=4 + armed=1 + 清上下文
                              │
                    （主循环下一轮）
                              ▼
   任务① 0x08007470  门控：mode==4 且 armed==1
     │  子门控：[0x2000403C].bit0（压力快照有效位）
     │  子门控：[ctx+0x168f]（前置完成位）
     │  累加 4 通道差值，判 >= 0x28
     ▼
   ★ 检测引擎 0x080059E0(r0=[0x2000403C+0xA], r1=ctx, r2=0xAF)
     │  门控：r2(0xAF=175) <= 0x2BC(700)
     │  门控：[ctx+0x168A] == 0（未在采集）
     │  ① 4 通道压力快照入环形缓冲
     │  ② 逐通道比较：新值 > 旧值 + 0x28 ？        ← ★ 判据
     │      命中 ⇒ [ctx+0x15E4]=1（detected）
     │              [ctx+0x15E6]=环形索引
     │  ③ detected==1 ⇒ 采集 20 个点入环形缓冲
     │      采满 ⇒ bl 0x08005E38                  ← ★ 输出例程
     ▼
   ★ 输出例程 0x08005E38
     │  把环形缓冲展开成 4 通道 × 20 时间点
     │  写入 ctx @0x2000495E
     ▼
   A1 查询族（22 条）取走
     ▼
   A2 回复帧 ──I²C1──▶ GT7868Q
     + PA3 拉低（门铃）
```

### 2.2 检测引擎 `0x080059E0` 的判据（原文）

```asm
080059F0  cmp.w   r0, #0x2bc          ; r2(输入计数) <= 700 才继续
080059F4  ble     0x80059fa
...
080059FA  ctx[0x168a] 读到 r0
08005A02  cmp   r0, #0                 ; 非 0（正在采集）就跳过
08005A04  bne.w 0x8005b12
08005A0A  bl    #0x800b760            ; 快照当前 4 通道压力
08005A16..5A58  循环 4 通道：把 [0x2000403C + i*2 + 2] 写入环形缓冲
08005A8A  ldr   r1, [sp, #0xc]        ; r0 参数 = [0x2000403C+0xA]
08005A8C  ldrh.w r1, [r1, r2, lsl #1] ; 上一帧该通道值
08005A90  adds  r1, #0x28             ; ★★ + 40
08005A92  cmp   r0, r1                ; 新值 vs 旧值+40
08005A94  bgt   #0x8005ac4            ; ★★ 触发
...
08005ABC  subs  r1, #0x28             ; ★★ - 40（另一侧）
08005ABE  cmp   r0, r1
08005AC0  bge   #0x8005ade
08005AC2  b     #0x8005ac4            ; ★★ 触发
...
08005AC4  ; 触发分支
08005ACC  movw  r2, #0x15e6
08005AD0  strh  r0, [r1, r2]          ; 记下触发时索引
08005AD4  movw  r2, #0x15e4
08005AD8  movs  r0, #1
08005ADA  strb  r0, [r1, r2]          ; ★ detected = 1
...
08005AEC  ctx[0x15e4] == 1 ?
08005B02  strh  r0, [ctx+0x168c]      ; 清
08005B0C  strb  r0, [ctx+0x168a]      ; collecting = 1 ⇒ 开始采集
...
08005B58  strh  r0, [r1, #0x28]       ; 采样点入环形缓冲
08005B6A  ctx[0x15e2]++               ; 环形索引
08005B78  adds  r0, #0x13             ; +19
08005B7E  cmp   r0, r1                ; 采满 20 个？
08005B8C  bl    #0x8005e38            ; ★★★ 调用输出例程
```

**⇒ 判据精确定义：`|当前压力值 − 上一帧压力值| > 40`（`0x28`），逐通道，任一命中即触发。**

### 2.3 ★ 三个任务**共用**同一个检测引擎

| 任务 | 入口 | 模式 | 调用点 | 参数 |
|---|---|---|---|---|
| ① | `0x08007470` | **4** | **`0x080075A4`** | `r2 = 0xAF` |
| ② | `0x08009780` | **1** | **`0x08009896`** | — |
| ③ | `0x0800A050` | **3** | **`0x0800A168`** | — |

⇒ **`0x080059E0` 不是"某一级的私有链"，是三任务共用的检测引擎。**
⚠️ 这纠正了 10.4.1 的框架：那里把它讲成"压力→判据→采集→打包→PWM→时序"一条纵链。

## 三、★ 输出例程 `0x08005E38` 全文（终点在这里）

```asm
08005E38  sub   sp, #8
08005E3A  strh.w r0, [sp, #6]         ; 入参 = 触发时的环形索引
08005E3E  movs  r0, #0
08005E40  strh.w r0, [sp, #4]
08005E46  ldrh.w r0, [sp, #4]
08005E4A  cmp   r0, #0x13             ; ★ 20 次（0..0x13）
08005E4C  bgt   0x8005eda             ; 出口
08005E50  ldrh.w r0, [sp, #6]
08005E54  adds  r0, #1
08005E56  strh.w r0, [sp, #6]
08005E5A  ldrh.w r0, [sp, #6]
08005E5E  movw  r1, #0xcccd
08005E62  movt  r1, #0xcccc
08005E66  umull r2, r1, r0, r1        ; ★ 除法魔数
08005E6A  lsrs  r1, r1, #4
08005E6C  add.w r1, r1, r1, lsl #2
08005E70  sub.w r0, r0, r1, lsl #2    ; r0 = idx % 20（环形回绕）
08005E74  strh.w r0, [sp, #6]
08005E78  movs  r0, #0
08005E7A  strb.w r0, [sp, #3]
08005E80  ldrb.w r0, [sp, #3]
08005E84  cmp   r0, #3                ; ★ 4 个通道（0..3）
08005E86  bgt   0x8005ecc
08005E8A  ldrb.w r1, [sp, #3]
08005E8E  add.w r0, r1, r1, lsl #2
08005E92  movw  r3, #0x495e           ; ★ ctx 基址 = 0x2000495E
...
08005ED4  strh.w r0, [sp, #4]
08005ED8  b     0x8005e46
08005EDA  add   sp, #8
08005EDC  bx    lr
```

**⇒ 它把环形缓冲展开成 `4 通道 × 20 时间点` 写进 `ctx(0x2000495E)`。**
**⇒ 全程只在 RAM 里搬数据，不碰任何外设。**

### ★ 唯一调用点

```
0x08005B8C  bl #0x8005e38      ← 全 asm 仅此一处
```

## 四、★★ 门控标志全景（回答"哪些内存标志门控它"）

### 4.1 门控链（按层次）

| 层 | 标志 | 地址 | 谁置 | 谁读 |
|---|---|---|---|---|
| 1 | **模式字节** | `0x20004094`（=`0x20004090+4`） | 见 4.2 | 主循环 `0x0800FDC8` · 三任务自证 |
| 2 | **`armed`** | `0x20005FEE`（=`ctx+0x1690`） | 见 4.3 | **三任务入口**（每任务第一件事） |
| 3 | 压力快照有效位 | `0x2000403C` bit0 | 采样链 | 任务① `0x080074A6` |
| 3' | 前置完成位 | `ctx+0x168F` | 任务①自置 | 任务① `0x080074F4` |
| **3''** | **触发累计阈值** | 4 通道差值累加 vs **`0x28`=40** | 任务① `0x08007564` | — |
| 4 | **入口计数门** | `r2` 参数 vs **`0x2BC`=700** | 调用方 | 引擎 `0x080059F0` |
| 5 | **`detected`** | `ctx+0x15E4` | **引擎** `0x08005ADA` | 引擎 `0x08005AEE` |
| 6 | **`collecting`** | `ctx+0x168A` | **引擎** `0x08005B0C` | 引擎 `0x08005A02` |
| 7 | 环形索引 | `ctx+0x15E2` | 引擎 `0x08005B72` | 引擎 `0x08005B6E` |
| 8 | 触发点索引 | `ctx+0x15E6` | 引擎 `0x08005AD0` | 输出例程入参 |
| — | 采样窗口开 | `ctx+0x1691` | `0x0A00`/`0x1300`(`0x08009A16`) | `0x08005BB8` |
| — | 累积完成 | `ctx+0x1692` | `0x08005C4E` | `0x08008794`（取走→`A2 10 <16B>`） |
| — | `0x0D00` 门控 | `0x2000495D` | 14 处引用 | `0x0D00` 入口 `0x080086BE` |

### 4.2 ★ 谁能写"模式字节"`0x20004094`

**只有 4 条 `0xA0` 命令：**

| 命令 | 写入值 | 机制 |
|---|---|---|
| **`0xA0/0x0D00`** | **4** | `0x0800D6C2` 直接 `strb #4` |
| **`0xA0/0x0E00`** | 1 或 2 | 经 `0x0800BE28`，看 `msg[4]` |
| **`0xA0/0x1100`** | 1 或 2 | 同上 |
| **`0xA0/0x1F00`** | 3 | 同上（`sel=2, msg[4]==1`） |

（另有 `0x08009CD4` 的调用者**不**写模式字节——它只 arm。）

### 4.3 ★ 谁能写 `armed`（`0x20005FEE` = `ctx+0x1690`）

**全 asm 只有 3 个写入者，2 个置 0/1：**

| 地址 | 动作 | 所属 |
|---|---|---|
| **`0x0800D6DE`** | **`strb #1`** | ★ **`0xA0/0x0D00`**（`0x0800D6B4`） |
| **`0x08009CF2`** | **`strb #1`** | ★ **`0xA0/0x1200` 与 `0xA0/0x2400`**（均指向 `0x08009CD4`） |
| `0x0800A2C2` | `strb #0`（**清**） | `0x0800A2A8`（`A1/0x0A00` 与 `A1/0x1300` 的**回复函数**清 armed） |

⇒ **能 arm 的只有 3 条命令：`0xA0/0x0D00`、`0x1200`、`0x2400`。**
⇒ **其中只有 `0x0D00` 同时设模式 4** ⇒ **只有它能把"模式 4 任务"跑起来。**
⇒ **`0x0D00` 是主机侧唯一的「启动检测引擎」入口。**

### 4.4 ★ 谁能碰引擎内部标志（`0x15E4`/`0x168A`/`0x15E2`）

| 标志 | 写入者 |
|---|---|
| `ctx+0x15E4`（detected） | **只有引擎自己**（`0x08005ADA` 置 1、`0x08005BA0` 清 0） |
| `ctx+0x168A`（collecting） | **只有引擎自己**（`0x08005B0C` 置 1） |
| `ctx+0x15E2`（环形索引） | **只有引擎自己** |

⇒ **39 个 handler 里没有任何一个能直接写这些引擎内部标志。**

## 六、★★★ 标签核对：`0x0B00` / `0x0D00` 两处都要改

### 6.1 `0xA0/0x0B00` —— 原标"写波形缓冲" ❌

**实测全文（`0x0800D8C0`，27 条指令）：**
```asm
0800D8C0  sub   sp, #0xc
0800D8C2  str   r0, [sp, #8]          ; r0 = 命令块
0800D8C6  ldrb  r0, [r0, #1]          ; 长度字节
0800D8C8  strb.w r0, [sp, #7]
0800D8CC  movs  r0, #0
0800D8CE  str   r0, [sp]
0800D8D2  ldr   r0, [sp]              ; i = 0
0800D8D4  ldrb.w r1, [sp, #7]         ; len
0800D8D8  cmp   r0, r1
0800D8DA  bge   0x800d8fa             ; 出口
0800D8DE  ldr   r0, [sp, #8]
0800D8E0  ldr   r2, [sp]
0800D8E2  add   r0, r2
0800D8E4  ldrb  r0, [r0, #4]          ; 源 = 命令块 + 4 + i
0800D8E6  movw  r1, #0x40e8
0800D8EA  movt  r1, #0x2000           ; ★ 目标 = 0x200040E8
0800D8EE  strb  r0, [r1, r2]          ; ★ 逐字节拷贝
0800D8F0  b     0x800d8f2
0800D8F2  ldr   r0, [sp] ; adds #1 ; str [sp] ; b 0x800d8d2
0800D8FA  add   sp, #0xc
0800D8FC  bx    lr
```

**⇒ 它做的唯一一件事：把命令块的 `len` 个字节拷进 `0x200040E8`。**

**`0x200040E8` 的消费者（全 asm 只有 1 处）：**
```asm
0800D892  ldr   r1, [sp, #4]
0800D894  movw  r0, #0x40e8           ; ★ 读 0x200040E8
0800D898  movt  r0, #0x2000
0800D89C  ldrb  r0, [r0, r1]
0800D89E  ldr   r2, [sp, #0xc]
0800D8A0  add   r1, r2
0800D8A2  strb  r0, [r1, #2]          ; 拷进 dest+2
```
而 `0x0800D868` 是 **`A2` 回复打包器**：
```asm
0800D874  movs  r0, #0xa2
0800D876  strb  r0, [r1]              ; dest[0] = 0xA2
0800D878  ldrb.w r0, [sp, #0xb]
0800D87E  strb  r0, [r1, #1]          ; dest[1] = 长度
```
**唯一调用者**：`0x0800E68A` → dest = **`0x20004128+0x8C`（响应缓冲）**

**⇒ ★ 结论（标签更正）：**
> ### `0xA0/0x0B00` = **「往 A2 回复载荷缓冲 `0x200040E8` 装载数据」**
> ### ❌ 不是「写波形缓冲」
>
> **它写的是【回给主机的那一帧的数据区】，而且这份数据随后由 `0x20004128+0x8C` 的回复缓冲经 I²C 发出。**
> **⇒ 它连"波形"都不是，它是在准备一条回复报文。**

⚠️ 这也**修订了**我在《全书》8.2.3 / 11.1 里沿用 `COL04-BOUNDARY` 的"写波形缓冲"标签。
（`COL04-BOUNDARY` 那句 `0x080088C0` 是 `0x08008898` 的循环体，且 `0x08008898` 是**另一条**链的调用者 `0x0800CF7C` 用的——见 6.3。）

### 6.2 `0xA0/0x0D00` —— 原标"清缓冲/arm"，部分对但太粗 ⚠️

**实测全文（`0x0800D6B4`）：**
```asm
0800D6B4  push  {r7, lr}
0800D6B6  sub   sp, #8
0800D6B8  movw  r1, #0x4090
0800D6BC  movt  r1, #0x2000
0800D6C0  movs  r0, #4
0800D6C2  strb  r0, [r1, #4]          ; ① 模式字节 = 4
0800D6C4  movw  r0, #0x495e
0800D6C8  movt  r0, #0x2000
0800D6CC  str   r0, [sp, #4]
0800D6CE  movw  r1, #0x1694           ; ② 清 ctx[0 .. 0x1694) = 5780 B
0800D6D2  bl    #0x80051c2            ;    memset
0800D6D6  ldr   r1, [sp, #4]
0800D6D8  movw  r2, #0x1690
0800D6DC  movs  r0, #1
0800D6DE  strb  r0, [r1, r2]          ; ③ armed = 1
0800D6E0  movw  r0, #0x426c           ; ④ 清 0x2000426C 起 44 B
0800D6E8  movs  r1, #0x2c
0800D6EA  bl    #0x080051c2
0800D6EE  add   sp, #8
0800D6F0  pop   {r7, pc}
```

**⇒ ★ 结论（标签更正）：**
> ### `0xA0/0x0D00` = **「设模式 4 + 清上下文 5780 B + arm」**
> ### ⚠️ 原名"清缓冲/arm"不算错，但**"缓冲"二字误导** —— 它清的是**整个主上下文**，不是波形缓冲。
> ### 准确的定位：**「启动模式 4 的检测/采集任务」**
>
> ⚠️ **而且它需要 `0x2000495D == 1` 才真正干活**（`0x080086BE` 那道门）—— 这个门控在旧文档里没有。

### 6.3 顺带更正：`0x28` 那条链**不是**任务① 私有的

`0x080059E0`（含 `0x28` 判据）被 **3 个任务**调用：
```
0x080075A4  ← 任务①（模式 4）   r2 = 0xAF
0x08009896  ← 任务②（模式 1）
0x0800A168  ← 任务③（模式 3）
```
⇒ **它是三任务共用的检测引擎。** 10.4.1 把它讲成一条纵向链（压力→判据→…→PWM→时序），**框架不准**。

**10.4.1 正确的部分**：链条"终点是上报" ✅
**10.4.1 不准的部分**：
- 它不是某个任务的私有链，是**共用引擎**
- 它**不经过 PWM/时序层**（那两层是独立初始化）
- `0x0B00/0x0D00` 不在**这条**链上（`0x0B00` 属 A2 回复装载；`0x0D00` 是**这条链的启动者**）

## 八、★★ 对"能否用软件让它震"的最终影响

```
【已证】TF100A 固件里：
  · 没有一条指令写马达 / 定时器 / PWM / H 桥
  · 唯一对外输出 = I²C 回复帧 + PA3 门铃
  · 检测引擎的终点是"把 4 通道 × 20 点写进 ctx"，随后由 A1 查询族取走 → A2 回复

【推论】
  TF100A 的角色 = 【检测 + 上报】
  真正的驱动动作在 GT7868Q 侧（收到这份压力指纹后决定何时震）
  ⇒ 该代码在 GT7868Q 的高熵区（主机侧不可读）

【⇒ 与本项目既有结论一致，但因果链现在完整了】
  主机 → 0xA0/0x0D00 → 模式4 + arm → 任务① 轮询
       → 检测引擎（|Δ压力| > 40）→ 采集 20 点
       → 输出例程 → ctx
       → A1 查询 → A2 回复 ──I²C1──▶ GT7868Q
       → 【GT7868Q 侧】决定震动
```

**★ 这也回答了"0x0B00 写波形缓冲"这个假设为何不成立：**
> 波形如果要下发给谁，得有一条**通往执行器的路**。
> 而 `0x200040E8` 的唯一消费者是 **A2 回复打包器** ——
> **它把数据原样回给了主机，不是写给任何执行器。**
> ⇒ **"主机写波形 → 设备播放"这条假设，在输出端的消费者上就被否掉了。**

## 九、方法学备注（本轮的可复用点）

| # | 要点 |
|---|---|
| 1 | **`movw`/`movt` 配对跟踪必须跨指令**——`0x40010800` 在 asm 里没有字面量，是 `movw #0x800` + `movt #0x4001` |
| 2 | **`movt #0x4001` 是 GPIO/EXTI/AFIO 区间的指纹**（全 asm 60+ 处） |
| 3 | **"零引用"结论必须声明搜索边界**——`0x200040E8` 只有 2 处字面量，但**消费它的函数用了不同基址**；只按字面量搜会得出"无消费者"的过强结论 |
| 4 | **Cortex-M 的除法魔数**（`0xCCCCCCCD` + `lsrs #4`）= `% 20`，是识别环形缓冲的好指纹 |
| 5 | **`0x0800F7FC(base, bit)` 是"写 GPIO_BRR"的惯用封装**——`base=0x40010800` + `bit=8` ⇒ `PA3` 拉低 |
