# 载荷 A 深度解剖 —— 2026-10-02 晚

> **一句话结论：载荷 A 是一份【4 字节记录 / 16 字节条目、含大量"空槽"的结构化数值数据表】，
> 不是代码、不是压缩流、不是加密残留、不是波形。**
> 并且它**已被完整分类**：13 个块按`type` + 零密度分成三类，其中**没有任何一块是触觉波形库**。

## 〇、先修正本轮自己踩的两个坑（方法学价值比结论更重要）

### 坑1：解密的相位基准 —— 会把13 块变成"同一份数据"

第一版循环写成：

```python
for s in info['subsys']:
    raw = buf[base : base + s['size']]      # ❌ off 从不推进
```

⇒ **同一段 raw 被重复解 8 次** ⇒ 8 个 8KB 块的 md5 **完全相同** ⇒
我一度以为"这些块是同一份数据，冗余存储"。

**正确写法**（块在数据区里连续排列，必须累进）：

```python
off = 0
for s in info['subsys']:
    raw = buf[base + off : base + off + s['size']]
    off += s['size']
```

**判别法（已内建进工具）**：解密后先打印各块 md5 去重数，**必须等于块数**。
若远小于块数 ⇒ 切分逻辑错了，不要继续往下分析。

> ★ 这与§19.27.9 记录的 `ObjectTypeIndex` 坑同型：
> **中间层（切分/索引）不稳定 ⇒ 静默产出结构上错误的样本。**

### 坑 2：自相关的基线不能拿"随机数据和自己比"

```
❌ rnd[i] == rnd[i+lag]        → 恒等于 100%，比值永远是 0.1×
✅ 正确基线 = 1/256 = 0.391%    （256 个字节值均匀分布的期望）
```

⇒ 第一版据此得出"载荷 A 的自相关**低于**基线"的结论，实际正好相反（**高 30–40 倍**）。

**判别法**：任何比值型指标，先问"分子分母是不是同一份数据"。

## 一、核心结构：★★★ 4 字节记录 / 16 字节条目 / 空槽式数据表 ★★★

### 1.1 决定性证据：零段长度的富集（带打乱对照）

零字节占 **14.99%**（15,043 / 100,352）。**零不是随机散布的，而是成段**：

| 零段长度 | 原数据 | 同数据打乱后 | 富集倍数 | 判读 |
|---:|---:|---:|---:|---|
| 1 | 946 | 11,031 | 0.1× | 随机噪声 |
| 2 | 57 | 1,563 | 0.0× | 随机噪声 |
| 3 | 43 | 238 | 0.2× | 随机噪声 |
| **4** | **349** | **38** | **9.2×** | ★★★ **结构信号** |
| **12** | **73** | **0** | **∞** | ★★★ **结构信号** |
| 68 | 26 | 0 | ∞ | ★★★ **结构信号**（= 4 的 17倍） |
| 76 | 5 | 0 | ∞ | 结构信号 |
| 858 / 1026 / 1034 / 5450 | 各 1 | 0 | ∞ | 大片空槽 |
| **合计** | **1,548 段，均长 9.72** | **12,874 段，均长 1.17** | — | **平均长度 8.3×** |

**⇒ 载荷 A 的平均零段长度是打乱后的 8.3 倍。这在信息论上排除了"加扰/加密残留"，证明零是【明文的空槽标记】。**

### 1.2 对齐决定性：349 个"4 零"记录的起点 mod 4

```
起点 mod 4  分布：1 → 348 个（99.7%），2 → 1 个
```

**⇒ 4 个零是一个 u32 字段，且它位于 16 字节条目的第 2 个 u32 位置。**

样本（真实字节，起点 `0x00549`）：
```
82 20 6D 00 | 00 00 00 00 | DB 87 27 8A | F6 DF 8D B4
   u32[0]   |u32[1]= 0   |   u32[2]   |   u32[3]
```
间距 **恰好 16 字节**（`0x00549 → 0x00559 → 0x00569 → 0x00579`）。

### 1.3 完整形态

| 项 | 实测 |
|---|---|
| 条目长度 | **16 B**（4 个 u32） |
| 条目数 | 6,272 |
| 每条零个数分布 | 0 零 68.8% / 4 零 **10.9%** / 8 零 1.9% / 12 零 1.3% / 16 零（整条空）10.9% |
| 各 u32 字段为 0 的比例 | `u32[0]` 11.3% · `u32[1]` **14.5%** · `u32[2]` 12.7% · `u32[3]` 16.5% |
| 非零 u32 的值域 | 接近满域（`0x2` ~ `0xFFFFFFFF`），**只有 0.2–0.4% ≤ 0xFFFF** |

**⇒ 这是一张"16 字节一条、约 11% 是空槽、部分槽位恒为 0"的数值表。**
形态与 §19.24.4 独立解出的**配置体(1024 B)** 的 u16 数组高度同构。

## 二、载荷 A **不是**什么（四个假说全部排除）

| 假说 | 判据 | 实测 | 判决 |
|---|---|---|---|
| **IEEE754浮点系数** | 按4 B 对齐读 float32，超小值(`0<\|v\|<1e-20`)比例 | **载荷A 33.5% / 32.4% / 31.9% / 30.9%**（四份固件）<br>**真随机对照 0.0%** | ❌ **否证**（四份一致，排除偶然） |
| **压缩流** | zlib 各级 | **0.752–0.756**（bz2 0.760 / lzma 0.693）<br>基线：代码 0.43–0.51 / 随机 1.00 | ❌ **否证**（既不像代码也不像压缩流） |
| **加密残留** | 零段长度 vs 打乱后 | 均长 **9.72 vs 1.17**（8.3×） | ❌ **否证** |
| **触觉波形库** | 幅值域 / 自相关 / 重复段 | 见下§三 | ❌ **否证** |

### ★ 自相关曲线（真基线 0.391%）

```
lag      载荷A     /基线        lag      载荷A     /基线
   1   13.852%     35.5×         64   11.919%     30.5×
  16   15.784%  ★  40.4×        128   15.111%     38.7×
  32   14.249%     36.5×        256   13.486%     34.5×
```
**峰值在 lag=16（40.4×）—— 正是条目长度。**
但注意：T3 排除零后同一 lag 只剩 **8.8×** ⇒ **自相关主体来自"零槽对齐"，不是"内容周期性重复"。**
两者必须分开看，否则会把"空槽"误读成"重复的波形"。

## 三、★★★ 载荷 A 里**没有**触觉波形库（对 §19.25 问题的直接回答）★★★

AW86927 的波形库是 **8 KB SRAM**（§19.15）⇒ 若GT7868Q 用 RAM 模式驱动它，固件里必须有一个 8 KB 波形数组。
载荷 A 恰有 **8 个 8192 B 的 type-0x03 块**（尺寸对得上）。逐项检验：

| 波形特征 | 8 个 8KB 块的实测 | 波形应该 |
|---|---|---|
| 幅值域（有符号 8bit） | **满域 −128..127** | 小有符号整数 |
| 自相关 AC(1) | **−0.083 ~ +0.016**（≈0，白噪声） | 显著平滑 |
| 自相关 AC(16) | +0.008 ~ +0.069 | 有周期结构 |
| 512 B 粒度重复块 | 仅 **3 个**，散乱不成组 | 多段波形应成组重复 |

**⇒ 8 KB 尺寸是巧合，形态完全不是波形。**
**⇒ 结合 §19.25.6 的 A/B 二分：波形数据不在线上 ⇒ 只能在芯片 ROM，或根本没启用。**

## 四、★★13 个块的分类（按 `type` + 零密度）★★

`type` 是位索引（官方 `firmware_flag & (1<<type)`）；`0x03` = 官方 `FLASH_SUBSYS_TYPE_CONFIG`。

| 类别 | 判据 | 块（flash / type / size） | 占载荷 | 解读 |
|---|---|---|---|---|
| **A. 稠密数值表** | 零 6–18%，4零组 6–17% | `0x16000`·`0x06000`·`0x08000`·`0x0C000`·`0x10000`·`0x04000`（全 type 0x03，各 8 KB）<br>`0x0FF00`·0x01·2 KB | ~52 KB | **主要数据载荷**（16 B 条目表） |
| **B. 稀疏/半空表** | 零 18–43%，但4零组<1% | `0x0A000`·0x03·8 KB（本机 74% 零 / GT9896 只有 1.7%）<br>`0x00000`·0x02·4 KB | ~12 KB | **大量空槽/ 未启用条目** |
| **C. 全空槽** | 零 >99% | GT9896 的 `0x12000`（**100% 零**）| — | **出厂预留槽位** |
| **D. 官方配置区** | 零 6.0%，**4零组 0%** | **`0x1E000`·0x03·8 KB**（= 官方 `FLASH_ADDR_CONFIG_DATA`） | 8 KB | ★ **唯一"4零组为 0"的块** ⇒ 形态与其它 0x03 块**根本不同** |
| **E. ISP 区** | — | `0x0FF00`·**0x01**·2 KB | 2 KB | 官方 ISP 程序（三芯片逐字节相同） |

### ★★ D 与 A 类的对立是本轮最有价值的结构发现

```
0x1E000（官方 CONFIG_DATA）：4零组 = 0%      ← 每条 4 个 u32 全都非零 ⇒ "实心表"
其它 0x03 块：             4零组 = 6–17%    ← 大量空槽⇒ "带预留槽的表"
```

**⇒ `0x1E000` 是一张被完整填满的参数表，其余 0x03 块是"预留了槽位但没填"的表。**
**⇒ 这直接支持 §19.23.5 的结论：配置数据确实存在且被固化进固件，且有大量未启用槽位。**

### ★★ B 类的 `0x0A000` 跨芯片形态突变（未解释的新现象）

| 芯片 | 0x0A000 零% | 4零组% |
|---|---:|---:|
| GT7868Q 2024（本机） | 74.2 | 73.9 |
| GT7868Q 2020 | 85.8 | 85.5 |
| **GT9896** | **1.7** | **0.3** |

**⇒ 同一个 flash 地址，在 GT9896 上是满表，在两代 GT7868Q 上几乎全空。**
**⇒ 这不是数据差异，是"这块在本芯片上是预留区"。**
⇒ **这是本轮挖出的第一个"槽位数在不同芯片上不等"的确证 —— 说明厂商按型号裁剪了配置槽位。**

## 七、本轮纪律（新增两条）

26. ★ **解密/切分类代码，第一件事是验证"切出来的块互不相同"**（打印 md5 去重数，必须 = 块数）。
    否则会对着"同一份数据重复 N 次"下结论。
27. ★ **任何"比值 / 倍数"型指标，必须先确认分子分母不是同一份数据。**
    `rnd[i] vs rnd[i+lag]`恒为 100%，用它做基线会让所有结论反向。
    正确基线要从**分布**推（本例：256个字节值均匀 ⇒ 1/256 = 0.391%）。
28. ★ **"高熵 + 有零 + 不能压缩"这个组合，最可能的答案是"稀疏数值表"，
    而不是"加密"。** 区分判据：**零段长度 vs 打乱后**（本轮 9.72 vs 1.17，单点定案）。
