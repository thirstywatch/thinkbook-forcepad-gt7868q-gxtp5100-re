| 器件 | 角色 | 状态 |
|---|---|---|
| **GXTP5100 / GT7868Q** | 触控主控，HID 设备 `VID_27C6/PID_01E9` | ✅ 实物 + HID 枚举 |

## 三、主机侧为什么"封死"

```
理想世界（Synaptics 触觉触控板）：
  主机 ──"Haptics Manual Trigger"报表──▶ 触控板 ──▶ 震
              （描述符声明 Usage Page 0x0E / Usage 0x21）

本机实测：
  主机 ── 私有封装 [0E 20 …] ──▶ hidi2c.sys ──✗ 拒绝 ──▶ 到不了触控板
                                   ↑
                    I²C-HID 只认 ACPI 声明的寄存器
                    （0x21 描述符 / 0x22 命令 / 0x23 数据 / 0x24 输入 / 0x25 输出）
                    越界即拒（协议层）+ hidi2c 严格转发（驱动层）
```

**三条实测证据**：
| 事实 | 含义 |
|---|---|
| Col02 只有 `0x0E/0x23`（强度），**没有** `0x0E/0x21`（扳机） | 设备没声明"主机可触发" |
| `Col02 Out = 0` | 输出通道不存在 |
| `GET_FEATURE(0x0e)` → `OSError: read error` | 私有命令在 HID 层被拒 |

**Col04（`0xFF00` 厂商定义）**：描述符里**确实有 64 B Output + 64 B Input**（蓝莓 Wiki 的汇顶描述符逐字印证），
但 `Col04 out=0` ⇒ 同样在 `hidi2c` 之上，发不下去。

## 四、"震动怎么实现"——三条路，本质区别只有一个

| 路线 | 谁最终驱动 LRA | 主机需要做到什么 | 状态 |
|---|---|---|---|
| **A. 求触控 IC 转达** | GXTP5100 命令 AW86927 | 给触控 IC 发一条"震"的命令 | ⚠️ **命令内容未知** |
| **B. 主机直接写触觉 IC** | 主机直接写 AW86927 | AW86927 必须挂在**主机可见的那条 I²C** 上 | ⚠️ **未验证（唯一决定性实验）** |
| **C. 主机硬驱** | 主机自己的驱动板 | 拆机接 `HDP`/`HDN` 焊盘 | ✅ 必然可行，但**要拆机** |

### ★ 核心认知

> **三条路共同的第一道门 = 主机得能在 I²C 上说话。**
> 路 A 和路 B 的区别只是"命令发给谁"；它们的**共同前提**是"主机有 I²C 话语权"。
> **而话语权，才是这一个月真正卡住的东西。**

## 八、下一步的唯一建议

> ### 先花 2 小时用 Linux live USB 回答母问题 1，再决定要不要投 3–5 天写驱动。

**理由（两条，都是硬的）**：
1. **顺序**：写函数驱动的工作量（接管 `hidi2c` 位置 + 实现 I²C-HID 报文 + 维持触控板功能）远大于交接文档估计的"部署关"。
   如果写完发现 AW86927 根本不在主机总线上，那几天全废。
2. **可行性**：现在没有管理员权限，**只有这个实验能立刻做**。

### 实验步骤（草案）
1. Ubuntu live USB 启动（`Try Ubuntu`，不装）
2. `ls /sys/bus/i2c/devices/` → 找到触控板所在适配器（对应 `i2c_designware` / `7E78`）
3. `echo <设备名> > /sys/bus/i2c/drivers/i2c_hid_acpi/unbind`（或 `i2c_hid_of`）
4. `i2cdetect -y <总线号>` → 看 **`0x5A` / `0x5B`** 是否有应答
5. 若在：`i2cget`/`i2cdump` **只读**摸清寄存器
6. 全程**只读**，不动 flash

### 红线（不变）
1. 禁批量轮询 `Col04`
2. 单次事务 ≤ 32 B，间隔 ≥ 500 ms
3. 🔴 **红线是四条，不是“三连”**：`00 10` / `00 11` / **`0E 12`（★ 真正写 flash）** / **`0E 13`（重启）** 绝不碰
4. 未获明确同意**不动 `bcdedit`**
5. 不删 `.workbuddy`、不删 `touchpad-lab`
