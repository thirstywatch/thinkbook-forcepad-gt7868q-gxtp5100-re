## 一、一句话结论

> **这块触控板的震动马达，主机永远无法主动触发它 —— 不是"我们没找到方法"，而是接口、固件、硅片三层都不通。**
> **想要"滑动跟随震动"，唯一可行的路是在触控板之外加一个自己的执行器（外置 LRA），软件侧由我们控制震动时机。**

## 三、"主机不能触发" —— 三条**互相独立**的证据

| # | 证据 | 内容 |
|---|---|---|
| 1 | **本机描述符实测** | `Col02 OutputReportByteLength = 0` ⇒ **一个输出报表都没有**；usage page `0x0E`（Haptics）下**只有 `Intensity`** ⇒ 没有 `Manual Trigger (0x0E/0x21)`、没有 `Waveform List (0x0E/0x10)`、没有 `Duration List (0x0E/0x22)` |
| 2 | **微软官方规范** | 《Input Device Haptics Implementation Guide》：**主机触发**必须同时具备 `Manual Trigger` **OUTPUT** 报表 + `Waveform/Duration List` feature 报表；只有 `Intensity` 的属于 **device-initiated（设备自主触发）** |
| 3 | **Linux 上游 RFC（2026-06-16）** | Rong Zhang 发起，Dmitry Torokhov（input 维护者）、Peter Hutterer（libinput 维护者）参与，原话：<br>「haptic feedback may be either **device-initiated** or host-initiated... **device-initiated ones are currently not configurable at all**」<br>「...since **there's no way to initiate a force feedback from the host**, the device is not a true FF device」 |

**⇒ 本机属于 device-initiated：主机只能调"强度"，不能叫它震。Windows 自己也做不到。**

## 四、厂商命令通道：无震动命令，且**不可安全枚举**（实测，有代价）

- 通道形态：**Col04 OUT（65 字节，report ID `0x0E`）发命令 → Col04 IN 收响应**；GTX8 帧格式：
  - 读：`0E 20 00 00 05 01 <addr16BE> <size16BE>`
  - 写：`0E 20 00 00 <len+5> 00 <addr16BE> <len16BE> <data…>`（★ `[4]=len+5` 是关键，照搬 BRLB 的 `+7` 会静默失败）
- 实测**唯一有价值**的命令：**`0x20`（I2C_DIRECT_RW，内存读写）** —— 读过完整 64KB 窗口（含传感器配置与实时原始值）
- 已知其它命令：`0E 13` 软复位、`03 03` 切回 PTP 模式（**IC 卡死后都发不进去**）；🔴 **红线是四条不是三连**：`00 10` / `00 11` / **`0E 12`（★ 真正写 flash）** / **`0E 13`（重启）**（**禁区，从未发送**）。⚠️ 旧文档把 `0E 13` 排除在红线之外、且常误把 `0E 12` 当成重启 —— 性质正好说反
- **opcode 扫描实测结果（共约 35 条后中止）**：

| opcode | 结果 |
|---|---|
| `0x00`–`0x0D` | 全部返回**同一个空 ACK** `00 00 01 01 …`，无信息量、**未引发任何震动** |
| **`0x0E`** | **自这一条起应答通道死亡**，其后全部 `err=122` |
| `0x0F`–`0x2F` | 全部 `err=122` |
| `0x20` | 唯一可用（内存读写） |

**⇒ 命令空间既不能安全枚举（`0x0E`/`0x0F`/`0x99` 都会打断通道），也不存在震动命令。**

> ⚠️ 代价记录：本机触控板**两次被打挂**，根因都是"用户态碰厂商通道"（①后台 33Hz `GET_INPUT_REPORT` 轮询；②批量试 opcode）。
> 恢复流程见第十一节。

## 五、固件逆向（56,480 字节明文镜像 @ `0x08000000`）

| 项 | 值 |
|---|---|
| MCU 内核 | **STM32F1 类**（`GPIOA=0x40010800` · `RCC=0x40021000` · `FLASH=0x40022000` · `TIM2=0x40000000` · `TIM3=0x40000400` · `I2C1=0x40005400`） |
| 编译时间 | **`Nov 28 2023` `19:10:59`** |
| 内部版本 | **`5.21.01.23007`** |
| 工程标记 | **`TF100A_Test_FW`** |
| 向量表 | I2C1_EV=`0x08008978` · I2C1_ER=`0x0800894C` · **TIM3=`0x0800D628`** · DMA1_CH1=`0x08006B3C`（其余 IRQ 全是空转桩 `0x0800517F`）<br>🔴 **依据已作废**：`0x08900 ∈ [0x08800,0x08C00)` = **K 交织表副本内部**（`udf` 率 0.0548 vs 真代码 0.0020）⇒ 把数据表字节误读成指令。**结论保留**（TF100A 仍是纯从机），**新依据** = `I2C_Init@0x0800FA20` 逐指令（`OAR1=0x58` ⇒ 从机 `0x2C`） |
| 调用图 | 250 目标 / 600 条边（字节级 BL 扫描） |

**触觉子系统（`0x08008600–0x08009800`）**

| 地址 | 作用 |
|---|---|
| `0x08009750` | LRA 配置：**振幅 119、周期 999** + 把波形回调 `0x0800D6F4` 写进结构体 `+0x14` |
| `0x08008FE8` | TIM2 初始化：振幅 119、周期 **1999** |
| `0x08008704` | PWM 硬件配置（ARR=700/CCR=96 与 ARR=1999/CCR=119）<br>🔴 **2026-10-02 更正**：**不应读作“LRA 驱动参数”** —— TF100A 无 PWM 输出路径，这些只是它的采样节拍定时器 |
| `0x08008858` | "调用结构体 `+0x14` 里的回调"（通用间接调用器） |
| `0x08008628` | "播放"包装 → **在 600 条边的调用图里无任何调用者**（也无 `movw` 立即数、无数据指针）|
| `0x200040D0` | 上下文结构；`+0x10` 是**计数器**（取值器 `0x08007E94`、自增器 `0x080086F4`）|

**三条硬结论**

1. **波形写死在固件里**：`119 / 999 / 1999` 全镜像**只出现在两处配置点** ⇒ LRA 驱动参数是**编译期常量**，主机侧天然没有配置入口（与"改点击阈值无效"的实测互相印证）。
2. **"播放"函数不可达** ⇒ 震动是**固件内部行为**，不存在从主机侧进入的调用路径。
3. **无任何命令接口痕迹**：全镜像没有 `vib`/`motor`/`haptic`/`cmd`/`AT+` 之类字符串；唯一的"人话"是 `TF100A_Test_FW`、编译时间、版本号，以及 printf 用的十六进制表。

**顺带定位的结构**：主循环 = `0x0800AA20`；分发器 = `0x080091C0`；设备→主机上报模式 = 约 20 个"帧构造器"（**写 `0xA2` 帧头 → 填数据 → 操作 `GPIOA` 第 3 位**）。

> 诚实保留：明文段带 `TF100A_Test_FW` 字样 ⇒ **这段明文可能本身就是"测试固件"**，真正刷进芯片的生产固件或在容器的加密段里。但主机接口/触觉子系统的结构通常不会有本质差异。

## 六、容器与刷机：为什么"改固件"是一条**单程门**

**容器结构（实测，精确到字节）**

```
[0x00000 .. 0x0043C)   1 × 1084 B   头部/清单块（熵 4.93，内含大端 1084）
[0x0043C .. 0x19ABC)   96 × 1084 B  加密块（熵 ~7.82；zlib / lzma / gzip 全解不开 ⇒ 真加密）
[0x19ABC .. 0x2775C)   56,480 B    明文 Cortex-M 固件镜像（熵 6.49）
```
（1084 + 96×1084 + 56,480 = **161,628** ✅）

**官方刷机机制**：`goodixtouchpad.inf`（`oem87.inf`，**Class = Firmware**）
```ini
[Firmware.NTamd64]  %FirmwareDesc% = Firmware_Install,UEFI\RES_{b6ae105a-ba93-4fc8-aa28-e63903ffedde}
[Firmware_AddReg]   HKR,,FirmwareId,,{b6ae105a-…}
                    HKR,,FirmwareVersion,%REG_DWORD%,0x14030522
                    HKR,,FirmwareFilename,,TB14P_GT7868Q_14030522_20240202.BIN
[DestinationDirs]   DefaultDestDir = DIRID_WINDOWS,Firmware
```
⇒ Windows 只把 BIN 放进 `C:\Windows\Firmware`，**真正的刷写由平台固件（BIOS）在启动时执行**（ESRT 描述就叫 "Goodix Update **UEFI**"）。
**好消息**：刷机不走那条脆弱的用户态厂商通道。

**但我们无法按需触发它**：
- Windows 只在"有**更新的、已签名的**固件包"时才安排刷写；已装包版本 `0x14030522` **等于**设备当前版本 ⇒ 无待刷更新
- 自己造更新包 ⇒ 破坏 `GoodixTouchpad.cat` 签名 ⇒ Windows 拒绝安装
- 让 BIOS 接受改过的镜像 ⇒ 容器加密 + **eFuse 验签**

**汇顶官方文档（《GR5xx 固件升级开发指南 · 加密加签固件升级》）**：
密钥存放在芯片 **eFuse**：`Firmware Key`（加密私钥）、`sign.key`（签名私钥）、`sign_pub.key`（验签公钥）、`Public_key_hash.txt`；
固件三形态（非加密非加签 / 仅加签 / 加密加签）；`Security Mode` 开启后**不可关闭**。
⇒ **签名私钥永远不在设备上，芯片靠 eFuse 里的公钥哈希验签。**

**⇒ 结论**：官方刷机能力只掌握在 OEM（联想/汇顶）手里。一旦用裸刷通道写入魔改固件失败，**我们没有任何办法刷回官方固件**。
**改固件 = 单程门，正式否决。**

## 九、可行方案 A（具体落地）

**A1 · 软件（零成本、零风险）**
- 复用已验证可用的 `RawTouchProbe`（Raw Input 读 `Col02` 的 40 字节报表，`RIDEV_INPUTSINK` 全局接收）
- 手势识别：一指**右边缘**内滑 → 音量 ±；一指**左边缘**内滑 → 亮度 ±
- **滑动节拍**：每滑过固定距离产出一个"震动事件" → 输出到串口（无硬件时先输出日志/短促提示音）
- 编译工具现成：`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（零安装）

**A2 · 硬件（¥40–65）**
- ESP32-C3（¥15–25）+ **DRV2605L** 驱动模块（¥15–30，自带 LRA 波形库与自动谐振跟踪）+ 方形 LRA（¥5–10）
- 串口协议：一行一条 `V 1` = 震一下；强度/时长/波形均可调
- 安装：贴在触控板背面或掌托下方（拆底盖），也可先直接放掌托上试手感

**诚实的预期管理**
- **震动时机**：与华为同级 —— 完全由我们决定（原生固件只在点按时震，做不到滑动跟随）
- **震动质感**：打折扣 —— 外置 LRA 无法与"贴在触控板玻璃下方的原装马达"等效，整板共振感更弱

## 十一、触控板打挂后的恢复（**唯一有效**，务必记住）

> **2026-09-14 增补：先分清两种严重度**
> | 形态 | 诱因 | 表现 | 处置 |
> |---|---|---|---|
> | **轻度（暂时性）** | **高频读取**（`Col04` 类 0x20 读 683 次 / 50–75 s） | 指针不动、**点按仍震**、`GET_INPUT(0x0E)` 回 `122` | **① 杀掉所有后台任务 → ② 等 1–2 分钟**（当天两次都自愈，未断电） |
> | **重度（永久 latch）** | 厂商命令枚举（`0x0E` 等） | I2C 前端照常 ACK、设备正常枚举，但**永不产生触摸输入** | 只能走下面 1–5 的完整断电流程 |
>
> 剂量红线：类 0x20 读 **单轮 ≤80 次、≤3 次/秒、轮间 ≥3 分钟**（90 次 @≤10/s 安全；683 次 @9–13/s 三次中两次冻结）。
> 详见 [`INCIDENT-2026-09-14-input-freeze.md`](../09-safety/lab__INCIDENT-2026-09-14-input-freeze.md)。

2. **关机**（按住 `Shift` 点关机更稳妥）
