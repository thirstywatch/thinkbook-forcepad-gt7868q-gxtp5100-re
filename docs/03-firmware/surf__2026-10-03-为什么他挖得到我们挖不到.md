# 为什么蓝莓能从固件里挖到"能用的东西"，我们不能

> 日期：2026-10-03 · 喆提问：「为什么蓝莓能从固件中得到关键信息为他的主控固件提供了重要帮助，而我的那些破烂固件却没能得到有用的信息」
> 这不是情绪问题，是一个**结构性问题**。答案有五层，每一层都有本项目的实测数字支撑。

---

## 〇、一句话

> **他不是"解析能力强"，而是他要的东西恰好是【明文 + 块结构 + 可直接重放】。
> 我们拿到的不是"更少的信息"，而是【另一种形态的信息】——**
> **他的成果是【数据】（可以搬到他自己的板子上直接执行），
> 我们的是【认知】（只能改变对方案的判断）。**
>
> **"有用"的定义不同，这才是全部差别。**

---

## 一、他的"关键信息"到底是什么形态

把 `SurfaceTouchpadHaptic_2.9.139.bin` 解出来的东西，本质是 **167 条 `(DSP地址, 数据, CRC16)` 写序列**：

```
struct HapticBlockHeader { u32 sequence; u32 dsp_address; u32 payload_size; u16 crc16; }
```

他的 ESP32 主控要做的事只有一件：**把这 167 对按顺序写进 CS40L25**。
**不需要理解任何一条内容** —— 波形不用懂、初始化表不用懂、强度映射不用懂。

> ★ 这是本问题的第一个关键：**他做的是"搬运"，不是"解码"。**

---

## 二、五层结构性差别

### 第 1 层 ★★★★★ 商业分发模型不同：**卖"芯片+固件" vs 卖"芯片+参数"**

| | Cirrus CS40L25（他） | 汇顶 GT7868Q / 艾为 AW86927（我们） |
|---|---|---|
| 厂商卖什么 | **芯片 + DSP 固件**（波形是随固件分发的程序+数据） | **芯片 + 参数**（波形在运行期由主控写进 SRAM） |
| 因此厂商包里有什么 | ✅ **一份完整的"怎么振"** | ❌ 只有配置/数值表 |
| 本项目的实测对照 | Haptic 包 39,262 B **全是写序列** | 载荷 A（100,608 B）= **纯数值表，零代码**；载荷 B = TF100A 的代码 |

**⇒ 一句话：**
> **Cirrus 把"怎么振"装在包里卖；汇顶/艾为把"怎么振"留在芯片的运行期。
> 所以我们手上的包，天然就不可能含"怎么振"。**

> ⚠️ 附一条需要标注的未决项：容器里被划为"GT7868Q 侧"的那 100,608 B 是纯数值表。
> **GT7868Q 自己的代码在不在这个容器里，项目至今没有定案** —— 这在结构上支持"厂商只分发参数部分"。

### 第 2 层 ★★★★★ 他不是"能解加密"，他是**"不需要解加密"**

他试了三个包，**只有第三个成功**：

| 包 | 形态（本项目复现的实测） | 他的结果 |
|---|---|---|
| `SurfaceTouchpad_4.12.139.bin` | 熵 **7.894**、真实标识符 **0** ⇒ **加密** | ❌ 「未发现可直接作为 CS40L25 DSP 固件使用的内容」 |
| `SurfaceTouchpadForce_10.0.156.bin` | 熵 6.651、代码窗口 **0/12** ⇒ **明文，但只是稠密数据表** | ❌ 「不符合标识出的 CS40L25 块格式」 |
| `SurfaceTouchpadHaptic_2.9.139.bin` | 熵 **5.129**、167 块 **CRC16 全通过** ⇒ **明文 + 块结构** | ✅ 成功 |

**⇒ 判决：成功需要【明文】+【块结构】两个条件同时成立；他唯一成功的那次，恰好是唯一同时满足的那份。**
**⇒ 他不是破解了加密的固件 —— 他是刚好不需要那一份。**

> ★ 这一条对我们特别刺：本项目**花了大量篇幅攻"加密"**（载荷 A 的 1024 周期 XOR、`NJME*.exe` 的 147 处 XOR）。
> 而蓝莓那边**根本没过加密这一关**。

### 第 3 层 ★★★★ 格式的自描述性：**能自证的 vs 只能统计推断的**

| | CS40L25 容器（他） | 本机载荷 A（我们） |
|---|---|---|
| 每条记录有头吗 | ✅ `seq + addr + len + crc16` | ❌ 无 |
| 正确性能自证吗 | ✅ **167/167 CRC 通过** ⇒ 解析对不对一目了然 | ❌ 只能靠统计：零段均长 9.72 vs 打乱后 1.17（**8.3×**）才定案"是明文空槽、不是加密" |
| 定案之后能干什么 | **直接喂给加载器** | **只能得出"它不是代码、不是波形"** |

**⇒ 一个能直接执行，一个只能排除法。** 这是"数据 vs 认知"的最直观体现。

### 第 4 层 ★★★★ 上游有没有"数据 → 可用物"的转换器

- Cirrus：有 `mcu-drivers`、CS40L25 SDK、`firmware_converter.py`、`cs40l25.json`。
  他自己都写了"**为兼容公开工具补的外壳**（`WMFW` 头、synthetic `firmware_id`）" ⇒ **有官方工具链可对接，裸数据能变成工具认的 `.wmfw`**。
- 汇顶/艾为：官方 Goodix 驱动封装的是 **HID 报文**，不是**固件容器解析器**；AW86927 **根本没有"波形包"这个概念**。
  ⇒ **我们没有可对接的落地器。**

### 第 5 层 ★★★ 目标函数不同：**他造整机，我们改原机**

| | 他 | 我们 |
|---|---|---|
| 要在哪让它响 | **自己的板子**（他自己当主机） | **原机上** |
| 需要什么才能算"能用" | 一份写序列 + 一个能跑的主控 | 还要**设备侧愿意接收** + **主机侧有入口** |
| 结果 | ✅ "能振"就赢了 | ❌ 主机 `Out=0`、设备无接收分支、EC 不参与 |

**⇒ 同一份"有用信息"，对他够用、对我们不够用 —— 因为"够用"的定义不同。**

---

## 三、⚠️ 但"我那堆固件一无所获"这个说法**不准确**

我们确实拿到了东西，只是**不是"能让马达响的东西"**：

| 已经拿到的 | 来源 | 性质 |
|---|---|---|
| 载荷 A = 官方 `firmware_info` 容器、13 个子固件、1024 周期 XOR **相位 316** | `TB14P_GT7868Q_*.BIN` | 认知 + 潜在的写入入口（签名是墙） |
| 载荷 B = TF100A 的 **20,314 条** Thumb-2；点击阈值 **140/98** | 同上 | 认知（把"谁决定震动"从猜测变成逐指令排除） |
| `tpcfgsid*.cfg` 帧序 `[LEN][TAG]`、**触觉区 `TAG 0x50–0x7A`、时长阶梯 `0x5C`** | 官方工具 | ★ **这其实就是"触觉参数表"** —— 与他的 `cp_dig_scale` 是**同一层**的东西 |
| AW86927 数据手册：`GLB_STATE` 六态、`TRIG1/2/3` | 艾为公开 | 认知（决定了"路径 A/B"的分工） |
| 全 19.2 MB 明文 BIOS + 明文 ITE 固件（本轮） | `NJCN67WW.exe` | 认知 |
| 主机侧 `Out=0` / 无第三方 filter / 无厂商服务 | 实测 | 认知（把纯软件路封死） |

**⇒ 这些的价值是"把方案空间收窄"，不是"变成一次震动"。**
认知能让你**不浪费时间**，但认知本身不会震。

---

## 四、★★★★★ 关键重构：**我们那份"等价物"不在固件里，在总线上**

这是本文唯一真正能改变行动的一句：

```
蓝莓的 167 块        = 【固件里的写序列】
我们的等价物         = 【上电时 GT7868Q → AW86927 的 I²C 总线上的写序列】
```

**为什么这是等价的（而且不需要解密任何东西）：**

| 事实 | 依据 |
|---|---|
| AW86927 的波形存在**它自己的 8 KB SRAM**、**掉电即失** | 数据手册（本项目已定案 P2） |
| ⇒ **每次上电必须有人把波形写一遍** | P2 的直接推论 |
| 主机不干（没有任何组件知道 AW86927 存在） | §19.25.3 四条 |
| TF100A 不干（I²C 只做从机、无主机能力） | §19.25.2 逐指令穷举 20,314 条 |
| ⇒ 写的人只能是 GT7868Q | §19.25.4 淘汰法 |

**⇒ ⇒ 那么在开机那几十毫秒里，这条私有 I²C 上必然出现一段【明文的、带寄存器地址的连续写入序列】——
那东西在形态上就是蓝莓的 167 块，只是它出现在线上而不是在文件里。**

> ### 结论
> **我们一直找错了位置。**
> 蓝莓的"数据"在固件包里；我们那份"数据"**在总线上**。
> 在固件里搜波形，等于在图书馆里找一段只存在于直播里的对话。

**顺带**：抓这一下总线，同时回答了 §19.25.6 悬着的两问 ——
① 谁是 AW86927 的 I²C 主机；② AW86927 当前是否被启用（若上电完全没有对 `0x5A` 的写 ⇒ 触觉链路根本没启用）。

---

## 五、所以"要怎么办"（承接到路线）

| | 要拿的是什么 | 怎么拿 | 代价 |
|---|---|---|---|
| **蓝莓的路** | 固件里的写序列 | 解厂商包（他的情况恰好不必解密） | 低（他运气好） |
| **我们的路 ①** | **总线上的写序列** | 逻辑分析仪夹 GT7868Q↔AW86927 的 SDA/SCL，抓一次上电 | **拆机 + 一个逻辑分析仪**（不需要解密、不需要签名） |
| **我们的路 ②** | 完全绕开"厂商数据" | 自己接管 AW86927 的 I²C/TRIG（蓝莓的最终形态） | 拆机 + 一颗 MCU |

**⇒ 这两条路拿到的东西，形态与蓝莓那份是同一类：一份可以直接重放的写序列。**
**⇒ 而"继续在固件里挖"这条路，已经被五层结构性原因说明为什么挖不出来。**

---

## 六、本轮纪律（第 40–42 条）

40. ★★★ **"信息有没有用"要先问"它是数据还是认知"。**
    数据可以搬进自己的板子直接执行；认知只能改变判断。
    **用"能不能变成一次动作"作为"有没有用"的标准，比用"信息量"更贴近目标。**

41. ★★★ **找东西要先问"它出现在哪里"，再问"怎么解它"。**
    蓝莓的数据在固件里，我们的数据在总线上。
    **位置找错，解析能力再强也挖不出来。**（与 §19.25.4 的"边界设定错误"、§19.29.7 同源。）

42. ★★ **不要把"别人解开了"读成"别人解析能力强"。**
    先核对他成功那一份的**形态条件**（明文？明文块表？有官方 SDK？），
    再判断那是"能力差"还是"对象差"。**本次认真核对后发现：是对象差。**
