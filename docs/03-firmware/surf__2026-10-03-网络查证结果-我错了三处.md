## 二、本轮查到的硬东西（都可复核）

### 2.1 ★★★★★ **AW86927 有一份完整的上游 Linux 驱动**（2025-08 提交，2025-10 已合入）
`drivers/input/misc/aw86927.c`（854 行），作者 **Griffin Kroah-Hartman**，
配套 dts：`qcm6490-fairphone-fp5: Add vibrator support`（commit `ebb14a39c0596`）。
**⇒ Fairphone 5 的振动马达就是 AW86927。**

驱动里给出了：
```c
/* SRAM 波形头（5 字节，大端） */
struct aw86927_sram_waveform_header { u8 version; __be16 start_address; __be16 end_address; } __packed;
#define AW86927_RAM_BASE_ADDR 0x800            /* SRAM 基址 */
#define AW86927_RAMADDRH_REG 0x40
#define AW86927_RAMADDRL_REG 0x41
#define AW86927_RAMDATA_REG  0x42              /* ★ 连续写入口，地址自动递增 */
#define AW86927_SYSCTRL3_REG 0x45              /* EN_RAMINIT */
#define AW86927_CHIPIDH/L    0x57/0x58 ; #define AW86927_CHIPID 0x9270
#define AW86927_TMCFG_REG    0x5b ; UNLOCK 0x7d
#define AW86927_RSTCFG_REG   0x00 ; SOFTRST 0xaa
/* 出厂 SRAM 基址：BASEADDRH=0x08, BASEADDRL=0x00 */
```
**以及一份可直接使用的正弦波形**（102 字节，`round(84*sin(x/16.25))`，二进制补码）。

**完整的 SRAM 上传序列**（`aw86927_ram_init()`，逐步骤）：
```
① 轮询 0x3F(GLBRD5) 直到进 STANDBY
② SYSCTRL3(0x45) |= EN_RAMINIT
③ BASEADDRH(0x2D)=0x08, BASEADDRL(0x2E)=0x00     ← 设 SRAM 基址
④ RAMADDRH(0x40)=0x08,  RAMADDRL(0x41)=0x00      ← 设写指针
⑤ 连续写 RAMDATA(0x42) ← 5 字节波形头
⑥ 连续写 RAMDATA(0x42) ← N 字节波形数据
⑦ DETCFG2(0x4E)/DETCFG1(0x4D) 启动检测序列 → 延时 3ms → 收尾
⑧ SYSCTRL3(0x45) &= ~EN_RAMINIT
```

### 2.2 ★★★★★ **数据手册给出了 SRAM 的完整结构与播放序列**（图 9 / 图 10）
```
SRAM = [ waveform library version ][ waveform header ][ waveform data ] + [ RTP FIFO ]
header 里是 Waveform #1..#N 的 start/end 地址对  ← ★ SRAM 里可放【多条波形】
```
**播放序列（原文 Figure 9）：**
```
Power on → EN_RAMINIT=1 → 下载波形 → EN_RAMINIT=0 → 全局配置
   → 收到播放请求，四选一：
       CONT 模式 → Set GO=1
       RAM  模式 → Set GO=1
       TRIG 模式 → Set GO=1（或硬件 TRIG 引脚直接覆盖 PLAY_MODE）
       RTP  模式 → 等 GLB_STATE=4'b1000 → 写数据进 RTP FIFO
```
其它公开要点：`VBAT[9:0]` 与 `RL[9:0]` 都在 `0x4F/0x50`；`写 0xAA 到 0x00 = 软复位`；
**波形采样率 12k/24k/48k 可选**；**F0 检测与跟踪**；**8 KB SRAM**；**1 MHz I²C**；**3 根 TRIG**；**Immersion IP 授权**。

### 2.3 ★★★★★ **艾为官方文章直接写出了本机这一类方案的架构**
> 「以艾为……马达驱动芯片 AW86927 为例，在**艾为的压感触控板方案**中：
> **AW8680X 计算出面板所受的力后，会根据压力值的对应等级发送振动波形给 AW86927**」

**被点名的采用方（官方原文）**：苹果、微软、**联想**、惠普、**阿里云无影笔记本**。
**已确认用 AW86927 的终端**：**Fairphone 5**、**阿里云无影笔记本**（艾为方案 + 钛方/NDT 压力）、
**小米 Book Pro 14（2026 款）**（艾为「Haptic+Force SoC」官方稿）。

★ 另一条线索：**钛方科技 = NDT**（无影笔记本用的是「NDT 压感触控解决方案」）⇒
**本机的 `钛方 TF100A` 就是 NDT 的压力芯片**，与无影笔记本同一路方案谱系。

### 2.5 ★★★★ **汇顶的厂商命令 framing 在开源代码里有**
`goodix_advance_touch_platform/hid.c`：
```c
tmp_buf[tx_len++] = ((report_type == HID_FEATURE_REPORT ? 0x03 : 0x01) << 4) | reportnum;
tmp_buf[tx_len++] = ((report_type == HID_FEATURE_REPORT ? 0x03 : 0x02) << 4) | reportnum;
```
⇒ **主机用「report number + 载荷」发汇顶厂商命令**。**而本机 `Col04` 实测 `Out=65`（Report ID 0x0E + 64 B）** ——
**这就是那条通道。** 项目已实测到「**强度写入零影响，但反推转发通道存在**」（追加十五）⇒ **通道在，只是命令没找对。**

### 2.6 ★★★★ **汇顶官方 Linux 固件升级工具（berlin 家族）也在手上**
`fwupdate_for_berlin_linux/`：通过 `registers` sysfs 节点更新固件，用法

## 四、由此打开的三个入口（按成本从低到高）

### 入口 1 ★★★★★ 先枚举厂商命令空间，别再假设它没有（**零硬件、当天可做**）
事实：`Col04` `Out=65` 可写 + 汇顶 framing 公开 + 项目已实测"转发通道存在"。
**做法**：用现有 `GoodixCmd.cs` / `ColProbe.cs`（`touchpad-lab\poc\`）**系统性地枚举 report number 与命令字**，
对照 `tpupdate_7868q` 的工具语义（`FwImage::initPid` / `cfg version` / `subFwType`）
—— **重点是找"能把数据下发到私有总线"的那条**。
> ⚠️ **红线仍在**：`00 10 / 00 11 / 0E 12 / 0E 13`（切 patch / 起更新 / 写 flash / 重启）
> 是**真写 flash** 的四条，**先枚举其它命令字，这四条留到最后**。

### 入口 2 ★★★★ 用**官方 Windows 工具链**做已知明文实验
拿戴尔那份 `tpupdate_7868q`（同一工程、同一芯片家族）当**参照实现**：
它的固件文件带 `VID/PID` 字段、有 `subFwType`、有 `cfg version`。
**⇒ 可以拿它对我们本机的 `TB14P_GT7868Q_*.BIN` + `tpcfgsid0.cfg` 做一次格式对照**，
看本机包是否符合 `tpupdate_7868q` 的输入格式。
**若符合 ⇒ "改固件再刷回去"这条路在格式层就是通的**（签名是下一关，但先确认格式）。

### 入口 3 ★★★★ 换思路：**不越过 GT7868Q，而是问它"为什么不转发"**
艾为官方架构说得很清楚：**Force IC 算完力之后，按压力等级把波形发给 AW86927**。
本机的 Force IC = TF100A，但项目已逐指令穷举证明 **TF100A 没有 I²C 主机能力**。
⇒ 两种可能，**都可查**：
- 本机 TF100A 是定制版（固件镜像自称 `TF100A_Test_FW`，项目自己标注过"疑为部分镜像"）
- 或**由 GT7868Q 中继**（这正是"转发通道"要做的事）

> ★ **一个立刻可做的对照**：去比对**无影笔记本 / 小米 Book Pro 14** 的固件包
> （都是 NDT 压力 + 艾为 AW86927 的同一路方案），看它们的**Force IC 固件里有没有"发波形给 AW86927"的代码**。
> 有 ⇒ **本机 TF100A 是阉割版**，方向明确；没有 ⇒ 必须走 GT7868Q 中继。

## 六、纪律（第 43–45 条）

43. ★★★ **"没有 X 的容器" ≠ "没有 X 的接口"。**
    我拿"CS40L25 有固件包"当模板，判 AW86927 "结构性不存在可挖对象" ——
    但人家是**寄存器 + SRAM** 型器件，**编程接口全公开，还带一份 upstream 驱动**。
    ⇒ **形态不同不等于能力缺失。**

44. ★★★ **"标准接口不存在" ≠ "接口不存在"。**
    `Col02 Out=0` 是真的，但那只说明**没有标准 HID 触觉通道**；
    厂商命令通道（`Col04`）从第一次实测起就是可写的，而且**官方工具靠它刷固件**。
    ⇒ **下"封死"结论前，必须把"非标准通道"也列进候选。**

45. ★★★ **别人一句"我查过了"要当成"没查完"来对待 —— 包括我自己。**
    本条由喆直接指出：他在同一天里让我去查 AW86927、Goodix 开源、小米机型这三条，
    **三条我都没真查过就下了"没有"的结论**。
    ⇒ **"我搜过"必须能出示：搜了什么词、命中什么、哪条被否。**
