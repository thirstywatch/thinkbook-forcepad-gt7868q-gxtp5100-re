## §1 为什么要探这个（目标）

`NEXT-SESSION.md` §4 已写明一条**被"作废"两字掩盖的机会**：

> 历史探测帧的**子命令恒为 0**，而真分发器按 **类字节 + 16 位子命令** 取命令 ⇒ **扩展空间（`0x80`/`0xA0`/`0xA1`）从未被探测过**，且其中 **`0xA0-0x0B` / `0xA0-0x0D` 直通触觉波形缓冲**。

**⇒ 三个推论**：
1. 过去的探测**方法本身是错的**（子命令位置一直是 0，等于在问同一个问题）
2. **真正的扩展命令空间从未被打开**
3. **其中至少有一组子命令直通触觉波形缓冲**（`0xA0-0x0B` 写 `0x200040E8`、`0xA0-0x0D` 清缓冲并置状态字）

**如果扩展空间里存在"播放波形"这类命令** ⇒ **不用拆机、不用读固件、不用内层注入** —— 主机侧直接发一条即可触发震动。**这是所有路径里成本最低的一条。**

**同时它还回答另一个关键问题**：GT7868Q **会不会把命令转发给 TF100A**（路线 ② 的核心未证实前提）。`0xA0-0x0B` 直通"波形缓冲"这一点，**已经暗示存在转发路径**。

## §2 帧格式（⚠️ 字节序待定案 —— 见 `COL04-BOUNDARY.md` §4/§5）

> **2026-09-14 晚 修正**：静态解出分发器后发现，固件比较的值形如 `0xNN00`（**低字节必须为 0**）。
> 而 `VibLink.Send()` 把 sub 按小端放 `[2]/[3]`，`sub=0x000B` ⇒ 内部读到 `0x000B` ≠ `0x0B00` ⇒ **永不匹配**。
> **这正是"历史子命令恒为 0"的根因。执行本方案前，必须先做 `COL04-BOUNDARY.md` §5 的定案实验。**

```
[0]  0x0E          固定（Col04 的 report ID）
[1]  类            0x80 / 0xA0 / 0xA1（0xA2 = 回复类【禁发】，0x0E = 固件更新族【禁发】）
[2]  子命令 ?      ← ★ 待定案：H1 放 0x00 / H2 放 sub&0xFF
[3]  子命令 ?      ← ★ 待定案：H1 放 opcode / H2 放 sub>>8
[4]  长度          = payload 长度 + 1（方向字节）
[5]  方向          0x00 / 0x01
[6..] payload
```

**已知的参照帧**（来自已验证的读帧，其子命令恰为 0，故两种字节序都成立 —— 这也是当初误判"已确认"的原因）：
```
0E 20 00 00 05 01 <addr16BE> <size16BE>      ← 类 0x20（内存读，已知安全）
0E 20 00 00 07 01 <addr32BE> <len16BE>       ← 类 0x20 v2（Dell 工具反汇编）
```

**目标帧形态**（字节序待 §5 定案后填）：
```
0E A1 <??> <0B> <len> <dir> <payload...>     ← H1 写法
```

## §3 ★ 探测分级（2026-09-14 晚 重排）

> **核心原则：先定字节序 → 只读查询 → 写入 → 数据块。**

| 级 | 内容 | 动作性质 | 风险 |
|---|---|---|---|
| **L0** | ⚠️ ~~字节序定案实验（发识别帧 + 读 RAM `0x4134`）~~ **已作废** —— 真机实测证明读窗口够不到 TF100A（`COL04-BOUNDARY.md` §10）。字节序只能靠"发 → 看响应"在样机上定 | — | — |
| **L1** | `0xA1` 类 · 子命令 **`0x0B00`**（其余 21 个值见边界表） | **纯读**（结果进响应缓冲） | ★ 最低 |
| **L2** | `0xA1` 类 · 其余 21 个已知值**定点探**（不再盲扫） | 纯读 | 低 |
| **L3** | `0xA0` 类 · **16 个已知值**逐点探（优先只读性最强的 `0x3300`） | **写**（会改状态） | ★ 高 |
| **L4** | `0x80` 类 · 暂缓（形态疑似定长数据块 + 校验） | 疑似写入 | ★★ 最高 |

> **合法值已全量列出**（`0xA0` 16 个 / `0xA1` 22 个），**边界外的值 = 静默 no-op**（安全），故 L2 的"`0x0000`–`0x0020` 盲扫"已删除。
>
> 🔴 **前置门（2026-09-14 新增）**：L0 作废后，第一件要回答的不再是"字节序"，而是
> **「GT7868Q 会不会把类 `0xA0`/`0xA1` 转发给 TF100A」**——这一点至今无证据。
> 若样机上 L1 连响应都没有，则**整条主机侧路径的最底层假设不成立**，应直接转拆机路线，不要继续耗 L2/L3。

### L1 · 单发验证（最关键的一发）
```
类=0xA1  子命令=0x000B  payload=<n>   方向=1
```
**判读**：
- 返回**非空数据** ⇒ **通道可达扩展空间** ⇒ 继续 L2
- 返回**空 ACK**（与历史一致）⇒ 通道到不了扩展空间 ⇒ **本方案终止**（该结论即最终答案）

### L2 · `0xA1` 子命令扫描（只读）
对 `sub = 0x0000 … 0x0020` 逐个发 `0xA1 <sub> <小 payload>`，记录：
- 是否回复
- 回复长度
- 回复内容
- **是否伴随震动**（人工观察）

### L3 · `0x80` 类（形态未知，只读尝试）
同上，但先只发最短 payload（1 字节）。

### L4 · `0xA0` 类（写 —— 谨慎，且需 L1–L3 结果支撑）
- 优先 `0x000B`（写波形缓冲）与 `0x000D`（清缓冲）
- **最小 payload**，单发
- **发前记录、发后体检 + 观察是否有震动**

## §5 安全规程（硬性）

1. **只在台面样机上执行** —— 编排器强制要求 `-IAmOnSampleUnit` 参数，缺省拒绝运行
2. **禁止发类 `0x0E`**（固件更新族，会打断应答通道 —— 已成因的记录在案）
3. **单发、低频、间隔 ≥200 ms**；不连续轰炸
4. **每发一次，前后各做一次体检**（`类 0x20 读 0x1000×16` 是项目里唯一"已知安全"的命令）
5. **出现以下任一情况立即中止**：
   - 体检失败
   - 返回 `err=122`（应答通道已乱）
   - 读操作被阻塞（>2.5 s）
   - 人工观察到触控板行为异常
6. **不并发**：同一时刻只有一个探测进程

## §11.1 ★ 2026-09-14 晚 新增：边界已静态解出

> **执行本方案前，先读 `COL04-BOUNDARY.md`。** 它给出了：
>
> - **完整边界**：3 个类（`0x80`/`0xA0`/`0xA1`）+ 回复类 `0xA2`；`0xA0` 恰好 **16** 个合法子命令、`0xA1` 恰好 **22** 个（逐值列出）
> - **边界外 = 静默 no-op**（安全），所以探测清单可精确到 38 个值，不必盲扫
> - **安全分级**：`0xA1` = 查询（只读）→ `0xA0` = 命令（写）→ `0x80` = 疑似数据块（最后）
> - **★ 字节序根因**：固件比较值形如 `0xNN00`，低字节必须为 0；而 `VibLink.Send()` 把 sub 放了低字节 ⇒ **永不匹配**
> - **★ 定案实验**：只用已知安全的类 `0x20` 内存读，发一条可识别帧后读回 `0x20004134`，一次看清映射
> - **修正**：`re/vib_handlers_out.txt` 的"触觉"标记存在**过度归属**（stub 区连续排布导致窗口串位）；真正直通触觉的只有 `0xA0-0x0B` / `0xA0-0x0D` / `0xA1` 读回族

## §12 附录：PowerShell 版本与脚本编码（★ 重要，实战踩过）

**本项目 `poc/` 下所有 `.ps1` / `.cs` 均为「无 BOM + 含中文」。**

| 解释器 | 默认读取编码 | 读无 BOM 的中文脚本 |
|---|---|---|
| **PowerShell 7**（`pwsh`，本机 **7.6.6**） | **UTF-8** | ✅ 正确 |
| Windows PowerShell **5.1** | 中文系统为 **ANSI(GBK)** | ❌ **乱码，甚至报语法错误** |

### ⇒ 结论：本目录的脚本**必须用 pwsh7 运行**

**本次实际踩坑记录**：`col04-ext-probe.ps1` 第一版内部用 `powershell.exe`（5.1）去调 `vib-link.ps1`，结果中文注释被 GBK 误解析，报出一串「表达式或语句中包含意外的标记」——
- `line 17: 意外的标记 ")"`（实际那是**注释行**）
- `line 83: 意外的标记 "!!"`（来自 `Log ("!! ...")`）
- `line 148: 字符串缺少终止符`

**这些全是编码假错误，不是脚本写错。** 改成优先 `pwsh` 后一次通过。

**编排器已内置自动处理**：`col04-ext-probe.ps1` 会自行探测解释器（**优先 `pwsh`，缺失时才回退 `powershell.exe`**），并在日志首行打印实际使用的解释器。

**手工调用时请用**：
```powershell
# ✅ 正确
pwsh -NoProfile -File .\vib-link.ps1 HEALTH

# ❌ 错误（中文系统上会乱码）
powershell.exe -File .\vib-link.ps1 HEALTH
```

**另**：`col04-ext-probe.ps1` 自身保存为 **UTF-8 with BOM**，这样 5.1 与 7 都能正确读取（冗余保险）；但这不改变「跑起来必须用 pwsh7」的结论——因为它**调用的** `vib-link.ps1` / `ColProbe.cs` / `VibLink.cs` 仍是 no-BOM。
