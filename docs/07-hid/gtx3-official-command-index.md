## 0. 传输层约定（先看这个）

**两条原语**（`gtx5/gtx5.cpp`），**语义完全不同**：

| 原语 | 函数 | 用途 | 首字节 |
|---|---|---|---|
| **A · 地址写** | `Write(addr, buf, len)` `:227-276` | 往**某地址**写数据（可自动拆包） | `0x0E` 强制 |
| **B · 命令帧** | `Write(buf, len)` `:281-309` | 发**元命令**（`0x10/0x11/0x12/0x13`） | **`buf[0]` 被无条件覆盖为 `0x0E`** |
| 读 | `Read(addr, buf, len)` `:132-197` | 读某地址（先发 read-start 帧，再 `GET_FEATURE` 回收） | `0x0E` 强制 |

### 原语 A 的帧格式（**与本项目已知的 Col04 报文逐字节同构**）

```
[0]=0x0E   [1]=0x20(_I2C_DIRECT_RW)   [2]=follow(0x01/0x00)   [3]=pkg_num
[4]=len+5  [5]=0x00(写)               [6..7]=addr(BE)         [8..9]=len(BE)   [10..]=data
```
- 常量：`_I2C_DIRECT_RW = 0x20` · `GDIX_PRE_HEAD_LEN = 5` · `GDIX_DATA_HEAD_LEN = 5` · `GDIX_RETRY_TIMES = 6`（`gtx5/gtx5.h:36-43`）
- **每帧最多 55 字节数据**（65 − 5 − 5）；更大自动拆包：`[2]=0x01`（follow）、`[3]` 递增包号、**地址自动递增**
- 读：`[5]=0x01`（`0x0E 20 00 00 05 01 <addr16BE> <len16BE>`）

> **★★★ 结论**：本项目 Col04 通道 == 官方 `_I2C_DIRECT_RW`。**我们缺的不是通道，是命令编排。**

## 2. 逐命令布局表

### `0x12` — 把 RAM 的 4 KB 块写进 flash（★ 最关键）

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `0x0E`（report id，传输层强制） |
| 1 | 1 | `0x12` = 命令码 |
| 2–3 | 2 | `0x00 0x00` |
| 4 | 1 | `0x06`（固定） |
| 5–6 | 2 | `unitlen`，**大端**（本块长度，≤ `RAM_BUFFER_SIZE`=4096） |
| 7 | 1 | flash 地址 `[23:16]` |
| 8 | 1 | flash 地址 `[15:8]`（**低字节恒 0** ⇒ 地址 256 对齐） |
| 9–10 | 2 | **校验和，大端** |

**校验和算法**（`gtx2_update.cpp:165-168`）：
```cpp
for (check_sum = 0, i = 0; i < unitlen; i += 2)
    check_sum += (data[i] << 8) + data[i+1];   // uint16 ⇒ 自然模 65536
```
⇒ ★ **按【大端 16 位字】累加**，**不是逐字节累加**（与容器级校验和**不是同一种**，勿混）。

**前置**：本块数据须先由**原语 A** 写到 `FLASH_BUFFER_ADDR = 0xC000`。
**后置**：`usleep(80000)` → 轮询 `Read(0x5096,1)` 直到 `== 0xAA`（最多 100 次 × 2 ms）；成功后往 `0x5096` 写 1 字节 `0x00` 清零。

### `0x10` / `0x11` / `0x13` — 直发命令帧

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `0x0E` |
| 1 | 1 | 命令码 |
| 2–3 | 2 | `0x00 0x00` |
| 4 | 1 | `0x01` |
| 5 | 1 | `0x01` |

**共 6 字节。** 后置延时：`0x10` → 250 ms；`0x11` → 100 ms；`0x13` → 300 ms。

### 写 `0x4160`（`CMD_ADDR`）的命令

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `0x0E` |
| 1 | 1 | `0x20`（原语 A 的标志） |
| 2 | 1 | `0x00` |
| 3 | 1 | `0x00` |
| 4 | 1 | `0x0A`（= 5 + 5） |
| 5 | 1 | `0x00`（写） |
| 6–7 | 2 | `0x41 0x60`（= `CMD_ADDR`，大端） |
| 8–9 | 2 | `0x00 0x05`（长度 5，大端） |
| 10–14 | 5 | `{cmd, dataHi, dataLo, ckHi, ckLo}` |

## 3. 特殊寄存器区（`0x4160` 家族 / 状态地址）

| 地址 | 名称 | 语义 | 出处 |
|---|---|---|---|
| **`0x4160`** | `CMD_ADDR` | **命令寄存器**：`0xFF`=IC 空闲；写 `80/83/7D/32/33/34`；读回应答 `82/7F/7E..` | `gt7868q/gt7868q.h:23` |
| **`0x5095`** | `BL_STATE_ADDR` | **bootloader 状态**，轮询到 `== 0xDD` 表示已进升级态 | `gtx2/gtx2_update.h:25` |
| **`0x5096`** | `FLASH_RESULT_ADDR` | **flash 写结果**，`== 0xAA` 表示本块写成功（之后写 `0x00` 清零） | `gtx2/gtx2_update.h:26` |
| **`0xC000`** | `FLASH_BUFFER_ADDR` | **RAM 暂存区**（每块 ≤4096 B，写入后再发 `0x12`） | `gt_update.h:9` |
| **`0x96F8`** | `CFG_START_ADDR` | **配置的 RAM/xdata 暂存地址**（交互路径写这里；也是配置版本读取地址，读 3 B） | `gt7868q/gt7868q_update.cpp:41` |
| **`0x19000`** | `CFG_FLASH_ADDR` | ★ **配置在 flash 里的地址**（ISP 路径经 `0x12` 写这里 ⇒ **持久**） | `gt7868q/gt7868q_update.cpp:40` |

> ★ **`0x96F8` vs `0x19000` 是"RAM 暂存 vs flash 落盘"的分界** —— 这是本项目 B12 症状的根。
> 另注：本项目实测 `0x96F8` 只能读 32 B，是**相位问题**（见《全书》§19.34 与第十四轮），与本表不冲突。

## 4. 两条完整序列（对照用）

### 4.1 固件更新（`GT7868QUpdate::fw_update`，`gt7868q_update.cpp:122-311`）

```
① 0E 10 00 00 01 01              （切 patch）      → usleep 250ms
② 写 0x4160 ← {33,00,00,00,33}   （关坐标，重发 3 次）
③ 读 0x5095 轮询 == 0xDD         （等 bootloader，6×30ms）
④ 0E 11 00 00 01 01              （启动更新）      → usleep 100ms
⑤ 逐个子固件：{ 写 0xC000(≤4096) → 0E 12 … → 轮询 0x5096==0xAA }
⑥ （可选）配置 ISP：同 ⑤ 但目标 0x19000
⑦ 写 0x4160 ← {34,00,00,00,34}   （开坐标）
⑧ 0E 13 00 00 01 01              （复位，重试 3 次）→ usleep 300ms
⑨ 写 0x4160 ← {32,00,00,00,32}   （切 PTP）
失败分支：同样执行 ⑦→⑧→⑨
```

### 4.2 交互式配置（`cfg_update`，`gt7868q_update.cpp:393-592`）

```
① 写 0x4160 ← {33,…} ×3          （关坐标）
② Read(0x96F8, 3)                 （读旧版本）
③ 轮询 0x4160 == 0xFF             （等 IC 空闲，10×10ms）
④ 写 0x4160 ← {80,00,00,00,80}    （"我要发配置"）→ usleep 250ms
⑤ 轮询 0x4160 == 0x82             （等确认，6×30ms）
⑥ 写 0x96F8 ← 配置字节            （★ 只是 RAM 暂存）→ usleep 100ms
⑦ 写 0x4160 ← {83,00,00,00,83}    （"xdata 已就绪"）→ usleep 80ms
⑧ 轮询 Read(0x4160,5) == 0x7F 或 7E 00 07   （6×30ms）
⑨ 写 0x4160 ← {7D,00,00,00,7D}    （★ end send cfg）
⑩ 读 0x96F8 复核
收尾：仅写 0x4160 ← {34,…}（开坐标）
```

> ★★ **`7E 00 07` = "配置与 flash 相同"**（`"config data is equal with flash"`）—— **是正常结果，不是失败。**
> ★★ **⑥ 单独做不够**：必须完成 ⑦（`0x83`）+ ⑨（`0x7D`）才算"告知 IC 落盘"。

## 5b. ★ 状态寄存器取值全表（2026-10-12 补；源自《全书》§19.46.1）

### `0x5096`（`FLASH_RESULT_ADDR`）—— flash 写结果

| 值 | 含义 | 出处 |
|---|---|---|
| **`0xAA`** | **成功** | 官方 gtx2 / gtx3 / gtx5 / gtx8 / gtx9 / gt7868q / berlin_a / marsei **全部只认它** |
| **`0xBB`** | ★ **IC 收到的数据校验和错误** | `marsei` / `gtx9`（官方唯一出处） |
| **`0xCC`** | IC 从 flash **回读**的校验和错误 | 同上 |
| `0x00` | 成功后由主机清零 | `gtx2_update.cpp:206` |
| `0x75` | 空闲 / 复位默认值 | ⚠️ **仅本项目实测；公开材料查不到** |

> ⚠️ **辨析**：`gtx9/gtx9_i2c_update.cpp` 里的 `FLASH_CMD_TYPE_WRITE = 0xBB` 是**命令类型**，
> **不是**结果状态，勿混。
>
> ★ **本项目实测到的 `0xBB` 根因**（2026-10-11，见《全书》§19.46）：**不是** IC 之谜，
> 而是主机侧 `gxmem.write()` **静默截断**（4096 B 实际只发出 55 B）⇒ 校验和不符 ⇒ 报 `0xBB`。
> **⇒ 排查 `0xBB` 的第一步永远是：先确认主机侧"声明长度 == 实际发出长度"**（纪律 133）。

### `0x4160`（`CMD_ADDR`）—— 命令寄存器取值

| 值 | 含义 |
|---|---|
| `0xFF` | 空闲（`wait until ic is free`） |
| `0x82` | 对 `0x80`（请求发配置）的应答 |
| `0x7F` | 配置处理成功 |
| `0x7E 00 07` | 配置与 flash 中一致（`config data is equal with flash`）—— **正常结果，不是错误** |
| `0x80` / `0x83` / `0x7D` | 命令码：发配置 / 配置就绪 / 结束发配置 |

> ⚠️ **`7E 00 02` 官方源码未见**，属本项目自测推断；且 2026-10-08 已证 `7E 00 02` 只代表
> **"RAM 暂存区被改写"**，**不是**"已写入 flash"（登记表 **B12**，见《全书》§19.42b.4）。

### `0x5095`（`BL_STATE_ADDR`）—— bootloader 状态

官方只定义 **`0xDD`**（ISP / mini-system 就绪）。
⚠️ 空闲态的变值（实测 `0xBE / A7 / C2 / B7 / CC / DA / E1 / B4`）**任何公开材料都查不到解释** ⇒
判"是否已进 bootloader"必须**连续 N≥5 次读一致**（登记表 **B23** / 纪律 126）。

---

### ★★ `CFG_FLASH_ADDR` 在源码里有**三个互不相同**的值（本机实测选哪个）

| 家族 | 源码里的值 | 本机实测 |
|---|---|---|
| `gtx2` / **`gtx3`**（gt7868q 的父类） | `0x3E000` | — |
| `gt7868q` | `0x19000` | 🔴 **写它致退化**（落在镜像未覆盖区） |
| **fwupd `gtx8`** | **`0x1E000`** | ✅ **写它无害**（2026-10-12 实测） |

⇒ **地址常量不能只看名字/出处，必须以【本机固件映射】裁决**（纪律 **143**）。

### 🔴 `0x5096 == 0xAA` **不等于**「配置被接受」

2026-10-12 实测：把 cfg **只改 2 个字节**后写入 flash ⇒ `0x5096` 回 **`0xAA`**，
**但 IC 随后拒绝该 cfg、回退到内置默认**（`0x96F8` 变 `22 01 11 00 34 01…`）。

⇒ `0xAA` ⇔「`0xC000` 被完整 4096 B 覆盖 + u16BE 字和匹配」= **传输层成功**；
**配置是否被 IC 接受/生效，必须用重启后的状态验证**（纪律 **144** / 登记表 **B32**）。
