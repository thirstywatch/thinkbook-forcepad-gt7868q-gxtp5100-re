## 〇、先搞清楚：到底是谁拦的

RWE 报错 `Driver cannot be loaded`。事件日志（`Microsoft-Windows-CodeIntegrity/Operational`）原话：

```
id=3023  The driver \Device\HarddiskVolume3\Windows\System32\drivers\RwDrv.sys
         is blocked from loading as the driver has been revoked by Microsoft.
id=3077  ... did not meet the Authenticode signing level requirements or
         violated code integrity policy
```

### 本机当前状态（2026-10-01 实测）

| 机制 | 状态 | 是否拦 RwDrv |
|---|---|---|
| VBS / 虚拟化安全 | `VirtualizationBasedSecurityStatus = 2`（运行中） | 它本身不直接拦，但承载 HVCI |
| **HVCI（内存完整性）** | `Enabled=1` | ✅ **拦**（强制所有内核驱动通过 Microsoft 签名） |
| **易受攻击驱动程序黑名单** | `VulnerableDriverBlocklistEnable = 1` | ✅ **★ 主要元凶**（`RwDrv.sys` 正是"被吊销"名单里的） |
| 内核 CI 策略 | `CodeIntegrityPolicyEnforcementStatus = 2`（强制） | 配合上面两层生效 |
| Secure Boot | 未取到（需管理员查询） | 若黑名单由固件变量下发，则**必须关 Secure Boot** |

### ⇒ 结论：**要关的是这两样**

1. **易受攻击驱动程序黑名单**（`RwDrv.sys` 被点名的直接原因）
2. **HVCI / 内存完整性**（它要求所有驱动通过 Microsoft 签名）

VBS 本身可以先不动（关掉 HVCI 后 VBS 通常自动停）。

## 一、关闭步骤

> 全程需要**管理员**。两处改完**重启一次**才生效。

### 1.1 关"内存完整性"（HVCI）

**方式一：图形界面（推荐，最直观）**

1. 开始菜单搜 **"核心隔离"** 或 **"Windows 安全中心"**
2. Windows 安全中心 → **设备安全性** → **核心隔离详细信息**
3. 把 **"内存完整性"** 开关**关掉**
4. 它会要求重启 —— **先别急着重启**，把下面 1.2 也做完一起重启

**方式二：命令（管理员 PowerShell）**

```powershell
reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 0 /f
```

### 1.2 ★ 关"易受攻击驱动程序黑名单"

**这是关键的一步。**

```powershell
reg add "HKLM\SYSTEM\CurrentControlSet\Control\CI\Config" /v VulnerableDriverBlocklistEnable /t REG_DWORD /d 0 /f
```

⚠️ **重要**：在较新的 Windows 11 上，这个黑名单可能**同时由 UEFI 变量（SMM）下发**。若只改注册表无效，则必须：
- 进 BIOS **关闭 Secure Boot**，或
- 该设置由 Windows 安全中心的"本地安全机构保护 / 内核隔离"页面统一管理

⇒ **改完重启后，先用第 3 节的验证命令确认真的生效了**，再试 RWE。

### 1.3 重启

```powershell
shutdown /r /t 0
```

## 二、重启后的验证（务必先做这步）

**管理员 PowerShell** 跑这一段，三个值必须都是 `0` / 不运行：

```powershell
"--- HVCI ---"
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity' -EA SilentlyContinue).Enabled
"--- 黑名单 ---"
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CI\Config' -EA SilentlyContinue).VulnerableDriverBlocklistEnable
"--- VBS 状态 (0=off 1=enabled 2=running) ---"
(Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard).VirtualizationBasedSecurityStatus
```

期望：`HVCI=0`、`黑名单=0`、`VBS=0 或 1`

**如果黑名单还是 1** ⇒ 它是被固件/UEFI 强制的 ⇒ 需要进 BIOS 关 Secure Boot。

## 三、跑 RWEverything 扫 I²C

工具已就位：

```
<LAB>\touchpad-lab\rwe\Win64\Portable\Rw.exe
```

### 3.1 启动
**右键 `Rw.exe` → 以管理员身份运行** → UAC 点"是"
→ 这次**不该**再报 `Driver cannot be loaded`。如果还报，回第 1.2 节。

### 3.2 进 I²C 界面
顶部菜单 **`Access`** → 找 **`I2C`** 或 **`SMBus`** / **`I2C/SMBus`**
（不同版本位置略不同；若找不到，把菜单截图发我）

进去后左侧会列出总线（本机有 3 条可见控制器：`7E78` / `7E7A` / `7E7B`，对应不同 bus number）。

### 3.3 读寄存器（**只读**）
对**每一条总线**重复：

| 字段 | 填什么 |
|---|---|
| Device / Slave Address | `5A` |
| Register / Command | `57` |
| Length / Count | `1` |
| 操作 | **Read**（绝不点 Write） |

记录读回值。然后同样方式读 **`58`**。

### 3.4 ★ 判定表

| 读 `0x57` | 读 `0x58` | 结论 | 下一步 |
|---|---|---|---|
| **`0x92`** | **`0x70`** | ★★★ **确认是 AW86927，且在主机可见总线上** | **纯软件路成立**！按 Fairphone 流程写它就能震 |
| 有值，但不是 `92/70` | — | 该地址是别的设备 | 试 `5B`，并换下一条总线 |
| 无应答 / 全 `FF` | — | 这条总线上没有它 | 换下一条总线 |
| **所有总线都无应答** | — | 芯片在主机够不到的地方（EC 总线 / 模组内私有线） | 纯软件路到头 → 只剩拆机 |

### 3.5 三条铁律

1. **只读**。看到 `Write` / `Modify` / `Set` 一律不点。
2. **绝不碰** `0x00`（软复位）、`0x5B`（TMCFG 解锁）、`0x09`（PLAYCFG4 GO）。
3. 读的时候**手别碰触控板**。

## 四、恢复步骤（做完就恢复，别忘）

```powershell
# 恢复内存完整性
reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 1 /f
# 恢复易受攻击驱动黑名单
reg add "HKLM\SYSTEM\CurrentControlSet\Control\CI\Config" /v VulnerableDriverBlocklistEnable /t REG_DWORD /d 1 /f
# 重启生效
shutdown /r /t 0
```

（若曾在 BIOS 关过 Secure Boot，记得回 BIOS 打开。）

## 五、⚠️ 风险告知（我不替你决定，但你该知道）

| 关掉的东西 | 少了什么保护 |
|---|---|
| **HVCI / 内存完整性** | 内核驱动的代码完整性校验。恶意/有漏洞的内核驱动可被加载 → 可提权到内核 |
| **易受攻击驱动程序黑名单** | Windows 不再拒绝已知有漏洞的驱动（BYOVD 攻击面） |
| Secure Boot（若需要关） | 开机引导链不再校验签名 |

**期间注意事项**：
- 尽量**别装/运行来路不明的软件**
- **别在这段时间插不认识的 U 盘/设备**
- **探测做完立刻按第四节恢复**

## 六、备选方案（如果 A 走不通）

| 情况 | 备选 |
|---|---|
| RWE 关掉安全机制后**仍报驱动错误** | 说明 RwDrv 还要求 Microsoft 签名 ⇒ 换 **PawnIO**（它带 WHQL 签名的驱动，走"签名的通用底层访问"路线，不受此限） |
| 黑名单关不掉（固件强制） | 走 **Linux live USB**（Linux 内核自带 I²C 驱动，**完全不存在签名问题**）—— 你说过有可格式化的 U 盘 |
| 读不到任何 I²C | RWE 版本对 Intel Serial IO 支持有限 ⇒ 换 PawnIO 路线 |

### 关于 PawnIO（值得记一笔）
`thinkcentre-fan-control` 项目用的就是它：**PawnIO 驱动是签名的**，通过加载不同功能模块（如 `LpcACPIEC.bin`）来做底层端口/EC 访问。
⇒ 如果 RWE 一直被拦，**PawnIO 可能是 Windows 上唯一可行的带签名底层访问通道**——既能读 EC（`0x62/0x66`），也可能有 I²C 模块。
