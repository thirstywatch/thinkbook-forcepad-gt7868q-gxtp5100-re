## 〇 一句话现状

**GT7868Q 加扰区的 1024 字节 keystream 已完整恢复，整个加扰区成功解密，
产出明文固件 `GT7868Q_plain.bin`。**

关键转折：**不需要"外部明文锚点"**。厂商固件里本来就有**明文全 0 的填充段**，
而 `0 ⊕ K = K` —— 密文在该段**直接等于 K**。锚点一直就藏在固件自身里。

## 一 突破路径（三步）

### 1.1 触发点：搜索"明文孪生"时意外发现「纯区」

为 A③ 找锚点，下载了 Goodix **GT9896**（同代 Yellowstone GTX8，触屏）的
ihex 固件 → 解出 96,512 B。它是**头部明文 + 主体加扰**结构（熵 7.95–8.0）。

随后做「K 泄露扫描」时发现：`cont` 与 `anchor` 各有一段
**1024 自相关 = 1.000000（100%）** 的区域：

```
cont   [0x084F0 .. 0x0923B]   3403 B   "1024 周期纯区"
anchor [0xD900  .. 0xF0FF]    6143 B   "1024 周期纯区"
```

100% 的 1024 自相关意味着 `C[i] == C[i+1024]` **恒成立**。
对 `C = P ⊕ K`（K 周期 1024）而言，这等价于 `P[i] == P[i+1024]`
—— **最自然的解释就是该段明文全为 0（未使用区）**。

### 1.2 提取 K

若纯区明文 `P ≡ 0`，则 `C ≡ K`，直接读出：

```
Mc = cont[0x084F0 : 0x084F0 + 1024]
K[j] = Mc[(j − 240) % 1024]          // 240 = 0x084F0 % 1024
```

解码公式：`P[x] = C[x] ⊕ K[x % 1024]`（x 为文件偏移）。

数学自洽检验：纯区 `x = 0x084F0` ⇒ `x % 1024 = 240` ⇒ 用 `K[240] = Mc[0] = C[0x084F0]`
⇒ `P = C ⊕ C = 0` ✓ 与"明文全 0"假设闭合。

### 1.3 跨型号交叉验证（证明 K 是厂商常量，不是巧合）

```
cont   [0x084F0 : +1024]  ==  rotate( anchor[0xD900 : +1024], 692 )   相同率 = 1.0000
```

**两个不同型号的固件里存在同一个 1024 字节序列（模循环移位）** ——
这只能是厂商软件常量。K 的真实性由此确立。

## 二 K 的形态

| 属性 | 值 |
|---|---|
| 长度 | **1024 字节** |
| 熵 | **8.0000** |
| 唯一字节值 | **256 / 256** |
| 每个值的出现次数 | **恰好 4 次**（1024 ÷ 256） |
| 前 32 B | `c6 cc 3a 3c 56 e8 6a 5c d6 ec 7a 7c 4e d8 2b 1d ce dc 3b 3d 5e f8 6b 5d de fc 7b 7d 47 c9 aa 1e` |

**"每个值恰好出现 4 次"是人为构造的铁证**：真随机 1024 序列的字节计数
服从泊松分布（均值 4），**不可能 256 个值全部精确等于 4**。

产物：`GT7868Q_scramble_key.bin`（1024 B）

## 四 解出的固件是什么

```
0x00000 – 0x011FF   明文头（未加扰）  YELSTO / 7868Q / 配置表
0x01200 – 0x197FF   加扰主体（本次解开）  99,840 B
0x019A00 – end      TF100A 段（另一芯片固件，未加扰）
```

**主体成分**（按 512 B 块统计）：50.0% 代码区间（熵 6–7）+ 33.5% 密集数据（7–7.6）
+ 8.2% 全 0 填充 + 8.2% 稀疏表。

**地址常量证据**（随机数据不可能出现）：
- `0x08000000`（Flash 基址）出现 3 次：0x05619 / 0x077F1 / 0x0BE71
- `0x20000000`（SRAM 基址）出现 2 次：0x126B9 / 0x18729
- `0x40000000` 1 次：0x127E1

**与 GT9896 的同源性**：`cont[0x116C]` 与 `anchor[0x0030]` 有 35 B 逐字节相同的
配置表（`03 00 00 20 00 00 60 00 …`）；头部 `YELSTO` 前后结构一致。

产物：`GT7868Q_plain.bin`（161,628 B）

## 七 可复用方法（已同步进 skill）

1. **纯区探测**：对密文做 1024 自相关扫描，找 `== 1.0` 的区块
   ⇒ 明文常量填充 ⇒ `C ≡ K`，K 直接暴露。
2. **相位搜索判据用"0x00 计数"而非熵**：正确相位会让 0 计数出现
   数量级尖峰（本例 7455 vs 534）。
3. **跨样本互证**：若两份不同型号固件的"纯区"互为循环移位，
   则 K 是厂商常量，可信度陡增。
4. **排除第二层**：检查解码后**是否存在熵 > 7.6 的块**。
   乱码/加密必然产生这类块；固件本体则不会。
5. **对照已知明文段**：同文件内的未加扰段（本例 TF100A）是最好的熵分布参照。

## 八 诚实的边界

1. **K 是否对所有 GTX8 型号通用？未确证。** 对 GT9896 做全相位搜索，
   最佳仅 588 个 0x00（基线 128）、最长 0 段仅 4 B —— **没有尖峰**。
   说明 GT9896 的加扰相位基准或主体布局与 GT7868Q 不同，
   不能想当然地把 K 套上去。
   （但两固件的"纯区"确实互为循环移位，说明同一个 1024 序列在两处都存在。）
2. **明文固件里没有找到可读字符串**（除明文头的 YELSTO / 7868Q）。
   已排除：位反转、字内字节交换、字节取反、UTF-16 —— 均无改善。
   结合"无高熵块"的 V5 判据，判断为**该固件本就不含 UI 字符串**，
   而非解密不完整。
3. **刷入风险不变**：ISP 三连 `00 10 / 00 11 / 0E 12` 绝不碰；
   高频轮询 EC/Col04 的硬红线继续有效。
