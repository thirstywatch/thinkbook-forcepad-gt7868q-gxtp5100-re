# 03 · 周期 XOR 加扰破解

> **是什么**：固件数据区看起来像随机噪声。判断它到底是**分组密码 / 压缩 / 周期加扰**，并在是加扰时恢复出周期密钥。
> **做什么**：三步 —— 定性 → 恢复密钥 → 验证。
> **得到什么**：明文固件 + 一套"我凭什么相信解对了"的判据。

---

## 一、是什么

**加扰（scramble）** 不是加密。它没有密钥管理、没有轮函数，只是：

```
ciphertext[x] = plaintext[x] ^ K[x % P]
```

其中 `P` 是周期（本项目 **1024**），`K` 是长度为 `P` 的字节表。

**为什么厂商要这么做**：不是为了保密，而是为了**让 flash 上的数据看起来白噪声化**（均衡磨损 / 避免长串 0/1 / 防止简单读取）。**这意味着它通常很弱，且密钥常常可以从数据自身恢复。**

---

## 二、做什么

### 步骤 1：定性 —— 三项定量判据

| 判据 | 怎么算 | 随机基线 | 本项目实测 |
|---|---|---|---|
| **真压缩器可压比** | `zlib/lzma` 压缩后大小 / 原始大小 | `os.urandom` → 1.0004 | **0.8797** |
| **条件熵 H1 − H0** | 一阶条件熵减零阶熵 | 随机 → 7.4576 | 本区 **7.1009**（低 0.36 bit） |
| **lag1 自相关** | 相邻字节相关 | 随机 → 0.00381 | **0.01149 = 2.94×** |

**判读规则**：

| 现象 | 结论 |
|---|---|
| 三项**全落在随机基线** | 可能是分组密码 |
| 三项**全部偏离**，但**偏离很弱** | ★ **正是周期 XOR 加扰的特征** |
| 可压比显著低（如 0.47） | 有真代码 / 强结构 |
| 压缩器能抓出 zlib 流 | 有压缩层 |

> 🔴 **本项目最贵的教训**：当时从"三项偏离随机"外推出"所以没有加扰" —— **错的**。
> **加扰恰好是一种能让三项判据都只呈现"弱偏离"的变换。**
> **⇒ 写结论时必须分开写"排除了什么"和"排除不了什么"。**

**阳性对照（必做）**：埋一段真 zlib 流进去，确认你的压缩探测器**能抓出来**。探测器不灵敏 ⇒ 你的"没搜到"毫无意义。

### 步骤 2：恢复周期密钥 K

#### 2.1 周期怎么定？

对候选周期 `P`，做**自相关 / 重复块间距统计**。本项目：块级重复率 12%，且重复间距集中在 1024 的倍数。

#### 2.2 K 从哪来？

**关键洞察**：加扰区里如果存在**大段零填充**（空白 flash 的正常形态），那么：

```
plaintext = 0x00  ⇒  ciphertext = 0x00 ^ K = K
```

⇒ **raw 中会出现 K 的原样副本。**

**提取方法**：在 raw 中找长度为 `P`、且**字节直方图"人工配平"**的窗口。

```python
# 人工配平 = 256 个值每个恰好出现 len(K)/256 次 ⇒ 卡方 ≈ 0
from collections import Counter
c = Counter(K)
expected = len(K) / 256
chi2 = sum((c.get(i,0) - expected) ** 2 / expected for i in range(256))
# 本项目 K：1024 B，256 个值各出现 4 次 ⇒ chi2 == 0.00
```

#### 2.3 相位怎么定？

**穷举全部 1024 个相位**，对每个相位解一遍，用**判据打分**选最优。

```python
for phase in range(1024):
    k2 = rot_left(K, phase)
    dec = bytes(v ^ k2[(i + 0x100) % 1024] for i, v in enumerate(data_region))
    score = sum(block_entropy(b) for b in split_to_blocks(dec))
    # 取 score 最小者
```

**★ 必须用多份独立样本交叉验证。** 只靠一份样本，从 1024 个相位里挑 1 个，**毫无统计力** —— 随机数据也能挑出一个"最优相位"。

本项目：**四份独立固件全部指向同一相位** ⇒ 定案。

| 项 | 值 |
|---|---|
| 最优相位 | **572**（数据区相对）/ **316**（容器相对） |
| 次优 | 60（熵明显更高） |
| 13 块求和 H0 最小 / 均值 | **88.4678 @572** / 102.4734 |

> **换算**：数据区起点 = 容器 + `0x100`，所以 `316 + 0x100 = 572`。

### 步骤 3：验证解对了（★ 三条，缺一不可）

| # | 验证 | 通过标准 | 为什么这条可信 |
|---|---|---|---|
| ① | **K 的直方图是否人工配平** | 卡方 ≈ 0 | 真随机/真数据不会恰好均衡；keystream 才会 |
| ② | **穷举相位 + 多份独立样本交叉** | 四份固件指向同一相位 | 排除过拟合 |
| ③ | **解出后出现整块零填充** | 有 | 空白 flash 的正常形态，随机碰不出来 |

**本项目验证结果**：

| 指标 | 加扰区（100,352 B） | 解出后 | 对照 |
|---|---|---|---|
| 熵 H0 | 7.9977 | **7.0066** | 随机 8.0 |
| 二元组熵 H2 | 15.100 | **12.395** | — |
| 零字节 | 0.36% | **14.99%** | 空白 flash 正常水平 |
| **最长连续零串** | **4 B** | **5450 B** | ★ **最硬的一条** |
| 子固件块数 | — | **13** | = 官方 `subsys_num` ✅ |

## 三、得到什么结果

13 个子固件明文全部解出。其中 `type=0x03 / flash_addr=0x0A000` 那块：

| 指标 | 值 |
|---|---|
| H0 | **2.7385** |
| 零字节 | **74.16%** |
| 最长零串 | **5450 B** |

**⇒ "解对了"的铁证。**

### ⚠️ 但"解出来了"不等于"是有用的东西"

解出后 13 块的 H0 仍在 **6.8–7.4**，说明**载荷主体不是代码**（是系数 / 基线 / 校准数据 / 空白）。

这曾被误读为"解密失败"。**正确理解**：
> **"读到的不是代码"是内容问题，不是可读性问题。**

## 四、🔴 必读：本项目在这里犯过的错（两天）

### 错误 1：循环论证（根因）

曾列了五条"决定性证据"论证「K 不是密钥」，**全部是循环论证**：

| 曾经的"证据" | 真相 |
|---|---|
| `tpfw.bin` 里 10 个「完美均衡块」 | 其实是 **10 处零填充**（`tpfw` 自己也加扰） |
| `tpfw[0x1C00:0x2000] == rot_left(K, 316)` 逐字节 0 误差 | **这恰恰是正确答案的相位！**（316） |
| K 的 256 个旋转变体在 `tpfw` 中命中 4619 处 | 连续斜坡 = 一整段零填充 |
| 45 对均衡块两两命中率 1.0000 | 同一零填充块的 1024 B 切片 |
| raw 中 2645 处 K 循环片段 | 实测其中 **4438/4441 是相邻位置**，只分 **3 段连续区** ⇒ 不是 2645 份副本，是 3 段零填充 |

**⇒ 从来不是"同一份数据重复铺 10 遍"，而是"10 段零填充把 K 照了出来"。**

### 错误 2：由此沉淀的纪律也是错的

> ~~一张表在文件里出现 ≥2 份完全相同 ⇒ 它是数据表，不是密钥。密钥不需要副本。~~ ❌

✅ **正确纪律**：
> **当密钥候选来自数据自身时，"出现次数"完全不能作为判据（循环）。**
> 必须改用：① 直方图是否人工配平 ② 穷举相位 + 多份独立样本交叉 ③ 解出后是否出现整块零填充。

### 错误 3：漏掉一条 10 秒可得、方向相反的判据

`tpfw[0x1C00:0x2000] == rot_left(K, 316)` 早就写在文档里了，**躺在项目里两天没人认出来**。

> **发现"正确答案"时不要急着否掉它。**

### 错误 4：窗口边界错 ⇒ 后续所有统计跑偏

早期所有分析跑在错误边界 `0x1400–0x19800` 上（跨块 + 偏移 452 B）。
> **先解容器 → 拿到块边界 → 再统计。**

### 错误 5：跨层越界

"外层是 UEFI 合约"**推不出**"内层不是加密固件"。
> **跨层推断要显式声明。**

## 五、判据速查卡

```
□ 周期 P 已确定？                    → 自相关 / 重复块间距
□ K 的直方图人工配平（卡方≈0）？     → 否则不是 keystream
□ 穷举了全部 P 个相位？              → 否则是猜
□ 多份独立样本指向同一相位？          → 否则是过拟合
□ 解出后出现整块零填充？             → 否则没解对
□ 块数与官方 subsys_num 对得上？      → 交叉验证
□ "排除了什么"和"排除不了什么"分开写了？
□ 阳性对照做过了吗？                 → 否则"搜不到"无意义
```
