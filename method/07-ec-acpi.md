# 07 · ACPI 导出 / EC RAM 读取与差分

> **是什么**：排查"震动是不是由 EC（嵌入式控制器）参与/触发"，并从 ACPI 拿到权威的总线与地址信息。
> **做什么**：零权限导出 ACPI → 反编译 → 扫描 → EC RAM 读取 → 6 相位差分实验。
> **得到什么**：EC 线关闭（在本探针灵敏度下）+ 一套零权限 ACPI 导出技巧。

---

## 一、★ 零权限导出完整 ACPI（可复用技巧）

### 注册表路径

```
HKLM\HARDWARE\ACPI\<表键>\<OEMID>\<OEMTABLEID>\<REV>  →  值名 "00000000" = REG_BINARY
```

### 🔴 关键

> **`SSD1..SSDS` 是【平级表键】，不是 SSDT 的子键。**

遍历错了只能导出 3 张表（本项目最初的失败原因）。修正后：**32 表 / 761,859 B**。

### iasl 反编译正确用法

```bash
iasl -e <SSDT...> -d <DSDT.bin>
```

> ❌ **反编译模式不能用 `-o <path>`**（报 `Option requires a single-character suboption: -o`）

产物：DSDT 反编译 **100,645 行 / 3.82 MB**。

## 二、扫描

触觉关键词（vib / haptic / motor / LRA / buzz / …）在本机 ACPI 中 **全部 0 命中**。

## 三、DSDT `TPAD` 子树机制

| 项 | 内容 |
|---|---|
| `TPID` | 五厂商表（按厂商/型号给出从地址） |
| `IICBADR0` | **从地址的真身** —— `IICB(ADR0,"\_SB.PC00.I2C0")`，`ADR0 = TPID[GXTP5100][1] = 0x2C` |
| `_DSM` | 完整伪 ASL 见 `docs/06-ec-acpi/` |
| 中断资源 | 见 `docs/06-ec-acpi/` |
| 资源模板机制 | **`_CRS` 决定 SPB connection ID** ⇒ 这是 Windows SPB 规则的根 |

> ### ★ 结论
> **I²C 子设备地址的权威在 `_CRS`，不是 `_ADR`。**
> 本项目曾长期把 `_ADR = 1` 当成 I²C 地址 —— **错的**。

## 四、EC RAM 读取

### 工具：PawnIO

```
pawnio_open → pawnio_load(blob) → pawnio_execute(handle, "ioctl_xxx", in, out, &retSize)
```

| 项 | 说明 |
|---|---|
| 模块 | `LpcACPIEC.bin`（2,612 B），端口仅 **`0x62` / `0x66`**，握手 `RD_EC` |
| 权限 | **必须管理员**（非管理员 `pawnio_open` 返回 `0x80070005`） |
| 签名 | ⚠️ PawnIO 校验 **RSA-4096** 签名，官方版只加载官方签名模块 |
| 其它模块 | `SmbusI801.bin`（55,540 B，PCH SMBus）、`SmbusIntelSkylakeIMC.bin`（19,828 B） |

> **Windows 上读 EC 的唯一途径 = 内核驱动**（**没有** `IOCTL_ACPI_READ_EC`）。

## 五、★ EC 差分实验

### 设计

| 项 | 值 |
|---|---|
| 相位 | **6 个**：IDLE / TOUCH / LIGHT / HARD / HOLD / IDLE2 |
| 轮次 | **6 轮** |
| 对照 | 静置噪声对照 + 稳定性过滤 |
| 判定 | A强 / B中 / C弱 三级 |
| **★ 只读保证** | `0x81`（写）出现 **0 次** |

### 结果

| 阶段 | 结果 |
|---|---|
| 自检 | ✅ `pawnio_open HR=0`、`pawnio_load HR=0`（2612 B）；3×256B 连读失败 57/27/32（per 256）、非 0xFF 197/227/222、**MD5 逐轮不同（RAM 活跃）** |
| 采集 | ✅ 6 相位 × 6 轮 |
| 分析 | **⚠ 全零**：所有相位"变化 > 噪声底"的偏移 = **0**；**噪声底 = 98** |

### 判定

> **"EC RAM 未见与按压/震动相关的稳定活动" ⇒ EC 线关闭（不再投入）。**

### ★ 保留意见（必须一并写出）

1. **噪声底 98 偏高 ⇒ 灵敏度有限。**
2. **若 EC "不经 RAM、直接驱动硬件"，本判据测不出。**

> ### ★★ 纪律
> **观测判据必须报"灵敏度"。**
> **"全零"只能得出"在此灵敏度下未见"，不能升格为"不存在"。**

（加严参数 `-Rounds 15 -GapMs 40` 可重跑，约 5 分钟。）

## 六、EC 附带的其它事实

| 项 | 说明 |
|---|---|
| EC 固件结构 | 已定位（payload **未解出**，3 MB 加密） |
| EC 与触觉的关联 | ❌ **无证据**（但也不是"已排除"） |
| 曾被怀疑的名字 | 已归因并更正（本项目一次错误推断的完整纠正，见 `docs/06-ec-acpi/`） |
| `0xC620/0xC621 = 5A/A5` | ⚠️ 这是**另一个项目**（开盖角度）的 EC 间接读签名，**不是** GT7868Q 的主机报文魔数 |

## 七、检查单

```
□ ACPI 表键按"平级"遍历了（SSD1..SSDS）？
□ 导出 32 表而不是 3 表？
□ iasl 用了 -e 且没用 -o？
□ 触觉关键词扫描做了？
□ 地址取自 _CRS 而不是 _ADR？
□ PawnIO 以管理员跑了？
□ EC 实验的只读保证验证了（0x81 出现 0 次）？
□ 结论里写了"灵敏度"（噪声底）？
□ 结论没有从"未见"升格为"不存在"？
```

## 八、附：EC 工具链的两处"真语法陷阱"

| # | 陷阱 | 根因 | 修复 |
|---|---|---|---|
| 1 | `L ("…")` 换行后接 `-f` 解析失败 | **PS 5.1 不认这种续行** | 改单行 |
| 2 | 文件开头 **3 个 BOM** | 多余 U+FEFF 被当"智能引号" ⇒ `param()` 不再是首语句 | 收敛为 1 个 BOM |

> **⇒ 交付纪律**：任何 ps1 交付前跑 `[ScriptBlock]::Create((Get-Content -Raw …))` **官方解析器全量检查**。
> 本项目据此扫描 ~60 个 ps1，发现 **16 个历史脚本有解析错误**（均不在当前流程）。
