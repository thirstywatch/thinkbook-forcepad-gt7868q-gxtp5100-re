# 10 · 语义定义 · 命令空间与配置格式

> **是什么**：本项目解出的全部**协议语义** —— 四张命令表、帧格式、cfg 的 TLV 与 TAG 命名空间。
> **做什么**：按"第几层"查表。
> **得到什么**：一套能直接照着构造/解析报文的语义定义。

---

## 一、★ 四张命令表（必须声明是第几层）

| # | 名称 | 器件 | 入口 | 条数 |
|---|---|---|---|---|
| **①** | **TF100A 内部分派器** | TF100A | `0x0800E1C0` | **39**（`0x80`×1 + `0xA0`×16 + `0xA1`×22） |
| **②** | GT7868Q 内部分派器 | GT7868Q | `0x22C7C` | **16**（`0x0100`–`0x3500`） |
| **③** | GT7868Q 官方命令集 | GT7868Q | `CMD_ADDR 0x4160` | 约 10 |
| **④** | GT7868Q 主机报文 | GT7868Q | `0x1ACEC` | 6 种类型 |

> ### ★★★ **① 与 ② 的命令号完全一致**
> ⇒ **那 16 条属 TF100A，GT7868Q 侧只是中继副本。**
> **所以不存在"GT7868Q 有 16 条命令"这回事。**

> `39` 与 `38` 是**同一个东西**：39 = `0x80`×1 + `0xA0`×16 + `0xA1`×22；38 = 后两类子命令之和。

## 二、① TF100A 命令空间（39 条）

### 类 `0x80` —— 单入口

| 类 | 子命令 | handler | 形态 |
|---|---|---|---|
| `0x80` | 任意 | `0x08001628` | 不按子命令分发；`bl 0x08008900`，随后 `r1=0x80; bl 0x08001C2`（**按 0x80 字节块做校验**），并把 `0x20005FF4+0x34` 钳到 `0x3E8`(1000) |

> ⚠️ **形态判断**：带 0x80 字节块 + 校验的路径 → **疑似固件/数据写入族**。
> **三个类里最危险的一个。**

### ★ 类 `0xA0` —— 恰好 **16** 个合法值（完整表）

| 值 | handler | 目标子函数 | 形态 |
|---|---|---|---|
| `0x0100` | `0x0800937E` | `0x08001F8C(ctx+4)` | 命令 |
| `0x0500` | `0x0800932A` | `0x08001694` | 命令 |
| **`0x0B00`** | `0x08009368` | **`0x080088C0(ctx)` ← 写波形缓冲** | ★ **触觉** |
| **`0x0D00`** | `0x08009378` | **`0x080086B4()` ← 清缓冲 / arm** | ★ **触觉** |
| `0x0E00` | `0x080092F4` | `0x08006E28(1, ctx+4)` | 命令 |
| `0x1100` | `0x080092E0` | `0x08006E28(1, ctx+4)` | 命令 |
| `0x1200` | `0x08009308` | `0x08004CD4()` | 命令 |
| `0x1400` | `0x080093BC` | `0x08002F30()` | 命令 |
| `0x1700` | `0x08009332` | `0x080013AC(ctx+4, 0x2000616E)` | 命令 |
| `0x1F00` | `0x0800934E` | `0x08006E28(2, ctx+4)` | 命令 |
| `0x2000` | `0x080092CE` | `0x080049EC(ctx+4)` | 命令 |
| `0x2400` | `0x08009362` | `0x08004CD4()` | 命令 |
| `0x2600` | `0x080093AA` | `0x08001F70(ctx+4)` | 命令 |
| `0x3200` | `0x08009396` | `0x08001FC0(ctx+4, 0x1B)` | 命令 |
| `0x3300` | `0x08009390` | `0x08001F68()` | 命令 |
| `0x3500` | `0x0800930E` | `0x08004A20(ctx+4, 0x2000616E)` | 命令 |
| **其它** | `0x080093C2` → `0x080093C4` | 置 `[0x20004946]=1` 后返回 | **no-op** |

> ### ★ 只有 `0x0B00`（写波形缓冲）和 `0x0D00`（清缓冲/arm）与波形有关 —— **它们写的是 TF100A 自己的缓冲，不是马达。**
> **★ `0xA0` 里有 4 条命令能改变固件运行模式。**

### ★ 类 `0xA1` —— 恰好 **22** 个合法值（**全是查询**）

**全部把结果写进响应缓冲 `0x200041B4`（`ctx+0x8C`）⇒ 这一族是查询（只读）。**

| 值 | handler | 值 | handler |
|---|---|---|---|
| **`0x0203`** ★ | `0x080095B2` | `0x1600` | `0x080096E0` |
| `0x0400` | `0x0800954A` | `0x1800` | `0x08009586` |
| `0x0700` | `0x08009508` | `0x1D00` | `0x080094F0` |
| `0x0800` | `0x080095D8` | `0x2300` | `0x08009632` |
| `0x0A00` | `0x08009690` | `0x2800` | `0x08009728` |
| **`0x0B00`** | `0x08009674` | `0x2900` | `0x080096F8` |
| `0x0F00` | `0x08009618` | `0x2B00` | `0x080095A2` |
| `0x1300` | `0x08009564` | `0x2C00` | `0x08009710` |
| `0x1500` | `0x080096C2` | `0x2E00` | `0x08009532` |

### 类 `0xA2` —— 回复类（**固件自己发，主机禁发**）

> 🔴 **`0xA2` 是异步产物，不是命令的同步应答。**
> **⇒ "没收到 `A2`"不能证明设备拒绝。**

### ★ 边界外探测是安全的

兜底行为已确认：往分派器发非法值不会触发写操作。
（但**仍要守红线**：单次 ≤32 B、间隔 ≥500 ms。）

## 三、③ GT7868Q 官方命令集（`CMD_ADDR 0x4160`）

| 项 | 值 |
|---|---|
| 命令帧 | **5 字节** `{cmd, param, 0, 0, cksum}` |
| 完整命令表 | **仅 10 条**：`0x32/0x33/0x34` · `0x80/0x83/0x7D` · `{00 10}` / `{00 11}` / `{0E 13}` / `{03 03}` |
| **有无马达/触觉命令** | ❌ **无任何马达/触觉命令** |

**写时序（离线解出）**：

| 项 | 值 |
|---|---|
| 状态判据 | `0xFF` = 空闲是**常态**；写完 5 字节命令后字节0 一律回 `FF`（**不是接受信号**） |
| `0x82` | **仅**为命令 `0x80` 的应答，且需等约 **250 ms** |

**★ 一次真 bug 的修复**：`Gx::Write` 的 16 位帧长度字段应为 **`+5`**（官方），曾误用 `+7` ⇒ **所有写探针的每一帧都被设备静默丢弃**。
修后实测：`+7` 时 `0x4160` 毫无变化；`+5` 时变成 `FF 00 00 00`（**写入落地**）。

## 五、`tpcfgsid*.cfg` 格式（★ 完整解出）

### 5.1 文件头（64 B，定案）

| 偏移 | 字段 |
|---|---|
| `0x3B` | `u16LE` = TLV 区长度 |
| `0x3D` | `u8` = 条目数 |
| **`0x40`** | TLV 区起点 |

**★ 自校验闭合**：`0x40 + 1238 = 1302` ✅（= 文件长度）

### 5.2 ★★ 帧序：`[LEN:u8][TAG:u8][payload: LEN-2]`

> 🔴 **旧线的 `[TAG][LEN]` 是反的。**

同起点 `0x40` 头对头对比：

| 帧序 | 覆盖率 | TAG 递增性 |
|---|---|---|
| **`[LEN][TAG]`** | **94.8% / 96.4%** | **55 / 53 条严格递增 1.00** |
| `[TAG][LEN]` | **0.0%** | — |

**⇒ 判定帧序的方法：头对头对比覆盖率 + 看 TAG 是否单调递增。不要猜。**

### 5.3 ★ TAG 命名空间**跨厂商共享**

- sid0（Xiaomi 7867）vs sid3（LaiBao 7986P）**共有 40 个 TAG**
- **`TAG 0x5C` 逐字节相同**

### 5.4 ★★ 触觉配置区 = `TAG 0x50 – 0x7A`

| TAG | 语义 |
|---|---|
| **`0x5C`** | **时长阶梯模板**（10, 20, 80, 800, 1000, 2000, 8000, 10000 … ms） |
| **`0x5D`** | **机型相关档位**（32,64,192 vs 64,128,192） |
| `0x50` / `0x60` / `0x68` | **以 128 为零点的 ± 微调表**（u16） |

### 5.5 ★ 54 B 跨厂商公共骨架

三份 cfg 共有的一段 54 字节结构（sid0/sid2/sid3 均存在）。

### 5.6 ⚠️ 例外

**`sid2`（7863）不是 `[LEN][TAG]` 帧格式。** 不要对所有 cfg 套用同一解析器。

## 六、配置体（1024 B，固件内）与 cfg 的关系

| 结论 | 内容 |
|---|---|
| ★ | **固件配置体与 cfg 只共享 `TAG 0x01`（索引表）** |
| ★ | **触觉区在固件配置体里 0 命中** ⇒ **触觉参数只随 `tpcfgsid<sid>.cfg` 下发** |
| ★★ | **本机的 cfg 映像就在自己的固件里** —— 外层 4,412 B 明文含 **4 份配置副本**，与活体 `0x96F8` **逐字节相同** |

### 三份 cfg 的机型归属（**都不是本机**）

| 文件 | 机型 | SID |
|---|---|---|
| `tpcfgsid0_Xiaomi7867_20240307.cfg` | Xiaomi 7867（MARSEI） | sid0 |
| `tpcfgsid2_20230407.cfg` | NOR_G1 7863 | sid2 |
| `tpcfgsid3_LaiBao7986P_20220701.cfg` | LaiBao 7986P（BERLIN） | sid3 |

### ★ 官方命名佐证

较新 `tpupdate_driver.dll` 有整套 `cfgUpdate*`：
`Chip cfg version ↔ cfg file version` **双向比对**、`Write cfg data to 0x%04X`。

> **⇒ 触觉参数确实由 GT7868Q 接收并配置 —— 但"参数"不等于"触发"。**
> 主机仍无法"让它在某一刻震"。

## 七、AW86927 语义（TRIG 与波形）

| 项 | 内容 |
|---|---|
| **TRIG1/2/3** | 真实存在（数据手册定案） |
| ⚠️ **"只靠一个脉冲"不成立** | 需要完整的波形下载 + 配置序列 |
| **边沿 → 波形映射** | 官方应用电路给出映射关系（见 `docs/02-hardware/`） |
| **8 KB SRAM 波形库** | **掉电即失** ⇒ 每次上电必须有主控经 I²C 下载 |
| 播放 | `0x09 = 0x01`（GO） / `0x09 = 0x02`（STOP） |
| 状态 | `0x3F` 低 4 位 STATE，0 = STANDBY |
