# 04 · ARM/Thumb 反汇编与追踪

> **是什么**：对解出的固件反汇编，回答"代码在哪、什么架构、基址多少、命令分派器在哪、最终输出到哪个引脚"。
> **做什么**：定基址 → 判指令集 → 定位分派器 → 建调用图 → **反向追溯输出端**。
> **得到什么**：完整命令表 + 一条"从现象倒推到引脚"的链路。

---

## 一、是什么

本项目能完整反汇编的只有 **TF100A**（钛方压力 MCU，STM32F1 类 = **Cortex-M3**）。
GT7868Q 的代码**拿不到**（在 ROM 里，读不出来，见下）。

> ⚠️ **注意区分两个程序、两套地址空间**：GT7868Q 与 TF100A 是两颗不同的芯片，
> **它们的地址不得混在一张表里用**。本项目曾因此产生 **5 项连带更正**。

---

## 二、做什么

### 步骤 1：★ 地址映射三步解法（可直接照抄）

| 步 | 做什么 | 本项目结果 |
|---|---|---|
| **①** | 读向量表首 8 字节：`SP`（+0）/ `Reset`（+4） | `SP=0x200076C8`、`Reset=0x08005165` |
| **②** | 用 `SP` 反推 SRAM 基址、用 `Reset` 反推 flash 基址 | `0x20000000`（SRAM）/ `0x08000000`（flash）⇒ 确认 STM32F1 类内存映射 |
| **③** | 用"文件偏移 ↔ 运行地址"的一对锚点求**加载偏移** | **加载基址 `0x08005000` ↔ file `0x19ABC`** |

**★ 三重交叉验证定案 `0x08005000`**（不是 `0x08000000`）：
1. 向量表 `Reset` 值落在 `0x08005xxx` 段
2. 代码中的绝对地址引用全部落在 `0x08005xxx` 以上
3. 文件尾 `0x19ABC + 56,480 = 0x2775C =` 文件长度，算术闭合

> 🔴 **曾犯的归属错误**：`0x19A00–0x2775C` 那段 ARM 代码曾被归给 GT7868Q，**实际是 TF100A**。

**校验**：镜像开头 = 标准 ARM 运行库 ⇒ **"解析正确"的最强佐证**。

### 步骤 2：指令集判定 —— ★ 必须做四类反例标定

| 判据 | 在各类输入上的表现 | 结论 |
|---|---|---|
| ~~"Thumb 消费字节%"~~ | **全 0x00 → 100%**；**英文清单 → 94.7%**；真 Thumb 码 → 高 | 🔴 **不专一**，只是"非随机判据" |
| **真代码对照样本** | GT7936L（BERLIN 族真明文）代码段覆盖 **64.1%** | 本项目载荷 13 块最高 **2.4%** ⇒ **不是代码** |

> ### ★★ 纪律
> **凡"覆盖率 / 消费率"型判据，必须做【真代码 · 随机 · 全零 · 纯文本】四类反例标定。**
> **凡判据在"全零/文本"上也给高分，就不能用来判代码。**

用 capstone 实测（含基线标定）：**13 块明文全部不是代码**。

### 步骤 3：定位命令分派器 + 穷举命令全集

| 目标 | 方法 | 本项目结果 |
|---|---|---|
| 分派器入口 | 找"取子命令 → 跳表 / 连续 `cmp`"模式 | TF100A **`0x0800E1C0`** |
| 命令全集 | 从分派器穷举所有合法值 | **39 条** = `0x80`×1 + `0xA0`×16 + `0xA1`×22 |
| 类 `0x80` | 单入口 | 1 条 |
| 类 `0xA0` | **恰好 16 个合法值**（完整表） | 其中 4 条能改变固件运行模式 |
| 类 `0xA1` | **恰好 22 个合法值**，**全是查询** | — |
| 类 `0xA2` | **回复类**（固件自己发，**禁发**） | — |
| 调用图 | 脚本提取 caller/callee | 见 `tools/analysis/` |

**★ 边界外探测是安全的**：兜底行为已确认，往分派器发非法值不会触发写操作。
（但**仍要守红线**：单次 ≤32 B、间隔 ≥500 ms。）

### 步骤 4：★ 输出端反向追溯（本项目最有价值的一次追踪）

> **思路转变**：不要去猜"哪条命令能震"，而是**从"震动"这个可观测现象倒推到引脚**。

| 环节 | 结果 |
|---|---|
| 判据 | `\|Δ压力\| > 40`（立即数 `0x28`） |
| 检测引擎 | **`0x080059E0`** —— ★ **三任务共用的检测引擎**，不是震动专属 |
| 点击阈值 | **140 按下 / 98 抬起**（2760 条报文实测） |
| 输出 | `PA3` 门铃（`0x0800D8B2` → GPIOA BRR）+ `A2` 异步回复帧（`0x08008A70` 打包器） |
| 输出例程 | **`0x08005E38`**，全 asm **唯一调用点 `0x08005B8C`** |

**★ TF100A 不驱动 LRA 的四条否定证据**：

1. 全 asm **无马达 / PWM / 定时器写**
2. `CR1.START` 全镜像 **0 次** ⇒ 只做从机，**不是 I²C 主机**
3. **无执行器路径**
4. `TIM2 = 200 Hz` **不是马达时基**（比"未必"更硬）

**⇒ 链路闭合，但终点不是马达。**

## 三、得到什么结果

| 项 | 值 |
|---|---|
| 完整命令表 | 39 条，分层（4 类） |
| 输出端链路 | 测压 → 判据 `\|Δ\|>40` → 检测引擎 `0x080059E0` → `PA3` 门铃 / `A2` 回复帧 |
| **关键否证** | TF100A **不驱动** LRA ⇒ 触觉执行在别处 |
| **破局点** | 判据立即数 `0x28` 是**可改的字节级目标**（见 METHOD.md 第 10 章） |

## 四、🔴 三个必须知道的陷阱

### 陷阱一：32 位常量搜索的假否定

| 案例 | 错误做法 | 真相 |
|---|---|---|
| `FLASH_KEY1 = 0x45670123` | `D.count(b'\x23\x01\x67\x45')` → "不存在" | 在 `0x2410A`，由 `movw r0,#0x0123` + `movt r0,#0x4567` 拼成，**从不以连续 4 字节出现** |
| `0x40005400` | 当作 I2C1 基址 | 实为 **GPIO 引脚助手** |
| `0x40005410` | 当作 `I2C1_DR` | 实为 **UART 数据寄存器** |

> ### ★ 纪律
> **验证 ARM/Thumb 的 imm32 常量必须用 `MOVW`/`MOVT` 配对解码或真反汇编，绝不能字节搜索。**

### 陷阱二：`0xA2` 是异步产物，不是同步应答

`0x20004090` 是一块 **16 字节控制块**，那三个 `cmp #N` **不是子命令编号**（曾误读）。

> ### ★ 纪律
> **"没收到 `A2`"不能证明设备拒绝。**

### 陷阱三：`lea` 目标地址计算（x86 侧）

反汇编 BIOS DXE 模块（x86-64）时，`lea` 的目标地址容易算错 —— 必须手工核对 RIP-relative 寻址。

## 五、为什么拿不到 GT7868Q 的代码

| 原因 | 说明 |
|---|---|
| **代码在 ROM** | 官方源码给出硬答案：GT7868Q 的核是 **8051（Turbo51）**，代码在 mask ROM，**flash 里只有数据** |
| **离线不可得** | 芯片自身的 I²C/GPIO 控制器痕迹，离线拿不到 |
| **曾用错 ISA** | 🔴 本项目曾**只测了 ARM / RISC-V，没测 8051** ⇒ 漏项 |
| **读固件通路已穷举关闭** | CMD/flash 读命令在软件层全部不通 |

**真正可能拿到代码的四条路**（按可行性）：
1. 找同芯片的其它厂商固件包（可能含可 dump 的 RAM 镜像）
2. 硬件 SWD/JTAG（TF100A 疑似有 **7 个外露金属触点 = SWD 编程焊盘**）
3. 拆片读 mask ROM（ destructive，成本高）
4. 厂商泄漏的调试固件

## 六、检查单

```
□ 基址经三重交叉验证？（不要默认 0x08000000）
□ 指令集判据做过四类反例标定？
□ 有同类真明文固件做对照样本？
□ 32 位常量是反汇编/MOVW-MOVT 得到的，不是字节搜的？
□ 命令表声明了是"第几层"？（四张表别混）
□ 0xA2 按异步处理了？
□ 地址属于哪个器件，标注了吗？
```
