# 06 · I²C / SPB 边界与旁路

> **是什么**：回答"主机能不能绕过 `hidi2c`，直接对模组里的触觉驱动 IC（AW86927）说话"。
> **做什么**：清点控制器 → 逐条总线实测 → 评估三条 Windows 路线 → Linux 交叉验证。
> **得到什么**：**"主机侧不存在任何可达 AW86927 的 I²C 通道"**（5/5 定案）。

---

## 一、本机 I²C 资源全谱

| 项 | 数量 |
|---|---|
| ACPI 定义的 I²C 控制器 | **16 个** |
| Windows 实际暴露的 | **3 条** |
| 触控板所在 | `\_SB.PC00.I2C0`（`PCI 8086:7E78`，0:15.0） |

**触控板连接参数（SPB 资源）**：

| 项 | 值 |
|---|---|
| 总线 | `\_SB.PC00.I2C0` |
| 频率 | **400 kHz** |
| 从地址 | **`0x2C`**（`_CRS` 权威） |
| 描述符寄存器 | `0x20` |
| 驱动 | `hidi2c`（**I²C-HID，非 SPI**） |

> ⚠️ **`_ADR = 1` 不是 I²C 地址** —— `Name (_ADR, One)` 只是 DSDT 模板遗留。
> **I²C 子设备地址权威在 `_CRS`**（本项目曾长期用错）。

---

## 二、★ 硬约束（微软文档原文）

1. **SPB 驱动只能用自己硬件资源里带的 connection ID**，而它由 **ACPI `_CRS`** 决定。
2. **用户态明文禁止**发 SPB 请求。
3. **同一外设的连接同时只能一家持有** ⇒ 「并列 SPB 客户端」这条路**从原理上就不成立**。

**本轮实证**：**全 DSDT 里没有任何设备声明在 `0x5A`。**

---

## 三、逐条总线实测（5/5 闭合）

| 总线 | 结果 |
|---|---|
| **I2C0**（触控板所在） | 已被 `hidi2c` 独占；另 `i2cdetect` 会**崩内核** |
| **I2C2 / I2C3** | ❌ **BAR 基址 = 0**（`0x4` 属性位、无地址；`restart-device` 成功但**不分配**）⇒ 主机不可访问 |
| **I2C4 / I2C5** | 同形态，已扫清 |
| **PCH SMBus** | ❌ 已排除（**有阳性对照 `0x44`**） |

> ### ★ 重要区分
> **"有 BAR 范围" ≠ "主机能访问"。**
> BAR = 0（未编程地址）时，`restart-device` **会成功但不分配地址** ⇒ 看起来"操作成功"，实际探针无效。

---

## 四、Windows 侧三条路线与可行性

| 路线 | 做法 | 前提 / 代价 |
|---|---|---|
| **W1** | 关 HVCI + 驱动黑名单 → 用 **RWEverything** 直打 I2C0 的 MMIO | 最快，**降安全性**；**唯一完全不动 Secure Boot 的路**；实验后必须 `step9-restore` 还原 |
| **W2** | 自写 **PawnIO 模块**（`pci_config_read_dword` + `io_space_map` + `virtual_write_dword`）直驱 I²C 控制器 MMIO | 🔴 **PawnIO 校验 RSA-4096 签名**，官方版只加载官方签名模块 ⇒ 要么提交上游签名（W4），要么装 Unrestricted edition（= 未签名内核驱动 ⇒ **关 Secure Boot**） |
| **W3** | 补 ACPI 节点（SSDT 覆盖）+ 自签 KMDF SPB 客户端 | 唯一可长期留驻形态，**代价最高** |

**建议顺序**：**W4（提交模块，长线）× W1（RWEverything，短线）并行。**

## 五、🔴 工具陷阱（必读）

### RWEverything 的 `Access → I²C/SMBus` 是假阴性源

> 该菜单走的是 **PCH SMBus（i801）**，**不是**触控板所在的 `\_SB.PC00.I2C0`（DesignWare MMIO）。
> **⇒ 照它做必然是假阴性。**

✅ **修正版**：改用 RWE 的 **Memory（`R32`/`W32`）直打 I2C0 的 BAR**，并**必须**先做阳性对照。

**阳性对照怎么做**：划手指，看 `IC_STATUS`（**+0x70**）的 **bit0 / bit5** 是否跳变。不跳 ⇒ 探针无效。

### RWE 脚本的两个坑

| 坑 | 说明 |
|---|---|
| **变量名越界** | RWE 脚本变量名**只能是 `Local0`–`LocalF`**。用 `Local10`+ 的脚本"看起来完好、从未成功执行过" |
| **`/LogFile` 静默失败** | 不报错但不出结果 ⇒ 必须另做结果校验 |

## 七、得到什么结果

**"主机侧不存在任何可达 AW86927 的 I²C 通道"**（5/5 定案）：
每条总线要么已扫清、要么主机根本不可访问。

**⇒ 剩下的只有硬件判据**：万用表通断档测 AW86927 的 SDA/SCL 接到哪颗主控、`HDP`/`HDN` 接到哪 —— **一次测量定案"路径 A 还是 B"**。

```
□ ACPI 定义的控制器 vs Windows 暴露的，都清点了？

□ 阳性对照做了（划手指看 IC_STATUS bit0/bit5）？

□ RWE 脚本变量名在 Local0–LocalF 范围内？
```
