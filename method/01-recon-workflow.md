# 01 · 侦察工作流总览

> **是什么**：一套"从零开始搞清楚一个未知触控板模组"的固定流程。
> **做什么**：八步，先分层、再逐层拿证据、每层标注证据强度。
> **得到什么**：一张逐环节证据分级表，能说出"哪段已确认、哪段是推断、哪段没证据"。

---

## 一、工作流

```
① 资产采集      固件 / ACPI / HID 描述符 / 驱动 / 官方源码     （只读，零风险）
        ↓
② 容器解析      BIN 是什么格式？边界在哪？                      （纯离线）
        ↓
③ 加扰破解      高熵区能不能还原？                              （纯离线）
        ↓
④ 反汇编追踪    代码在哪？命令分派器在哪？输出到哪？             （纯离线）
        ↓
⑤ 主机侧探测    HID 能发什么？设备栈长什么样？                   （真机，只读）
        ↓
⑥ 总线边界      I²C 能不能碰到目标器件？                         （真机，高风险）
        ↓
⑦ 固件侧旁证    EC / ACPI / BIOS DXE 有没有别的通路？            （真机 + 离线）
        ↓
⑧ 收口          逐环节定级，判断"路走不走得通"
```

## 二、每一步的核心产出与"做完"的判据

| 步 | 核心产出 | 这一步算做完的判据 |
|---|---|---|
| ① 资产采集 | 固件 / ACPI / 描述符 / 官方源码 | 全部 sha256 已归档；官方源码**拿全**（含 `gtx2/`） |
| ② 容器解析 | 子固件边界表 | **官方校验和通过** + 各 `size` 合计自洽 |
| ③ 加扰破解 | 明文固件 | 三条验证全过（直方图配平 / 相位多样本交叉 / 解出后整块零填充） |
| ④ 反汇编追踪 | 命令表 + 输出链路 | 基址三重交叉验证；判据做过四类反例标定 |
| ⑤ 主机侧探测 | 三条硬事实 | `OutputReportByteLength` 读到；设备栈与进程查过 |
| ⑥ 总线边界 | 逐总线判定 | 每条都有结论，且**有阳性对照** |
| ⑦ 固件侧旁证 | EC/ACPI/BIOS 结论 | 结论含"灵敏度"标注 |
| ⑧ 收口 | 证据分级表 | 每环节有级别 + "缺什么" + "排除不了什么" |

## 三、两条元纪律

### 1. 先离线、后真机

**①–④ 是纯离线的**，只要有材料就能在任何机器上重跑 —— **应该做满再碰真机**。
本项目 20 轮里最有价值的两个推进（加扰破解、输出端追溯）**都是离线做出的**。

### 2. "是什么 / 做什么 / 得到什么"三段式

每做一个动作，都写下：
- **是什么**：这个环节在回答什么问题
- **做什么**：工具 + 步骤 + 关键参数
- **得到什么**：结果 + **我凭什么相信它**（判据）+ **排除不了什么**（边界）

> **漏写"排除不了什么"，是本项目几乎所有重大错误的共同点。**

## 四、本工作流的实际收益

| 环节 | 传统做法 | 本工作流 |
|---|---|---|
| 判断"固件是不是加密" | 看熵 ≈ 8.0 ⇒ "加密了" | 三项定量 + 周期分析 ⇒ "1024 周期 XOR 加扰，可解" |
| 找"哪条命令能震" | 穷举所有命令 | **反向追溯**：从"震动"倒推到引脚 ⇒ 直接定位判据立即数 |
| 判断"能不能控制" | 试一堆工具 | 三条独立硬事实 ⇒ 一次性结构性封死 |
| 判断"路走不走得通" | 凭感觉 | **证据强度 × 可改性** 矩阵 ⇒ 唯一路径浮现 |
