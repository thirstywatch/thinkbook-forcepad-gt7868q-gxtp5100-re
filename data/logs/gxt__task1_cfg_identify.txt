任务 #1 结论：本机固件内嵌 4 份 0x43C 记录，而非驱动 CAB 里的 sid0/sid2/sid3
==================================================================================

### 1. 记录定位（用 ASCII 标记串验证周期性）
```
 标记 "777777" 出现于：0x00287, 0x006C3, 0x00AFF, 0x00F3B
 间隔：0x43C, 0x43C, 0x43C
 ⇒ 记录长度 = 0x43C = 1084 B
```

### 2. 四份记录的头部（前 44 B）
```
 #0 @0x00000  73 c0 11 04 00 00 04 3c 00 00 04 3c 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00

```

 解读：
   #0  [0:4]=73 c0 11 04 | [4:8]=00 00 04 3c | [8:12]=00 00 04 3c | [12:44]=全零
       ⇒ 出厂默认模板（长度字段 0x43C，其余占位）
   #1~3 [0:4]=c7 80 08 03 | [4:8]=50 28 28 41 | [8:12]=10 32 0d 19 | ...
       ⇒ 量产配置（三份完全一致）

### 3. 差异定位（#0 vs #1）
```
 差异索引范围 0x000..0x04B，共 70 处
   → 0x000..0x02B：记录头（44 B，完全不同）
   → 0x02C..0x04B：机型差异字段（32 B，部分不同）
   → 0x04C..0x43B：公共主体（1008 B，完全相同）

 #0 vs #1：头差异 44 · 主体差异 26
 #0 vs #2：头差异 44 · 主体差异 26
 #0 vs #3：头差异 44 · 主体差异 26
 #1 vs #2：头差异 0 · 主体差异 0
 #1 vs #3：头差异 0 · 主体差异 0
 #2 vs #3：头差异 0 · 主体差异 0
```

### 4. 驱动 CAB 的 sid0/sid2/sid3 是否在固件里
```
 sid0.bin ( 1302 B)：完整匹配 0 处 · 64B 中段匹配 0 处
 sid2.bin (  552 B)：完整匹配 0 处 · 64B 中段匹配 0 处
 sid3.bin ( 1866 B)：完整匹配 0 处 · 64B 中段匹配 0 处
 ⇒ 全部为 0 ⇒ 驱动 CAB 里的 cfg 不是本机固件内嵌的配置
 ⇒ 它们是「主机侧待写入 payload」，格式同族但内容不同（不同机型/方案商）
```
