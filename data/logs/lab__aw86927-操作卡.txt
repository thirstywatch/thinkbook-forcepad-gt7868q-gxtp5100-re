======================================================================
 AW86927 操作卡 v2   —— 2026-10-03 修订（v1 有一处会导致失败的错）
 用途：在 RWEverything 里手工让触控板震一下
======================================================================

【前提】已按《方案A》第 1、2 节关掉 HVCI + 易受攻击驱动黑名单 → 重启
        → 且 Rw.exe **不再报 `Driver cannot be loaded`**（仍报=固件强制，见审计文档漏洞5）

【★ 位置，别搞错】
  ❌ 不要用 `Access → I²C/SMBus` —— 那个页面走 **PCH SMBus（i801）**，
     不是触控板所在的那条总线。用它读 0x5A 必然是假阴性（审计文档漏洞 1）。
  ✅ 用 `Access → Memory`（物理内存/MMIO）：
     先在 `Access → PCI` 里选 **bus 0 / dev 0x15 / fun 0**（= 8086:7E78）
     读出 **BAR0**，低 4 位清零，记作 BAR。
  ✅ 顺手确认 DesignWare 指纹：读 **BAR + 0xFC**，应为 **0x44570140**。
     （不在就换 BAR+0x100 / 0x200 / 0x400 / 0x800 / 0x1000 再读 +0xFC）

【三条铁律】
  1) 只读 → 抄下原值 → 再写；任何一步异常，立刻写 0x09 ← 0x02 停
  2) 绝不写 0x00(软复位) / 0x06(BST 供电) / 0x45 / 0x4D / 0x4E
  3) ★ v1 的错：**不要整字节覆盖 0x08**。0x08 里有 AUTO_BST(bit4)，
     整字节写 0x02 会把升压关掉 → 很可能就不震了。必须**读-改-写**。

======================================================================
 第 0 步（只读，必做）：先看**厂商自己**是怎么让它震的
======================================================================
 在 Memory 里把这三处开自动刷新（RWE 的自动刷新间隔 MemoryInterval，默认 1500 ms）：
      0x3F  GLB_STATE      （0=STANDBY 6=CONT 7=RAM 8=RTP 9=TRIG）
      0x08  PLAYCFG3       （PLAY_MODE = bit[1:0]）
      0x09  PLAYCFG4       （STOP=bit1 / GO=bit0）
 然后在触控板上**点按**（就是平时那种"咔哒"的手感来源）。

 判读：
   A) 0x3F 从 0 跳到某个值 → **记下是哪一个**，那就是厂商用的播放模式：
        6 = CONT   7 = RAM   8 = RTP   9 = TRIG
      ⇒ 第 1 步就照抄那个 PLAY_MODE（比我们猜 CONT 靠谱得多）
   B) 0x3F 全程不动、0x08 也全程为 0
      ⇒ ⚠️ 点按震动**不经过 AW86927 的播放引擎**（可能是 TRIG 引脚硬件触发，
         或由模组里另一条路径驱动）⇒ **那我们写 GO 大概率也不会震**，
         需要换思路，而不是继续调寄存器。
   C) 点按瞬间 0x3F 跳但不稳定 / 一闪而过
      ⇒ 说明 RWE 的 1.5 s 刷新太慢，把 MemoryInterval 调小（如 100 ms）再试。

======================================================================
 第 0.5 步（只读）：抄原值（还原时要用）
======================================================================
  寄存器        名称          原值（抄这里）
  0x08          PLAYCFG3      0x______
  0x09          PLAYCFG4      0x______
  0x3F          GLB_STATE     0x______   (只读)
  0x07          PLAYCFG2 GAIN 0x______
  0x0A          WAVCFG1       0x______
  0x12          WAVCFG9       0x______
  0x18          CONTCFG1      0x______   (只有要走 CONT 才需要)
  0x1D          CONTCFG6      0x______   (TRACK_EN / DRV1_LVL)

  原值本身也是诊断信息：
   0x08 的 **bit4(AUTO_BST) = 1**  ⇒ 模块确实配置过它、自动升压已开 ⇒ 我们的写入更可能生效
   0x08 = 0 且 0x3F = 0            ⇒ 芯片处于未配置/待机 ⇒ 先回第 0 步，别急着写

======================================================================
 第 1 步：CONT 模式试震（★ 读-改-写）
======================================================================
  1) 读 0x08，得到 V
  2) 写 0x08 ← (V AND 0xFC) OR 0x02      ; 只改低 2 位 = PLAY_MODE=2(CONT)，保留其它位
        例：V=0x10 → 写 0x12 ；V=0x00 → 写 0x02
        （若第 0 步看到厂商用的是别的模式，这里就填那个值：RAM=0 / RTP=1 / CONT=2）
  3) 写 0x09 ← 0x01                       ; ★ GO —— 开始震（会持续，不会自己停）
  4) 立刻读 0x3F 看 GLB_STATE 变成什么（6=CONT 正常；仍是 0 说明没跑起来）
  5) 数秒内写 0x09 ← 0x02                 ; STOP —— 别走开

  震了 ⇒ 目标达成（想"滑动时震"，就把这套写进脚本、由滑动事件触发）
  不震 ⇒ 进第 1b 步（因为 "显式配置 + 上传波形" 比 CONT 更接近厂商路径）

======================================================================
 第 1b 步：RAM 模式（15 步，厂商/主线驱动验证过的路径）
          —— CONT 不震时再走这条
======================================================================
  ⚠️ 这条要碰 0x45 / 0x4D / 0x4E（供电与检测），确认无异议再做。
  完整 15 步见 `aw86927_play.py --dry-run --mode ram` 的输出，摘要：
  ① 0x45 ← (0x45 OR 0x04)      EN_RAMINIT
  ② 0x2D ← 0x08 ; 0x2E ← 0x00  SRAM 基址 0x0800
  ③ 0x40 ← 0x08 ; 0x41 ← 0x00  写指针
  ④ 0x42 ← 连续写 5 B 波形头:  01 08 05 08 6A    (ver=1, start=0805, end=086A)
  ⑤ 0x42 ← 连续写 102 B 正弦波形（字节表见 aw86927_play.py 里的 WAVE）
  ⑥ 0x4E ← 0x00                DET_SEQ0 = VBAT
  ⑦ 0x4D ← 0x01                DET_GO ; 等 ~3 ms ; 0x4D ← 0x00
  ⑧ 0x45 ← (0x45 AND 0xFB)     关 EN_RAMINIT
  ⑨ 0x07 ← 0x7C                增益（防失真）
  ⑩ 0x08 ← (V AND 0xFC) OR 0x10   PLAY_MODE=0(RAM) + AUTO_BST=1（读-改-写！）
  ⑪ 0x0A ← 0x01  WAVSEQ1=1 ; ⑫ 0x0B ← 0x00  WAVSEQ2=0
  ⑬ 0x12 ← 0x0F  SEQ1LOOP=0x0F（无限循环）
  ⑭ 0x09 ← 0x01   ★ GO
  ⑮ 数秒内 0x09 ← 0x02  STOP

======================================================================
 停止 / 还原
======================================================================
  停：    0x09 ← 0x02
  还原：  按第 0.5 步抄下的原值逐个写回（0x08 / 0x09 / 0x07 / 0x0A / 0x12，走 RAM 再加 0x2D/0x2E/0x40/0x45/0x4D/0x4E）
  兜底：  万一 RWE 崩了、芯片一直震 —— **关机/拔电池即复位**（芯片没有非易失状态）

======================================================================
 ★ 为什么可能不震 —— 诚实清单（别把"不震"当成"路走错了"）
======================================================================
 1) 整字节写 0x08 把 AUTO_BST 清掉        ⇒ 已在 v2 修正（读-改-写）
 2) **升压(BST)没人开**                    ⇒ 点按震动可能是"按需开启升压"的，
    我们在没人点按时写 GO，可能没升压 ⇒ 震不动。**这是目前无法排除的风险。**
    （缓解：先看第 0 步 —— 若点按瞬间 0x3F 跳，说明播放引擎在跑，升压路径是通的）
 3) **CONT 模式在 F0 未标定/TRACK_EN 状态下可能不出力** ⇒ 所以备了第 1b 步的 RAM 模式
 4) **总线并发**：hidi2c 一直在这条总线上收发触摸数据，我们的事务可能被 abort
    ⇒ 观察到传输失败，就先在设备管理器里**禁用 `ACPI\GXTP5100\1`** 释放总线再试
 5) **芯片被 RESET 脚拉住 / 实际在 0x5B** ⇒ 逐个排除（读 CHIPID 时就已经区分过）
 6) **点按震动根本不走 AW86927 的播放引擎** ⇒ 第 0 步的判读 B 就是这个情形

======================================================================
 成功率诚实估计（不是保证）
======================================================================
 - "0x5A 在主机总线上"：**未知**，约 50~60%（蓝莓两台同构模组都是同总线）
 - 若在总线上：**照抄第 0 步看到的厂商模式** → 成功概率较高
                直接猜 CONT 就写                    → 成功率明显更低（可能 3~5 成）
 ⇒ **所以第 0 步（只读、零风险）不是可选项，是提高成功率的关键一步。**
 ⇒ 本操作卡**不能保证一定震**；它能保证的是：每一步都可回退、且失败时能区分原因。
